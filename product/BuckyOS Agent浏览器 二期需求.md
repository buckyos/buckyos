# BuckyOS Agent浏览器 二期需求

主人从手机打开 BuckyOS Agent 浏览器，默认看到一个由自己的 Agent 持续维护的本地网站。平时，Agent 替主人看多个网站，把值得读的内容提前整理好。主人想办事时，可以在地址栏打开原站，登录账号，在聊天里把事情交给 Agent。这两条路径共用 Personal Server 上的浏览器，主要由 Agent 操作，主人可以随时参与。

## 一、首版跑通了什么，实际使用卡在哪里

首版已经跑通了「Agent 先看网页，再生成一个网页给主人看」。主人在原网页点击「重排」，URL 就是触发器。有现成结果，浏览器直接跳转到生成页。首次处理这个 URL，系统创建任务，通常按手机屏幕重新排版、翻译成主人的语言，也可以只保留主人感兴趣的内容，顺带滤去广告等干扰。

用雅虎日本首页测试时，两个问题最明显。

| 主人的实际操作 | 首版体验 | 二期需要达到的体验 |
| --- | --- | --- |
| 在手机上读到中文标题，点开一条新闻 | 又回到了日文原站。想读中文正文，需要再发起一次任务并等待。 | 首页上已发布的新闻可以直接点开，正文、配图和相关评论已随内容准备好。 |
| 隔一段时间回来，再点「重排」 | 有时立刻打开，却还是旧新闻。有时恰好触发刷新，连旧内容也看不到。主人无从判断结果有多新。 | Agent 平时在后台跟踪更新。主人打开就能读到最近一次准备好的内容，能看出同步时间，更新期间也能继续阅读。 |

## 二、初始化共用浏览器

第一次打开时，如果个人重排站还没有内容源，首页提供两个起点。主人可以导入已有收藏夹，也可以手动打开几个常看的网站，把想长期阅读的网站加入重排站。以后遇到新来源，仍可从原站直接加入。

需要使用账号时，主人在共用浏览器里亲自登录。例如，主人可以先登录 Amazon，之后让 Agent 分析购物记录。也可以登录 Google，之后让 Agent 帮忙处理邮件。账号按实际需要陆续接入。

浏览器记录主人在网页上的操作。Agent 可以据此知道主人已经打开了哪个站、走到了哪个页面，以及平时在哪些内容上停留较久。主人已经通过操作给出的线索，Agent 可以直接利用，省去逐项询问。手动访问提供的是浏览线索，点击「重排」则表达了把内容纳入个人站的意图。

## 三、用一个个人重排站阅读多个内容源

### 建站用 Work Session，维护用 Goal Session

主人首次建立个人重排站，是一个普通的 **Work Session**。它有明确的终点：选定的来源已经能从总首页读到，脚本和模板已经写好，并用实际页面核对过。主人在聊天里看进度、补充要求，拿到可用的站点。此后由一个长期的 **Goal Session** 接手，主要定期同步数据，并分析主人的浏览行为。

| | Work Session | Goal Session |
| --- | --- | --- |
| 怎样看这个站 | 一个要开发的项目 | 一个正在运行的站点 |
| 负责什么 | 建站，接入新来源，按主人的要求做版本升级 | 定期同步数据，分析浏览行为，处理小故障 |
| 怎样开始 | 主人提出新的要求 | 到了时间，或有值得处理的变化 |
| 怎样结束 | 主人要的结果做好 | 长期维护，主人可以随时暂停 |
| 留下什么 | 可用的站点、脚本和模板，以及交给 Goal Session 的维护目标 | 持续更新的内容，对选题的调整，给主人的建议 |

两者面对的是同一个工作区。Work Session 把它当作一个项目来开发，主人说需求变了，它才动手。在 Goal Session 眼里，这个工作区是活的，需要按时完成运维任务。这是 Agent 承担长期事务的通用做法，个人重排站是其中一例。

Work Session 完成时写定 Goal Session 的**维护目标**，包括维护哪些来源、各自多久更新、页面怎样组织、主人关心什么。以后主人要加来源、换栏目或改变关注点，再开一个 Work Session。它做完后改写同一个 Goal Session 的维护目标，站点和已有内容继续沿用。Goal Session 从下一次运行起按新目标维护。

运维的范围是让站点保持维护目标规定的样子，例如重试失败的同步、调整抓取频率、在原站小改之后修正脚本。遇到更大的问题，例如原站彻底改版、模板要重做、原来取内容的办法不再可用，Goal Session 说明发生了什么、影响哪些内容、建议怎样升级，请主人开一个 Work Session 做版本升级。主人决定之前，已发布的内容继续可读，没受影响的来源照常更新。升级期间站点继续用旧版本，新版本核对通过后再切换。

维护目标体现主人的意图，只有主人提出的要求能够改写它。Goal Session 从浏览行为里看出兴趣变化时，可以在现有目标内调整选题和排版。需要改变目标本身，例如增加一个来源，就向主人提出建议。主人能看到当前的维护目标，以及每次被改了什么。

### 从原站加入，从来源页读起

主人在雅虎日本首页点「重排」，表达的是「我想看这里的内容」。Agent 用一个 Work Session 将雅虎日本加入个人站的来源列表，按新闻站的特点选择文章模板，抓取选定范围内的列表、正文、配图和可见评论。首次准备好后，主人落到个人重排站里的**雅虎日本来源页**。下次从同一原站切入，可以直接打开已有结果。

| 站内位置 | 主人可以做什么 |
| --- | --- |
| 总首页 | 看各个来源的新内容。默认可以按时间浏览，也可以请 Agent 按主题、兴趣调整顺序和版式。 |
| 来源页 | 只看某个来源，例如筛选雅虎日本的文章。可回到总首页，继续看其他来源。 |
| 文章详情页 | 用自己的语言读正文、看配图和选入的评论。可以返回列表，也可以切到这篇文章的原始网页。 |

原站与个人重排站是两个独立的网站。Agent 抓取时将内容和阅读所需的资源保存在 Personal Server，并将已收录内容之间的链接指向相应的本地页面。主人从手机浏览的是普通网页，点标题、看图、返回列表都可以直接完成。即使原站暂时不可达，只要手机能连到 Personal Server，已同步的内容就能照常读。日常阅读也无需持续启动无头浏览器来渲染原站。

### 在后台更新，给前台保留可读内容

一个 Goal Session 持续维护一组来源及其共用的重排站。再加一个来源，由 Work Session 接入，做好后扩充这个 Goal Session 的维护目标，不另建 Goal Session。这样可以共用长期任务的运行成本，也便于把不同网站对同一事件的报道放在一起。

| 来源的状态 | 主人打开时看到什么 |
| --- | --- |
| 首次加入，还没有本地内容 | 显示正在准备哪个来源。主人可以继续读其他来源，稍后回来。 |
| 已有本地内容，后台正在检查或抓取更新 | 立即打开当前可读版本，并显示最近一次成功同步的时间。刷新中的列表和详情仍然可读。 |
| 新一批内容已准备好 | 新标题和相应的本地详情一起出现，主人点开即可阅读。 |
| 本次更新失败，或来源需要重新登录 | 已发布内容继续可读。来源页说明当前情况。需要登录时，主人可回原站完成，再由 Agent 继续。 |
| 遇到大问题，等主人决定是否升级 | 已发布内容继续可读。来源页说明问题和升级建议，主人可以从这里发起升级。 |

这里的「本地」指主人的 Personal Server。报道的发布时间和 Agent 最近成功同步的时间应分别表达，让主人能判断是原报道较早，还是这个来源尚未更新。各类来源的默认检查频率、首次抓取多少篇、保留多长历史，留待用实际站点验证。

### 例行更新主要由脚本完成

Goal Session 倾向于用脚本完成周期性的工作。接入来源的 Work Session 先看懂原站，写好脚本和模板，并用实际页面核对结果。来源稳定工作一段时间后，从原始站点到构造出重排页的流程主要由脚本完成，Goal Session 的推理留给需要判断的事。

| 由谁完成 | 做什么 | 什么时候 |
| --- | --- | --- |
| 脚本 | 检查更新，抓取列表、正文、配图和评论，去重，按模板生成页面，成批发布，记录同步时间 | 按这个来源的更新频率反复运行 |
| 脚本里的模型步骤 | 翻译、摘要、归类。每篇内容按固定要求处理一次，不启动 Agent 的推理 | 有新内容时 |
| Goal Session 的推理 | 分析浏览行为，调整选题，跟踪主人关注的事件，修复脚本的小故障 | 出现需要判断的事时 |
| Work Session | 建站，接入新来源，按主人的要求做版本升级，写好脚本和模板 | 主人提出要求时 |

脚本优先选择不依赖浏览器的办法。原站有订阅源或公开接口就直接用，其次直接取网页内容。只有内容必须经浏览器渲染才出现，或者要带着主人的登录状态才能看到时，才打开浏览器。例行更新因此很少占用浏览器，内存较小的 Personal Server 也能维护多个来源。

脚本正常退出不等于同步成功。每次运行都要核对拿到的内容是否完整，例如列表是否突然变空、正文是否过短、配图是否缺失。没有通过核对的内容不发布，也不更新同步时间。原站改版使脚本失效时，已发布内容继续可读，Goal Session 被唤醒修复脚本，用实际页面核对后恢复例行更新。改动超出运维范围时，请主人开 Work Session 升级。需要主人重新登录时，也告诉主人。

### 主人可以和 Agent 一起设计这个站

产品提供可用的默认站点和几句启动建站的引导话术。主人既可以只调一个来源的内容和版式，也可以按自己的逻辑重新设计首页、栏目和站内功能。例如，主人可以这样交代。

> 把我收藏的几个日本新闻网站加进来。首页用中文，手机上一列显示。同一件事有后续时，放在我上次读过的报道下面。

Goal Session 每天都有机会根据实际使用情况调整选题和排版。对于主人持续关注的事件，Agent 可以跟踪后续进展、寻找原始材料，也可以补充来自不同角度且有出处的报道。主人应能看出一条补充来自哪里，以及它为先前的报道增加了什么信息。

维护的目标是让主人获得更全面、真实的信息。页面停留时间是决定是否深挖一件事的重要线索，也要结合主人的明确要求、长期阅读习惯和内容类别。比如主人连续几天细读同一事件，Agent 可以多花一些 Token 查找后续和交叉印证的材料。对于平时只扫一眼的栏目，保持基本更新即可。停留时间用于分配有限的调查预算，优化效果取决于主人最终读到了什么。

## 四、从地址栏进原站，在聊天里交代任务

首页要让主人能立即找到地址栏和代办入口。输入网址后，浏览器打开原站，主人可以只完成登录，也可以把当前网页交给 Agent。聊天沿用当前页面、登录状态和操作进度，主人在一个 **Work Session** 里推进一件有明确终点的事。

以在手机上办理日本驾照相关业务为例，主人和 Agent 可以这样配合。

1. 主人从地址栏打开办理网站，完成所需的身份登录。如果已经手动找到办理入口，可以从当前页面接着办。
2. 主人发现手机版表单难用，点击「重排」。Agent 识别出这是办事页面，优先给出填写任务说明的入口。主人也可以自己选择「请 Agent 办事」，或改选阅读内容。
3. 主人在聊天里交代「帮我办这项业务」。Agent 接手已登录的浏览器，沿原站流程操作。主人可以从手机查看进度。遇到只有主人知道的信息，Agent 在聊天中询问，收到答复后继续。
4. 办完后，Agent 在同一对话里说明办理结果。如果网站仍需主人操作，Agent 说明当前步骤和待办事项，主人可以在当前页面接手。

同一个网站可能兼有内容和业务。主人看办事指南时可以临时请 Agent 解释，也可以在进入申请表后切换为代办。长期加入哪个内容源、这次要完成什么事，都由主人的意图决定。

## 五、可选的辅助浏览

偶尔遇到一页外文说明，主人可以在聊天里说「用中文总结这页」。一次 Work Session 就能给出结果，按需也可生成一次性重排页面。至于让主人把 Agent 浏览器当成日常主力浏览器、给任意网页配常驻问答侧栏，需求强度还有待验证。二期优先把个人重排站和聊天代办两条路径做完整。

## 六、二期验收场景

| 场景 | 通过条件 |
| --- | --- |
| 首次使用，导入书签后再添加雅虎日本 | 浏览器默认首页可见多个来源。从雅虎日本点「重排」能直接进入其来源页，再回到总首页。建站和添加雅虎日本各由一个 Work Session 完成，做好后都由同一 Goal Session 维护，它的维护目标里能看到新来源。 |
| 在手机上连续点开两篇已收录的日文新闻 | 两篇均能直接阅读中文详情和已收录配图，能切回对应原文。连读过程无需逐篇等待 Agent。 |
| 原站发布新文章，主人恰好在后台刷新时打开首页 | 旧列表和旧文章仍可读，同步时间可见。新文章出现在列表时，其本地正文已可打开。 |
| 一个公开新闻来源已稳定工作一段时间，主人没有提新要求 | 新文章按约定频率出现，列表、译文、正文和配图完整。这些例行更新由脚本完成，没有启动 Agent 推理。不打开浏览器就能取到内容的来源，更新期间也没有启动浏览器。 |
| 原站小改，脚本取不到正文 | 已发布内容仍可读，同步时间停在最近一次成功的时间，来源页说明当前情况。Goal Session 修复脚本后新文章恢复出现，主人无需操作。 |
| 原站彻底改版，原来的脚本和模板不再适用 | 主人收到一条升级请求，看得懂问题、影响和建议。主人同意后由 Work Session 升级，新版本核对通过再生效，Goal Session 继续维护。其间旧内容可读，其他来源照常更新。主人暂不处理时，不重复打扰。 |
| 主人要求把持续关注的新闻按事件组织 | 首页按约定调整。出现可核实的后续报道时，Agent 将其关联到已读事件，保留来源，主人可辨认进展。 |
| 主人在手机上打开办事网站并登录 | 可从当前页面立即交代任务，Agent 沿用登录态接手。主人看得见进度，能在同一对话中补充信息并看到结果。 |
