# File Browser UI 产品评审与实施建议

日期：2026-09-07。代码基线：`85609f6e`。评审对象：`src/frame/desktop/src/app/filebrowser`。

第 1–5 节保留基于 `85609f6e` 的原始评审，现状、行号和首次测试结果均指评审时的代码。第 6 节记录本轮实现与验收，第 7 节列出仍依赖后端或后续阶段的能力；优先级表示实施顺序。

## 1. 结论与评审范围

现有原型已经具备文件管理器的主要骨架：目录树、地址栏和历史导航、多标签和双栏、列表/图标视图、异步搜索、集合引用、元信息面板、上传队列，以及新建目录、重命名、移动、删除等操作。

下一阶段应优先让“看到的位置、选中的对象、实际执行的操作”保持一致，再补齐整理、查找、打开和恢复文件的完整流程。建议保留现有视觉风格及 Topic/Collection 设计，把文件列表和常用操作放到更容易使用的位置。

评审方法：

- 在 `src/frame/desktop` 执行 `pnpm run dev --host 127.0.0.1 --port 4173`，用 Chromium/Playwright 打开 `/?scenario=normal&fbData=mock`。
- 实际检查 1440×1000、1100×850 桌面视口和 375×812 触屏视口；桌面默认 Files 窗口为 1024×720。
- 对照组件、菜单分发、数据接口、Mock 与 NFSP 适配器代码，并参考 [现有 PRD](./filebrowser_PRD.md)。PRD 用于确认意图，当前行为以代码和运行结果为准。
- 执行现有 `tests/e2e/pages/filebrowser.spec.ts`：首轮 8/9 通过；侧栏失败重试用例未观察到预期错误态，单独重跑通过。该用例存在一次未稳定复现的失败，不能宣称整套首次通过。
- 未连接真实 NFSP 服务；涉及真实权限、批量部分失败、复制、回收站、打包下载的判断，分别注明代码依据或后端依赖。Mock 刷新恢复种子数据属于原型机制，不作为持久化缺陷。

应保留的已有实现：虚拟化和按需加载、搜索失败/部分结果提示、上传失败重试、表单校验，以及“文件夹删除实体、集合移除引用、视图只读”的语义区分。

## 3. 任务定义与验收

### FB-01：标签状态隔离，操作必须对应当前上下文

**现状与证据**

运行复现：在 Documents 选中 `Kyoto Trip Plan.md`，点击顶部 Pictures 标签，旧文件仍留在状态栏和右侧面板；此时“重命名”可用，弹框内仍是 `Kyoto Trip Plan.md`。该操作指向当前目录之外的文件，删除/移动共用同一份选择状态，也存在相同风险。

搜索 `trip` 后点击左侧 Downloads，标签与路径改成 Downloads，中间仍显示原搜索结果。手机关闭文件信息面板后，标题仍可能保留所选文件名。

代码入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L106)。`searchQuery`、排序、视图和选择保存在 pane 级；顶部选标签直接调用 `setActiveTabId`（约 1590 行），没有执行上下文切换流程；`navigate`（247 行）没有退出搜索。

**建议行为**

- 路径、历史、搜索、选择、滚动位置归属具体标签；切换标签恢复该标签状态。可先采用切换时清空选择和搜索的最小修复，再补恢复能力。
- 点击目录树、地址栏、面包屑进入目录时退出当前搜索；浏览器内的返回操作可恢复此前的搜索及其结果位置。
- 加载新目录时，旧目录的选择不能继续驱动删除、重命名和移动。操作提交时校验所属上下文；异步完成后不能清除用户在另一个标签中新选的对象。
- 手机关闭详情后，页面标题恢复当前目录；文件选择状态与是否展示详情分别管理。

**验收**

1. Documents 选 A → Pictures：Pictures 的工具栏、状态栏和详情均不使用 A；返回 Documents 后按既定策略恢复或清空选择。
2. 搜索 `trip` → 点击 Downloads：展示 Downloads 文件列表及正确路径；返回可恢复搜索状态。
3. A 标签发起慢操作 → 切换 B 并选中文件：A 的完成反馈标明原目标，B 的选择不受影响。
4. 在左右双栏重复以上场景，各栏的操作对象保持独立。

### FB-02：让用户知道批量操作到底完成了哪些文件

**现状与证据**

代码审查发现：剪切粘贴在 `moveSelected` 完成前清空剪贴板；失败后无法直接再次粘贴。[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L826) 的批量移动/删除只展示整批成功或一个错误提示。

[NFSP folderOps](../../src/frame/desktop/src/app/filebrowser/data/nfsp/folderOps.ts#L66) 逐项执行，全部完成后才通知目录刷新。如果第二项失败，第一项可能已经变更，而 UI 没有逐项结果；实时 watch 是否及时补偿未在本次验证。

**建议行为**

- 批量操作提供总数、已成功、失败、未执行/已取消四类结果，并可展开文件名、目标位置和失败原因。
- 已成功的源目录和目标目录立即更新。失败项保留选择，提供“重试失败项”；不得把部分成功显示成全部失败或全部成功。
- 剪切状态在移动成功后再清除；部分失败只保留未移动的条目。剪切条目显示淡化状态，Esc 可取消待粘贴状态。
- 用户取消的是剩余操作；已经成功的变更仍显示在结果中。有后端撤销能力时才显示“撤销”。

**验收**

Mock 注入三项操作：A 成功、B 同名冲突、C 无权限。UI 显示准确结果，A 在源/目标目录均及时更新；重试不会重复移动 A；剪贴板保留 B/C。另测目标目录失效、请求中断和操作期间切换标签。

**实施入口与依赖**

`data/folderOps.ts` 当前返回 `Promise<void>`，需补充逐项结果或等价的进度回调，并同步 Mock、NFSP、调用方和 `UI_DATAMODEL.md`。首先保证已有逐项后端调用的结果可解释，不预设服务端具备整批原子事务。

### FB-03：以 Files 窗口宽度决定布局

**现状与证据**

1440px 桌面视口中的默认窗口实测：宽 1024px，左导航约 260px，右详情约 320px，中间列表仅 442px；列表列宽最低合计 710px。工具栏可视宽 410px，内容宽 503px，搜索和排序需要横向滚动才能完整找到。未选文件时，空详情栏仍占据 320px。

代码入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L385) 使用 viewport 媒体查询；固定侧栏位于 1566、1721 行。[MainContent.tsx](../../src/frame/desktop/src/app/filebrowser/MainContent.tsx#L408) 固定各列最小宽度；[TopBar.tsx](../../src/frame/desktop/src/app/filebrowser/TopBar.tsx#L554) 工具栏整体横向滚动。

**建议行为**

- 按应用容器宽度决定单栏、双栏和详情的呈现方式。默认 1024px 窗口优先保证文件名及大小/修改时间可读，详情按需展开；侧栏可折叠、可调宽并记忆偏好。
- 窄窗口将次要操作收入“更多”，保留上传、新建、搜索、视图入口；搜索不应依赖发现横向滚动。
- 次要列可隐藏，文件名列优先分配空间。完整列模式允许明确的横向滚动，但不以它承载基本操作。
- 双栏显示清晰的活动栏标识，空间不足时收起详情/导航，或退回单栏；保持每栏文件名可读。
- 在所有宽度下保留“详情”入口。当前 901–1279px 桌面模式没有可见右详情栏，不能因此失去查看信息或打开文件的路径。

**验收**

覆盖 720、1024、1440px 应用容器及 375px 手机；验证默认窗口和最大化窗口。无需横滚即可找到搜索和主操作；长文件名不挤掉操作按钮；双栏两侧地址可辨识，切换焦点有可见反馈。

### FB-04：复制与移动应完成一个可预期的整理流程

**现状与证据**

复制按钮可用，但粘贴到普通目录只提示“Copying file content is not supported yet”；复制到集合实际添加引用，这部分语义已经区分。“移动到”只能选目录树根及第一层目录。文件右键菜单有“复制路径”，没有常规剪切/复制/粘贴，和工具栏不一致。

入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L784)、[menu/registry.ts](../../src/frame/desktop/src/app/filebrowser/menu/registry.ts#L150)。内容复制当前 UI 与操作接口未提供实际实现；不能把它当作已有能力接线即可。

**建议行为**

- 工具栏、右键菜单和快捷键使用同一操作定义；“复制文件”“复制路径”“添加到集合”明确区分。
- “移动到/复制到”打开可浏览任意层级的目标目录对话框，含面包屑、最近目标和“在这里新建文件夹”。双栏时提供“移动/复制到另一栏”。
- 目标必须可写；禁止目录移入自身或后代；同目录移动给出无需移动提示。
- 冲突统一呈现源/目标名称、类型、大小和时间，至少支持“保留两者”“跳过”“取消”。后端保证安全替换时再开放“替换”；文件夹合并单独定义，不能默认等同于文件覆盖。
- 同批次可“应用到后续同类冲突”。命名、冲突检测与实际提交都经过操作接口，避免只在当前已加载列表中判断重名。

**验收**

从 Documents 复制/移动到三级子目录；同名文件和同名目录走不同规则；目录移入自身被阻止；无权限目标可解释。复制到普通目录保留原件，添加到集合只增加引用。移动失败后的剪贴板行为满足 FB-02。

**分期**

本轮先实现移动目标选择、菜单一致性和不支持复制时的明确禁用说明。完整内容复制、替换及目录合并按后端能力分别交付，Mock 与真实模式使用一致的能力判断。

**用户体验后的后续要求**：文件复制是常用功能，已单列为 [P1 TODO：FB-04-COPY 文件复制端到端支持](./filebrowser_copy_TODO.md)。后续 Code Agent 必须补齐必要后端能力并完成真实 NFSP E2E 验收；仅提供禁用说明不满足该 TODO 的交付要求。

### FB-05：删除需要清楚展示后果，并提供恢复路径

**现状与证据**

普通目录已有 `window.confirm` 二次确认，文案明确不可撤销；随后直接删除，NFSP 适配器对目录传入 `recursive: true`。当前没有回收站。集合移除引用已有独立文案，应该保留。

入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L862)、[NFSP folderOps](../../src/frame/desktop/src/app/filebrowser/data/nfsp/folderOps.ts#L66)。这是删除恢复能力缺口，不是“没有任何确认”。

**建议行为**

- 近期把浏览器确认框替换为现有应用内对话框，列出文件名、数量、所在位置；包含目录时明确会影响其内容。不可恢复模式的按钮命名为“永久删除”。
- 有回收站能力后，常规 Delete 为“移到回收站”；提供原位置、删除时间、恢复、永久删除和清空操作。成功反馈可直接进入回收站。
- 恢复遇到原目录不存在或重名时，允许选目标或保留两者，复用冲突流程。
- 集合中继续显示“从集合移除”，不进入文件回收站，也不删除原文件。提示解释原文件仍保留。

**验收**

取消删除不改变任何条目；删除含子目录的文件夹时后果明确；移除集合引用后原件可见；启用回收站后的删除→恢复保持内容一致，并覆盖重名/原目录丢失。无回收站后端时不得展示虚假的恢复或撤销按钮。

### FB-06：搜索必须能限定范围，并直接打开和处理结果

**现状与证据**

已有异步搜索、命中原因、部分结果提示和分页。`useSearch` 支持 `scope`，但调用只传关键词；UI 没有范围和筛选入口。搜索结果卡片只处理单击选择，缺少列表中的双击打开、右键和多选。

实测 1100px 视口搜索 `trip` 并点击文档，仅状态栏变化；详情栏隐藏，用户无法从结果直接打开内容。点击目录树仍停留搜索的问题见 FB-01。状态栏数量取自原目录，而非搜索结果。

入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L121)、[SearchResultsPanel.tsx](../../src/frame/desktop/src/app/filebrowser/SearchResultsPanel.tsx#L87)、[data/search.ts](../../src/frame/desktop/src/app/filebrowser/data/search.ts#L63)。

**建议行为**

- 默认搜索当前目录及子目录，显式显示范围；一键扩大为“所有可访问文件”。集合/Topic 内的范围选项按后端支持提供，不能暗中把局部搜索变成全局搜索。
- 首轮筛选提供类型和修改时间，后续增加大小；“清除筛选”和“退出搜索”分别明确。
- 结果复用文件条目的选择、打开、右键和批量交互；跨目录结果的权限按目标文件判断，不能继承搜索前所在目录的写权限。
- 支持“打开所在位置并选中”：不仅进入父目录，还要把目标加载、滚动到可见并高亮。在上万条目录中不能只寻找首批已加载记录。
- 双击/Enter 打开完整 Preview；详情栏收起时仍能打开。后续预览导航使用当前搜索结果的顺序，不使用搜索前目录的文件序列。
- 状态栏展示已返回结果数、有无更多及当前选择。技术来源耗时放入可展开详情；保留用户能理解的“文件名匹配/内容匹配/相关主题”说明。

**验收**

同一关键词在当前目录与全局范围结果不同；切换范围能更新结果；选择结果后可打开、下载或定位原件。位于目标目录第 5000 项的文件可以被定位。搜索返回期间修改关键词时，旧响应不覆盖新结果；部分来源失效仍能操作已有结果。

### FB-07：真正可理解的全选与键盘操作

**现状与证据**

已支持 Ctrl/Cmd 单击多选和 Shift 已加载区间选择。实测 `stress-10k`：Ctrl+A 后仍只选原条目；右键“Select all”后状态栏为 `selected 200 of 10000`。界面虽展示数量，但“全选”实际只选已加载项。桌面列表行也没有完整键盘导航。

入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L167)、[MainContent.tsx](../../src/frame/desktop/src/app/filebrowser/MainContent.tsx#L483)。

**建议行为**

- 立即把现有行为命名为“选择已加载的 N 项”。完整版本提供“选择此目录/此结果中的全部项目”，使用结果快照或可取消的枚举，不能依赖滚动加载来决定范围。
- 跨页 Shift 选择要获取完整区间，或明确说明只选择已加载条目；用户确认前不得宣称完整选择。
- 增加行复选框和表头选择状态，包括部分选中态。选择数量持续可见；批量删除/移动前明确实际处理数量。
- 支持方向键、Shift+方向键、Enter 打开、F2 重命名、Delete、Ctrl/Cmd+C/X/V/A、Esc 清选择、Alt+方向键历史导航、Ctrl/Cmd+L 编辑路径。macOS 按键按平台习惯映射。
- 快捷键仅作用于活动 Files 窗口/栏；输入框内保留编辑行为。桌面列表有可聚焦条目、可见焦点及选中状态语义。

**验收**

全选 1 万项时数量与最终操作范围一致，DOM 继续保持虚拟化；取消全选枚举不会误发操作。在重命名输入框按 Ctrl+A 只选文本。两个 Files 窗口同时打开时快捷键仅作用于活动窗口。

### FB-08：上传下载围绕目标目录和任务结果设计

**现状与证据**

上传已有多文件选择、阶段/进度、取消和失败重试。空目录文案提示可以拖入文件，但本模块未实现拖放处理。上传重名在 NFSP 适配器中直接成为不可重试错误，没有冲突选择。传输悬浮面板不能整体收起，也没有“打开目标位置”。

下载目前直接触发浏览器链接；Mock 无下载数据面，NFSP 适配器支持单文件 URL。批量菜单可以包含目录，但 `downloadUrl` 对目录返回 null，混合选择时会静默跳过目录。

入口：[FileBrowserView.tsx](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L752)、[TransfersPanel.tsx](../../src/frame/desktop/src/app/filebrowser/TransfersPanel.tsx#L108)、[data/nfsp/transfers.ts](../../src/frame/desktop/src/app/filebrowser/data/nfsp/transfers.ts#L87)。

**建议行为**

- 支持拖入本地文件上传，覆盖区域明确显示目标目录；文件夹上传保留相对目录层级，按浏览器支持展示入口。内部拖动移动/复制复用 FB-04 的语义和冲突流程。
- 集合中拖入系统内文件应为添加引用；不能把本地上传悄悄变成引用。暂不支持的拖入来源用明确提示收尾。
- 同名上传进入统一冲突流程。大文件提供“准备中/上传中/保存中”等可理解状态；速率和剩余时间只在有可靠估算时显示。
- 任务面板可收起为数量入口，展示目标位置、总体进度、失败项、重试失败项、清理已完成；完成后可以定位文件。手机上传时不长期遮住列表主操作。
- 下载文件夹或多个条目提供打包下载能力；交付前明确标识不支持的目录，不得静默跳过。浏览器接管下载时反馈“已交给浏览器下载”，不伪称已落盘成功。

**验收**

拖入三个文件到指定目录，创建结果位置正确；重名时可保留两者或跳过；取消、失败重试保持明确状态。混合选择文件和文件夹下载时，每一项均被处理或明确列为不支持；收起任务面板后仍可再次查看任务。

**依赖边界**

文件夹打包、可恢复上传及大型服务器文件复制需专门确认服务端能力。现有 NFSP 上传先读整个文件到内存计算哈希，大文件真实表现未验证；后续增加真实大文件场景，不能仅凭 Mock 进度判断可用。

### FB-10：操作能力与状态文案必须可信

**现状与证据**

设置、新建文本、分享、相机等入口仍仅返回 mock 提示。菜单主要根据位置能力启用，缺少逐文件的“可重命名/可移动/可下载/可分享”等操作状态。已有 `LocationCapabilities` 是可复用基础，不必重新建立一套旁路判断。

入口：[工具栏占位](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L953)、[分享占位](../../src/frame/desktop/src/app/filebrowser/FileBrowserView.tsx#L1108)、[LocationCapabilities](../../src/frame/desktop/src/app/filebrowser/data/FolderReader.ts#L31)、[AI 状态](../../src/frame/desktop/src/app/filebrowser/PreviewPanel.tsx#L301)、[fileDisplay.tsx](../../src/frame/desktop/src/app/filebrowser/fileDisplay.tsx#L35)。

**建议行为**

- 每个动作区分“可用、无权限、不支持、状态加载中”，工具栏、菜单和手机动作面板读取同一规则；不可用原因能够被查看。
- 保留原型演示入口时明确标识其演示性质。生产路径不把占位功能作为可用操作；用户点击后不应只得到内部 mock 文案。
- 新建文本若保留，完成命名→创建→选中新文件→打开编辑的流程。分享先明确对象、访问范围和只读/可上传权限，展示可撤销的链接/共享状态；复制公开 URL 与创建授权分享分别命名。

- 0 字节显示 `0 B`，未知大小显示“未知”；文件夹递归大小未统计时显示“未计算”。多选大小只统计已知值时标注范围。

**验收**

## 4. 推荐交付顺序

1. **先保证操作可信**：FB-01、FB-02，加上 FB-10 的占位能力与未知状态修正。最小验收是切标签不操作错对象，失败后知道哪些文件已变更。
2. **完成日常工作路径**：FB-03、FB-06、FB-07、FB-09，以及 FB-04 的移动目标选择与 FB-08 的上传反馈。以“找文件→打开→批量整理→确认结果”为一条完整流程验收。
3. **补齐需要后端的文件能力**：内容复制、冲突替换、回收站/恢复、文件夹打包下载、完整分享。每项先有可演示的 Mock 流程及能力约束，再验证真实 NFSP。
4. **提高长期效率**：FB-11、任务面板增强和偏好保存。现有 Topic/Story 的扩展可继续推进，但基础文件工作路径应先稳定。
