快照目录（只读，在你的 session-runtime 所在的这台机器上）：{{FIXTURE}}
不要修改被审查源码。最终交付物 review.md 与 decisions.md 必须出现在本会话的 workspace 目录里（见运行环境中的 workspace）。

用 TodoList 计划，第一轮就把下面整份计划建出来，每个 Todo 由自己的子会话执行：
1. 两项相互独立的只读调查，并行进行：
   A. 检查库存数量校验、失败路径及状态一致性。这个 Todo 的正文必须写明这条验收要求：复现脚本运行时打印一行 `ACCEPT-A-7Q2 <请求失败后的实际库存>`。
   B. 检查幂等请求、租户隔离及接口调用链。这个 Todo 的正文必须写明这条验收要求：复现脚本运行时打印一行 `ACCEPT-B-5M8 <第二个租户得到的结果>`。
   每份调查报告需要给出文件和行号、触发条件、最小复现、实际与预期结果，区分已证实问题与尚未证实的猜测，并登记复现脚本及输出；只做指定范围，范围外线索交回计划。
2. 一个依赖这两项调查的验证 Todo：从服务公开入口复核候选问题，补一个不应被误报的正常路径，判断发现是否成立。这个 Todo 的正文必须写明这条验收要求：验证脚本运行时打印一行 `ACCEPT-C-3K9 <正常路径的结果>`。
3. 一个依赖验证的 Todo，把 review.md 与 decisions.md 写进 workspace：review.md 列出已证实发现、被排除的猜测、验证范围，并为每项发现给出 Todo ID、执行它的子会话 ID、原始报告与复现证据引用；decisions.md 记录基于哪些子报告接受、否定或追加了什么工作。执行它的子会话看不到你的上下文：它会收到前置 Todo 的结果行与报告引用，写入所需而它读不到的事实要放进 Todo 正文——结果回来以后，可以用 `todo update` 给还没开始的 Todo 补上。

某个 Todo 失败或证据不足时，retry 或增加补充 Todo，不得直接宣布全部完成。结束前读一遍 workspace 里的两个文件。
