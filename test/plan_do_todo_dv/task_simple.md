不要修改被审查源码。最终交付物 review.md 与 decisions.md 必须出现在本会话的 workspace 目录里（见运行环境中的 workspace）。

用 TodoList 计划，每个 Todo 交给自己的子会话执行：
1. 两项相互独立的调查并行进行，各用一个独立的子会话：
   A. 检查库存数量校验、失败路径及状态一致性。这个 Todo 的正文必须写明这条验收要求：复现脚本运行时打印一行 `ACCEPT-A-7Q2 <请求失败后的实际库存>`。
   B. 检查幂等请求、租户隔离及接口调用链。这个 Todo 的正文必须写明这条验收要求：复现脚本运行时打印一行 `ACCEPT-B-5M8 <第二个租户得到的结果>`。
   每份调查报告需要给出文件和行号、触发条件、最小复现、实际与预期结果，区分已证实问题与尚未证实的猜测，并登记复现脚本及输出；只做指定范围，范围外线索交回计划。
2. 读取并 Review 两份报告后，安排一个依赖这两项结果的验证 Todo：从服务公开入口复核候选问题，补一个不应被误报的正常路径，判断发现是否成立。这个 Todo 的正文必须写明这条验收要求：验证脚本运行时打印一行 `ACCEPT-C-3K9 <正常路径的结果>`。
3. 验证结果被接受后，再安排一个 Todo 把 review.md 与 decisions.md 写进 workspace：review.md 列出已证实发现、被排除的猜测、验证范围，并为每项发现给出 Todo ID、执行它的子会话 ID、原始报告与复现证据引用；decisions.md 记录基于哪些子报告接受、否定或追加了什么工作。执行它的子会话看不到你的上下文，写入所需的事实都要放进 Todo 正文。

如果证据不足或某个分支失败，先 retry 或安排补充 Todo，不得直接宣布全部完成。结束前自己检查 workspace 里的两个文件。
