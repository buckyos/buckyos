### 优先问题的复现与排查入口

**MH2U-1**：双方打开同一新会话；A 每次填入不同文本并按 Enter，t0 间隔实测 `323/319/317/329 ms`；等待 30 秒，双方只有 FAST1、FAST2、FAST4；reload 后 raw count 都是 3，A 输入框为空。源头候选：[ConversationComposer.tsx](../../src/frame/desktop/src/app/messagehub/conversation/input/ConversationComposer.tsx) 的 `handleSend`（约 227 行）在发送锁存在时直接 return，先前异步发送完成后无条件清空输入和附件；[store.ts](../../src/frame/desktop/src/app/messagehub/api/store.ts) 约 736 行还会清空持久草稿。需要验证两层清理都不会覆盖后续编辑。

**MH2U-2**：管理员 UI 创建 C → C 登录并在可用后给 devtest 发消息 → A 的 Requests 中点 Accept contact → UI 显示“Could not save. Your changes are kept; please retry.” → 再点仍失败。新消息仍进请求箱。排查 [main.rs](../../src/frame/msg_center/src/main.rs) 的 `sync_zone_user_contacts_once` / 启动与 reload 同步，以及 [contact_mgr.rs](../../src/frame/msg_center/src/contact_mgr.rs) 的 owner 联系人查找与更新。证据只证明“联系人缺失导致更新失败”；不把推测的调度原因当作已证实根因。

**MH2U-3**：在包含旧图片的历史中连续收发，或接收含图片/视频的新消息；对比截图中动态媒体与后续气泡的位置。排查 [ConversationHistoryPane.tsx](../../src/frame/desktop/src/app/messagehub/conversation/history/ConversationHistoryPane.tsx) 约 323 行的虚拟化测量、ResizeObserver 与滚动锚点。部分检查点仍处于加载过程，不能据此宣称稳定布局永远重叠。

**MH2U-4**：选择 `big.bin`（73,400,320 字节）→ 发送约 2637 ms 完成 → B 卡片显示 70 MB → 点击内容返回 413，提示“This attachment is too large to open here” → 菜单无原文件下载 → 之后文本可继续发送。排查 [object_access.rs](../../src/frame/msg_center/src/object_access.rs) 的 `MAX_CONTENT_BYTES = 64 * 1024 * 1024` 与附件上传/发送前的限额联动。

**MH2U-5**：普通对话停留即可重复。前端 `store.ts:refreshRuntime` 调用不带 owner 的 `listUiSessionState(sessionId)`；个人偏好 `ensureSessionPrefs` 带 owner，因此本轮 Pin/Mute/个人标题保存成功与该错误不矛盾。服务端 legacy handler 对 `obj://msg-center/ui-state` 授权失败；建议先确认应调用哪个接口。

## 四个问题与总评

1. **bob 能否无人指导收消息、回复、发照片、找回历史？** 本轮辅助操作可以完成这些主链路；姓名、列表和图片卡片可识别。但回形针/返回/发送缺可访问名称，长历史与多个 Direct Message 需要理解侧栏，不能由脚本完成就断言普通用户首次使用无需指导。
2. **devtest 能否确定送达、知道 bob 看过？** 能看到双勾，但反馈曾落后实际接收约 20 秒；bob 离线也能送达收件箱。没有已读回执，不能确定 bob 看过（MH2U-6、11、17）。
3. **两人是否始终认为在同一段对话？** 不是。并发发起拆成两个会话，话题标题对端不共享，需要按内容和侧栏未读寻找（MH2U-8、9）。
4. **最影响日常 IM 使用的三件事？** 快速连发静默丢输入（MH2U-1）；新成员无法建立正常联系人关系（MH2U-2、7）；媒体分享不稳定，既有气泡遮挡，也有上传成功却无法取回的大文件（MH2U-3、4）。此外，关闭 Hub 时桌面没有新消息提醒，是实际使用必须考虑的已知缺口（MH2U-10）。

**总评：不好用。** 依据文档规则，E01–E06 中 E01、E02 出现 FAIL，尤其 E02 涉及不可恢复的输入丢失。普通往返、断网重试、多设备同步和多数附件链路可用，但不足以抵消数据可靠性和新成员加入路径的问题。建议先修 MH2U-1/2，再处理 MH2U-3/4/5；补测三项 INCONCLUSIVE 后再重新评估。没有可比的上一批同版本运行记录，本报告不作改善或退化判断。
