# MessageHub 多用户 E2E 测试流程

Test Agent 用 Playwright 为每个用户各开一个浏览器，其中 bob 用手机视口，分别登录 DV Test 环境。
然后像真实用户一样看页面、找入口、完成日常的聊天任务。

每个任务给出两个结论：

- **能不能完成**；
- **好不好用**，附上理由。

## 1. 环境

**入口**：`https://test.buckyos.io`，MessageHub 也可以直接打开 `/messagehub`。
本机 `/etc/hosts` 把 `test.buckyos.io` 指向 `::1`，浏览器启动时要用 `--host-resolver-rules` 把 zone 域名映射到 `127.0.0.1`。

**账号**：

| 用户 | 密码 | 人设 | 设备 |
|---|---|---|---|
| devtest | `bucky2025` | zone 主人，懂技术 | 电脑浏览器 |
| bob | `buckyos2026` | 家人，不懂技术，主要用手机 | 手机视口（如 Pixel 7，宽度须小于 768 px） |
| alice | `buckyos2026` | 家人或朋友，不懂技术 | 电脑浏览器 |

**浏览器**：

- 每个用户各启动一个独立的浏览器，互不共享登录状态和本地存储。
- 通过登录页登录。

**参与的用户**：

- 私聊任务：devtest 和 bob。
- 群聊任务：三人都参与。群聊需要部署了 Self-host Group v2 的版本。如果界面上找不到“新建群”入口，说明部署版本不对，群聊任务全部跳过。

**测试数据**：

- 每条测试消息末尾加上本次运行的标签，例如 `[run-1001-#3]`，便于在历史中查找。
- 准备一张手机照片、一个 PDF 和一段短视频。

## 2. 执行方式

- **只通过页面操作**：看页面、找入口、点击和输入。不借助源码、test id、内部接口，也不用脚本直接改数据。
- **找不到做法时**：换思路再试；试过三种合理的路径仍不行，就记为未完成，并说明卡在哪里。
- **等待其他用户的结果**：最多等 30 秒左右。没有出现时刷新一次，并记下是否必须刷新才能看到。
- **截图**：在关键节点给每个参与者各截一张图，作为结论的依据。
- **还原**：任务中建的群、做的屏蔽、改过的设置，在任务结束时通过界面还原或删除。

## 3. 怎样评价“好不好用”

从角色出发评价：

- **devtest**：在意消息是否送到、对方是否看到。
- **bob 和 alice**：不懂技术。看到 DID、技术术语或报错代码，都算负担。

每个任务回答以下问题，并给出 1–5 分：

1. **完成情况**：完成、部分完成还是未完成？卡在哪里？
2. **入口**：第一次使用的人，能否不经提示就找到做法？用了几步？
3. **结果**：是否及时、可信？各方看到的内容是否一致？
4. **出错**：出错时能否看懂原因？能否恢复？会不会丢失或重复？
5. **手机**：在手机上操作是否顺手？

理由要指向实际看到的现象和截图。可以拿常见聊天软件的做法作为用户预期的参照，但要说明这只是参照。

全部任务做完后，私聊和群聊各给一个总体评价：**好用**、**可用但有明显障碍**或**不好用**，并列出最影响使用的三件事。

## 4. 私聊任务（devtest × bob）

### P01 第一次联系

devtest 在电脑上找到 bob，发出第一条消息。bob 在手机上登录 MessageHub，看到消息并回复。devtest 不刷新页面就看到了回复。

- **完成标准**：
  - 消息和回复各出现一次，双方顺序一致；
  - 双方处在同一段对话里；
  - 刷新后历史仍在。
- **看点**：
  - devtest 怎样找到 bob；
  - bob 打开应用后，能否立刻注意到新消息，并认出是谁发的。

### P02 你一句我一句

两人轮流各发几条消息。其中一人快速连发 5 条，另一人在对方连发时正在打字。

- **完成标准**：
  - 每条消息恰好出现一次，双方顺序一致；
  - 连发的消息没有丢失；
  - 正在输入的内容没有被打断或清空。
- **看点**：
  - 消息到达对方要多久；
  - 发送方能否看出消息已经送达。

### P03 不在聊天界面时来了消息

bob 先后处于三种状态：在看别的会话、停在手机的会话列表、关着 MessageHub。每种状态下，devtest 都发来几条消息。

- **完成标准**：
  - 有可见的未读提示；
  - bob 读过之后，提示消失，刷新后也不再出现。
- **看点**：
  - 在 MessageHub 之外，bob 有没有办法知道来了新消息；
  - devtest 能否知道 bob 看过没有。

### P04 离线留言

bob 未登录时，devtest 发了几条文字和一张照片。bob 稍后在手机上登录。

- **完成标准**：bob 登录后能看到全部消息，照片能打开。
- **看点**：
  - bob 离线期间，devtest 那边的状态显示是否会误导人；
  - bob 登录后要多久才能看到这些消息。

### P05 各种内容

devtest 发给 bob 以下几类内容：

- 多行文字；
- 表情；
- 中英混排；
- 链接；
- 像 HTML 代码的文字，例如 `<b>粗</b>`；
- 一段很长的文字。

然后 bob 在手机上回发多行文字和表情。

- **完成标准**：
  - 内容原样显示；
  - 像代码的文字按原文显示，不被当成网页执行；
  - 手机上没有横向溢出；
  - 全是空白的消息发不出去。
- **看点**：
  - 链接能不能点；
  - 长文字是否便于阅读。

### P06 发照片和文件

devtest 给 bob 发照片、PDF 和视频。bob 在手机上查看、播放并下载。然后 bob 用手机发一张照片给 devtest。

- **完成标准**：
  - 双方都能打开所有附件；
  - 下载的文件与原文件一致。
- **看点**：
  - 上传时有没有进度提示；
  - 在手机上预览和关闭是否顺手；
  - 文件过大时会怎样。

### P07 两人同时发起聊天

两人几乎同时点开对方并发出消息，之后再各回一句。

- **完成标准**：双方都能找到全部 4 条消息。
- **看点**：
  - 这些消息是在同一段对话里，还是分散到了两个会话；
  - 如果分散了，用户能否发现。

### P08 和同一个人聊多个话题

devtest 和 bob 分别开“周末烧烤”和“水电账单”两个会话，在各自的会话里来回聊。

- **完成标准**：两个话题的消息互不混淆，回复落在对应的会话里。
- **看点**：bob 能否分清这两个会话。

### P09 整理会话

- bob 把与 devtest 的会话置顶；
- devtest 先把这个会话归档，再把它删除；
- 期间 bob 继续发消息。

- **完成标准**：
  - 每人的整理操作只影响自己，不影响对方；
  - 收到新消息后，会话能重新出现。
- **看点**：
  - 删除前有没有确认；
  - 用户能否明白删除只对自己生效。

### P10 在手机上翻看长历史

会话里先积累几十条消息。bob 在手机上向上翻到最早的消息。翻看过程中，devtest 发来一条新消息。

- **完成标准**：
  - 历史完整，没有重复；
  - 阅读位置不被打断，并且有办法回到最新消息；
  - 返回、关闭等操作都不会走进死路。
- **看点**：
  - 触控目标大小是否合适；
  - 横竖屏切换后会怎样；
  - 怎样回到桌面或退出登录。

### P11 草稿和断网

- bob 写了一半的消息，切走再回来，然后刷新页面；
- 之后在断网状态下发送一条消息，联网后重试。

- **完成标准**：
  - 草稿没有丢失；
  - 断网时界面明确提示发送失败；
  - 重试后对方只收到一次。
- **看点**：
  - 错误提示 bob 能否看懂；
  - 重试的入口是否明显。

### P12 同一个人用两台设备

devtest 同时在电脑和手机上登录。bob 发来消息；devtest 在手机上回复，并在手机上读完消息。

- **完成标准**：
  - 两台设备都能收到 bob 的消息；
  - 从一台设备发出的消息，在另一台上显示为自己发的；
  - 在一台设备上读过的消息，另一台上也变为已读。
- **看点**：两台设备之间同步要多久。

### P13 共用一台设备

bob 在手机上留了一段草稿，然后退出登录。devtest 在同一个浏览器上登录。

另外，bob 尝试打开 devtest 的会话视图。

- **完成标准**：
  - devtest 看不到 bob 的会话、草稿和图片；
  - bob 重新登录后，自己的数据都还在；
  - 打开别人会话视图的尝试被拒绝。
- **看点**：在手机上找到退出入口有多难。

### P14 屏蔽与恢复（私聊任务中最后做）

bob 屏蔽 devtest，devtest 再发一条消息；然后 bob 恢复联系。

- **完成标准**：
  - 屏蔽期间 bob 收不到消息，devtest 看到发送失败；
  - 恢复后，双方又能正常互发。
- **看点**：失败提示是否让 devtest 明白发生了什么。

## 5. 群聊任务（devtest × bob × alice）

背景资料：[Self-Host-Groupv2.md](../../doc/message_hub/Self-Host-Groupv2.md)。用户可见的规则以它为准，例如：

- 好友拉人入群会自动加入；
- 群里的消息由群统一排序；
- 群内的子会话彼此隔离；
- 非成员看不到群的内容。

### G01 建家庭群

devtest 新建“家庭群”，把 bob 和 alice 拉进来，然后三人各说一句。bob 用手机，alice 用电脑。

- **完成标准**：
  - bob 和 alice 不用刷新就看到自己进了群；
  - 三人看到的成员、角色一致；
  - 三人看到的消息一致，而且没有重复。
- **看点**：
  - bob 和 alice 没有被询问就进了群，他们能否明白发生了什么；
  - 群里每条消息能否看出是谁发的。

### G02 三人一起聊

三人同时连续发言。

- **完成标准**：
  - 每条消息恰好出现一次；
  - 三人看到的顺序完全一样，刷新前后也不变。
- **看点**：
  - 自己发的消息会不会跳到别的位置；
  - 发得太快时会怎样。

### G03 @某人

- bob 把群设为免打扰；
- alice 在群里 @bob；
- devtest 发一条 @所有人。

- **完成标准**：
  - bob 能看出自己被 @ 了；
  - 普通成员不能 @所有人。
- **看点**：直接在输入框里打 `@bob` 能否生效。用户通常会这样操作。

### G04 回复、点赞、修改、撤回

- bob 在手机上回复 alice 的某条消息；
- 大家给这条消息点赞；
- alice 修改自己的一条消息，再撤回一条发错的消息；
- devtest 作为群主删除一条别人的消息。

- **完成标准**：
  - 三人看到的结果一致；
  - 撤回或删除的原文在任何人那里都看不到了；
  - 不能修改或撤回别人的消息。
- **看点**：
  - 在手机上这些操作好不好找；
  - 撤回之前有没有确认；
  - 点赞能否取消。

### G05 群里发照片和文件

三人在群里互发照片和文件，并各自打开、下载。

- **完成标准**：每个人都能打开所有附件，下载内容与原文件一致。
- **看点**：多人同时发图时，消息列表会不会错位。

### G06 群里开子话题

devtest 在家庭群里开“旅行计划”会话，设置标题和公告，然后：

- bob 在“旅行计划”里发言；
- alice 退出“旅行计划”；
- devtest 最后归档、再删除这个会话。

另外，devtest 尝试开一个只有自己和 bob 的子话题。

- **完成标准**：
  - 子话题的消息不会出现在主群聊里；
  - 标题和公告三人都能看到；
  - alice 退出后不再收到该话题的消息，但仍在群里；
  - 归档后只能看不能发。
- **看点**：
  - 在手机上能否找到并分清子话题；
  - “只和部分成员开话题”能否做到。

### G07 管理群

- devtest 把 bob 设为管理员；
- bob 在手机上修改群名；
- devtest 禁言 alice，再解除；
- bob 把 alice 移出群，然后重新邀请回来。

- **完成标准**：
  - 管理员能做管理操作，但不能任命管理员；
  - 群名变更后三人都能看到；
  - 被禁言期间 alice 不能发言，但能看消息；
  - alice 被移出后收不到群消息，回来后看不到不在群期间的消息。
- **看点**：
  - 角色、权限变化后，其他人要不要刷新才看得到；
  - 被禁言、被移出时的提示是否清楚。

### G08 退群和转让群主

- alice 退群；
- devtest 想退群，先把群主转让给 bob（bob 需要接受），然后退群。

- **完成标准**：
  - 群主不能直接退群；
  - bob 接受之前，转让不生效；
  - 取消转让后，bob 无法再接受这次转让；
  - 转让完成后，原群主可以退群。
- **看点**：bob 能否注意到转让请求，并明白接受后意味着什么。

### G09 用邀请链接入群

devtest 为一个 alice 不在的群生成邀请链接，在私聊里发给 alice。alice 用这个链接入群。之后 devtest 撤销链接，alice 退群后再用这个链接试一次。

- **完成标准**：
  - 用有效链接能入群；
  - 撤销后的链接不能再用，并有清楚的提示。
- **看点**：
  - 链接在聊天里能不能直接点；
  - alice 能否自己找到用链接入群的地方。

### G10 不想待的群

alice 被拉进一个她不想待的群。她先试着拒绝或退出；然后屏蔽 devtest。devtest 再次邀请她。最后恢复两人的好友关系。

- **完成标准**：
  - alice 能退出这个群；
  - 屏蔽后，邀请不会打扰到 alice；
  - devtest 能撤回这次邀请。
- **看点**：没有“拒绝”只有“退出”，对用户来说够不够用。

### G11 入群需要审批

devtest 希望新成员入群前要经过他批准。

- **任务**：
  - 先找一找有没有这样的设置；
  - 如果有，就让 bob 邀请 alice，或让 alice 申请入群，再由 devtest 批准或拒绝。
- **完成标准**：在审批前，alice 看不到群的内容。
- **看点**：
  - 群主能否及时注意到有人在等待审批；
  - 申请人能否知道自己在等谁批准。

### G12 请外人只参与一个话题

devtest 和 bob 的“装修群”里有一个“装修咨询”话题，想请群外的 alice（扮演设计师）只参与这一个话题。

- **任务**：通过界面尝试邀请 alice 作为访客加入这个话题。
- **完成标准**：
  - alice 要自己接受邀请；
  - 加入后，alice 只能看到并参与这一个话题，看不到群里的其他内容；
  - 大家都能看出这个话题里有外部人员。
- **看点**：如果做不到，记录卡在哪里，例如找不到允许访客的设置。

### G13 谁看过了

devtest 在群里发了一条通知，想知道谁已经看过。

- **任务**：先尝试找到并开启已读回执，再让 bob 和 alice 依次阅读。
- **完成标准**：已读人数或名单准确，并且会随着成员阅读而更新。
- **看点**：能不能开启回执，在哪里开启。

### G14 群外的人看不到群

devtest 和 bob 另建一个 alice 不在的群。alice 通过地址或链接直接打开这个群。

- **完成标准**：alice 只能看到自己不是成员的提示，看不到消息、成员和子话题。
- **看点**：提示是否友好，有没有暴露技术细节。

### G15 把 Jarvis 拉进群（可选）

- devtest 把 Jarvis 拉进群；
- bob 也试着把 Jarvis 拉进自己的群；
- 在群里 @Jarvis 提一个问题。

- **完成标准**：
  - 由 Jarvis 的主人拉它入群时直接生效；
  - 别人拉 Jarvis 入群时，需要主人确认；
  - Jarvis 在群里回答，而不是在私聊里回答。
- **看点**：主人能否看懂确认请求。

### G16 解散群（最后做）

群主解散一个三人群，其中 bob 是管理员。

- **完成标准**：
  - 只有群主能解散，管理员也不行；
  - 解散后，其他人都看到群已解散，并且不能再发言。
- **看点**：
  - 成员是否知道是谁、在什么时候解散的；
  - 解散后历史消息还能不能看。
