#### Sessions and runtime binding
Discover with `agent-session sessions --children --active` (`--finished <n>`: the last ones that ended, 1-20), `workspace list` and `runtime list` (`--json` for scripts). `runtime get|check` shows connector (`native|node_executor|ssh`), platform/baseline/tool checks, grants, usage and lifecycle. Retired runtimes are not candidates. Use `runtime check … --commands a,b`. A host session's service commands (`agent_tool dcrontab|check_task|cancel_task`) use the current Agent token from `.opendan/session.json`, ahead of development RPC overrides; no local CLI/device credentials are required.

The host injects `## Objects` with Agent/session/workspace, message sessions, owner home/files and AI Workspaces. Read these URLs with Agent identity. `obj://<agent_id>/sessions/<sid>` emits `changed` and one `finished`. A memory scoped to a URL can show it in a hint. Automatic IDs are `<kind>-YYYYMMDD-N` using the host's local date, one daily sequence per Agent; retries reuse the creation key's reserved ID. `sessions/<sid>/.opendan_agent_session/` contains `session_config.json` and `worklog.jsonl`; `agent-session read-session <sid> --turn <n>` (with `--after` / `--before <cursor>`, `--limit`) reads the records of a Turn. A conversation's history is compressed at 80% of the model's window, down to about 30% (`history_budget_tokens` sets a fixed budget instead); a UI session that comes back after an hour with a changed prompt is rebuilt with the new one.

The runtime is frozen in `runtime.frozen` at creation. A chat always uses `private` (Agent container or native service); other sessions use explicit `--runtime`, then the parent's, then private. `host` is the owner's machine; owner absolute paths refer to its default runtime. On Desktop Lite owner default and private may be the same native runtime with local shell, files and computer-driver IPC. A private session can `agent-session run --runtime <id|workspace> [--cwd <dir>] -- <cmd>` and copy files. Other runtimes are single-machine with local shell and tools, no `agent-session`. Standard node tools in `$BUCKYOS_ROOT/bin/agent-tools` take the Agent identity from `.opendan/`. `$BUCKYOS_ROOT/tools/bin` and `bin/agent-tools` are on command and check PATH.

A workspace is runtime + directory + optional URL independent of the session runtime. `agent-session workspace create --runtime <id> --directory <abs> --name <n> --key <k> [--url <url>]`, `import` and `set-url` require a workspace grant. Todos select runtime and workspace separately. Commands start in the working session directory (`$OPENDAN_SESSION_DIR` or node `<account home>/.opendan/<agent>/sessions/<sid>`). Use `$OPENDAN_WORKSPACE_DIR` only on the same runtime. Cross-runtime: `agent-session copy --from workspace:<path> --to session:<path>` and reverse for delivery (one regular file, hash-verified, `--replace` to overwrite, `copy status|cancel <id>`). Use that runtime's path format.

#### Reports and artifacts
`create-worksession --title` names the user-visible task (60 characters); Todo work inherits the Todo's title. A reply/yield while a task or child runs closes its Turn. A task result, child end or tick wakes it with a refilled tool budget; ticks back off (`tick_secs` doubling to `tick_max_secs`, any other input starts over). An idle reply without final report gets one nudge, then fails with `missing_end_report` — in a class with `waits_idle` it is a wait that the next tick ends. Past `max_life_secs` a Work gets one last Turn with only `report`. A bounded Work whose context does not fit after its compactions fails with `context_limit`; its last progress report stays its evidence. End a top-level explicit-report Work with `report(is_end=true,outcome=…)` or `<report end="true" outcome="succeeded">…</report>`. Outcomes: `succeeded` (verified), `failed` (work or checks failed), `blocked` (prerequisite missing). Omit outcome on progress; final reporting is refused while its tasks run.

Write deliverables under the working session directory. Report relative files, existing bucket URLs or object IDs using `report.artifacts` or `<artifacts>["rel/path"]</artifacts>`. AIGC tools return `detail.files[].url`. Accepted artifacts go to `obj://bucket/user/<agent app id>/<owner>/artifacts` under `<hash>/<name>` (owner's documents, backed up); external bucket results are copied. Other local paths are refused. A native `artifact` error can be corrected and retried. An XML report stays live with `last_error.kind="artifact"`; restore storage then resume the same session. Read `agent-session read-session <sid> --report --worklog 50` before replacing it. Intermediates belong in the seven-day `scratch` bucket (`buckyos bucket put` or `uploadNamed(…, {bucket:"scratch"})`). Use `materialize_resource 'obj://bucket/…' <path>` for local input. Report the workspace delivery path too.

#### Plans and Todos
`plan_simple` keeps its TodoList (`.opendan_agent_session/todos.json`), with read-only workspace and intent-bearing native calls. Todo work writes the workspace. `todo add` uses `work_simple`, inherits workspace; `todo explore` is read-only with no workspace. Without `--after`, depend on the preceding Todo. `--after none` starts immediately; repeat `--after <id>` for multiple prerequisites. The host dispatches as soon as dependencies succeed, within `--max-children` / `max_sub_sessions`. A failed, timed-out, stopped, cancelled or uncreatable attempt blocks dependents. Inspect `blocked_by` and the reason, then retry, update dependencies or cancel. A report with `failed` or `blocked` fails the Todo attempt.

`todo update <id> --reason <why>` can change content, acceptance, scope, evidence, dependencies, runtime/workspace or skills. Changes enter `updates`; the running child reads the whole new task and the plan's list before its next inference. A Todo's first input carries that list too (`<plan_todos>`). Acceptance criteria are optional; `todo add` without them says so. `todo pause|resume|stop <id> --reason <why>` controls that child; pause takes effect at the next inference boundary and tasks continue. `xagent ctl <sid> pause|resume` does the same for other sessions. Turn stop keeps the session; session stop ends Work and children or sleeps a Goal. Conversations end via archive (`/clean`, `ui.rotate`; `/new` too, except in a chat the owner created in Desktop, where Desktop opens a new default chat instead and this one stays). Host-restart interruptions stay paused until resumed with their interrupted children.

A plan lives at most 48 hours (`max_life_secs`), records reusable conclusions with `ctl perceive` and lists them in its report; its work sessions record nothing.

A `work_simple` that a UI session creates has an input queue and `policy.reads_messages`: a posted message stops the run at the next inference boundary and joins its open Turn; a final report is refused, or reopened as a progress report, while one is unread; after the end `post` answers that the session finished. Other Work takes only controls, a plan its forwarded messages.

A UI session's final reply follows its behavior's `[reply]` schema, with one correction. `agent-session ctl reply-mode compat|schema` (state `reply_mode`, kept across Turns, reset by a new session): in `compat` the final text goes out as it is and `submit_reply` (in the behavior's `tool_whitelist`) gives `{reply, topic, artifacts}`. `[reply] asks_field` is filled by the host with the `ask_user` questions of the context and their answers; `[reply] contract = "intent_analysis"` checks what an analysis result claims.

Review reports as evidence. Add a verification Todo when needed (`todo explore "verify …" --after <id>`). The plan may end on completion or impossibility; any still-running attempts then stop. Child ends and questions, ticks and forwarded user messages open plan Turns. `agent-session todo list` shows dependency and result state.
