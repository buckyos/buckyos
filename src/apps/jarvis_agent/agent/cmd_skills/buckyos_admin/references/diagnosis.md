# Logs, tasks and source

- `buckyos system status` reports control-panel host resources and warnings; service keys marked `unknown` are inventory only. `app status` needs a full App DID or instance such as `xiaobai.test.buckyos.io@devtest`; a short name becomes an unrelated DID (`APP_NOT_INSTALLED`). `task list --type app.install/v1`, `task get <id>`; Agents see tasks they created.
- List service ids with `buckyos log services`. `log query --service <id> [--level error|warning|info] [--keyword <text>] [--since <RFC3339>] [--direction backward] --limit 100`; page with `--cursor <next_cursor>`. `warn` aliases warning. Entries are host-local MM-DD HH:MM:SS.mmm without year. `buckyos --timeout 2m log tail --service <id> --from end` streams JSONL. Export via `buckyos log export --services a,b --since <RFC3339> --path "$OPENDAN_SESSION_DIR/logs.zip"`.
- Admin `buckyos diagnostic collect --services a,b --since <RFC3339>` waits for a bundle (~1 h expiry); `buckyos diagnostic export <bundle_id> --path "$OPENDAN_SESSION_DIR/diag.zip"` verifies SHA-256. Narrow scheduler log windows (tens of MB/hour). Include timestamps, symptoms, commands, trace_id, redacted matching lines and verification. Summarize relevant fields rather than dumping secrets, settings or keys.
- `log query` does not traverse `logs/apps/<instance>/`; `opendan` service logs are the host's. Read own container `/opt/buckyos/logs/`; native Agent log is `$BUCKYOS_ROOT/logs/opendan/opendan.<pid>.log`, pid/start/port in `local/app_native/<instance>.json`. For otherwise invisible host evidence supply owner commands (`uv run src/check.py`, `docker ps`, `ls "$BUCKYOS_ROOT/logs/apps/"`). Flashing Windows console at startup: check Rust launch site uses `src/kernel/buckyos-api/src/process_util.rs`; Python uses CREATE_NO_WINDOW without DETACHED_PROCESS/CREATE_NEW_CONSOLE (including `opendan.exe install-agent-tools`).
- `last_error.kind="artifact"`: container bucket RPC goes via host gateway `/kapi/nfs-server` (normally :3180). Host bridge :4110 signals outdated runtime; NFS listens on host loopback. Deploy current runtime and resume saved session (`opendan_agent_dev`).
- HTTP 503 `service_not_ready:<service>`: check requested name, `services/<service>/info`, node `gateway_info`, service/scheduler logs. Agent gateway uses full `/kapi/<agent_id>`, its WebUI `/api/opendan` on App host; `/kapi/opendan` is loader-local. For valid names during startup, retry after instance and route publication.
- CLI exits: 2 usage, 3 auth (AUTH_REQUIRED, INVALID_SESSION, SESSION_EXPIRED), 4 permission/confirmation, 5 SERVICE_UNAVAILABLE, 6 operation/not found, 8 timeout. On expired long wait/tail rerun in a fresh shell call (new injected token); for CONNECTION_REQUIRED supply `--endpoint http://host.docker.internal:3180` in the container. Use `--idempotency-key <k>` for supported App/diagnostic retries. On denial report code and owner procedure.
- For `bind_failed`/refresh inspect existing Agent kRPC `loader.status.authentication`, `errors`, `session.read` ACK/outbox, owner, instance, message ID. `retry_pending` is transient; `reauthorization_required`/`unavailable` needs host diagnosis. For authorization revocation/denial resolve through owner first. For authorized recovery confirm `buckyos command describe app restart` then `buckyos app restart <full_app_instance_id> --strategy recreate`: node-daemon rechecks active owner, enabled/installed App and binding before issuing fresh LoginAssertion. Docker restart reuses old assertion. Preserve AgentRootFS (`$BUCKYOS_ROOT/data/home/<owner>/agents/<full_agent_id>/`), message storage and session ACK/outbox. Verify original pending message answered once and later token renewals.

## Running version

Record Tool/SDK/runtime and system `build_version` (`build<YYMMDD>.<branch>.<commit12>[.dirty]`). Inspect mounted `/opt/buckyos/libexec/buckyos-tool/cli/modules/<module>.ts` (system-config = `system_config.ts`); find service and RPC. Compare file sha256 with `npm_files[].sha256` in `distribution.json`. Core `auth,config,identity,runtime,errors.ts` define identity, endpoint and exit codes. A Tool build_id `dev-<uuid>` is random; rely on version and per-file hash. `<commit>:<platform>:<arch>` identifies a Tool prepared from npm during that system build.

Match server checkout to commit12. Without a local tree, clone into session dir (`git clone --filter=blob:none --branch main https://github.com/buckyos/buckyos src && git -C src checkout <commit12>`). Trace CP `src/frame/control_panel/src/main.rs`, system-config `src/kernel/sys_config_service/src/main.rs`, RBAC `src/kernel/buckyos-api/src/rbac_config.rs`, verify-hub `src/kernel/verify_hub/src/main.rs`. A dirty build or absent commit limits proof to observed logs, client code and known differences. For a missing CP verb consult SDK `dist/*.d.ts` and `cli/modules/system.ts`; an optional untested pattern is a private `$OPENDAN_AGENT_ROOT/tools/<name>.ts` using `deno run --config /opt/buckyos/libexec/buckyos-tool/cli/deno.json` with current endpoint/session. Leave mounted files unchanged.

## Desktop node upgrades

Packaged Node Updater runs before service deployment. Linux installer `--silent --auto-update --tag latest` stops on SDK conflict before shutdown. On interrupted deploy keep services stopped, rerun installer for the recorded build, inspect updater JSON reader/data area/recovery state.

Historical evidence: host/device and devtest on test.buckyos.io, BuckyOS 0.7.0 build261017.main.1b6e277fadd9.dirty and Tool/SDK 0.7.131 (2026-10-17). Agent-grant findings came from policy/code; user/group/projection RPCs from source/unit tests (2026-10-21).
