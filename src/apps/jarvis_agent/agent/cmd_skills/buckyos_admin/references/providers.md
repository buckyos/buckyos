# AI Center and providers

- Inspect `buckyos ai providers` (configured auth kind, health, models), `ai routing`, `ai usage [--range last1d|last7d|last30d | --since <t>] [--group-by provider_instance_name,provider_model,user_group] [--bucket day]` (own calls; admins see the Zone in Desktop; `user_group` is admin only), and container `ai_provider health <exact_model>|models` for model health/prices and the client operation serving each API type (`via=`). AI Center owns writes to providers, routing weights, policies and the price list; usecase cells and routing groups can also be written with the CLI below.
- Usecase routing (`doc/aicc/aicc_router.md` §9, §11–§12): each of the 29 usecases (`llm.chat`, `llm.code`, `image.txt2img`, …) routes to one exact model `model@provider`. A cell (model, or what happens when it is unavailable) comes from the highest layer that sets it: default < Zone default (admin, may lock a cell) < the user's own layer < the routing group the user bound to the calling App/Agent < the group bound to the LLM session (child sessions follow it). A layer's model that is gone, hidden from the user or unfit for the usecase is skipped. `buckyos ai routing [--view self|zone|group:<id>|app:<app_id>] [--json]` shows the table: model, source layer, policy with the predicted backup, coverage (`covered`, `fallback_llm`, `uncovered` with `no_model_for_api_type` / `requirements_unmet`). Change a cell with `buckyos ai usecase set <usecase> [--model m@p] [--on-unavailable none|same_model|not_pricier|next_model] [--clear model|on_unavailable] [--zone-default|--group <id>] [--lock]` (own layer by default; `--zone-default` and `--lock` are admin only; the model must be exact, in an inventory, serve the usecase and be visible to the user); groups with `buckyos ai routing-group list|create|delete|bind|unbind`. These verbs are new: confirm flags with `--help`. The default route changes only when Providers are added, removed, enabled or disabled, model lists or metadata refresh, or admin weights change; health, latency and cost estimates never change it.
- When unavailable (`on_unavailable`): `none` (default) returns the real error; `same_model` uses the same model on another Provider; `not_pricier` routes again as if that Provider were disabled and takes the result only when every unit price is known and not higher; `next_model` routes again as if that Provider were disabled. At most one switch per request, after same-model retries, on timeout / 5xx / connection failure, model gone, upstream quota exhausted, a user quota rule refusing the model, or a Provider marked faulty; never on 400/401/403/409, cancel or a failure that consumed usage. A request naming an exact model (also one taken from `route.resolve`) never switches. A switch shows in `route_trace.fallback` (`kind: unavailable`), usage `fallback_from` and event `unavailable_fallback`. Users may set policies unless the admin locked them; `next_model` can land on a pricier model, say so before setting it. The fallback LLM row `llm.fallback` is off by default and only an admin turns it on (AI Center usecase page, Zone default view): LLM usecases with no model are then served by it and their sessions show a warning; it never covers a failing Provider.
- A failing Provider: read the real error first (Provider instance, exact model, upstream status and message); `no_candidate_model` only means the usecase has no model (`details.usecase`). Temporary outage: mark it faulty in AI Center Provider detail (`provider.update` with `marked_faulty`; no CLI verb): routing and the table stay the same, nothing is sent to it, usecases with a policy use their backup at once, the rest fail immediately with `no_provider_available` (`details.reason = "marked_faulty"`); clear the mark when it is fixed. Long-term fault: disable or delete it and the default route recomputes; first read `buckyos ai routing --view zone --json` (AI Center's confirm dialog lists the usecases that move or become uncovered). Events `provider_marked_faulty` / `provider_fault_cleared`.
- After adding a Provider: the wizard's coverage step compares the Zone's usecase table before and after (newly covered, changed defaults, still uncovered; unticking a change keeps the old model in the Zone default). Then check `buckyos ai routing --view zone` for `uncovered` and `fallback_llm` rows and fix them with `buckyos ai usecase set --zone-default` or another Provider.
- AI policy (`doc/aicc/aicc_user_policy.md`): one policy per subject decides visibility, price coefficient (0 = free) and 5h / 24h / 7d limits (Credit or tokens; a window starts at the first use). User side `type:admin|user|limited` < `group:<id>` < `user:<id>` (the more specific wins; among groups the value good for the user); App side `app:<id>`, `user_app:<user>/<app>` only narrows. Out of the box `type:admin` / `type:user` see everything for free. `buckyos ai policy [--app <id>]` shows balance and limit windows, `ai policy-effective [--user <u>] [--app <id>]` each visible model's source and Credit price, `ai policies [--manage]` the policies, `ai prices` the price list. A model without price is unusable for a user with a non-zero coefficient (`resource_not_permitted`, `details.reason = "unpriced"`): price it (`model:<driver>:<origin>` covers every Provider) or make that Provider free.
- AI Credit: refusal `credit_insufficient` is the user's balance, not a Provider account. Admins: `buckyos ai credit [--user <u>]`, `ai credit-ledger`, `ai credit-recharge --user <u> --amount <n> --id <order>` (same id credited once; check with `ai credit-recharge-get --id` after a timeout), `ai credit-adjust --user <u> --amount=-<n> --id <id> --note <why>` for refunds and charging `unpriced` / `unknown_usage` lines. Recharge needs RBAC `write` on `obj://aicc/credit/recharge`: the `admin` role has it; a payment gateway App or service is granted by appending `p, app:<gateway_app_id>,obj://aicc/credit/recharge,write,allow` to `system/rbac/policy` (being an App of an admin is not enough). The gateway uses its order id as `recharge_id` and keeps order data in `external_ref`.
- Provider 接入诊断：在 AI Center 查看发现模型、身份匹配、不可用预设及用途覆盖（加上它以后整个 Zone 的用途表变化）。协议兼容不会自动继承渠道预设；OpenRouter 等已有专用 profile 的渠道优先选内置项。校验不发推理请求，验收还要做真实对话。每个 Provider 实例有一组协议客户端：Known Provider 的默认客户端和有序的 `extra_protocol_adapters` 来自 `provider.catalog`，设置里的 `protocol_adapter_id` 只对 custom 实例生效（它的默认客户端，外加同协议族的其它 custom 可选客户端）；AI Center 的 Provider 概览列出这组客户端。遇到 `Inventory` / `multiple default operations`，检查报错模型、它的主客户端与操作映射；`filtered_capabilities[].protocol_adapter_id` 是该能力实际使用的客户端。Validation 和模型清单可展开 `filtered_capabilities`：缺协议绑定只移除对应能力，不能据此判断认证或网络故障。参阅 `doc/aicc/provider_server_defaults.md`、`doc/aicc/provider_ui_backend_mapping.md`。不要为单一模型改 Agent 媒体调用。
- 当前版本不能新建 custom Provider（添加入口已关闭，等“自定义 Provider 自动探测”上线）；用户要接自建网关时说明这一点，不要引导走 RPC 绕过。已有的 custom 实例照常可用，规则也能编辑。
- PC AI Center → Providers → custom provider → 模型规则 / Provider rules. Configure a discovered model (including disabled/unrecognized); choose tasks, the model's Protocol Adapter (one of the instance's clients; empty = instance default) and operations from any of those clients. Mappings are `<client>/<operation>` or a bare operation of the model's primary client, shown as `client · operation`. Unconfigured operations use the client defaults. Each supported_effort needs explicit provider_options (empty object is a valid enabled mapping); missing efforts are unsupported. Task admission retains upstream default thinking. Finish editing and apply validates/reloads. Failed save retains draft. Mobile lacks this module.
- Export before changing a working instance. “Model list / Full configuration JSON” displays or exports the current catalog/draft. The wizard selects a built-in channel preset; detailed edits happen in Provider rules. Import replaces the draft, keeping connection/policy settings and adapter. `provider.preview_rules` resolves inherited rules without apply/upstream call. Empty task/price can reflect an absent preset value; unresolved identities need aliases.
- `*.provider.json` uses `buckyos.aicc.provider-rules-catalog` with no outer envelope: `server_default_routes`, `models[].exclude`, existing `variants` + `match.provider_model_id` for effort (no `model_variants`). Retain headers, adapters, match conditions, units, and explicit empty task mappings only when present in source. A rule's `protocol_adapter_id` and qualified `operations` need `schema_revision` 2 (the editor raises it on save/export). Exports omit secrets, use actual inventory/instance values and keep missing prices empty. Protocol selection imports no prices; edited snapshots survive shared preset changes. See `doc/aicc/aicc-mgr.md`, `doc/aicc/provider_operation_bindings.md`, `src/kernel/buckyos-api/src/aicc_client.rs`, `src/frame/aicc/src/catalog/schema.rs`.
- AICC / `llm_understand_media` HTTP 504 or `response head timeout`: match gateway log with AICC task/trace/upstream address. Shipped `etc/boot_gateway.yaml` → `servers.node_gateway.response_timeout: 900s` covers local server upstream responses. Check effective overrides, reload and read back. Provider proxy/client budgets are independent; older gateways may report HTTP 500. Check original task outcome before repeating a timed-out call. Source: `doc/arch/gateway/boot_gateway的配置生成.md`.
