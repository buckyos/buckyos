# AI Center and providers

- Inspect `buckyos ai providers` (configured auth kind, health, models), `ai routing`, `ai usage [--range last1d|last7d|last30d | --since <t>] [--group-by provider_instance_name,provider_model] [--bucket day]` (own calls; admins see the Zone in Desktop), and container `ai_provider health <exact_model>|models` for model health/prices and the client operation serving each API type (`via=`). `ai quota [--app <app_id>]` shows applicable personal/shared/admin rules, settled/reserved/available and `reset_at_ms` (null = total account, admin recharge). AI Center owns writes to providers, model visibility, routing, quotas and recharges.
- Provider 接入诊断：在 AI Center 查看发现模型、身份匹配、不可用预设及聊天候选。协议兼容不会自动继承渠道预设；OpenRouter 等已有专用 profile 的渠道优先选内置项。校验不发推理请求，验收还要做真实对话。每个 Provider 实例有一组协议客户端：Known Provider 的默认客户端和有序的 `extra_protocol_adapters` 来自 `provider.catalog`，设置里的 `protocol_adapter_id` 只对 custom 实例生效（它的默认客户端，外加同协议族的其它 custom 可选客户端）；AI Center 的 Provider 概览列出这组客户端。遇到 `Inventory` / `multiple default operations`，检查报错模型、它的主客户端与操作映射；`filtered_capabilities[].protocol_adapter_id` 是该能力实际使用的客户端。Validation 和模型清单可展开 `filtered_capabilities`：缺协议绑定只移除对应能力，不能据此判断认证或网络故障。参阅 `doc/aicc/provider_server_defaults.md`、`doc/aicc/provider_ui_backend_mapping.md`。不要为单一模型改 Agent 媒体调用。
- 当前版本不能新建 custom Provider（添加入口已关闭，等“自定义 Provider 自动探测”上线）；用户要接自建网关时说明这一点，不要引导走 RPC 绕过。已有的 custom 实例照常可用，规则也能编辑。
- PC AI Center → Providers → custom provider → 模型规则 / Provider rules. Configure a discovered model (including disabled/unrecognized); choose tasks, the model's Protocol Adapter (one of the instance's clients; empty = instance default) and operations from any of those clients. Mappings are `<client>/<operation>` or a bare operation of the model's primary client, shown as `client · operation`. Unconfigured operations use the client defaults. Each supported_effort needs explicit provider_options (empty object is a valid enabled mapping); missing efforts are unsupported. Task admission retains upstream default thinking. Finish editing and apply validates/reloads. Failed save retains draft. Mobile lacks this module.
- Export before changing a working instance. “Model list / Full configuration JSON” displays or exports the current catalog/draft. The wizard selects a built-in channel preset; detailed edits happen in Provider rules. Import replaces the draft, keeping connection/policy settings and adapter. `provider.preview_rules` resolves inherited rules without apply/upstream call. Empty task/price can reflect an absent preset value; unresolved identities need aliases.
- `*.provider.json` uses `buckyos.aicc.provider-rules-catalog` with no outer envelope: `server_default_routes`, `models[].exclude`, existing `variants` + `match.provider_model_id` for effort (no `model_variants`). Retain headers, adapters, match conditions, units, and explicit empty task mappings only when present in source. A rule's `protocol_adapter_id` and qualified `operations` need `schema_revision` 2 (the editor raises it on save/export). Exports omit secrets, use actual inventory/instance values and keep missing prices empty. Protocol selection imports no prices; edited snapshots survive shared preset changes. See `doc/aicc/aicc-mgr.md`, `doc/aicc/provider_operation_bindings.md`, `src/kernel/buckyos-api/src/aicc_client.rs`, `src/frame/aicc/src/catalog/schema.rs`.
- AICC / `llm_understand_media` HTTP 504 or `response head timeout`: match gateway log with AICC task/trace/upstream address. Shipped `etc/boot_gateway.yaml` → `servers.node_gateway.response_timeout: 900s` covers local server upstream responses. Check effective overrides, reload and read back. Provider proxy/client budgets are independent; older gateways may report HTTP 500. Check original task outcome before repeating a timed-out call. Source: `doc/arch/gateway/boot_gateway的配置生成.md`.
