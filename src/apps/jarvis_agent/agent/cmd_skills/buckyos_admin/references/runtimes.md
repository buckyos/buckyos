# Identify the runtime

- `buckyos --version --verbose` reports the Tool manifest's system version/build, Tool/SDK/protocol versions, runtime executable and package root. The Desktop system-info card shows running version/build, signed-in user/type and Zone; Details adds DID/channel/platform. Restore the card in Settings → Appearance → Desktop. Copy excludes tokens. Unavailable fields indicate a failed read; compare Settings → General and `buckyos system info`.
- Agent container: `/usr/local/bin/deno` runs the host's read-only `/opt/buckyos/libexec/buckyos-tool`. `BUCKYOS_TOOL_ENDPOINT` is normally `http://host.docker.internal:3180`; `BUCKYOS_APPCLIENT_SESSION_TOKEN` acts as the Agent App (principal = owner, appid = AgentId). Host launcher: `$BUCKYOS_ROOT/libexec/buckyos-tool/runtime/deno`, device identity, `127.0.0.1:3180`, asks for `--yes`. On a node runtime, `$BUCKYOS_ROOT/bin/agent-tools/buckyos` runs the host launcher with the Agent identity obtained via the session token in `.opendan/`. Verify with `auth whoami`.
- In a container, `/opt/buckyos/logs` maps to host `$BUCKYOS_ROOT/logs/apps/<instance-hash>/`; `/opt/buckyos/etc` is read-only. Host `security/`, `bin/`, unrelated containers and processes are outside view. A missing Tool/mount requires host-side commands.
- Startup credentials, development CA keys and private scheduler templates belong in host `security/`. If container creation reports `etc/start_config.json` or `etc/ca_key.pem`, an authorized host operator moves those into the security root and restores the public boot template before exposing `etc/` (`doc/path_usage.md`). For a broken `.bns.did` link compare `machine.json` → `web3_bridge.bns` with host policy; absence uses defaults. Recreate after updating node-daemon/aios to pick up new mounts.
- `buckyos agent get <agent_id>` reports `permission_mode` from AgentSpec. Add Agent defaults to `read_write` and allows `read_only`. Owner home follows this mode; AgentRoot stays writable. Raw keys, CP, Desktop and sharing all enforce the grant. Protected records include `users/<u>/settings` (password hash), `users/<u>/agents/<agent>/key` and `security/*`. An Agent can still report its own info/instances and deliver mail. Owner rights, user type and user-login requirements still apply.

## Runtime selection

- `agent-session runtime list [--json]` / `runtime get <id>` report declared baseline/platform and `baseline_check` (missing, unmanaged, resolved, ext). `agent-session runtime baseline [--level extended]` lists requirements; `xagent runtime baseline --check [--level extended] [--overlay]` checks the local machine. `xagent runtime check <id> --commands a,b --full` also runs the commands to detect stubs. Checks leave declared baseline unchanged.
- Extension `$BUCKYOS_ROOT/tools/bin` precedes `$BUCKYOS_ROOT/bin/agent-tools` (node-daemon runs `opendan install-agent-tools`). Missing entries indicate an incomplete OpenDAN install; `provided_by: system` is a host fallback.
- `buckyos runtime list` (`agent.runtime_catalog`) shows the Zone inventory and users. `buckyos agent runtime list|enable|disable|default --agent <agent_id>` manages assignments. Owner changes node policy (dirs, ops, computer, baseline) via Settings → Agent Runtimes / `node.owner_agents_set {node_id, enabled?, workdir_roots?, computer?, baseline?}`; a URL-issued device's policy is fixed at issuance and it is enabled for one Agent at a time.
- `agent.runtime_directory [agent_id]` lists available targets. Select only directory entries with `agent.update {agent_id, runtimes: {"host": {enabled, computer}}, default_runtime_id}`; `agent.create` takes the same fields and retries reuse its saved choice. For a container use `runtimes: {"host": null}, default_runtime_id: "container"`. Add Agent offers a choice when both are available; `host_by_default` is true on Windows/macOS and false on Linux. Without a container node (`container_available: false`), selecting a container fails with `container_unavailable`.
- Owner Agent with default `host` runs natively (`apps/<instance>/run_mode: "native"`, directory `agent_service: {mode:"native",node_id}`). Switching host/container restarts the service. When running as the node's owner OS user, host = private: shell/files local, computer via local Unix socket or Windows named pipe with existing profile and ledger.

## Desktop Lite and startup

- `system.product.get` returns `edition:"lite"`. Control-panel publishes `etc/product.json` to `system/product` on start; a broken file stops startup. Lite reports `support_container:false`, skips Docker/WSLC, runs static Apps, preinstalled native script Apps and one Agent. `system/agent_slot` identifies the holder; `agent_slot_occupied` clears after its runtime App is uninstalled. Added Docker/script/mixed Apps fail Inspect with `UnsupportedTarget` (`product_container_app`, `product_service_app`, `product_mixed_packages`).
- Scheduler places script Apps with `need_container:false`; `run_mode` follows container availability and stays fixed after placement. Node-daemon requires a preinstalled product entry for native scripts. Closing `executor` or `owner_agents` stops a Lite host Agent: its instance falls back to a refused container. Inspect `local/app_native/<instance>.json`, `logs/apps/<instance>/native.log`, and `services/<spec_id>/instances/<node>.deployment_error` for `port_conflict` (free port, auto-retry), `exited` (last lines), `not_listening` or `interpreter_missing`. Backoff is 5 s to 5 min.
- Host `uv run src/check.py` tests processes/ports and reports log warnings even with exit 0. “Activation Ready” is waiting for activation. Default root is `C:\buckyos` on Windows, `/opt/buckyos` on macOS/Linux. OOD waits for authenticated system-config RPC then device registration, each transport retry budget 60 s; auth/permission errors fail immediately. Missing `boot/config` is valid at first activation. Check port 3200, node-daemon/system-config logs and full startup before diagnosing later services. Preserve identity and data.
- macOS LaunchAgent `com.buckyos.runtime` starts after the bound user (`etc/desktop_runtime.json`) logs in. Run `"$BUCKYOS_ROOT/bin/node-daemon/BuckyOS Runtime.app/Contents/MacOS/node_daemon" service status` for binding, launchd/autostart/Login Items and GUI permission status; `service start|stop|restart|autostart on|off` controls it. See `logs/node_daemon/launchd.err.log`. Grant Screen Recording and Accessibility to BuckyOS Runtime using `open -n "$BUCKYOS_ROOT/bin/node-daemon/BuckyOS Runtime.app" --args --request_permissions`, then restart. For a rebuilt ad-hoc signed app check TCC logs for code mismatch. Reset only stale grants with `tccutil reset ScreenCapture com.buckyos.runtime` and `tccutil reset Accessibility com.buckyos.runtime`; request, authorize and verify again.
