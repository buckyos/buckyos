# Build on the host

Read the repo's AGENTS.md. BuckyOS uses sibling buckyos-websdk, buckyos-devkit, cyfs-gateway. Run system Cargo/uv commands in buckyos/src. Runtime root is BUCKYOS_ROOT, default /opt/buckyos (macOS/Linux) or C:\buckyos (Windows).

- `uv run buckyos-build.py --help` reports build options/env without preparing artifacts. `uv run buckyos-build.py [-s <module>] [--skip-web]` uses modules from bucky_project.yaml and prepares SDK/Tool (sibling websdk source, else npm buckyos@latest; prebuilt inputs require all four BUCKYOS_SDK_TOOL_*). It stages tools/buckyos-agent in rootfs/libexec/buckyos-agent with adjacent Tool SDK import, then devkit builds and packs Jarvis/text_editor/buckyos_systest into rootfs/data/cache/<app_id>-<ver>.pikg. On macOS tools/macos_runtime_bundle.py assemble moves/signs node_daemon in rootfs/bin/node-daemon/BuckyOS Runtime.app. Use the system wrapper to include these files. Built-in text_editor and sys_test refresh Git #main SDK before each pnpm build; build Text Editor's selected local SDK first.
- All apply commands restart the Zone and need owner authorization: `uv run start.py` updates installed files and starts; `--skip-update` restarts; `--all` fresh dev install (devtest/test.buckyos.io, keeps data/home, data/srv, storage); `--reinstall release` fresh release install. Linux: run as regular user; scripts call sudo only where needed. Headless “needs sudo” requires the owner. macOS GUI owner session binds/launches com.buckyos.runtime; sudo or SSH launches directly without desktop control. Verify with `uv run check.py`: Activation Ready waits for activation.
- macOS pkg: `make_local_pkg.py build-pkg` then `verify-pkg` checks single signed Runtime, non-relocatable bundles and LaunchAgent scripts. Set Developer ID in BUCKYOS_MACOS_CODESIGN_IDENTITY before release build; ad-hoc rebuilds invalidate TCC grants.
- Container code (opendan, xagent, agent_tool, buckyos-agent, entrypoint): repo root `./build_aios --local-test` sets `$BUCKYOS_ROOT/etc/devenv.json` aios override to local/aios-test. Apply with `uv run src/start.py --skip-update` or wait for node-daemon image-ID reconciliation (~30 s). Node-daemon never pulls paios images. Dev installs need local <repo>:latest-<arch> (`docker pull paios/aios:latest-<arch>` or `uv run build.py`); releases load pinned tarballs in bin/paios-images.
- Startup credentials, dev CA keys and private boot templates belong in security/. Containers get a read-only etc/ mount. For existing installs move sensitive files from etc/, restore the public boot template and use the current backup script. See doc/path_usage.md and buckyos_admin. Refresh-race fixes may span host verify-hub/node-daemon and the aios image. Record commit/build ID, installed binary hashes and running image ID. Preserve verify-hub sessions.db and AgentRootFS; for an invalidated instance follow authorized App recreate and verify the pending reply and later renewal.
- Open-source catalog in src/frame/desktop/public/open-source is packaged as maintained. In src/frame/desktop run `pnpm run licenses:generate` for full refresh or add `--scope desktop --scope assets` to preserve other snapshots. Prepare dependency metadata, review/amend, commit after human confirmation, rebuild Desktop. Settings → General → Open-source software → Catalog coverage shows missing metadata. Generator src/tools/generate_open_source.py excludes host OS/base-image packages.
- Independent Linux/macOS Agent Daemon: from src `uv run buckyos-build.py --agent-daemon` builds rootfs/bin/buckyos-agent-daemon without SDK/Web. From repo root `uv run src/tools/package_agent_daemon.py --target <target> --output /tmp/agent-daemon-dist` emits package/manifest/checksum for x86_64-unknown-linux-musl, aarch64-unknown-linux-gnu, x86_64-apple-darwin or aarch64-apple-darwin (see wrapper for current targets). macOS builds need Xcode CLT, runtime macOS 14+; archive is unsigned/unnotarized. Stop before replacing, preserve per-executor ledger, restart with valid URL; default launch installs no service. Claim validation only for packages actually run on that architecture. See doc/arch/agent_daemon.md.
