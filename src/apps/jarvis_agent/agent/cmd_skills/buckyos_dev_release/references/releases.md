# Release workflows

- First-party BuckyOS: AGPL-3.0-only. Associated libraries, SDK and installer: Apache-2.0. Preserve third-party notices and stage licenses/buckyos/. Extension tools must ship each platform payload with matching -corresponding-source.tar.gz and manifest digests. Missing required source/license materials block release; follow doc/licensing.md.
- System: .github/workflows/build-all.yml on main prepares Linux/macOS/Windows with `python buckyos-build.py`, stages `buckyos-install --all`, writes .install-buckyos.json and uploads buckyos-<os>-<arch>-<ver>.tar.gz to R2 buckyos-installer (R2_*). Dev-test uses same wrapper. Keep src/VERSION, src/Cargo.toml and src/bucky_project.yaml in sync; binary build <ver>+build<YYMMDD>.<branch>.<commit12>[.dirty]. Built-in Apps and Jarvis ship in rootfs/data/cache and system/install_settings.
- Standalone daemon: .github/workflows/agent-daemon.yml on agent-daemon-v<version> tag or publish dispatch. package_agent_daemon.py derives <src/VERSION>+build<YYMMDD> from built binary (--version/doctor/status use buckyos-kit::get_version()). Archives, manifest.json, tag and latest.json share the version. Release assembly rejects mixed target versions, mismatched full tag or overwrite of an existing version (same-day rebuilds retain version). agent-daemon-latest provides rolling links; see doc/arch/agent_daemon.md.
- build-aios.yml/build-exttool.yml run from build-all on path changes since R2 pointer paios-images/main/<name>.json. DOCKERHUB_* credentials publish paios/aios and paios/exttool with immutable :<ver>-<commit12>-<arch>, mutable :<ver>-<arch> / :latest-<arch> tags and manifests. docker save tarballs go to R2 paios-images/<name>/<arch>/<sha256>.tar.gz; main payloads pin them in bin/paios-images/paios_images.json (check with `.github/scripts/paios_images.py validate <file>`). Local `./build_aios --push` uses host docker login and moves mutable tags only.
- Installers: make_local_pkg.py build-pkg / verify-pkg (deb/rpm/pkg/exe, scripts in src/publish submodule); dev-tests builds and verifies without upload. WebSDK/CLI: websdk npm buckyos, publish-to-npmjs.yml on publish<version> tag; system wrapper stages libexec/buckyos-tool with distribution.json (versions/file hashes) and SBOM.
- Desktop service payloads: build Node Updater with Node Daemon. Compare `bin/node-updater/node_updater --identity` to target and daemon build. bin/node-updater/release.json records reader schemas and executable SHA-256; format_sources records resolved format-library revision. Review src/kernel/node_updater/readers.toml periodically and before every weekly release: repo root `python3 .github/scripts/audit-node-readers.py` lists registered formats changed since `[review].commit` and, in sibling checkouts, since each `[audited_sources]` revision (`--base <commit>` or `--dependency ../cyfs-ndn` narrows it). It only sees registered files, so also look for new system-config keys, databases and node-local files. Afterwards always update `[review]` (commit, date, conclusion; `changed` when readers changed) and `[audited_sources]`; release.json carries the review. If retiring an SDK API, use the same BUCKYOS_MIN_APP_SDK across compiled components; leave unset for ordinary compatible releases.
