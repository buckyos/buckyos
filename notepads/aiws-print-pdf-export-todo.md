## 0. 结论

- 打印就是把画布导出成一份 PDF 文件。系统里没有任何打印机相关的画面。
- 基础功能是打印流模式画布：直接可以打印，内容自动分页。
- 高级功能是按演示路径打印：一步一页，路径可以跨画布。自由画布只能这样打印，没有演示路径时提示无法打印。
- 打印时选页面规格（A4、A5 等），还可以选一个 PDF Frame 控件。PDF Frame 带页眉、页脚和页码，按页面比例适用，一个工作区可以有多个。不选也能打印。
- 这些现在都没有实现。可以复用的有演示路径的解析、舞台渲染、组合控件、存入 Zone 的导出流程（§2）。
- 排版和分页不依赖用什么手段生成 PDF，可以先做。生成手段在 §5.2 里选。

## 3. 设计

### 3.1 流程

1. **入口。** “画布”菜单里加一项（文案见 Q8），手机主菜单里同样有。需要 `export` 能力，没有时置灰并写明原因。
2. **条件。**
   - 流模式画布：直接进入对话框。
   - 自由画布：需要一条经过本画布的演示路径。一条都没有时不进入对话框，提示“这个画布没有演示路径，无法打印”，并给出进入演示路径编辑的入口。
3. **对话框。** 手机上是整屏。
   - 演示路径：只在按路径打印时出现，多于一条时选择。
   - 页面规格：A4、A5、A3、Letter、16:9、4:3，以及纵向或横向。
   - PDF Frame：可选，默认“不使用”。列出工作区里调用者读得到的 PDF Frame，比例与所选规格一致的才可选（Q12）。
   - 页数和问题清单：会被跳过的步骤、读不到的内容、用占位代替的内容。
4. **保存位置。** 与工作区导出包一致，先选位置再生成。默认存入 Zone，用系统文件选择器的保存模式选文件夹和文件名，默认文件名是画布名或路径名。其次是“下载到本机”。
5. **生成。** 显示进度，可以取消。生成期间继续编辑不影响这次输出。
6. **结果。** 成功后提示保存到了哪里。失败时说明原因和受影响的页，不留下半份文件。

### 3.2 页面从哪里来

一页由三部分组成：页面尺寸、内容区、页面装饰（页眉、页脚、页码）。页面尺寸由对话框里选的页面规格决定。

| | 流模式画布（基础） | 按演示路径（高级） |
| --- | --- | --- |
| 内容 | 整个画布，按阅读顺序 | 所选路径的全部可播放步骤，按路径顺序，可以跨画布 |
| 分页 | 按内容区的宽度排版，按内容区的高度自动分页 | 一步一页。步骤的矩形等比缩放后放进内容区并居中，不裁切，不拆页 |
| 默认页面规格 | A4 纵向（Q5） | 路径的舞台比例 |
| 没选 PDF Frame | 内容区是页面减去默认边距 | 内容区是整页 |
| 选了 PDF Frame | 内容区、页眉页脚取自 PDF Frame | 同左。步骤的比例与内容区不同时留白 |
| 背景 | 画布背景 | 路径背景；Frame 步骤用它自己的背景 |

按路径打印沿用放映的规则：

- 步骤里声明隐藏的 Block（`step.hide`）在该页不出现。
- 停用的步骤、目标已删除的步骤、落在流模式画布上的步骤跳过，并列入问题清单。
- 旋转过的 Frame 按不旋转输出。
- 讲稿备注不输出。
- 路径上有调用者读不到的画布时，那些步骤跳过并列入问题清单。

流模式的分页规则（文档 10“流式自动分页”）：

- 分页点只能落在合法断点上：Block 之间，富文本的段落和行之间，表格的行之间。
- Block 可以声明“不可拆分”和“与下一块同页”，后者用来避免标题留在页尾。
- 表格跨页时重复表头。
- 单个不可拆分的内容高于一页时，等比缩小到一页，并列入问题清单。不能靠裁掉内容来凑页。
- 页眉、页脚和边距先从页面高度里扣除，再分页。

两种打印都适用：

- 打印是一个独立的呈现模式。Block 只用 `Static` 表现，不运行宏和许愿格，不同步数据源，不播放媒体，不产生任何写入。
- 视频输出封面图。音频和没有静态快照的 HTML 输出带名称的占位，并列入问题清单。
- 选区和个人折叠状态不输出。手写笔迹是内容，照常输出。评论和批注见 Q7。
- 主题按页面背景的深浅取浅色或深色（沿用 `stageTheme`），不随 Desktop 当前的主题。
- PDF Frame 实例本身不作为内容输出。它放在流模式画布里时，分页跳过它。

### 3.3 PDF Frame 控件

对应文档 10 的“背景控件”。界面上的中文名待定。

- **形态。** 随标准库发行的组合控件，与待办、日历一样是内置的。实例放在画布上，直接在画布上编辑（Q2、Q11）。
- **页面比例。** 每个 PDF Frame 有一个页面比例：A 系列（A3、A4、A5 共用）、Letter、16:9、4:3，或自定义，再分纵向和横向。控件在画布上的外形始终保持这个比例。
- **多个。** 一个工作区可以有多个 PDF Frame。不同比例各有各的，同一比例也可以有几个不同设计的，打印时选其中一个。
- **按比例套用。** 打印时把 PDF Frame 等比缩放到所选的页面规格上。A4 和 A5 比例相同，用同一个 PDF Frame（Q12）。
- **页眉和页脚。** 各是一个 slot，可以放文本（label）、图片和形状。高度可调，可以为 0。
- **内容区。** 页眉和页脚之间、左右边距以内的区域。编辑时显示为占位，打印时放入当页的内容。
- **页码等变量。** label 增加一种取值来源“页面上下文”，有页码 `page`、总页数 `pages`、标题 `title`、日期 `date`。值由打印宿主在排版时给出。在画布上编辑时显示示例值。
- **不复制数据。** 每页的页眉页脚都是同一个实例的投影。

### 3.4 排版与生成分开

文档 10 要求 PDF 编码可以更换，不改变页面语义。所以分成两层：

- **打印宿主。** Desktop 里一个专用的打印页面。它按 §3.2 自己完成排版和分页，把每一页排成一个固定尺寸的页面元素，全部内容就绪后给出“可以输出”的信号和问题清单。分页由宿主做，不交给浏览器的打印分页，这样页码和总页数在排版时就是确定的。
- **PDF 编码。** 把排好的页面写成 PDF 文件。手段见 §5.2，将来换成无头浏览器也只换这一层。

### 3.5 固定基线、权限与失败

- **基线。** 开始时固定一份一致的只读状态，生成期间的编辑不进入这次输出。做法参照放映克隆（`clone_for_show`），生成结束就释放。
- **权限。** 需要 `export`：流模式查当前画布，按路径打印查路径经过的每个画布。只输出调用者读得到的内容。读不到的 Block 留空并计入问题清单，不暴露它的名称。
- **资源。** 字体、图片等在排版前备齐，缺失的列入问题清单。
- **失败。** 成功表示全部页面都已生成。失败或取消时不写出文件。Zone 里已有同名文件时由选择器询问，不直接覆盖。

### 5.2 Q1：不用无头浏览器，PDF 怎么生成

打印宿主排好页面之后，写成 PDF 有四种做法。

| | 做法 | 好处 | 代价和风险 |
| --- | --- | --- | --- |
| A | **在浏览器里直接写矢量 PDF。** 打印页面在用户的浏览器里排好版，程序读出每一行文字、每个图形和图片的位置，用 JS 的 PDF 库写成文件 | 所见即所得。文字可选可搜，文件小。手机上能用。不需要服务端组件 | 两个新依赖：一个写 PDF 的 JS 库，一套随系统分发的中文字体（浏览器读不到系统字体的文件，PDF 里必须嵌入）。打印表现只能用程序认得的那部分样式。emoji 和复杂文字要转成小图片。没有浏览器的 Agent 和 CLI 用不了。四种里开发量最大的是“读位置再画出来”这一段 |
| B | **在浏览器里出图片 PDF。** 每页转成位图再拼成 PDF，另加一层不可见的文字供搜索 | 写 PDF 的部分简单 | 浏览器没有把页面转成图片的正式接口，现有的库在 iOS 上不稳定。文件大，放大后模糊。HTML Block（iframe）截不到 |
| C | **转成 Office 文档，再用 `soffice` 转 PDF。** 流模式画布导出成 ODT 或 DOCX，交给 ext-core 里已有的 `soffice` | 不需要新依赖。分页、页眉页脚、页码、表头重复都由 Writer 完成。顺带得到“导出 Word”。Agent 和 CLI 能用 | 不是所见即所得，版式由 Writer 决定。每种 Block 要写一份到文档格式的转换，控件和图形只能变成图片。PDF Frame 的页眉页脚只能映射成文字和图片。按路径打印的页面是画面，不是文档，要另找办法 |
| D | **用客户端壳的 WebView 导出。** 在 BuckyOSApp 里调用系统 WebView 的导出 PDF 接口 | 效果与浏览器打印相同，不出现打印机画面 | 只在 BuckyOSApp 里能用，浏览器里打开的 Desktop 用不了。每个平台要各写一段原生代码。AIWS 是否在 BuckyOSApp 的 WebView 里打开，我没有核对 |

建议：

- 选 A。它是唯一同时满足所见即所得、手机可用、文字可选的做法，代价是两个轻量的新依赖和一段较大的开发量。
- 动手前先做 T0 的验证：一页含中文富文本、表格、图片和图形的流模式画布，在手机浏览器里生成 PDF，看效果和耗时。验证不过再退到 C（只覆盖流模式）。
- 无头浏览器的讨论有结论后，可以把它接成另一种编码手段，供 Agent 和 CLI 使用。打印宿主、分页和 PDF Frame 都不用改。

需要 owner 确认的是：是否接受 A 的两个新依赖（PDF 库和中文字体）。

## 6. 验收

- 流模式画布：含长富文本、跨页表格和图片的画布导出为多页 PDF，没有内容被裁掉，表格跨页有表头。
- 页面规格：同一个画布选 A4 和 A5 各导出一次，页面尺寸正确，分页随之变化。
- PDF Frame：选中后每页都有页眉页脚，页码和总页数正确。同一比例有两个 PDF Frame 时可以任选。比例不一致的不可选。不选也能打印。
- 按路径：一步一页，顺序、隐藏和背景与放映一致，跨画布的步骤都在。自由画布没有演示路径时提示无法打印，不产生文件。
- 界面里没有打印机选择、打印队列之类的画面，全程不出现浏览器的打印对话框。
- 在手机上能完成发起、选页面规格和 PDF Frame、存入 Zone，并在 Zone 里看到文件。
- 生成期间别人继续编辑，输出仍是开始时的内容。
- 没有 `export` 能力的人用不了入口。读不到的内容和讲稿备注不出现在 PDF 里。
- 打印过程不产生 Commit，不运行宏和许愿格。

## 7. 不在本期

- 选择页码范围，或只打印选中的内容。
- 首页不同、奇偶页不同、装订边距、水印。
- PDF 书签、PDF/A、表单域。
- 一次打印多个流模式画布。跨画布的内容用按路径打印。
- 用许愿格生成或调整页面布局（文档 10 提到，放到后续）。
- 集成无头浏览器（另行讨论）。
