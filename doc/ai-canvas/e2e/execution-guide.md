# AI Canvas：Agent 浏览器执行约定

本文件服务于 [七条协作场景](test-requirements.md) 和 [长文交付场景](long-form-writing.md)。目标是让测试设计在 UI 变化后继续适用，
同时保留能复现当次运行的操作与证据。它不是自动化框架安装指南，也不引入产品实现改动。

## 1. 每次运行的输入

给执行 Agent 一个小任务包：场景编号与名称、参与角色、资料、明确的用户目标、冻结的成功和
失败判据、当前可用能力、证据目录与停止条件。具体按钮和元素定位留到观察 UI 后决定。
测试数据必须能独立核算，合成哨兵用来区分范围外信息；期望值不能调用被测聚合函数计算。

执行前记录仓库 commit、相关未提交差异、入口地址、浏览器版本、视口、语言、适配器、数据集
版本与账号性质。先核对原型 README；T-A 用 `src/frame/desktop` 的 `pnpm run dev` 和
`/?scenario=normal` 桌面入口。复用已验证的现有依赖，不为文档或一次检查安装工具链。
运行产物、下载、日志、浏览器临时目录统一放工作区 `.work`，长进程 detached 启动并轮询。

## 2. 观察、行动、核对

1. 观察当前页面的可见内容、可访问名称与状态；记录准备达成的子目标。
2. 根据当前界面选择操作，优先语义定位，例如角色、标签、可见名称，并限定所在窗口或弹窗。
3. 通过真实用户入口点击、输入、键盘、拖拽、文件上传或下载。等待有意义的 UI 状态或请求终态，
   使用有上限的条件等待；不能靠无限等待或反复重试掩盖失败。
4. 核对该子目标的数据和界面结果，留下截图及操作轨迹，再进入下一个子目标。
5. 找不到入口时重新观察，尝试合理的导航或菜单；同一阻塞最多尝试三种有证据的路径后停止
   该子项并记录原因。此限制是执行预算，不是产品响应时间 SLA。

同一套场景可在新 UI 上重新找入口。语义定位不唯一时先检查上下文；必要的布局操作可以用
当次截图和边界确定位置，但这些坐标不成为长期验收标准。脚本版本记录具体定位方法，场景
文档只记录用户意图。若使用稳定 test id，仍需证明它对应用户可见、可操作的入口。

不通过 `store.dispatch`、reducer、直接写 IndexedDB、注入预期结果或伪造成功事件达成目标。
预先准备的文档可走正常导入入口；专门的坏数据变体明确标注为夹具，不能冒充用户创建成功。
浏览器文件输入可用自动化上传；剪贴板夹具必须注明，不能代表真实 Excel 或系统输入法。

## 3. 结果证据和观察边界

| 要证明什么 | 主要证据 | 补充观察与限制 |
|---|---|---|
| 用户完成操作且看懂状态 | Playwright trace 或可复核的逐步浏览器操作日志、关键截图、可见状态 | 内部事件不能替代实际绘制帧；截图不能独自证明原子提交 |
| 资料和成果正确 | 原始夹具、独立预期、UI 下载的导出文件及内容差分 | 可做离线解析与计数；不要按当前错误输出反推期望 |
| 上下文边界与异步行为 | 实际请求、响应、事件时序和请求计数 | T-A 可用受控 HTTP；不证明真实身份或真实模型 |
| 保存、撤销和原子性 | 重开/独立读回、前后业务差分、修订及撤销计数 | 可附加只读观察器；观察器不得改变执行决策或替换产品返回 |
| 多人行为 | 独立角色会话、各自观察到的内容及提交因果关系 | 两个隔离浏览器的文件交接不等于共享同一在线文档 |

UI 主路径应先在不包裹内部函数的条件下运行。确需内部观察的断言单列诊断变体，说明插桩位置
和限制，保留正常对照；不能把插桩调用次数当成最终用户成功的充分条件。故障注入是显式的测试
安排，需要证明故障确实命中，不能隐藏为正常运行。

保存失败和竞态测试可以控制存储或网络时点，但正常文档编辑仍走 UI。每种故障独立运行并记录
时序闸门；页面无法完成用户流程时，诊断只解释原因，不绕过去把主流程改判通过。

## 4. 第一条连续旅程的任务包

**场景：S01 可信初稿 → S02 人工修订 → S03 文件交接；层：T-A。**
作者希望把一份小型销售分析交给同事。同事必须看得见资料、生成结果和作者补充的判断，并能
继续修改。当前执行使用本地 Mock，两名参与者由两个隔离浏览器上下文先后承担。

使用三行 CSV：产品 A 的数量 2、单价 10、销售额 20；产品 B 的数量 3、单价 20、销售额 60；
产品 C 的数量 1、单价 30、销售额 30。全表销售额为 110；只选择 A、B 时为 80。另准备一条
不选中的合成资料和一段唯一人工说明。后续把 B 的销售额由 60 改成 90，则全表为 140，A、B
合计为 110。运行前冻结本次到底选择全表还是选区，并记录相应期望，不能运行后更换范围。

| 子目标 | 用户要完成什么 | 核对内容 |
|---|---|---|
| 整理 | 创建画布、导入 CSV、检查资料、建立用于分析的许愿格 | 原始值、行列与选择范围 |
| 生成 | 表达分析目标并运行，查看结果和来源 | 可见进度、选源、独立核算值及实际支持的输出结构 |
| 修订 | 加入人工说明，修改来源，取消一次刷新，再保留人工结果重新生成 | 过期范围、取消不改内容、人工说明完整、新结果数据正确 |
| 恢复 | 撤销并重做生成，保存，关闭并重新打开 | 一次运行的撤销边界、持久化后的业务内容 |
| 交接 | UI 导出；另一隔离上下文导入、核对并修改后再次导出 | 来源和结果关系、人工说明、接收方改动、凭据隔离 |

本任务包不是 PRD-21.1「主链路验收」的完整复跑；该项仍需季度示例的全部 15 步和固定输出
数量。连续旅程不通过时保留断点，先报告已经验证的子范围；可独立运行后续场景，但必须说明
起点改用了夹具，不能声称端到端旅程完整通过。对请求最小化和输入快照等内部边界，追加独立
观察记录；主路径仅凭 UI 和导出不足以通过 TA-C1「上下文最小化」或 TA-C3「当次输入快照」。

## 5. 多角色和结论纪律

作者和文件接收者使用隔离存储，防止共享浏览器状态掩盖导出缺项；TA-N05「双窗口编辑」则
特意使用共享存储的两个页面，两种环境不能混用。未来真正多人测试使用独立账号及会话，在
各自 UI 验证可见性；“锁定位置”不代表只读权限，Mock 身份也不代表授权通过。

结果采用 [八字段格式](assertions.md#8-结果记录与问题归属)，同时标场景与断言的编号、名称。
PASS 需要所有选定判据的证据；FAIL 需要实际违反判据的证据；INCONCLUSIVE 用于已尝试但证据
不足；NOT_RUN 用于尚未执行。定位失败、环境问题、未实现能力、规格待定与产品缺陷分别解释，
不要一律记为产品失败，也不要把选择器修复算成产品修复。

新记录放在本目录的 `runs/<执行日期>/<批次>/`，该目录由 Git 忽略。执行包包括任务包、
实际路径、八字段结果、证据清单及可复用的执行脚本或工具版本。证据需去掉真实凭据及私有数据；
大 trace 可留在受控归档中，记录可获取位置和摘要。没有可获取证据的断言不得标为可复核通过。
复跑新增本地记录，保留旧结果。

## 6. 可选的语义复核

初稿、修订、交接与恢复后，可按 [语义评估约定](semantic-evaluation.md) 将已有证据提交给 Jev
等评估器，判断交付完整性、信息诚实性与协作上下文。先校准再接检查点；当前工具只做独立旁路
评估，未自动接入浏览器。模型判断不替代数字、请求、持久化等独立断言，不改变原有结果，
也不发明未观察到的事实。仍按用户目标完成浏览器动作后留证，UI 改版不改变这些成功标准。
