# AI Canvas 场景式 E2E：完成一部小说与一篇论文

本文把验收单位从单个控件改为用户要交付的作品。执行 Agent 通过当前 Canvas UI 完成任务，使用 Playwright 等浏览器工具观察、操作和留证；按钮、布局和选择器由当次运行决定，本文固定的是输入、目标、关键决策、交付物和判据。两条旅程分别检验长篇创作的连续性，以及研究写作的证据纪律；其他交付目标见 [W03–W20 场景目录](user-goal-scenarios.md)。它们是 [七条协作场景](test-requirements.md) 的交付物型补充，不替代 [PRD 验收附录](assertions.md) 中的逐项断言。

## 共同执行约定

每次运行先冻结任务包：场景编号、用户目标、素材版本、允许使用的来源、禁用来源、目标长度、模型与适配器、费用和时长上限、账号和浏览器环境、人工审阅人、停止条件。测试 Agent 不得调用 Canvas 内部 store、直接改导出 JSON、在外部聊天产品生成成品再粘贴，或为凑长度重复段落。正常路径仅经浏览器中用户可用的入口。可以离线解析从 UI 下载的文件，计算字数、核对事实和比较版本；解析器不能替代用户操作。

两个场景都有两种明确不同的运行范围：

| 范围 | 今天能证明什么 | 结果记录 |
|---|---|---|
| T-A 本地承载 | 人工准备的分章或分节文本经 UI 放入 Canvas，验证编辑、分块、保存、重开、撤销、导入导出和交接。可用 Mock 注入失败分支。 | 只给这些子目标判定；不能声称 Canvas 生成了小说或论文。 |
| T-A 写作生成 | 经 Canvas UI 使用已配置且可审计的 HTTP Agent，逐步生成、修订并交付作品。实际请求和返回可留证，真实模型及其成本在运行前确认。 | 满足下文全部结构、事实、持久化和内容审阅判据后，才能判整条旅程 PASS。 |

当前 Mock Agent 对文本来源只生成摘要，不能承担长文写作的正常路径。HTTP 适配器存在不等于写作服务已可用。若没有写作 Agent、模型凭据或允许的预算，生成子目标记 `NOT_RUN` 并写明前置缺口；不得把粘贴的预制作品或 Mock 摘要改称生成成功。当前原型没有在线分享、真正多人协作或 Office 高保真导出；交付物以 UI 导出的 `.aicanvas.json` 和接收者再导入为准。T-B/T-C 暂不启动。

一次运行至少保存：任务包、原始素材与独立预期、浏览器 trace 或逐步操作轨迹、关键截图、生成请求与响应摘要、失败注入命中证据、UI 导出物、离线字数与事实核对报告、审阅意见、按 [八字段格式](assertions.md#8-结果记录与问题归属) 写的逐步结果。真实数据和凭据不进入仓库；运行包放在被 Git 忽略的 `runs/`，脚本及浏览器临时文件放项目 `.work`。长度按导出物中最终正文的 CJK 汉字数量计算，排除标题、目录、提示词、提纲、参考资料和附录；同时报告原始字符数，避免不同软件的“字数”口径掩盖差异。

## W01 · 用户完成一部约两万字的网络短篇小说

**用户需求。** 作者想把一个设定发展成可读、可修改、能交给编辑继续工作的完整中文悬疑故事。一次生成一大段并不够：人物和时间线要跨章节一致，作者改动不能在重写时丢失，最后下载的内容必须和重新打开时看到的内容相同。

**冻结的创作素材。** 任务包使用原创设定《海雾尽头的七号线》：2028 年的虚构海港城，维修员许澜与档案员沈砚是旧友；七号电车在 2017 年一次事故后停运；许澜收到一张写有失踪司机姓名的旧车票，必须在档案销毁前查明记录为何被改动。风格为现实悬疑，结局需要解释车票、事故与记录篡改的因果关系，不以超自然力量或梦境取消已发生的事件。允许作品自行发展支线，但角色身份、停运时间和关键物件在版本内必须自洽。另放一段可识别的范围外虚构素材，只用于验证未选择的内容没有进入生成请求。

**交付物。** 一份可从 Canvas 打开、继续编辑并重新导出的文档，含作品提纲、人物与时间线、八章正文、作者修订记录或等效可辨识版本。最终正文为 18,000～22,000 个汉字；每章有实质内容，不通过重复句段、空白或复制提纲凑数。作者在第三章亲手加入的句子“海雾退去之前，我会把名字写回车票。”必须逐字保留。作品仍以 Canvas 块表达；本场景不要求 PDF、EPUB 或排版精度。

| 检查点 | 用户要完成的事 | 执行 Agent 的浏览器旅程 | 可观察的完成条件 |
|---|---|---|---|
| W01-1 规划 | 从设定得到可执行的八章结构 | 新建画布，放入并选中设定，表达目标；审阅提纲与人物、时间线，再确认进入正文 | 提纲覆盖开端、调查、转折和结局；关键事实可定位；请求只含作者选定的素材。 |
| W01-2 分章写作 | 逐章得到一份长文 | 以章或适当批次运行许愿格；每批读回结果，再把必要的已有章节或摘要作为显式来源继续写 | 八章都能在 UI 找到，顺序清楚；每次运行的结果和来源可追溯；没有静默覆盖前章。 |
| W01-3 作者修订 | 中途改变创作判断并保护手写文字 | 完成前四章后，在第三章加入指定句子；把设定中“2017 年停运”改为“2016 年停运”，要求检查并修订已写和后续章节 | 系统提示相关结果过期或要求明确处理；作者句子保留；最终版本不混用 2016 与 2017 两条事故时间线，旧稿的去留可解释。 |
| W01-4 中断恢复 | 写作中断后继续，而非重复生成 | 在一章运行期间引入一次受控慢响应、取消或失败；回到画布确认状态，再按 UI 提供的路径重试 | 失败批次不留下半章冒充完成；已完成章节和作者输入不丢；重试后没有重复章节或迟到结果覆盖新稿。故障需证明实际命中。 |
| W01-5 完稿交接 | 把完整作品交给另一个人继续编辑 | 检查结局与目录，保存、离开、重开；经 UI 导出，在隔离浏览器中导入，做一处编辑并再次导出 | 两次导出与 UI 可见内容一致；八章、作者句子、人物关系和最终时间线往返保留；接收者不依赖作者浏览器私有状态。 |

**独立判定。** 离线核对最终正文汉字数、章节数量与顺序、指定作者句子、旧年份残留、重复段落和导入导出差分。人工审阅至少回答四个预先固定的问题：主角的行动动机是否清楚、调查与结局是否有可追溯的因果链、跨章人物与时间线是否一致、是否存在大量机械重复或未交代的重要支线。审阅人标注章节与证据；分歧未复核前，内容质量为 `INCONCLUSIVE`。模型或 Jev 可以提示待看段落，但不能单独宣布文学质量通过。长度达标也不能抵销内容缺失或保存失败。

## W02 · 用户完成一篇有来源约束的研究论文初稿

**用户需求。** 学生希望在 Canvas 中完成题为《社区图书馆延时开放与到访量变化》的中文课程研究论文初稿。系统要帮助组织论点和证据、计算给定数据、写清研究限制；不能为了让论文“像真的”而捏造研究对象、参考文献、DOI、访谈或因果结论。此场景验收可供导师继续修改的论文初稿，不宣称达到正式投稿标准。

**冻结的受控资料。** 本任务的资料均为合成教学材料，不得表述为真实馆藏统计或已发表论文：`DATA-1` 为同一虚构图书馆延时开放前后各四周的日均到访量，前期依次为 120、128、118、122，后期依次为 135、138、130、141；`METHOD-1` 记录后期每天延长开放两小时、没有随机分组，且后期含考试周，天气和其他活动未控制；`SURVEY-1` 记录便利抽样的 18 名受访者中 12 名自述使用了晚间时段，但样本不能代表全体读者。独立预期为前期均值 122、后期均值 136、差值 14、相对前期约 11.5%。这些数字和资料标识在执行前冻结，不从模型输出反推。另置一份未获选中的合成笔记，用于检查上下文边界。

**交付物。** 一份 4,500～6,500 个正文汉字的论文初稿，包含题目、摘要、研究问题、资料与方法、结果、讨论、限制、结论和资料清单。正文只引用任务包允许的资料 ID；资料清单把 `DATA-1`、`METHOD-1`、`SURVEY-1` 标为合成教学材料，不伪装成真实学术文献。若将来运行者提供真实文献，应在运行前冻结文件、版本、作者、页码或稳定标识，并单独增加“真实文献核验”变体；没有该素材时不把论文称为完成了文献综述。

| 检查点 | 用户要完成的事 | 执行 Agent 的浏览器旅程 | 可观察的完成条件 |
|---|---|---|---|
| W02-1 建立证据 | 先看资料，再决定能写什么 | 新建画布，经正常 UI 放入三份资料；选中允许的来源，要求列出研究问题、可算指标及不能推出的结论 | 提纲区分“到访量变化”与“延时导致变化”；未选笔记不进入实际请求；三份来源可辨识。 |
| W02-2 分节成文 | 从证据形成论文初稿 | 逐节生成并检查摘要、方法、结果、讨论等；对每个数字和重要事实回到来源 | 正文长度和结构达标；122、136、14、约 11.5% 的口径正确；每个引述可追到允许的资料；没有虚构引用。 |
| W02-3 数据修正 | 来源改了，论文也需要改 | 用户把 `DATA-1` 后期第四周由 141 改为 125，再触发受影响部分的复核与修订 | 最终后期均值为 132、差值 10、相对前期约 8.2%；摘要、结果、讨论及结论不保留旧数值；未受影响的作者评论不被覆盖。 |
| W02-4 质疑结论 | 论文需要承受审阅者追问 | 用户提出“既然上升了，能否写成延时开放造成增长？”并要求检查考试周和抽样限制 | 最终稿不把观察性前后差异写成已证明的因果效应；说明混杂因素、样本边界及进一步研究方法。 |
| W02-5 保存交接 | 导师能继续核对和修改 | 保存、离开、重开，经 UI 导出；在隔离浏览器中导入，核对资料、正文和修订，再修改一段讨论并导出 | 完整论文与来源关系可读；修正后的数字、限制及导师改动在往返中保留；没有静默丢失。 |

**独立判定。** 用冻结的资料重新计算四个数值，逐条核对正文中的数值、调查描述、资料标识和任何参考文献。人工审阅研究问题、方法与结论是否匹配，以及限制是否足以防止因果过度主张；需要指出具体句段，不能只给“写得像论文”的印象分。若格式齐全但事实或引用有一处编造，相关子项为 `FAIL`。若没有人工内容审阅或无法取得实际请求证据，分别将质量或上下文边界标为 `INCONCLUSIVE`，不能用漂亮的 UI 截图补足。

## 变体、追溯与推进顺序

| 变体 | 要揭示的风险 | 初始范围 |
|---|---|---|
| W01-L 长上下文 | 后几章遗漏早期设定、把旧稿当最终稿，或超过上下文上限时悄悄截断 | T-A 写作生成；记录每轮实际发送的来源和裁剪提示。 |
| W01-R 跨章重写 | 一次修改牵动多个章节，却只更新了其中一处，或覆盖手工文字 | T-A 本地承载可先测保护与过期；语义一致性需写作生成。 |
| W02-C 引用越界 | 模型把合成资料包装成真实论文、杜撰 DOI 或引用未选资料 | T-A 写作生成；人工和离线资料核对并行。 |
| W02-U 真实文献 | 用户提供可核对的 PDF、网页或文献元数据后，逐项检查引文与页码 | 资料准备完成后单独运行；网络研究连接器能力不预设已实现。 |
| W01/W02-F 故障恢复 | 取消、超时、保存失败、旧请求迟到后出现半成品或假成功 | T-A 受控故障；先有正常对照，并证明注入点命中。 |

W01/W02 的规划与来源选择对应 S01、S05；作者修订和数据更新对应 S02、S04；中断对应 S06；导出交接与审阅对应 S03、S07。执行时同时记录这两个层次的“编号 + 名称”。先跑本地承载子项，确认两类长文能被编辑、重开和交接；再在写作 Agent 就绪时跑完整生成旅程及失败变体。每个检查点独立写结果，整条旅程只有在所有必需检查点都有可复核证据、内容审阅完成时才判 PASS；`NOT_RUN`、`INCONCLUSIVE` 与 `FAIL` 不能合并为“基本通过”。本文件是测试需求，尚无本轮执行结果；发现产品问题先保存在本地执行包，不自动创建 GitHub issue。
