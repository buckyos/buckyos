## 用户目标、数据与实际路径

任务依据为 [浏览器执行约定 §4](../../../execution-guide.md#4-第一条连续旅程的任务包)。本轮选
sales.csv 的全部三行，明确请求“按产品汇总销售额，生成销售额总计、图表和汇报摘要”；独立
期望为 110，B 的销售额从 60 改为 90 后为 140。未选择的合成文本、作者说明和接收者说明都
使用唯一标记；没有使用真实凭据或私有数据。

操作路径：桌面 AI Canvas → 新建并命名 → 文件选择器上传 CSV → 确认表头和数据 → 从表格创建
许愿格 → 写目标并运行 → 双击摘要增加人工意见 → 双击源单元格更新 → 取消刷新 → 保留旧结果
生成新版本 → 一次撤销 / 重做 → 刷新桌面并重开 → UI 导出 → 独立上下文导入 → 继续编辑、保存
并重开。26 段 [当次操作脚本](steps/01.mjs) 与 [逐步 UI 日志](evidence/01.json) 保存真实路径，
文件名按步骤递增；不是承诺改版后仍能原样重放的固定脚本。

整个用户流程未调用内部 Store、reducer 或写入 IndexedDB，没有用预制文档跳过前段流程。
只有文本块放置使用当时截图确定坐标；其他主要操作按可见名称定位，数据核对读取 UI 下载文件。

## 失败与无法判定

**图表目标未交付。** 初次导出 9 个块：来源表、许愿格、未选中文本，加 3 指标 / 1 结果表 /
1 摘要 / 1 结果组，没有 chart。UI 与 [导出](evidence/initial.aicanvas.json) 一致。
当前 [Mock 源码](../../../../../../src/frame/desktop/src/app/canvas/agent/mock.ts) 的销售分析分支
只在存在区域列时生成区域图；本数据按产品分析，所以没有图表。归属原型 Mock 能力差异，
不归为内核或应用业务缺陷，不自动提交 issue。保留这一未达成目标后，继续检查现有成果能否
安全修订和交接；没有修改输入去“补出”一张图，也没有把整条旅程判为通过。

**缺失输入的解释仍需补测。** 原数据没有成本或目标，输出却有 100% 毛利率和 0% 目标完成率；
属性面板又提示“未找到成本列，毛利率按 0 计算”，目标列在结果表显示为“—”。见步骤 17 UI
与初次导出。团队接手时可能把默认值理解成事实；本轮只冻结了销售额的独立预期，将缺失输入
应如何表达列为 TA-N17 后续重点，未据此另加一次动态缺陷计数。文件交接成功不证明这些结论可信。

**实际输入范围证据不足。** 导出只说明 contextRefs 选择了全表，不能证明产品 Agent 收到什么。
因此 TA-C1「上下文最小化」未获得本轮通过证据；下一轮应在不改变 UI 操作路径的前提下增加
实际请求观察。TA-C3「当次输入快照」、凭据哨兵、媒体、异常保存、真实权限和多人在线协作
本次未执行，旧结果不因此改变。

**自动化与证据限制。** 步骤 01 预期中文桌面按钮超时，实际名称是 AI Canvas；观察后重新定位。
步骤 04 截图超时，步骤 05 成功捕获编辑器；两者均保留记录，未判产品失败。只有作者页面安装
了 pageerror 收集，不能据其空列表断言全部窗口没有错误。撤销保留运行历史、lastRunId 和当前
相机；本次按 TC-009 核对生成内容、绑定、既有业务对象与重做恢复，完整差异留在原始导出中。
