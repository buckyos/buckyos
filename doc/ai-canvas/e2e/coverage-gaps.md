## 2. 为什么现有通过项还不够

| 已有证据 | 没有覆盖的关键分支 | 对用户的影响 |
|---|---|---|
| TC-004「许愿格成功与进度」、TA-V00～16「补丁边界与保护」 | 表格 AI 单元格走 `runCell`，与独立许愿格 `run` 的校验和写入路径不同 | 同一条“过期结果不误写”不能凭另一入口通过就算覆盖 |
| TC-001「空白画布创建」、TC-011「持久化」 | 存储失败、事务中止、保存期间继续编辑、正常离开、两个窗口写同一份文档 | 顶栏可能给出错误的保存信心，或新内容被旧副本覆盖 |
| TC-007「取消」、PROTOCOL-CONFLICT「修订冲突」、PROTOCOL-HTTP「HTTP 协议」 | 临界时序、取消后重试、旧响应晚到、分帧事件、错误任务 ID | 旧任务可能影响新任务；一次正常 HTTP 请求不能证明异常网络时序可靠 |
| TC-006「人工修改保护」 | 已测取消与保留副本；未完整验证替换失败后的旧结果保护、解除 AI 管理和再次运行 | 人工内容可能在恢复、替换或后续刷新时丢失 |
| TC-009「撤销生成」、TC-011「活动 Sheet 恢复」 | 命名快照恢复、复杂 Sheet 复制、引用重映射、在运行中恢复 | 撤销一次生成不等于所有用户操作都有正确的逆操作 |
| TA-C1「上下文最小化」、TA-S1「同源三图表展示隔离」 | 嵌套组、范围重映射、输入截断与图表数值核算 | 发送了更多数据、遗漏了关键行，或者三张图一致地算错，都可能漏检 |
| TC-012「导入导出一致性」、TA-F1/F2「未知块与版本」 | 损坏但可解析的文档、循环组、媒体资源和结构异常 | “能 JSON.parse”不等于能安全打开、保存和恢复 |

2026-09-24 的覆盖评审核对了当时两阶段实际脚本；上述条目指缺少对应动态断言，不是按标题推测。原始执行档案留在原执行仓库，本次只迁移需求；历史问题编号与结果边界见 [入口说明](README.md)。

## 4. 首批：P0 用例设计

### TA-N01 · AI 单元格写回边界、覆盖确认与撤销

- **依据与缺口**：PRD §11.6、§11.13。`runner.ts:180` 的 `runCell` 单独构造请求并写单元格；已有许愿格补丁检查不能代替它。
- **步骤**：在空格、非空普通格分别“转为 AI 单元格”；对覆盖提示分别取消 / 确认；响应返回标量与短文本；再恢复普通格，逐步撤销 / 重做。另返回二维结果、邻格改写或长文结果，单列 PRD §11.6 声称的扩展能力。
- **断言与证据**：取消覆盖的请求增量为 0，原格及邻格全文不变；确认后只有授权位置改变，值、类型、AI 标记、`cellWishes` 一致。每个用户动作可撤销，撤销后无孤立 AI 元数据或幽灵 running 状态。记录每步单元格矩阵、命令和 undo 增量；不能预设运行状态写入也各算一个用户撤销动作。
- **能力边界**：二维扩展 / 关联结果若当前入口不支持，记录可复现的能力缺口；不能把“没有执行这一分支”写成安全通过，也不把它推给 T-B。

### TA-N02 · AI 单元格运行中编辑、删除与过期返回

- **依据与缺口**：PRD §11.6、§13.1 的用户内容保护；过期写回是对该独立入口的补充验收。
- **步骤**：发起慢计算后，分别手工修改目标、修改输入行、恢复目标为普通格、删除行 / 列 / 表、关闭后重开。对同一格连续发起两次不同目标的计算，先返回第二次再返回第一次。
- **断言与证据**：旧计算不能覆盖后来的人工值或新运行结果，不能把已转普通的格重新变成 AI 格；删除的目标不复活，也不写入其原位置的另一行 / 列。错误有明确终态，重开后无永久 running。捕获 `(canvasId, tableId, rowId, columnId, runId)`、输入修订、回包次序与逐格 diff。并发若被产品禁止，应明确拒绝第二次；不要求一定支持并行。

### TA-N03 · 保存失败、事务中止与保存状态真实性

- **依据与缺口**：FR-DOC-002 要求保存失败不静默。`saveNow` 等待存储 Promise；`indexeddb.ts:46` 同时处理 request 和 transaction 事件，需要覆盖它们不是同一个完成点的情况。
- **步骤**：分别注入打开库失败、quota 错误、写请求失败，以及 put 请求成功后事务 abort；随后解除故障并重试保存。使用独立测试存储，禁止清理用户实际数据库。
- **断言与证据**：失败不能显示最终“已保存”或清除未持久化编辑；旧的已完成持久化版本仍可读，新内容仍可复制或导出。重试成功后重新打开得到新内容。记录 request success / transaction complete / abort 的顺序、dirty / saveStatus 以及另一个读取连接读到的值；不能只用 mock Promise 的成功模拟真实提交。

### TA-N04 · 保存期间继续编辑、离开与异常恢复

- **依据与缺口**：FR-DOC-002、FR-SHEET-001；正常保存后刷新没有覆盖中途离开。源码已有 dispose、保存刷新和 beforeunload 处理，值得直接验收。
- **步骤**：版本 A 的保存尚未完成时写入 B；分别点击返回画布列表、切换 Sheet、关闭编辑器、刷新。另在发生保存错误后点击返回。独立执行一次进程异常终止变体。
- **断言与证据**：迟到的 A 不能使 B 被错误标成已保存；正常离开应完成保存，或保留可恢复编辑并明确阻止 / 确认丢弃，不可静默丢失。异常终止只承诺最后一次**已完成持久化**的版本可恢复，不要求恢复尚未持久化的每次按键。记录 A/B 摘要、存储完成顺序、导航发生时的状态和重开结果；浏览器离开提示与应用内返回须分开测。

### TA-N05 · 同一文档双窗口编辑不静默覆盖

- **依据与缺口**：新增数据安全验收建议。它是同一用户、同一 IndexedDB 的窗口竞争，**不是**多人协作 T-C；存储接口已有 `expectedRevision` 参数，实际保存调用是否利用它必须用场景验证。
- **步骤**：两个页面打开同一版本；A 保存新内容，B 保存旧副本上的另一修改；再测双方各自把 revision 从 n 改为 n+1 的同号分叉、B 保存延迟、A 已删除文档而 B 仍打开。
- **断言与证据**：不能只比较 revision 数值就认定两份内容相同。重新打开必须能解释最终采用的版本，不能两个窗口都声称成功而静默丢掉另一份编辑。产品可选择冲突提示、另存副本、单窗口只读等策略，不要求自动合并；**选择哪种策略需确认后冻结**。记录两个完整内容摘要、写入顺序、删除前后文档列表，观察是否产生意外复活。

### TA-N06 · 取消、重试、切换文档后的迟到回调

- **依据与缺口**：FR-AGENT-003/004、编辑器卸载约束；已有取消用例只覆盖正常慢任务响应取消。
- **步骤**：在返回头、completed 事件、结果回包三个边界附近分别取消；取消后立即重试；A 文档运行时切到 B；运行中删除许愿格 / Sheet；页面重开后放行旧响应。用夹具闸门控制顺序，不能靠随机 sleep 碰运气。
- **断言与证据**：以捕获到的取消 / 已提交先后顺序判断胜者。提交前取消则无写入；提交后取消不得反称“已取消且无结果”。旧任务不能写 B、替换新任务状态、重复追加历史或撤销条目。每个 runId 终态及提交次数可计数；卸载后旧 run 的提交增量为 0，新文档摘要不变。

### TA-N07 · HTTP 分帧、异常终态与任务身份校验

- **依据与缺口**：PRD §13 协议及任务归属的一致性补充；已有 HTTP 用例把完整事件串一次性返回。
- **步骤**：按字节拆分 UTF-8 中文与 SSE 分隔符；测 CRLF、心跳、正常 completed 后连接不关闭、重复 completed、failed 后断流、没有终态的截断流、result 500 / 非 JSON。另给正确 revision 但错误 `runId` 的结果、缺失 jobId、上一任务的结果包。
- **断言与证据**：有效分帧消息完整解析，成功至多提交一次；重复 completed 不重复写入。失败 / 不能确认归属的结果不得应用；截断后若结果接口能明确返回匹配任务的完整结果，可按冻结协议恢复，不能仅因流结束便判成功。没有终态的任务须有界失败或明确恢复。保留原始响应字节、请求次数、runId / jobId 对照、终态和 undo 计数；不以 Mock 的确定性代替真实 HTTP 适配器验证。

### TA-N08 · 补丁多入口保护与最终结构一致性

- **依据与缺口**：PRD §13.5；TA-V12「先创建再更新绕过文本上限」和 TA-V13「修改用户组」说明只逐个覆盖操作名不够。
- **步骤**：参数化操作组合：创建后更新 `id/type/sheetId/generated`；更新到其他 Sheet；对另一许愿格结果、已解除 AI 管理的块、用户组执行 update / regroup / resize；重复块 ID、重复绑定 ID、组包含自己 / 相互包含；更新不存在的 columnId；前面合法、最后非法。另加入同一运行拥有的合法结果更新作为正对照。
- **断言与证据**：按补丁**最终效果**检查身份、类型、所属 Sheet、所有权、大小和完整引用关系，禁止通过其他操作入口绕过保护。非法整包拒绝后业务内容、旧结果组、绑定、revision、undo 不变；合法对照必须能写入。各变体保存完整 patch 与前后图关系。现有四条失败仍归原编号；这些新变体不重复冒充新缺陷数。

### TA-N09 · 非可信文本、链接及媒体不执行宿主代码

- **依据与缺口**：PRD §16 的宿主边界。Markdown、导入文档、媒体来源和 Agent 输出都已存在，不需要等待交互块沙箱实现。
- **步骤**：通过正常导入 / Agent 返回放入含 HTML 事件属性、脚本协议链接、带无害脚本哨兵的 SVG、异常媒体 URL 的内容；分别打开、预览、点击、导出后重新导入。使用本地受控接收器，所有数据为合成数据。
- **断言与证据**：不执行宿主脚本、不读取测试 cookie / 存储哨兵、不向夹具中指定的非授权接收点发送哨兵。安全的 https 链接和正常图片作正对照，不能把所有内容不渲染当通过。记录执行哨兵、网络请求、弹窗及页面错误；React 或浏览器可能已拦截某些路径，不能仅凭源码未显式过滤就判漏洞。P0.5 独立 iframe 的完整能力仍另行验收。

### TA-N23 · 运行中切换 Agent 服务配置不串服务

- **依据 / 独立缺口**：新增任务归属验收建议。TA-N06「迟到回调」改变任务 / 文档，TA-N07「任务身份校验」改变回包；这里改变的是任务所在的服务。`http.ts:17` 每次构造 URL 都读取配置，运行中保存设置值得单独核对。
- **步骤**：在本地服务 A 提交任务，分别在创建响应、SSE 连接、result 拉取前通过设置 UI 切到 B，再分别继续、取消、超时；补 HTTP→Mock 的切换。A/B 使用不同结果哨兵，也设置同名 jobId 正对照，避免仅靠 ID 相同就误判同一任务。完成后新建任务验证新配置生效。
- **判据 / 证据**：已经发给 A 的任务，其后续查询和取消不能无提示地改发 B；产品可固定当次配置、禁止运行中修改，或明确终止旧任务再启用新配置。新任务使用选定服务；切到 Mock 不会把旧 HTTP 结果冒充 Mock 结果。记录 `(runId, jobId, adapter, origin)`、两端请求日志、实际返回哨兵和终态；B 收到旧任务请求的计数为 0。不得自动重发完整输入到新服务。超时设置对当前 / 下一运行的生效口径另列待定。

### TA-N24 · 连续手势与异步提交的撤销隔离、重做分支

- **依据 / 独立缺口**：FR-HISTORY-001、PRD §5.4 / §11.8。TC-009「撤销生成」只覆盖静止时的一次提交；`beginTransient/endTransient` 合并手势期间的命令，需验证异步完成不被合进同一个撤销单位。
- **步骤**：先完成最后一个拖拽位移但暂不松手，再通过可达运行入口或已配置的 on_change 发起任务，确保输入 revision 等于该位移后的版本；松手前放行合法补丁。与“先松手再回包”“拖拽中补丁因修订过期被拒绝”分别对照。逐次撤销 / 重做后，再测创建 A→创建 B→撤销 B→创建 C→重做，以及 99/100/101 个独立修改的历史边界。
- **判据 / 证据**：若补丁已接受，一次撤销 AI 结果不能一并撤销独立拖拽，逐步逆操作后两者各自可恢复；若产品选择延后提交，须验证排队至手势结束而非丢弃。过期拒绝不计作接受路径通过。新修改 C 清除旧 B 的重做分支，不能复活已放弃内容；静默进度 / 相机事件不能挤掉内容历史。记录命令序列、匹配的请求 revision、是否真正进入应用、每次 past/future 长度及业务差分。100 是当前实现观测边界，不把它升级为未承诺的永久历史容量。

### TA-N25 · 弹窗与桌面窗口的操作焦点隔离

- **依据 / 独立缺口**：新增防误操作建议。TA-N20「中文输入与快捷键隔离」关注编辑控件；这里关注弹窗遮住的编辑器和桌面后台窗口。当前键盘 / 粘贴监听在 `window` 上，焦点为 body 时也视为作用域内。
- **步骤**：画布先选中块，再打开设置 / 导入 / 确认弹窗，把焦点停在按钮、遮罩和输入框，分别 Delete、Ctrl/Cmd+Z、Ctrl/Cmd+Enter、粘贴、Escape；再切到另一真实桌面应用或系统可打开的第二画布窗口，覆盖按钮被替换后焦点落 body 的情况。
- **判据 / 证据**：动作只由当前明确的交互层处理；弹窗中操作不能删除背后选中块或额外运行许愿格，Escape 只关闭最上层可关闭界面。非活动画布的业务命令 / Agent 请求增量为 0；回到画布后合法快捷键正常。保存 activeElement、活动窗口身份、带 canvasId 的命令 / 请求计数和前后文档摘要。若桌面限制单 Canvas 实例，双画布分支记录不可达，不能通过人工挂载第二 EditorShell 冒充真实桌面 E2E。

## 5. 第二批：P1 用例设计

### TA-N10 · 结果链替换与分叉不改变来源选择含义

- **依据 / 缺口**：FR-BIND-001/002、FR-WISH-003；README 声明支持结果组串联和替换重定向。TC-015「循环依赖」不证明正确的非循环链能持续工作。
- **步骤**：构造 A→B→C 和 A→B/A→C；B 分别只引用 A 的整组、一个子表、子表的 2×2 范围；修改 A 并替换，观察 B/C，随后按顺序刷新、撤销、重做。其他子块放范围外哨兵。
- **判据 / 证据**：绑定和状态指向可解释的新版本，旧组无意外悬空引用，未受影响的分支不改。原本选择子表 / 范围时，不能未经确认升级为发送整组；无法精确对应时应明确中断并要求重选。记录每次真实上下文、引用集合和 fresh/stale/broken；**子结果消失或一变多时如何重映射需冻结产品口径**，不默认“第一新组”正确。

### TA-N11 · 替换失败保留人工结果，解除 AI 管理有效

- **依据 / 缺口**：FR-RESULT-003、FR-AGENT-004、PRD 流程 D；TC-006 已测取消和保留旧版，不能覆盖替换后的失败回滚。
- **步骤**：手改结果后确认替换，再分别注入请求失败、最后一项非法、通过初步检查但写入时失败；对旧组解除 AI 管理再改来源并运行；撤销 / 重做解除操作。
- **判据 / 证据**：所有失败下旧组全文、人工文本和旧依赖仍在；解除后再生成不得替换或重新管理普通内容，撤销解除则恢复一致的归属。记录组 ID、成员、generated / bindings 摘要及每步 undo。失败路径若未触发预定故障点，标为夹具不足，不能通过。

### TA-N12 · Sheet 与内容块复制后的引用、归属和独立性

- **依据 / 缺口**：FR-SHEET-001、FR-CANVAS-002；已测普通文本复制、新建 Sheet 和恢复活动页，未测有图关系的复制。
- **步骤**：复制一个含表、引用图表、许愿格、结果组、AI 单元格和讲述步骤的 Sheet；另分别复制完整结果组及其中一个块；修改 / 删除副本，再撤销重做。
- **判据 / 证据**：新对象 ID 唯一；明确应复制的内部引用指向副本，不能出现“副本图表还读原表”。源文档内容不被副本修改污染，无重复 Sheet 成员或丢失的组关系。跨 Sheet 外部引用及 AI 管理归属是“共享来源”还是“独立副本”需先明确；逐边核对，不能只数新块。保存 / 重开后的关系与复制完成时一致。

### TA-N13 · 命名快照恢复、运行中恢复与撤销对称

- **依据 / 缺口**：FR-DOC-004 明确要求快照完整且恢复可撤销；当前已有创建、预览、恢复入口。
- **步骤**：命名快照 A；改文本、表、Sheet、图表配置和讲述路径为 B；恢复 A→撤销→重做→重开；在慢 Agent 运行时恢复快照，再放行旧响应。删除快照另测不删除当前文档。
- **判据 / 证据**：按文档数据 / 视图状态 / 运行状态分别比较，恢复的是完整业务状态，文档自身身份不变；一次恢复可以撤销回 B，不能恢复永远 running 的运行状态。旧响应不能因数字 revision 恰好相同而误写。记录快照内容、状态变迁、前后摘要及撤销单位。命名快照与 TA-C3 要求的“自动保留当次输入”是两项不同能力。

### TA-N14 · 上下文裁剪、嵌套范围与字节上限可解释

- **依据 / 缺口**：FR-WISH-003/005、§16.2；当前有 2000 行、200000 文本字符裁剪及 4 MiB 序列化字节上限，TA-C1 只测了一个小选区。
- **步骤**：分别放入第 2000/2001 行才出现的异常值、末尾关键结论、多字节中文 / emoji、大图片；嵌套组中再放其他 Sheet / 隐藏元数据 / 评论 / 历史哨兵。对 4 MiB 附近按实际编码字节构造两侧值。
- **判据 / 证据**：请求只含实际选择的来源；数量与裁剪范围可见且与预览一致。若发送子集，不能把结果表述为完整原始数据集的结论；超限预检请求增量为 0，缩小范围后可成功。保存原文 / 实际输入长度与摘要、UTF-8 字节数、预览和警告；不以 JS 字符串长度代替字节数。裁剪后允许直接运行还是要求确认，是新增待明确口径。

### TA-N15 · 损坏文档、循环组与异常结构的导入恢复

- **依据 / 缺口**：FR-DOC-003、§17；TA-F1/F2 只验证了有良好结构的未知块和明确高版本。
- **步骤**：独立夹具覆盖截断 JSON、非法版本字符串、`sheets=[null]`、块缺 content、键与块 id 不一致、重复 Sheet / 行列 ID、无效坐标、悬空绑定、组自引用 / 间接环、深嵌套、重复导入同一文件。另以合法旧格式 / 未知字段作容错对照。
- **判据 / 证据**：合理拒绝或明确告警并容错，不白屏、无限递归或改坏已有文档。每次失败后仍能创建和打开正常文档；合法未知数据按既有兼容口径保留。记录导入前后文档列表、已保存文档摘要、错误和 pageErrors；超时要采集原因，不能只写“没显示”。循环组的上下文遍历与 TA-V11 的 binding 环是不同结构。

### TA-N16 · 真实表格数据语义与导入边界

- **依据 / 缺口**：FR-TABLE-002/003/004；已有 GBK、中文和大表路径，缺少值语义及复杂文件内容。
- **步骤**：CSV 的引号、字段内逗号 / 换行、空尾格、BOM、重复表头；字符串学号 `00123`、长编号、空值、0、false、负数、小数、日期歧义。测 20000/20001 行、100/101 列和文件大小边界的选择 / 取消。XLSX 在入口缺陷修复后补缓存公式值、无缓存公式、空工作表、合并单元格与多 Sheet。
- **判据 / 证据**：与独立夹具期望矩阵逐格比值、类型和显示值；类型不明确或精度不能保证时不得悄悄改写。截断数量和取消行为明确，取消无残留块 / undo；不执行宏和公式重算。学号等自动推断策略、文件 MB 单位与阈值来自冻结规则或记录为待定，不能根据实现现值反造期望。XLSX 的入口失败与后续未覆盖断言分别记录。

### TA-N17 · 图表与指标的数值独立核对

- **依据 / 缺口**：FR-CHART-001/002、PRD 主链路；三个图读数相同不能排除三者共用同一个错误算法。
- **步骤**：用人工算得出的数据：A 组 10、20、空值，B 组 -5、0；核对 sum / avg / min / max / count 与排序，加入多系列、空表、缺列、全非数值、0 分母。改源值及表头后再比较图表和指标。
- **判据 / 证据**：例如数值非空计数口径下 A 的 sum=30、avg=15、count=2，B 的 sum=-5、avg=-2.5、count=2；count 是所有行还是数值非空行必须明确。SVG 可访问描述 / 可复制数据与独立期望一致，缺列不能静默换另一指标，NaN/Infinity 不伪装成正常值。若数字字符串、空值、重复列名规则未定，先标待定再冻结，不用被测 `resolveChart` 计算期望。

### TA-N18 · 增删行列、改表头后的引用与目标单元格身份

- **依据 / 缺口**：FR-TABLE-001/005、FR-WISH-003；TA-D1 只涉及块 ID 改名，不涉及表内结构变化。
- **步骤**：建选区许愿格和 AI 单元格，在目标前插行列，再删目标行 / 列、改表头，分别撤销 / 重做；含一份列名相同但 columnId 不同的数据。
- **判据 / 证据**：单元格目标不因位置变化写到另一记录；请求预览与实际发送坐标、rowId / columnId 对应一致。需要补齐“范围跟坐标还是跟记录”的产品口径；无论选哪种，删除来源不允许悄悄改用同名或相邻对象。记录操作前后坐标→ID→值对照、实际请求和 dataRevision，不能把表内容变化仅当成显示变化。

### TA-N19 · 自动刷新、同时运行与失败后的请求收敛

- **依据 / 缺口**：FR-BIND-002，原型已有 on_change 定时调度及失败后不自动重试逻辑；此前主要为手动单次运行。
- **步骤**：开启自动刷新，连续多次改源；运行中再改；分别注入失败、取消、人工修改保护；同时运行两个许愿格并反序返回；对链式 A→B 开启自动刷新后关闭页面。
- **判据 / 证据**：相同来源修订失败 / 取消后不无限重试；后续新修订可再次触发。未授权替换人工结果不能因自动刷新绕过确认；卸载后请求不增长。同一文档的并发运行可以显式冲突并重跑，不要求全都成功，但不得串状态或半写。按来源修订统计请求数、运行状态、历史和未释放连接；用可控时钟跨过调度周期，不自行发明产品性能毫秒门槛。

### TA-N20 · 中文输入、表内结构粘贴与快捷键隔离

- **依据 / 缺口**：FR-TABLE-001、§8.5；已有基本输入快捷键和 TSV 新建表格测试，没有覆盖编辑中状态与扩表粘贴。
- **步骤**：文本、标题、Prompt、表格编辑中的中文 composition；候选未确认时 Enter/Escape；表内粘贴需要同时增行增列的区域、粘贴超限、粘贴到锁定表；快速失焦并切 Sheet；内部块剪贴板与外部 TSV 各测一次。
- **判据 / 证据**：确认候选不会误运行 Agent / 删除块 / 结束输入；最后一次编辑不丢。合法结构粘贴是一个可逆用户动作，超限 / 锁定拒绝无残留结构。记录最终文本、事件、矩阵和 undo；合成 composition 事件只算浏览器分支覆盖，不能等同 Windows 实际输入法验证。TC-003 的真实 Excel 复制缺口继续单列，不重复计成新缺陷。

### TA-N21 · 图片、视频和 AIGC 结果的保存与导出生命周期

- **依据 / 缺口**：当前 README 明确已有图片插入及角色→分镜→帧预览的离线链；既有 JSON 往返主要是表格 / 文本。
- **步骤**：插入图片、替换、压缩边界和损坏文件；生成含 SVG 帧的视频预览；保存、刷新、导出、在新上下文导入并离线打开；本地内嵌资源与 http(s) 引用分别测试。
- **判据 / 证据**：宣称内嵌的媒体在新上下文可解码，不能依赖已失效 blob URL；帧数、顺序、替换关系与媒体摘要可对照。外部引用断网可明确不可用，不要求凭空离线播放，也不能把引用型资源称为已内嵌。非法文件不留空壳，用户原图 / 旧内容可保留或撤销；Mock 帧预览不能计作真实视频编码验证。

### TA-N22 · Mock 网络边界与错误、事件、反馈的数据最小化

- **依据 / 缺口**：PRD §16.1/16.4、FR-FEEDBACK-002；TA-C2 检查画布导出凭据，不覆盖错误详情、行为事件和反馈。
- **步骤**：给表格、完整 Prompt、其他 Sheet 和测试凭据各放不同哨兵；分别 Mock 成功 / 失败、HTTP 返回含哨兵的错误体、复制技术详情、提交并导出本地反馈。正常主动填写反馈内容作正对照。
- **判据 / 证据**：画布 Mock 操作没有新增 Agent 外发请求；排除桌面本身静态资源 / 已知轮询的基线噪声。默认事件和反馈只含允许的类型、时间与用户自愿填写内容，不夹带完整输入或凭据；技术详情的敏感内容提示符合 PRD。保存网络差分、事件、反馈原文与各哨兵命中计数。原始测试证据可含合成输入，不把测试观察器故意采集的数据误判为产品泄漏。

### TA-N26 · 导入取消、重新选择与图片替换的迟到完成

- **依据 / 独立缺口**：FR-TABLE 导入流程的补充时序验收；TA-N06 只控制 Agent，TA-N16 核对解析值，TA-N21 核对媒体持久性，都不覆盖本地解析任务的归属。入口在 `ImportDialogInner`、解析 worker 和 `setBlockImage`。
- **步骤**：延迟文件 A 解析，取消并重新打开导入 B，先完成 B 再释放 A；分别在解析前、预览后取消。已有图片上连续选择 A、B 并反序完成；解码期间删除目标、撤销占位块、切 Sheet 或关闭文档。解析线程异常后重新导入正常小文件；每种时序都从可达 UI 触发，若解析中不允许重选，就通过取消后重开构造，不能虚构按钮。
- **判据 / 证据**：预览文件名、工作表、矩阵和最终 source 元数据来自同一次有效选择；取消后表格块增量为 0；图片旧回调不覆盖后来确认的图片，不复活已删除块，也不写到切换后的其他目标。故障后有终态，可重试成功；正常变体只创建一次。记录文件哈希、解析请求 ID、目标文档 / Sheet / blockId、完成顺序和创建次数。图片占位后的取消应保留还是回滚需明确，不能用“允许占位”解释晚到旧内容误写。

### TA-N27 · 跨文档剪贴板与系统复制失败的可解释性

- **依据 / 独立缺口**：FR-CANVAS-002 的跨入口补充；TA-N12「复制关系」关注副本图结构，TA-N20「结构粘贴」关注表格输入。原型另有内部 clipboard 与系统 `aicanvas-blocks` JSON 两条路径，成功提示和实际粘贴来源需一致。
- **步骤**：从 A 复制表 + 依赖图到 B，B 预放同名对象，并通过合法导入构造与 A 相同块 ID 但不同值的来源；关闭 A 后粘贴。分别拒绝系统剪贴板写权限、保留旧系统内容、外部复制新文本 / TSV，然后走 Ctrl/Cmd+V 与明确的内部粘贴菜单。混合文本 / 图片 MIME 的一次粘贴另记优先级。
- **判据 / 证据**：不能静默把 A 的引用解析成 B 中碰巧同 ID 的对象；独立复制、显式失联或询问选择按先冻结的产品策略判定，不强求跨文档实时引用。系统复制失败不能让用户误以为已能在外部粘贴新内容；如保留内部复制能力应说明范围。一次用户粘贴最多执行一次选定格式的创建，不重复插入，也不偷偷改用旧内部内容。记录两种剪贴板实际载荷摘要、权限结果、新对象关系图与源文档摘要；不同菜单语义不能预设必须完全相同。本条不代表真实账号权限隔离已通过。

### TA-N28 · 手势中断、末帧提交与锁定位置一致性

- **依据 / 独立缺口**：FR-CANVAS-002。已有 TC-002 滚轮问题不能代表拖拽 / 缩放 / 框选验收；当前实现把指针事件合并到动画帧，并在 pointerup / pointercancel 结束瞬态历史。
- **步骤**：移动、缩放、框选分别覆盖最后一次 move 尚未绘制就松手、pointercancel、移出窗口后松手、系统失焦、按住空格切走后回来；再执行一个普通编辑，检查手势已结束。多选含锁定 / 未锁定块和组子块，走拖拽、方向键和缩放手柄；文本编辑期间拖动选字作正对照。
- **判据 / 证据**：正常松手包含最后一个已收到的位移，没有跳回或额外重复移动；失焦 / 取消后不持续拖拽，不把下一次编辑合入上次手势，空格释放不会永久卡在平移模式。锁定块位置尺寸保持不变，未锁定多选保持相对位置。中断时提交已完成位移还是整段回滚先明确；二者均应可解释且不产生混合状态。记录指针 / 帧时序、最终矩形、手势后的命令和 undo 差分。PRD 是“锁定位置”，不把它擅自当内容只读或 ACL。

### TA-N29 · 浏览导航不改变业务数据或制造修订冲突

- **依据 / 独立缺口**：FR-CANVAS-001、来源 / 展示分离及现有 quiet 命令约定。TA-S1「三图表展示隔离」只改展示配置；本条检查完全没有内容编辑的行为会不会触发误冲突或自动运行。
- **步骤**：记录当前数据和各类 revision，发起慢任务后只做选择 / 取消选择、平移缩放、展开侧栏、切换 Sheet 后回来、查看运行历史、进入和退出讲述；放行原修订合法结果。另对 on_change 许愿格做同样浏览，随后真实编辑来源作正对照。
- **判据 / 证据**：纯浏览不改变数据 / 内容修订、generated.userModified 或 fresh/stale 状态，不增加内容撤销条目，不导致原本合法任务被业务修订冲突拒绝；on_change 请求增量为 0，真实来源修改能触发预定行为。视口和 activeSheet 的持久化允许发生，不能错误要求“所有 JSON 字节 / 存储写入都不变”。比较明确排除视图、诊断和正常运行历史后的业务字段，并单独记录相机保存、文档 revision、dataRevision、请求与撤销计数。

### TA-N30 · 讲述路径重排、目标变化与播放退出

- **依据 / 独立缺口**：FR-PRESENT-001/002。TC-010「三步讲述」没有覆盖多路径、删改后的索引以及多 Sheet 目标；当前步骤保存 camera / targetBlockIds，播放调用相机动画。
- **步骤**：创建两条路径，包含从视口和选中块创建的步骤；重排、删除首 / 中 / 末步骤，撤销重做后播放。再移动 / 删除目标块或所属 Sheet，覆盖空路径、最后一步、返回当前步骤、连续快速前后切换和退出。分别在不同 Sheet 建步骤，并在编辑器恢复 / 重开后播放；播放中收到合法异步结果的变体记录路径变化。
- **判据 / 证据**：步骤计数、标题、备注和实际播放步骤对应；无越界、残留遮罩或不可退出状态；播放键不同时移动 / 删除背景块。跨 Sheet 讲述若受支持应呈现正确 Sheet；若不支持应明确阻止或提示，不能把同坐标的另一张表当目标。目标移动后是跟随目标还是固定镜头、退出时是否恢复进入前视口属待定口径，不能根据当前实现倒填。保存 stepId 顺序、activeSheetId、实际可见目标和相机轨迹；目标缺失需可解释，缺失策略确认后再判定完整通过。

### TA-N31 · 缩放、窗口尺寸与坐标命中的一致性

- **依据 / 独立缺口**：FR-CANVAS-001/002。坏矩形由 TA-N08 / TA-N15 覆盖；本条只用合法几何，检查不同显示条件下用户点中的对象是否就是被修改的对象。
- **步骤**：在当前 10% / 100% / 400% 缩放、负坐标及相距较远的合法块上点选、双击编辑、框选、拖拽、缩放、右键插入；调整桌面窗口 / 侧栏宽度，分别改变浏览器缩放和 DPR。覆盖空 Sheet 的适应全部、极小视口、切 Sheet 恢复，以及一次动画结束前再次缩放 / fit。
- **判据 / 证据**：用独立的屏幕→画布公式计算预期，点选 ID、插入位置和移动距离相符；滚轮缩放锚点保持在指针附近，移动后的组关系正确；相机始终为有限值且 zoom 为正，内容能通过合法导航找回，不出现只能刷新才能退出的画面。记录视口、DPR、相机、矩形、命中 ID 和截图；像素容差在夹具中事先声明，用于测量误差，不冒充产品性能指标。极远块受最小缩放限制而无法同时全部看清，与“对象无法再定位”分开判定。

### TA-N32 · 200 块工作负载与重复开关后的资源收敛

- **依据 / 独立缺口**：PRD §15.5 的 200 普通块目标、FR-HISTORY-002 的最近 10 次摘要。首轮 §7 仅提观察项，本轮补为可重复用例；单次功能通过不证明长时间使用后仍正常。
- **步骤**：在固定浏览器 / 设备构造 200 个普通块；大表和媒体另设有界组合负载，不把它们暗含进“200 普通块”承诺。预热后重复 20 轮打开文档→导入 / 取消→运行 / 取消→进入讲述→退出，回到相同空闲态采样；另完成 11 次运行核对历史。解析 worker 异常、HTTP 持续 progress 后取消、图片失败各加一轮。所有文件、时长和内存观测设夹具预算，不运行无限流或失控展开文件。
- **判据 / 证据**：数据与命令结果仍正确，关闭的编辑器无后续提交，取消后活动请求释放；监听器 / 定时器 / worker / 对象 URL 的存量与明确允许的共享资源相符，无每次打开就多一份的孤立活动资源。每个许愿格的运行历史只保留最近 10 次摘要且顺序正确。记录每轮资源计数、未决解析请求、堆快照 / 堆趋势、交互延迟分位数及错误数；浏览器 GC 波动或预期单例 worker 常驻不能单凭内存未立即下降判泄漏。流畅度数值门槛尚未冻结，性能数据先作为观察；有明确未释放活动资源或错误副作用才按对应断言判失败。

### TA-N33 · 键盘可完成流程与非视觉状态可辨识

- **依据 / 独立缺口**：PRD §18 已明确键盘、图标名称、焦点、非颜色状态、图表文本入口和减少动态效果。这些是现有承诺，不是等界面美化之后才考虑的新需求；TA-N20 / TA-N25 只能证明按键没有误操作，不能证明用户有能力完成任务。
- **步骤**：只用键盘完成创建块→编辑→选择来源→运行 / 取消→查看错误→打开并关闭弹窗→保存 / 导出；记录焦点顺序和可见焦点。检查图标可访问名称、fresh/stale/error 的非颜色表达、图表文字摘要或数据入口；切换系统减少动态效果后播放和定位。真实读屏软件再独立验收状态和错误的可感知性。
- **判据 / 证据**：关键流程可达、可退出且不丢焦点；控件名称能说明动作，状态不会只能靠颜色区分，图表有可读替代入口；减少动态效果实际影响动画。保存按键序列、焦点轨迹、可访问性树、状态文本和动画观测。DOM 中有 aria 属性不等于实际读屏通过；缺少读屏环境时该子项为 NOT_RUN，不用自动扫描代替人工辅助技术验证。具体焦点返回位置和动态通告策略可补充约定，不预设某一 ARIA 实现才合格。

## 7. 执行顺序与判定纪律

先补 TA-N01～N09 的写回 / 保存 / 生命周期 / 宿主边界，并把 TA-N23「配置切换」、TA-N24「撤销事务隔离」、TA-N25「操作焦点隔离」加入同批 P0。随后补 TA-N10～N22 的数据、引用、调度、媒体和隐私，再补 TA-N26～N33 的异步导入、剪贴板、手势、浏览、讲述、几何、资源与可访问性。XLSX 深层变体待入口恢复后继续；真实 Excel / 输入法 / 读屏需单列原应用环境。资源测试按 TA-N32 的有界负载进行，不用没有产品依据的耗时数字判缺陷。

执行前统一规则：

1. 每项沿用主需求 §8 的八字段；子变体用 `TA-Nxx/a` 等标识，同时写出名字。`NOT_RUN` 是未执行，`INCONCLUSIVE` 是执行后证据不足，二者不混用。
2. 除规定允许改变的时间、诊断、运行历史外，使用业务摘要、完整导出、数据库读回、请求数和撤销计数判定；对快照、人工编辑等场景明确比较哪一版，不能一律套“全文不变”。
3. 故障注入必须证明真的到达故障点，并配正常对照；不通过替换被测函数为预设返回值来宣布 E2E 通过。夹具服务器、日志和临时文件全部放 `.work`，长任务 detached 启动。
4. 并发与迟到响应记录事件顺序，用闸门或受控时钟复现。若只是偶发超时，保留原始证据后重查环境，不能直接归因产品。
5. 优先澄清 N05 的双窗口策略，N10/N12/N18 的引用与复制语义，N14 的截断确认，N16/N17 的类型与聚合口径；其余明确的安全否定断言可先写脚本。第二轮还需明确 N23 的配置生效点、N26 的占位取消、N27 的跨文档引用 / 剪贴板语义、N28 的中断提交以及 N30 的镜头 / Sheet 策略。这里列出待定项，不擅自替底座决定实现。
6. 已知 CANVAS-L01～L09 是已有缺陷 / 规格差异；本文是在它们周边补覆盖，不再新建同义问题，也不通过改期望把它们变绿。
