# AI Canvas 交付物型 E2E 场景目录：W03–W20

用户在 Canvas 中面向完整交付物工作。本目录收录十八个可扩展的测试场景：每条都说明用户带来什么、要交付什么、过程中发生什么变化，以及怎样从浏览器行为和最终文件判断结果。[W01 两万字小说与 W02 研究论文](long-form-writing.md) 已有完整任务包；本目录为后续任务包和实际执行提供稳定编号。通用的 Playwright／执行 Agent 方法、八字段记录和结果状态沿用 [浏览器执行约定](execution-guide.md) 与 [验收附录](assertions.md)。

## 执行边界与选例原则

每条场景的正常路径都由执行 Agent 对着当前 Canvas UI 完成。首次执行前，把下文的输入摘要扩成冻结任务包：具体素材及版本、允许选择的来源、独立预期、内容审阅人、模型与费用上限、运行环境和停止条件。没有冻结素材或独立预期时可以探索 UI，但不能把内容正确性判为 PASS。操作轨迹可以随 UI 改动；用户目标、关键变化和最终判据保持稳定。

每条场景分别记录四种结论：**文档承载**（编辑、布局、保存、读回、导入导出）、**生成内容**（真实写作或分析质量）、**变化处理**（来源、条件、人工内容变化后的结果）、**交接可用性**（隔离浏览器的接收者能否继续）。可以只通过其中一个子范围，不能据此宣布整条场景通过。当前 Mock 对销售与通用数值表、文本摘要，以及角色设定图→故事板→逐帧预览有确定性能力；它不证明开放式写作、翻译、真实图像质量或跨材料研究。生成类判据需要可审计的 HTTP Agent 及人工或独立资料核对；缺少前置时标 `NOT_RUN`。T-A 的文件交接不代表在线分享或跨账号授权；T-B/T-C 本目录不启动。

以下场景均使用原创或合成材料，避免真实私人信息、受版权限制的全文和不断变化的在线价格。执行包留在 Git 忽略的 `runs/`，新发现的问题先本地记录，不自动创建 GitHub issue。

## W03 · 用户完成一部短片的分镜方案

**输入与交付。** 原创八场剧本、三名角色的设定表和少量参考图片；交付角色设定图、分镜表、逐镜画面和可播放的预览，能够由下一位剪辑者继续使用。**步骤。** 用户先确认角色设定，再按剧本顺序生成分镜与预览；中途把主角外套由蓝色改为红色，检查涉及该角色的后续镜头，保存并交接。**判据。** 场次和镜头顺序、人物、对白与剧本对应；变化影响相关镜头且保住人工修订；导出重开后图片、分镜和预览引用有效。Mock AIGC 可先验证链路，画面质量和真实视频文件另行判定。

## W04 · 用户完成一次事故复盘报告

**输入与交付。** 带时间戳的合成事件记录、两份互相矛盾的证言和一段缺失日志；交付事实时间线、已知影响、待证假设、行动项与证据目录。**步骤。** 用户先按时间整理资料并形成初稿，再补入一段新日志，要求修订受影响结论，交给审阅者追查每项说法。**判据。** 事实、证言和推测分开；未证实的根因不写成定论；新日志改变的结论可定位，旧版本不被静默抹去。真实事故处置建议不属于本合成场景的通过结论。

## W05 · 用户完成一套十二讲自学课程

**输入与交付。** 冻结的学习目标、概念清单、先修关系和目标读者水平；交付十二讲的内容结构、练习、答案与讲述路径。**步骤。** 用户建立知识地图，逐讲安排讲授和练习；完成后把一个先修概念提前两讲，再修订受影响课程并播放整套路径。**判据。** 目标概念都有对应章节；练习能由已讲内容作答，答案可独立核对；调整先修关系后顺序和引用不矛盾。此处只测个人制作与文件交接，不宣称具备真实课堂或学生权限。

## W06 · 用户完成一份项目资助申请初稿

**输入与交付。** 合成征集文件中的八项硬性要求、已有项目事实、团队资质清单和总额 100,000 元的预算表；交付申请书、要求回应表和一致的预算说明。**步骤。** 用户先列出每项要求与可用证据，再分节成文；随后资助上限降至 80,000 元，调整项目范围和预算，重新导出。**判据。** 每项要求有回应或明确缺口；分项合计、申请金额与正文一致；没有编造人员资质和已完成成果；降额后不存在旧金额或无法执行的承诺。

## W07 · 用户完成小产品上市方案

**输入与交付。** 合成访谈摘录、成本与销量试算表、产品图片；交付目标人群、定位、价格理由、宣传文案、图表和对外汇报路径。**步骤。** 用户先选择证据并形成方案，再改变单位成本或目标人群，检查文案、价格和图表，交给同事复核。**判据。** 数字可独立复算；对外承诺不超出资料支持；变化后各部分说的是同一版产品。素材图片和文字经文件交接后仍可读。

## W08 · 用户完成技术手册的中文版修订

**输入与交付。** 用户拥有使用权的十节英文原稿、术语表和旧中文稿；交付章节齐全、术语一致、可继续编辑的中文版。**步骤。** 用户按节修订并核对术语；原稿中的一条安全警告随后更新，用户定位所有受影响译文并完成新版本交接。**判据。** 章节与重要警告没有遗漏；数字、单位和术语一致；作者在旧译中写的批注不被覆盖。双语审阅人需逐节检查语义；仅靠字数、模型评分或 Mock 摘要不能判翻译通过。

## W09 · 用户完成有依据的设备采购建议

**输入与交付。** 三家合成供应商的冻结报价、规格、三年维护费用和一条不可放宽的硬性规格；交付比较表、三年成本计算、建议与取舍说明。**步骤。** 用户过滤不达标方案并比较总成本，再收到一家供应商的新报价，更新建议。**判据。** 硬约束不会因总评分较高而被忽略；价格和三年成本可独立核算；新报价进入最终排名，旧判断不残留。该测试不依赖实时市场价格。

## W10 · 用户维护一份持续更新的研究资料包

**输入与交付。** 不同日期、可靠程度不同且有冲突的五份合成资料；交付“已证实／有争议／尚未知”的结论板、来源索引和简报。**步骤。** 用户先形成第一版判断，随后加入更正材料，检查受到影响的结论，再交给另一位读者复核。**判据。** 每项说法可追到具体来源及版本；冲突不被合并成虚假的一致结论；更正后可区分历史判断与当前判断。外部网页自动抓取不是本轮前置能力。

## W11 · 用户完成一本十六页绘本

**输入与交付。** 原创故事梗概、角色外观卡和目标年龄段；交付十六页有顺序的图文绘本工作稿。**步骤。** 用户先定角色和分页，再逐页制作文字与插图；中途修改主角服装，检查后续页面并导出给编辑。**判据。** 每页图文描述同一事件，角色跨页身份与外观可辨，故事有完整开端与结尾；调整后没有新旧服装混杂或丢失人工修图。当前图文块可先验承载，完整图像生成与审美由真实 Agent 和人工审阅验证。

## W12 · 用户完成一场小型展览的策划方案

**输入与交付。** 十二件合成作品的图片、标题、说明和授权状态；交付主题分区、作品说明、参观顺序与讲述路径。**步骤。** 用户把作品排成三个展区并预览讲述；随后一件作品撤回授权，用户调整布局、说明和路径，导出交给执行者。**判据。** 说明对应正确作品；最终路径不经过撤回作品；导出后图片与顺序仍可复核。真实展陈尺寸与许可法律判断另有专业流程，本场景只检查给定授权标记的传播。

## W13 · 用户完成一份家庭口述史

**输入与交付。** 合成口述记录、附有已知出处的照片及两种冲突日期；交付区分“受访者原话、编者整理、尚待核实”的叙述和图片索引。**步骤。** 用户整理资料并成文，家人后来纠正一个时间点，用户修订关联段落后进行文件交接。**判据。** 不编造引语、不猜照片人物身份；冲突和更正可追溯；未获选的私密资料不进入生成请求。若私密资料与对外交付内容处在同一可整份导出的画布，不能声称已经实现选择性导出或撤销访问。

## W14 · 用户完成年度经营复盘

**输入与交付。** 十二个月的合成销售 CSV 与月度解释资料；交付全年趋势、异常说明、汇总表和管理层讲述路径。**步骤。** 用户逐月导入、选择分析范围并形成复盘；随后修正十二月数据，检查全年图表与文字。**判据。** 年度合计、同比或环比采用任务包规定口径且能独立复算；月度异常与来源相符；更正后最终导出无旧数据混用。Mock 的单表汇总通过不能替代跨月综合质量。

## W15 · 用户完成一场活动的执行方案

**输入与交付。** 合成场地条件、人员安排、预算和原定日期；交付任务表、时间线、费用表与对外通知草稿。**步骤。** 用户先排依赖和负责人；场地通知活动推迟两周，用户调整准备工作和通知。**判据。** 日期、依赖、人员和费用在同一版计划中自洽；未确认场地或人员不被写成已预订；交接者能区分待确认与已完成事项。外部订票或发送通知不在 Canvas 原型范围。

## W16 · 用户从访谈完成一份产品需求包

**输入与交付。** 六份合成用户访谈，含相互矛盾的需求与一个明显的边缘案例；交付问题陈述、需求优先级、取舍、验收场景及证据索引。**步骤。** 用户先归纳访谈，再加入冲突的新访谈，要求重新评估优先级并交给产品同事。**判据。** 用户原话、研究者推断与产品承诺分开；优先级改变有依据；少数反例未被删掉；每条重要需求可回溯到资料。输出是需求文档，不意味着 Canvas 已实现其中的产品功能。

## W17 · 用户完成一份实验复现报告

**输入与交付。** 合成实验步骤、五次测量、单位定义和一条异常记录；交付原始数据、计算、图表、误差与限制说明。**步骤。** 用户按步骤整理并解释测量，再发现一次录入单位错误，修正来源并刷新报告。**判据。** 计算和图表由修正后的数据独立复现；异常值的保留或剔除有明确规则；摘要与结论没有旧单位或旧值；有限样本不被写成普遍规律。

## W18 · 用户完成一份可交付的个人作品集

**输入与交付。** 五个合成项目的说明与图片，以及一份明确标为私人草稿的材料；交付按阅读顺序组织的公开作品集。**步骤。** 用户选择作品、补充个人贡献并导出，接收者在隔离浏览器中导入检查。**判据。** 每件作品说明对应素材，贡献可辨；公开交付不包含私人草稿。当前若 UI 只能整份导出，必须如实报告交付范围缺口；不能通过手工编辑导出 JSON 伪造选择性导出通过。T-A 只能验证本地文件边界，不能推断真实访问控制。

## W19 · 用户比较一个故事的两种走向

**输入与交付。** 同一份原创人物和开端，两个互斥结局方向；交付两份可辨版本、比较理由和最终选定稿。**步骤。** 用户从共同设定探索 A/B 两版，选定 A 后继续修改，再回看 B 并尝试撤销一次 A 的改动。**判据。** 两个版本不串稿，选定与撤销不吞掉另一版，接收者能识别版本来源。用导出文件或复制文档保留两版只算 T-A 手工分叉，不等于原生分支或多人合并已实现。

## W20 · 用户把小说改编成短片剧本

**输入与交付。** W01 已确认的小说版本、改编目标和十二场上限；交付场景表、对白、分镜草案及小说到场景的对应说明。**步骤。** 用户选定小说来源并生成改编稿；小说中的关键时间线随后修正，用户决定是否更新衍生稿，再交给制作人复核。**判据。** 核心人物动机和因果链保留，场景对应可追溯；来源更正不会悄悄替换人工对白或留下前后矛盾。当前只验证 Canvas 中显式来源和本地修订；不预设跨文档自动同步。

## 从目录推进到可执行任务包

先把 W03、W04、W06 扩成与 W01/W02 同等详细的冻结任务包：它们分别覆盖原型已有的多媒体纵向链路、冲突证据的诚实表达，以及“硬性要求＋长文＋预算”的组合。其余场景按主要风险选择，不以数量替代覆盖。每个任务包应补齐精确素材、独立预期、允许的生成后端、一次明确变化、接收者动作和人工审阅规则，然后按检查点报告 `PASS`、`FAIL`、`INCONCLUSIVE` 或 `NOT_RUN`。本目录没有新增执行结果；任何场景的质量通过都需要实际浏览器操作、导出物和可获取的审阅证据。
