## 1. 分层、环境与执行顺序

| 层 | 对象与依赖 | 执行边界 |
|---|---|---|

以下为原型删除前的执行步骤（归档状态见 [入口说明](README.md)）：从 `src/frame/desktop` 运行 `pnpm run dev`，打开 `/?scenario=normal`，从第一页「AI 画布」进入。

响应服务，明确它不是真实 Agent 后端。使用隔离的浏览器数据，不能清空用户实际文档来制造环境。
长测试进程 detached 启动，夹具、日志、暂存统一放工作区 `.work`，完成后将需要的证据归档。

历史阶段 1 对应 §2 + §3，历史阶段 2 对应 §4；后续执行顺序以 [主文档 §5](test-requirements.md#5-推进顺序与完成口径) 为准。
分阶段执行并先报告再继续，场景覆盖按下表逐条核对。记录被测 commit、浏览器版本、适配器与夹具版本；不根据 README 的“已实现”
直接宣告通过，也不为了通过测试修改被测对象。

| TC-015 | 循环依赖 | 尝试让两个许愿格互相依赖 | 系统拒绝并提示循环关系。 |

保留请求、补丁、前后业务摘要、文档修订及撤销计数，不能只直接调用校验函数。
补丁数值上限是历史原型基线的判据，未来内核上限需另按冻结契约验收。

| TA-F2 | 较高格式版本拒绝且不替换已有文档 | 导入比当前支持版本更高的文档时明确拒绝；已有文档不能被替换或破坏 |

TA-V01～16 的共同否定断言是：拒绝后无任何先行合法操作的残留，文档 revision、块 ID、绑定、
业务内容与撤销计数不变。失败诊断和运行历史可以更新，不能因此要求整个运行状态对象逐字节不变。
已有 TC-007/008/009 和 PRD §21.2 继续覆盖取消、非法引用、正常生成的原子撤销；Mock 的
`#fail` / `#slow` / `#timeout` 可构造失败、修订冲突与超时，不需要等内核服务。

原型成功返回后直接写入，没有候选集“先返回、以后采纳”的独立生命周期；上述用例不能替代
候选不采纳 / 稍后采纳契约。TA-D1/TA-D2 也不能替代基于名称的歧义候选解析和确认。

执行记录应区分内部四阶段事件与用户可见进度；TC-003 使用 TSV 等价夹具时必须明确尚未覆盖
Microsoft Excel 原应用复制路径；TA-C3 必须同时验证输入版本标记和内容可恢复性。阶段 1 发现的
原型缺陷不会因为分层修订而被改判通过，历史判定不因文档迁移而改变。

## 8. 结果记录与问题归属

每个用例及子变体都写出编号和名字，再记录以下八字段：

| 字段 | 内容 |
|---|---|
| 用例编号 | 稳定 ID + 名称；变体如 TA-N23/a「创建任务后切换服务」 |
| 层 | T-A / T-B / T-C，不混淆原型与内核契约 |
| 环境 | 节点 / 账号或 Mock 身份、被测 commit、浏览器与适配器 / 夹具版本 |
| 复现步骤 | 可按次序执行的操作、时序闸门和必要前置 |
| 实际结果 | 原始状态、计数、内容或错误；单列判定 PASS / FAIL / INCONCLUSIVE / NOT_RUN |
| 期望结果 | 引用冻结判据，待定产品口径不得由当前实现倒填 |
| 证据 | 日志 / 请求 / 补丁 / 导出物 / 存储读回 / 截图 / 计数及其路径，必要时含摘要 |
| 归属 | BuckyOS 原型 / 内核、应用缺陷、环境 / 夹具不足或规格待定；不可仅按现象猜归属 |

FAIL 必须提供可核查证据；INCONCLUSIVE 表示已经执行但证据不足，NOT_RUN 表示未执行。
一条中的多个必要变体不能只测一个通过就整条 PASS。历史结论只适用于当时版本；复跑另建记录，
不能覆盖原证据或为了通过修改期望。错误诊断、运行历史允许变化时，明确比较的业务字段。

Canvas 开发阶段的问题先留在仓库文档，不自动创建或重开 issue。迁移不改变历史问题状态，
不把未执行的未来内核能力判为缺陷，也不在应用代码中加入规避实现。
