## 布局、模式、工具栏与 App 模式

### 自由布局与流式布局

Surface 是具有稳定身份的工作页，多个 Surface 共享 Workspace 的数据空间。布局模式影响几何与阅读顺序，不另建业务数据或权限体系。

| 布局 | 持久化内容 | 宿主责任 |
| --- | --- | --- |
| 自由模式 | 坐标、尺寸、旋转、堆叠顺序及明确的父子关系 | 画布变换、命中、缩放、对齐、吸附及可视范围管理 |
| 流模式 | 稳定内容顺序、容器结构、宽度和排版约束 | 按可用宽度布局、测量、滚动、插入位置和阅读顺序导航 |

自由模式的视觉包含不自动建立成员关系。Frame、分组与 control 应各自说明拥有子节点、约束位置或仅定义关注区域中的哪一种语义。

流模式不能把自由坐标当作阅读顺序；自动测量的位置属于派生结果。跨布局移动保持 Block 身份和绑定，显式转换无法直接沿用的几何属性，不通过截屏丢弃原始内容。

组件可以声明适用布局；不支持某布局时使用确定的静态表现、整体嵌入或明确拒绝，不静默丢掉子节点。跨布局的复制和导出仍遵守同一引用与所有权规则。

### 相互独立的模式维度

| 维度 | 取值或作用 |
| --- | --- |
| 布局模式 | 自由、流式及明确声明的容器布局 |
| 工作视图 | 画布视图、数据源视图 |
| 呈现模式 | 编辑、查看、放映、打印/导出 |
| 交互状态 | 设计态选择与配置；运行态触发业务动作 |
| 设备能力 | 鼠标、触摸、手写、键盘、屏幕大小与可用性能 |
| 有效权限 | 当前主体、目标、操作和执行授权共同决定 |

编辑模式提供设计和编辑入口，但不授予权限。查看模式可以允许评论、个人状态或明确开放的业务交互；这些写入分别经过相应授权。放映模式使用其独立基线与运行上下文，不把现场交互隐式写回原作品。

设计态点击按钮用于选择、移动和配置；运行态点击才触发动作。宿主必须把这个区别传给 Block，不能要求每个控件自行猜测用户意图。

手机和桌面复用相同文档及操作模型，根据输入能力采用不同交互。依赖 hover、精密拖动或键盘组合的操作必须有触摸入口；暂不支持的编辑能力应明确显示，不改变数据结构或假装修改成功。

模式变化不自动迁移数据、发起宏或重新执行任务。回放与打印采用无业务副作用的呈现上下文，不能复用运行态挂载行为触发新操作。

### 数据源视图

数据源视图按内核数据类型和 Schema 提供标准检查与编辑入口，不依赖某个 Block Renderer 才能理解数据。Table、对象、富文本、资产和目录均有通用可解释视图；未知业务 Schema 保留原始内容。

Block 扩展不必同时实现数据源编辑器。Source 的只读、类型、字段和引用约束由数据层提供，视图只表达当前能力；不能因切换到数据源模式绕过来源写入限制。

数据源树与 Block Tree 分别组织数据和呈现。显示路径可以变化，持久绑定与权限目标仍使用稳定身份。

### 可定制工具栏与 App 模式

Workspace 与 Surface 可以保存工具栏配置，声明工具区、布局、分组、顺序、显示条件及绑定动作。配置引用统一动作标识和参数，不内嵌另一套绕过运行时的执行入口。

Workspace 提供默认工具栏，Surface 可明确继承、追加、覆盖或隐藏。相同工具项使用稳定标识，合成顺序必须确定；个人固定、折叠和位置偏好存于 User State，不悄悄修改共享默认布局。

Block/control 的局部工具栏由宿主与当前选区、焦点和模式组合，复用其声明的动作。菜单、快捷键、按钮和 Agent 调用使用同一动作语义，具体事件与执行规则见[统一事件与动作模型](07-事件宏与公式预留.md#统一事件与动作模型)。

隐藏所有系统工具区形成 App 模式。它是宿主界面呈现配置，不是新的权限角色、执行环境或数据格式；应用仍遵守能力检查、保存状态和运行反馈。

App 模式可以通过自定义控件提供主要操作入口。宿主提供受控的退出、错误、授权和必要恢复入口；管理入口可以位于 Workspace 外或授权快捷入口，不要求保留可见工具区。

## 附加层、用户私有状态与草稿

### 附加层与私有状态

评论、标色和便签可用独立 Overlay 表达。它们通过稳定引用锚定目标，拥有自己的可见性；目标失效时保留可解释锚点。若“待核对”成为业务流程状态，应建正式业务记录，不能让业务判断依赖颜色。

用户私有状态保留 KV 模型，键以 `block:<entity_id>/` 表达 Block 命名空间。身份切换必须隔离；同一用户不同 Session 可以有不同实时选区。

持久状态的条件写使用服务修订号，不用跨设备不可比的客户端时间戳。调用方可选择覆盖或处理冲突。Block 永久删除、不能恢复后清理关联私有状态；Fork、普通克隆和恢复导入不传播原用户的私有状态。

### 草稿恢复

表单直提交使用当前用户身份，不为普通保存额外创建 run：

1. 保存草稿，并记录将使用的 `idempotency_key`、epoch 和必要目标信息。
2. 用该身份和 key 提交共享变更。
3. 确认 accepted 后清理草稿。
4. 重新打开时若有待核实 key，先查询提交结果；已接受则只清理，结果未知则在有效窗口内重试同一请求，不再生成一次插入。

epoch 或历史窗口变化时转入冲突恢复，不能仅凭草稿存在就重新发送。任务结果另按 run 的实际写入 principal 查询，不与表单用户幂等空间混用。
