## 对外接口与冻结治理

### 服务入口与契约来源

AIWS 的服务名是 `aiworkspace`，服务模式监听 `127.0.0.1:4120`，主入口为 `POST /kapi/aiworkspace`。kRPC 请求为 `{ method, params, sys: [seq, token] }`。网关转发不代替 AIWS 的身份验证；服务将验证后的身份转换为 `Caller`，再按 Workspace、实体范围及 run 委托授权。

| 契约 | 当前源码入口 |
| --- | --- |
| kRPC 方法及稳定级别 | [server/src/lib.rs](../../../src/frame/aiworkspace/server/src/lib.rs) 的 `METHOD_LEVELS`、`krpc`、`dispatch`；字段说明见[服务 README](../../../src/frame/aiworkspace/README.md#protocol) |
| HTTP、WebSocket 与对象访问 | 同文件 `build_router`；schema、healthz 公开，资产代读、媒体 stream、session WebSocket、publication、wish-host 与 `obj/*` 路由按各自规则检查访问 |
| 身份、受限会话与动态授权主体 | [server/src/auth.rs](../../../src/frame/aiworkspace/server/src/auth.rs)、[store/src/workspace.rs](../../../src/frame/aiworkspace/store/src/workspace.rs) |
| 格式、协议与存储版本 | [core/src/model.rs](../../../src/frame/aiworkspace/core/src/model.rs)、[store/src/schema.rs](../../../src/frame/aiworkspace/store/src/schema.rs) |
| 操作、错误与扩展格式 | [schemas](../../../src/frame/aiworkspace/schemas)、[core/src/error.rs](../../../src/frame/aiworkspace/core/src/error.rs) |

`GET /kapi/aiworkspace/healthz` 只返回进程路由存活状态 `ok`，不检查 system-config、对象桶、AICC 或 Agent 是否可用。不能用一次 healthz 成功替代后端依赖验收。

### API 分级

API 分为稳定、内部、实验三级，由服务方法目录声明，不按前缀笼统分类。

| 级别 | 范围与规则 |
| --- | --- |
| 稳定 | 基础 Workspace 管理与授权、分享入口、解析/读/查、prepare/commit/stage、提交查询、undo、变更拉取与等待、私有状态、lock、资产接入与 stream URL 等；变化遵循协议版本与契约测试 |
| 内部 | outline、诊断、replica、传统 show 等实现接口；随配套客户端演进，不作为外部通用承诺 |
| 实验 | 未完成稳定发布条件的任务、发布、快照或独立会话接口；必须显式标记，不能因本文冻结了语义就宣称方法已稳定 |

截至本次整理，服务声明 FORMAT 1.0、PROTOCOL 1.1、存储 schema 5；这三者独立演进，实体及 RichText Schema 另行版本化。具体方法级别见 [METHOD_LEVELS](../../../src/frame/aiworkspace/server/src/lib.rs)：`proc.*`、托管配置、发布、checkpoint/export 和 `session.*` 等仍应按目录中的实验标记使用，不能写成全部 `ws.*` 稳定。

资源上传复用 NDM 与对象桶，以 `asset.import_object` 接入 Workspace；不恢复历史草案的 `asset.begin_upload/finish_upload` 或本地上传路由。资源代读仍须经过 Workspace 授权，不能要求协作者直接拥有 Owner 对象桶权限。

### 错误与失败行为

错误枚举、`retryable` 和冲突详情属于协议；调用方不能按自然语言错误文本分支。Commit 保持三态结果，其他方法按其 Schema 返回错误信封。

当前 wire 行为需要区分以下层次：

- 普通业务结果位于 kRPC `result`：成功为 `{ ok: true, ... }`，失败为 `{ ok: false, error: { code, retryable, detail, sub_code?, data?, denial? } }`；提交结果使用 `status: accepted | conflict | rejected`。
- 无效 token、未知方法和无法解析的请求使用 kRPC 顶层 `error`。受限会话被拒使用 `{ error, code: "access_denied", data: AccessDenial }`；`ws.join_entry` 的拒绝也走这个共享 SSO 信封，其其他错误走普通 kRPC error。
- kRPC 处理器通常返回 HTTP 200；请求体限额及资产、媒体等 HTTP 路由另有 HTTP 状态语义。调用方必须检查结果内容，不能只检查 HTTP 是否成功。

| 类别 | 代表错误或处理 |
| --- | --- |
| 请求身份不一致 | `IDEMPOTENCY_MISMATCH` |
| 历史无法接续 | `EPOCH_MISMATCH`、`BASE_TOO_OLD` |
| 内容不再保留 | `VERSION_NOT_RETAINED`、`RESOURCE_RECLAIMED` |
| 不可补偿 | `NOT_UNDOABLE` |
| 执行上下文或委托失效 | `EXECUTION_CONTEXT_MISSING`、`DELEGATION_STALE` |
| 运行取消或执行资格失效 | `RUN_CANCELLED`、`RUN_REVOKED` |
| 资源准入失败 | 配额/流量错误及可回收、所需额度等结构化详情 |
| 后端存储或对象不可用 | `STORAGE_FULL`、`STORAGE_IO_ERROR`、`DEPENDENCY_UNAVAILABLE`；桶错误映射见下文，区别于 Workspace 自身的逻辑配额 |
| 版本超出支持范围 | `UNSUPPORTED_VERSION`，不猜测未知语义；已承诺旧正式版本走兼容载入或转换 |

权限不足与内容不存在的对外细节须服从可见性策略。`retryable` 不表示可以改用新 key 盲目执行；结果 unknown 时先恢复接受事实。

### FORMAT 1.0 必须表达的内容

| 契约结构 | 来源决策 |
| --- | --- |
| 实体业务 Schema 标识/版本及 RichText Schema 版本 | D01 |
| 资源目录与确定性 DirObject 物化 | D01、D25 |
| owns、引用目录、live/fixed、strong/weak | D05 |
| 纯应用型日志与规范化操作的分工 | D20 |
| 历史位置/内容寻址两类 fixed 身份 | D03、D10 |
| `$formula` 的显式值形状与类型标记；服务端不求值 | D18 |
| run 能力、任务配置摘要、输出声明与委托记录 | D14–D16、D22、D23 |
| 用量账本及可释放的保留承诺 | D06、D19；保留物由对象桶绑定实现 |
| user_state 修订号与命名空间 | D13 |
| 历史下界与 epoch | D06、D07 |

该表冻结语义，不要求恢复已被对象桶替代的 `retentions` 物理表。新增类型、操作、选择器、引用种类或日志语义时，必须评估协议与格式影响，同步内核、服务、共享类型、SDK、WASM、副本、前端、Schema、文档和相关 Agent 手册。

稳定接口必须有可执行的契约向量。新增业务 Schema 可以不升级 FORMAT；新增或改变数据内核行为不能假装只是业务配置。宿主 API、宏 API、扩展 manifest 和标准库接口也要有版本化契约与旧版本兼容向量。

## 当前 AIWS 服务依赖的 Backend APIs

这里列的是 **AIWS 服务发起的调用**，包括 runtime/共享库代它发起的调用；`ws.*`、`doc.*`、`proc.*` 等是 AIWS 对外提供的接口，不是下游服务。下表使用 wire 方法名，必要时同时列出 Rust 客户端方法。服务地址由 runtime 解析，不能把开发环境端口当成固定远端地址。

### 启动、身份和授权

| Backend / 入口 | 实际 API 与数据 | AIWS 使用场景及身份 | 当前依赖与失败行为 |
| --- | --- | --- | --- |
| verify-hub，`/kapi/verify-hub` | `login_by_jwt`、`refresh_token` | `KernelService` runtime 将启动 assertion 换成服务 session，随后续期；不是用户交互登录 | 启动登录或首次换票失败则退出；后续跨服务调用使用 runtime 当前 session |
| system-config，`/kapi/system_config` | `sys_config_get`（客户端 `get`）：`boot/config`、`system/rbac/policy` | runtime 加载 Zone 配置、信任材料与 RBAC；使用 runtime 的启动/服务身份 | 属于运行时基础依赖；RBAC 策略缺键允许默认值，其他读取失败不能当成授权成功 |
| 同上 | `sys_config_get`：`services/aiworkspace/settings` | 启动读取限额、历史保留和 Wish 配置 | 当前读取或反序列化失败会使用 `AiWorkspaceSettings::default()`；验收须确认实际生效配置，不能假定失败会阻止启动 |
| 同上 | `sys_config_get`：`services/<service>/info` | runtime 发现 nfs-server、AICC、msg-center、verify-hub 和 Agent 绑定服务的地址 | 使用服务实例信息选本机端口或网关路径；地址发现失败影响对应调用 |
| 同上 | `sys_config_set`（客户端 `set`）：`services/aiworkspace/instances/<node>` | runtime 定期上报本服务实例状态、端口等 | 属于运行时注册/保活依赖，不是 Workspace 文档写入 |
| 同上 | `sys_config_list`（客户端 `list`）：`users`、`system/user_groups`；`sys_config_get`：`system/user_groups/<id>`、`system/user_groups/_projections` | `ws.list_subjects` 获取用户与组目录，使用服务身份；读取 projections 是 `load_user_groups` 的附带行为 | 用户列表或组目录读取失败时，相应候选会被省略；候选列表不构成授权结果 |
| 同上 | `sys_config_get`：`users/<principal>/settings`、`users/<principal>/doc` | 解析 `group:<id>` 的成员关系、账户 DID，或核验 contact 授权条目的拥有者 | 无法确认的主体记为 `unconfirmed`；若现有已确认授权不足以满足请求，则拒绝并带 `authorization_unavailable` |
| 同上 | `sys_config_get`：`system/sso/settings` | `ws.join_entry` 将分享入口方式与 Zone SSO 开关取交集 | 仅缺键使用默认值；其他读取或解析失败返回 `authorization_unavailable` |
| 同上 | `sys_config_get`：`users/<owner>/agents/<agent_id>/spec` | hosted run 分发前读取 Owner 指定 Agent 的 `binding.service_name` | 只在托管分发时需要；失败记录在 run 的 `dispatch` 中 |
| msg-center，`/kapi/msg-center` | `contact.check_membership`，请求 `{ owner, did, tag }`，读取结果 `member` | 解析 `contact:<owner_did>#<tag>` 授权主体；服务 session 调用，以请求中的 DID 核验成员 | 无法确认时不授予该主体的权限；已独立获得所需能力的调用不必因此失败 |

源码依据：[main.rs](../../../src/frame/aiworkspace/server/src/main.rs)、[auth.rs](../../../src/frame/aiworkspace/server/src/auth.rs)、[wish/exec.rs](../../../src/frame/aiworkspace/server/src/wish/exec.rs)；底层 wire、配置键和 runtime 行为见 [system_config.rs](../../../src/kernel/buckyos-api/src/system_config.rs)、[control_panel.rs](../../../src/kernel/buckyos-api/src/control_panel.rs)、[runtime.rs](../../../src/kernel/buckyos-api/src/runtime.rs)、[verify_hub_client.rs](../../../src/kernel/buckyos-api/src/verify_hub_client.rs)、[msg_center_client.rs](../../../src/kernel/buckyos-api/src/msg_center_client.rs) 与 [msg_contact.rs](../../../src/kernel/buckyos-api/src/msg_contact.rs)。

两项容易误读的边界：

- `get_control_panel_client()` 在上述路径返回基于 system-config 的 `ControlPanelClient`。`get_user_list`、`load_user_groups`、`get_user_settings_by_username`、`get_user_did` 和服务发现并不发起 control-panel HTTP RPC。
- `verify_session_token_opened(token, SessionScope::AiWorkspace)` 使用 runtime 本地信任材料验签并检查 session ceiling，不是每个 AIWS 请求都调用 verify-hub `verify_token`。组和 contact 在授权请求中重新解析；system-config 客户端当前只缓存 `services/`、`system/rbac/` 前缀，用户、用户组与 SSO 配置不在该缓存名单中。

### 对象、资产、导入导出和扩展库

| Backend / 入口 | 实际 API | AIWS 使用场景及身份 | 当前依赖与失败行为 |
| --- | --- | --- | --- |
| nfs-server，`/kapi/nfs-server` | `bucket.put` | 服务 session 将对象绑定到相应用户的资产、版本/快照、导出或扩展库桶；资产/快照等记录返回的 `version` | 正式存储路径的核心依赖；对象保留由绑定建立 |
| 同上 | `bucket.get` | 服务 session 查询绑定；导入时先要求 `bucket_id` 等于调用者自己的指定 AIWS 桶，再读取 `key` | 缺 key 或 delete marker 表示无绑定，不允许仅凭服务可读就导入他人的桶 |
| 同上 | `bucket.delete` | 服务 session 解除临时上传、历史资产、快照/导出、删除工作区或扩展库的绑定 | 缺 key 按幂等成功处理；删除绑定不等于立即删除底层共享对象 |
| 同上 | `bucket.create_access_token` | 服务 session 为导出包、replica、扩展包生成指定单 key、仅 `read` 的下载 token | 当前导出 token 有效期 1 小时；返回下载描述，由客户端读取数据面 |
| nfs-server NDM，HTTP | `POST /ndm/v1/store/get_object`，body `{ obj_id }` | 转发**原调用者 bearer**，核验其可读裸 FileObject；用于 `asset.import_object`、`ws.import`、`ext.build`、`ext.install` 的相应裸 `obj_id` 路径 | 未配置 NDM gateway 返回 `DEPENDENCY_UNAVAILABLE`；HTTP 非成功当前统一为 `PERMISSION_DENIED`；网络/超时为 `STORAGE_IO_ERROR`，超时 30 秒 |

桶命名为 `user/aiworkspace/<owner>/<name>`，当前声明四类：`assets` 保留资产，`objects` 保留快照/版本的 DirObject 闭包，`exports` 保存临时导出、replica 和 fixed 发布内容（默认 7 天），`library` 保存安装的控件和模板。桶定义见 [aiworkspace_client.rs](../../../src/kernel/buckyos-api/src/aiworkspace_client.rs) 的 `aiworkspace_bucket_decls`。

其中资产、快照、`doc.export` 和 replica 使用 Workspace Owner 的桶；`ext.pack` 使用调用者自己的 `exports`，扩展安装使用目标 library owner 的桶，不能把这些 owner 混为同一身份。

`ext.install mode=installer` 是例外入口：仅接受 control-panel 服务身份，由 Installer 交付其已验证的暂存包，不重复做用户裸对象检查；普通 `mode=dev` 仍须证明对象可读。这是 control-panel 调用 AIWS 的入站流程，不是 AIWS 调用 control-panel 的后端依赖。

桶错误由 [server/src/buckets.rs](../../../src/frame/aiworkspace/server/src/buckets.rs) 映射：`quota_exceeded` / `object_too_large` → `STORAGE_FULL`，`content_not_available` / `content_evicted` / `not_held` → `DEPENDENCY_UNAVAILABLE`，未被 get/delete 特殊分支处理的 `no_such_key` / `bucket_not_found` → `NOT_FOUND`，其他错误 → `STORAGE_IO_ERROR`。调用方不得把这些映射都当成可盲目重试的网络故障。

对象字节本身通过**进程内 NamedDataMgr** 访问：`is_object_exist`、`is_object_stored`、`put_object`、`put_chunk`、`get_object`、`get_chunk_data`、`open_reader`；文件入库还复用 `ndn_toolkit::cacl_file_object`。Zone 模式使用 `runtime.get_local_named_store()`，不是把上述写入改成 NDM HTTP 上传。文档、授权和运行状态使用本地 SQLite，扩展库使用 `library.sqlite`，没有额外的远端数据库或扩展库服务。

源码依据：[store/src/objects.rs](../../../src/frame/aiworkspace/store/src/objects.rs)、[store/src/export.rs](../../../src/frame/aiworkspace/store/src/export.rs)、[server/src/lib.rs](../../../src/frame/aiworkspace/server/src/lib.rs) 的 `own_binding` / `authorize_object` / 导入处理、[server/src/ext.rs](../../../src/frame/aiworkspace/server/src/ext.rs)、[bucket_client.rs](../../../src/kernel/buckyos-api/src/bucket_client.rs)。

### AI 执行与 Source 外部读取

| Backend / 入口 | 实际 API | 调用条件、身份和结果约束 |
| --- | --- | --- |
| AICC，`/kapi/aicc` | `helper.llm_chat` | Wish 使用 `buckyos` provider 且模型为别名（不含 `@`）时，经 xllm 请求模型路由；默认分析、执行和 map 模型走此路径 |
| 同上 | `chat.completions.create` | 模型名含 `@` 时直接请求指定模型。与 helper 路径一样使用 `Immediate`，携带服务 session 和固化的 `on_behalf_of` |
| Owner 指定 Agent 的 OpenDAN 服务 | `goals.create`、`goals.activate` | hosted run 通过 `AgentSpec.binding.service_name` 解析入口，以 AIWS 服务 session 调用。create 的 `request.key` 为 `aiws/<run_id>`，携带运行说明和 claim token，初始手册为 `aiworkspace_run`；返回非空 goal ID 后 activate |
| OpenAI 兼容 HTTP provider | `POST <base_url>/chat/completions` | standalone 显式配置 `provider.type=openai` 时的替代路径；使用配置的 API key 环境变量和 headers，不使用 AICC 委托 |
| 公开 HTTP Source | `GET <source.url>` | 无凭据请求；30 秒超时，正文上限 32 MiB；解析失败或上游不可用时记录 run 错误，保留旧有效内容 |
| 其他 Zone 的 Workspace 发布源 | `GET <publication-url>?format=json[&fixed=...]` | 无凭据获取发布信封并检查格式；默认 URL 为 `https://aiws-<workspace_label>.<zone>/-/<entity>`。同服务的 Workspace 发布及可识别的本服务发布 URL 直接读 store |
| 同上 | `POST <publication-url>/referrers` | 无凭据登记引用方，10 秒超时，尽力发送；登记失败不使已获取的内容刷新失败 |

AICC 的资源归属包含 `mode`、`user_id`、`operator_id`、`run_ref { workspace_id, entity_id, run_id }`。缺归属返回 `DEPENDENCY_UNAVAILABLE` / `AI_ATTRIBUTION_UNAVAILABLE`，不能用服务自己的 AI 额度兜底。当前 AICC 适配器不接受 `Running` 异步响应，不发起 task 轮询或取消 API。hosted 分发失败则记录 `dispatch.status=unavailable`，run 仍可由执行器领取；不能把创建 run 成功等同于 Agent 已开始执行。

服务定时器跳过 `auth_mode: hosted` 的 Source；手工刷新当前仍走无凭据 fetch，不会取用托管凭据或分发 Agent。不能据此声称已经依赖凭据服务、通用后台连接器或 Agent 同步脚本。服务内 Wish 的 Deno 是本地子进程，且当前允许 `--allow-net`；浏览器程序沙箱的网络限制不能套用到这个执行器。

源码依据：[wish/llm.rs](../../../src/frame/aiworkspace/server/src/wish/llm.rs)、[wish/mod.rs](../../../src/frame/aiworkspace/server/src/wish/mod.rs)、[wish/exec.rs](../../../src/frame/aiworkspace/server/src/wish/exec.rs)、[wish/runner.rs](../../../src/frame/aiworkspace/server/src/wish/runner.rs)、[source.rs](../../../src/frame/aiworkspace/server/src/source.rs)；AICC 最终调用见 [agent_tool/src/xllm.rs](../../../src/frame/agent_tool/src/xllm.rs) 的 `AiccLlmClient` 与 [aicc_client.rs](../../../src/kernel/buckyos-api/src/aicc_client.rs)。

### 通知、客户端数据面与部署边界

| 能力 | 当前依赖边界 |
| --- | --- |
| 变更与锁通知 | `KEventClient::pub_event` 发布 `/obj/aiworkspace/<workspace_id>/head`（`epoch/head_seq`）和 `/obj/aiworkspace/<workspace_id>/locks`（`counter`）。AIWS 是 `KernelService`，当前用本地共享内存 ring，不是 kevent kRPC；发布失败只记录日志，客户端可回退 `doc.wait_changes` |
| 上传与包下载 | WebSDK/CLI 的 NDM 上传、`PUT /bucket/v1/...` 和 `GET /bucket/v1/<bucket_id>/<key>?token=...` 属于端到端客户端数据面。AIWS 接管绑定、返回下载描述；协作者资产代读仍走 AIWS 授权，不要求协作者拥有 Owner 桶权限 |
| 演示与音频 | `show` / `session` 共用现有授权与存储；语音是进程内 `str0m` SFU 和本机 UDP，录音写回 Workspace asset，当前没有独立 RTC/TURN 服务依赖 |
| 页面与对象适配 | `pages.rs` 读本地 Desktop 构建文件；`obj_provider.rs` 转入本服务 kRPC 处理，不新增 control-panel 或其他对象服务调用 |
| standalone | 不带 `--nfs-server` 时使用静态身份及嵌入式 Named Store/BucketStore；带该参数和 `--named-store-config` 时用固定 nfs-server 测试客户端。两者都不能代替真实 Zone 身份、续票和桶权限的集成验收 |

通知实现见 [main.rs](../../../src/frame/aiworkspace/server/src/main.rs)、[runtime.rs](../../../src/kernel/buckyos-api/src/runtime.rs) 的 `build_kevent_client`；媒体见 [media.rs](../../../src/frame/aiworkspace/server/src/media.rs)。当前 AIWS 没有直接调用 task-manager、workflow、Node Executor、repo-service 或通用凭据服务；托管 Agent 自身使用的能力属于该执行器的后续依赖，不能混入 AIWS 的直接调用清单。

## 组合验收与后续扩展边界

以下是冻结契约的验收要求，不表示这些场景已全部通过。实现交付应提供对应测试或真实环境证据，并明确未覆盖项。

### 后端依赖的组合验收

| 场景 | 必须验证的结果 |
| --- | --- |
| Zone 冷启动、服务 session 到期和续票失败 | 首次换票成功后才服务；后续桶/AICC 调用取当前 token；拒绝或过期不能被其他身份兜底；healthz 与依赖就绪分别记录 |
| settings 缺失、格式损坏、服务发现失败 | 能辨明配置默认回退与服务不可达；报告实际配置及地址发现错误，不以“进程存活”判定业务可用 |
| 用户组/contact 撤权、目录不可用、受限会话 | 在声明的生效窗口后撤权有效；未知成员关系不授予新权限；候选目录不可用不等于已有授权被全部撤销 |
| 同一 FileObject 由有权和无权用户通过裸 `obj_id` 导入 | 真实 NDM 使用各自 bearer 判定，AIWS 服务级存储能力不能绕过调用者权限；installer 特例只能由 control-panel 使用 |
| 协作者上传后接入 Owner Workspace | 验证上传者自己的绑定，建立 Owner 的资产绑定，清理临时绑定；重启后仍可提交和读取，不能导入其他用户桶 |
| 桶满、对象被回收、解绑重试、导出 token 到期 | 错误分类与上述映射一致；缺 key 删除幂等；合法保留根不丢内容；下载 token 仅访问指定 key，过期拒绝 |
| AICC Owner/current-user 归属、额度不足、异步响应 | 账单与固化归属一致，结构化失败可见；缺归属不执行；不把不支持的异步响应判为完成 |
| Agent 绑定失效、goal 创建/激活失败、旧 attempt 回报 | `dispatch` 失败可见且 run 可恢复领取；不自动切换系统执行身份；过期 lease、取消和委托变化阻止迟到写入 |
| Source 超时、非法发布信封、referrer 登记失败 | 前两者不替换旧有效版本；登记失败不撤销成功读取；同服务发布不依赖外部 DNS/HTTP |
| kevent 不可用 | Commit 接受事实和变更日志不丢失；`doc.wait_changes` 仍能恢复新 head；通知不携带实体内容 |

### 数据与协作验收

| 场景 | 必须验证的结果 |
| --- | --- |
| 对象改名、旧名被复用、离线修改迟到 | 修改仍指向原 ID 或明确失败，不写入同名新对象 |
| 创建数据、Block 与绑定后中途失败 | 全部生效或全部不生效，无半成品引用 |
| 不同字段并发、unique 收紧、集合增删 | 原语约束成立，读集合发现真实依赖变化；不虚称支持任意业务不变量 |
| accepted 响应丢失后权限/锁变化 | 可按可见性恢复接受事实，不重复执行；同 key 不同请求被拒 |
| 旧日志经新 planner 版本的客户端重放 | 不重新规划、不调用外部能力，结果与记录一致 |
| 旧 epoch、低于历史下界的请求 | 明确要求重新同步与恢复意图，不当新请求执行 |
| 自有/共享内容复制、跨画布引用、删除与 pin | 归属规则一致，级联受强引用和权限约束，其他使用者不丢数据 |
| 首次 Source 失败、刷新失败、刷新超额 | 不发布无效初始结果，旧有效版本保留，暂存和预留可释放 |
| 发布一组素材，下游手动同步，上游撤回 | 配套版本一致；入口失效可见，合法本地副本不被远程抹除 |
| 内容分享与个人备份分别导出 | 分享不含完整编辑历史；未知 Schema/Renderer 不丢数据；缺失依赖明确 |
| 释放最后保留根、跨 Workspace 共享资产 | 只回收不再被保留的内容，过期恢复返回明确错误 |
| 满额后取消任务、清理暂存、释放历史资产 | 维护通道可用并受授权/预算限制，账本与保留一致 |
| 公式定义与普通前缀字符串 | 无损保存、复制与交换；服务端不求值，前端求值结果不写回，普通字符串类型不变 |
| run 意图落盘后崩溃、Apply 时断线 | interrupted 可见，先核对结果再恢复，不自动重做未知副作用 |
| 仅 run 协作者执行、配置改变、旧 attempt 迟到 | 使用 Owner 指定托管身份；旧委托和失效尝试不能写入 |
| 用户任务缺失上下文，宿主已有系统 runtime | 明确拒绝，不借系统身份或其他用户资源兜底 |
| 本地生成程序尝试网络、存储、token 或伪造消息 | 沙箱与桥共同限制，取消/超时终止对应程序 |
| AI 结果经人工修改后刷新或解除管理 | 失败保留旧结果，替换需重新校验，不被迟到计划覆盖 |
| 表单 accepted 后草稿清理失败，换设备重开 | 查询原接受事实，不重复插入，不泄露其他记录 |
| 固定演示期间编辑、撤权、资源回收 | 基线不变，授权变化生效，必要资源被保留 |
| 模板确认后继续编辑，随后跨实例汇总 | 汇总固定确认版本并报告覆盖范围，不读取新草稿冒充审核结果 |
| 新增 3D Scene 等业务 Schema | 使用现有原语，不为业务类型升级格式，旧副本可保留与重放 |

### 新增宿主范围的验收

| 场景 | 必须验证的结果 |
| --- | --- |
| 旧正式工作区在新版本打开、编辑、保存、再打开 | 内容、稳定身份、引用及已承诺能力保持兼容，不能仅验证文件可解析 |
| 转换中断或校验失败 | 原工作区可恢复，不留下半转换状态；重试路径可判定 |
| 旧标准 Block、扩展及宏在新宿主运行 | API 行为保持兼容，外部依赖问题与数据格式问题分别报告 |
| Block 在编辑、查看、放映、打印及手机环境呈现 | 模式回退明确，渲染本身不产生写入或重复业务副作用 |
| control 组合普通、复杂与嵌套子节点 | 布局由父容器控制，子节点身份、绑定、slot、复制与撤销保持一致 |
| 多客户端观察同一次按钮或工具栏动作 | 只产生一次获准业务执行，重试复用提交/run 身份 |
| Workspace/Canvas 宏访问范围与 ACL 不同 | 同时检查作用域和权限，缺少能力不会借宿主权限兜底 |
| 隐藏全部工具栏形成 app 模式 | 文档和权限不变，有权用户仍可经宿主入口管理，隐藏不代替授权 |
| 同步脚本失败、重试、撤权或取消 | 保留旧有效数据，候选不越权写入，迟到尝试被拒绝 |
| 同一文件从文件选择与剪贴板进入 | 共用探测/转换逻辑，多目标由统一向导选择，损失和缺失可见 |
| 依赖不完整的扩展包或不兼容 build | 不替换最后可用定义，错误指出依赖或受影响实例 |
| 普通 `=...` 文本及公式对象经历复制和导出导入 | 字符串不变成公式，公式定义无损保留；无法求值时显示表达式，不以零或空值冒充结果 |
| 自由布局分页、流式长文档、缺少打印 Renderer | 分页和裁切规则明确，使用静态回退，不执行宏或重新生成 AI 结果 |
| BuckyOS 组移除成员、节点移动或名称复用 | 后续授权按有效成员和稳定目标计算，不残留隐含权限 |

### 后续扩展边界

服务端公式求值器、函数库与自动重算，函数对象，自由表格，列组 Source，当前用户 Agent 的托管选择，Guest 自带模型与跨 Zone AI 能力，以及具体额度与计费可独立演进。具体 CAD 等文件解析器、行业 control、后台连接器和公开会话产品细节不要求在本次全部实现，但接入本文统一契约。

本次已把 Block/control 宿主、事件与动作、宏对象 API、扩展贡献、Import、工具栏和打印框架纳入 core 冻结范围，不能再以“属于扩展”为由略去它们的公共边界。具体函数、字段或贡献清单的新增版本必须补齐协议定义、能力协商和兼容验收后再发布。
