## 权限、路径 ACL 与 Workspace 权限组

权限在服务端的数据边界执行，包括名称枚举、解析、查询、切片读取、资产访问、写入、导出和任务触发。不可见对象不应仅因某个列表或错误详情而泄露内容。

| 能力或边界 | 约束 |
| --- | --- |
| `read` 与 `export` | 能显示不等于可批量导出或工作区 Clone |
| `append`、`update`、`delete`、`structure` | 分别授权，追加表单不等于任意改表 |
| `comment` | 可操作获准附加层，不自动修改正文 |
| `run` | 可触发获准任务，不等于编辑任务程序或任意写入输出 |
| `manage` | 管理授权、托管配置及明确的维护操作 |
| 数据与 Overlay | 分别授权，读数据不自动可读所有标注 |
| 跨 Workspace 引用 | 不传递隐含授权；ObjId、名称、URL 都不是凭据 |
| Owner 委托 | 当前 Owner 授权、执行身份限制和任务能力范围共同约束 |

只读 Workspace 可以开放评论、个人视图或受限录入。访问者只收到其有权读取的投影；不能先传输完整数据，再隐藏不应显示的 Block 或记录。

Guest 是受作用域限制的参与身份，Session 是一次会话，分享入口授予的能力又是另一层。需要持续匿名参与时，可保留有限范围身份与个人状态，但不能依赖永久 Session 或把匿名身份当作现实身份。匿名写入入口由产品定义相应的限流与管理能力。

导入程序和 AI 运行中生成的程序按不可信内容处理。HTML 扩展的信任在引入工作区时决定，激活后与页面同权，见[HTML、版本与回退](05-Block控件与标准库.md#html版本与回退)：写入或修改 HTML 定义的代码（`html`、`on_bind`、`on_init_control`）要 `manage`，写入者在定义上留下“已信任”标记（`trusted { by, rev }`）；查看模式的宿主只自动运行已信任的定义，其余显示快照、点击才运行。打开文档或恢复内容不自动执行脚本、启用远程 AI、继承委托或获得宿主文件与网络能力。

### 稳定目标与继承

数据树和 Block Tree 都允许按节点或子树配置授权。接口用核心 API 的实体路径（`/`、`/data/销售`、`~<id>/…`）或实体 ID 指定资源，持久条目绑定稳定实体 ID（`/` 即工作区）；重命名和同名复用不改变授权目标。路径的每一步都要可读；个人范围和会话范围的实体不是授权目标，它们的可见性由范围决定。

路径继承按当前树结构计算。移动节点可能改变继承结果：移动照常执行，不增加门槛；如果有主体因此对被移动实体新获得了能力，这次 Commit 的结果和操作记录里各写一条“可见范围扩大”（`visibility_widened`：哪些主体、新得到哪些能力）。复制出的新实体按新位置继承，不带针对旧实体的条目，创建者是复制的人；永久删除（purge）一并删除实体上的条目，普通删除保留以便恢复。

每条条目是“主体 × 资源 → 允许、拒绝”。调用者对实体 E 的能力 c 这样决定：

1. owner 恒有全部能力，不能被授权、拒绝或改变；
2. 可见范围（`user:` / `presenter` / `participant:`）不让他看则拒绝；
3. 从 E 沿祖先到 `/`，第一层有条目提到 c 的那一层决定；
4. 层内按主体的具体程度分档：单个调用者，然后逻辑组和 `@creator`，然后 `@guest` 和 `@all`；第一档提到 c 的决定，档内只要有一条拒绝 c 就拒绝；
5. 一直没有条目提到 c：拒绝。

这修改了此前“沿用允许授权的合并模型”的约定：显式拒绝存在，近的层先于远的层，同一层里具体的主体先于宽泛的主体，同一档内拒绝优先。“私有子树”用拒绝表达：在子树根上拒绝 `@all` 的 `read`，再允许需要看的人。基础 ACL 定位实体与子树，不因数据支持行列选择器而自动提供行列级 ACL；受限表单应使用受控提交与读取入口。授权必须由服务读取投影、变更流与提交共同执行；`ws.get_info.acl_rev` 与 `doc.wait_changes { after_acl_rev }` 让打开着的客户端在权限变化后重新取能力。

只有 owner 能做的：授予或收回 `manage`（含改变带 `manage` 的组的成员）、删除工作区、配置托管执行、覆盖式恢复。其余 `manage` 操作管理者可以做：建组、加减成员、写不带 `manage` 的条目（含拒绝）、匿名访问开关、分享入口、发布、宏的组绑定、维护。条目、组、成员、匿名开关、入口、发布、宏绑定、托管配置、owner 专属操作和“可见范围扩大”都写入只追加的操作记录（谁、按谁判定、何时、对象及当时路径、改前、改后），管理者可读，不随导出传播。方法级的检查集中在服务的方法表（`server/src/methods.rs`），服务 README 的授权表由它生成。

按提交者归属的记录（见[数据模型](02-数据模型与引用.md#table-与-richtext)）是表格上的受控提交，写入资格如下：

| 调用者在该表上的能力 | 可以做的写入 |
| --- | --- |
| `append`，没有 `update` | 插入一条记录（每人至多一条）；只能修改、清除自己那条记录的值 |
| `append`，没有 `delete` | 只能删除自己那条记录；撤销删除时的恢复按同一规则判断 |
| `update` / `delete` | 照常修改、删除任意记录；提交者字段本身仍只由服务填写 |

动别人的记录返回 `PERMISSION_DENIED`；既没有相应能力也没有 `append` 时照常拒绝。这不是行级读取规则：读取仍需要表的 `read`，能读表就能读到全部提交。

### Workspace 权限组

条目的主体只有三类：单个调用者（用户 ID、External DID、Agent DID、`guest:<id>`）、本工作区的逻辑组 `@<组 ID>`、固定组。

| 固定组 | 成员 | 约束 |
| --- | --- | --- |
| `@owner` | 工作区的 owner | 恒有全部能力，不是条目 |
| `@all` | 能进入工作区的所有人：组成员、有直接条目的人、匿名访问打开时的 `@guest` | 不能带 `manage`、`run` |
| `@guest` | 匿名访客，以及已登录但不属于任何组的人；只在匿名访问打开时存在 | 不能带 `manage`、`run`；它的权限是所有人的下限 |
| `@creator` | 对每个实体，创建它的人（`created_by`） | 不能带 `manage` |

Workspace 权限组（逻辑组）是本工作区的角色/主体集合，具有稳定组 ID。成员可以是单个调用者、BuckyOS 用户组 `group:<id>`、联系人组 `contact:<owner_did>#<tag>`（只有该 owner 能加）、Zone 全体不受限账号 `*`，以及经分享入口加入的人（带 `via_entry`）；`group:`、`contact:`、`*` 不直接出现在条目里。BuckyOS 用户组作为成员来源引用进入工作区组，不复制成永远不更新的静态名单。重命名组不改变身份，加入组也不绕过对应能力检查。分享入口指向一个目标组（不带 `manage`、`run`），只有出示入口才能加入；关闭入口可以同时移除经它加入的人。

权限设计（组定义、组和固定组的条目、宏的组绑定）随模板、Clone、管理者导出的包传播，装入时组成员为空、匿名访问关闭；成员、单人条目、匿名开关、入口只随覆盖式恢复。

Agent 用自己的身份调用工作区；工作区的条目或组成员里没有提到它的 DID 时，按它的 owner（取自 AgentSpec）判定，新建的工作区也归 owner；一旦提到，它在整个工作区里就是独立的主体。

| 调用者 | 能成为的主体 | 限制 |
| --- | --- | --- |
| 账号（不受限） | 自己、所在逻辑组（含经 `group:`、`contact:`、`*`）、`@all`、不在组里且匿名打开时 `@guest`、`@creator` | 可以拥有工作区 |
| 账号（受限）、External | 同上，但不匹配 `*` | 不能拥有；`ws.list` 只列点名自己或所在组的工作区 |
| 访客（`gt_` 令牌） | 自己（经入口加入后是组成员）、`@guest`、`@all` | 不能拥有，不能本地运行 |
| Agent | 未配置时按 owner；配置后按自己 | 可以为 owner 建工作区 |
| run token | 运行的触发者（按记录的类别重建，成员关系现查），只限该运行 | 只在当前尝试运行中有效 |
| inner-path 发布的读者 | 只有 `@pub:<实体 ID>` | 只经发布路由，进不了工作区 |
| 服务内部（`kind: internal`） | 以工作区 owner 的名义（数据源刷新、会话时间线） | 由服务自己声明 |

成员关系解析与 ACL 判断分开：先确定用户当前属于哪些获准主体，再按同一套 ACL 计算能力。管理组映射、修改成员和调整授权属于 manage 操作，应有审计记录；组变化不能通过内容导出自动在另一部署生效。

撤权与成员变更必须使后续受影响的读取、提交和执行重新使用有效成员关系。成员缓存有可失效机制；权威来源不可用时不得把“无法核实”解释成新增授权或无限期沿用旧权限。已经 accepted 的提交事实仍按幂等规则恢复，不因撤权被改写。

本版本先支持直接主体与外部 BuckyOS 组映射，不依靠递归嵌套才能表达基础角色；组套组显式拒绝。以后开放嵌套时必须规定循环检测、深度及成员失效传播，不把无限递归留给运行时猜测。成员关系查不到时，如果那个组在这个工作区有任何条目，就拒绝请求（`authorization_unavailable`）：少算一个带拒绝的组，结果可能从拒绝变成允许。

工作区组是同一 ACL 的主体组织方式，不形成第二个权限引擎。数据引用、Canvas 宏作用域、查看/运行模式、app 模式和工具栏可见性均不产生额外权限。

## 资源准入、额度与维护

### 计量口径

资源归属独立于底层是否去重。Workspace 的逻辑占用与 Owner 应用对象桶的实际额度分别核算；一个物理对象被其他 Workspace 释放，不得无说明地改变当前 Workspace 的额度归属。

| 资源 | 核算范围 |
| --- | --- |
| 文档与资源 | 当前结构化内容、资产及声明的保留资源 |
| 历史与快照 | 保留期内历史资产、checkpoint、生成版本及其他固定保留 |
| 临时交付物 | 导出、bootstrap、固定内容交付包，按对应临时桶策略计量与过期 |
| 演示 | 克隆、基线资源和并发数量；不能把 Guest 当作默认费用承担者 |
| 暂存 | 上传、同步、任务候选产物与分块提交 |
| 网络 | Source 拉取、上传与下载 |
| 内核工作量 | 操作数、请求大小、扫描范围、引用数、结构深度等 |
| 外部计算 | AI 与计算环境各自的承担者、预算和用量，不混入轻量数据 Apply |

v1 未提供历史截断前，结构化提交历史不计入会使用户永久失去写入能力的可回收逻辑额度；它仍是实际存储成本，服务必须监测。历史资产按保留策略计量，不能据“日志不截断”要求资产无限期保留。

### 准入与恢复

用量账本随提交或相关资源状态变更更新。上传、Source 和任务输出都在接受前检查与预留，避免多个并发操作分别通过检查后共同超限。失败、取消和过期必须释放预留或进入可恢复清理状态。

逻辑额度充足不代表物理写入必定成功；磁盘、named store 或桶绑定失败仍遵守事务与确认边界。

单个资产的大小上限按媒体类型分设：服务按内容识别出的音频、视频不超过 `max_media_bytes`（默认 2 GiB），按 Range 流式播放；其他资产不超过 `max_asset_bytes`（默认 32 MiB）。Desktop 在上传前做同样的检查。

触限时拒绝不满足准入条件的业务写入，返回可解释的错误，区分“释放后可重试”和“需要提高额度”。错误数据应能表达所需空间、可回收空间及有权维护的主体。流量和计算触限分别处理，不用一个全局只读标志替代所有资源状态。

维护通道按 manage 权限开放并有独立、有限预算，包括解除保留、删除 checkpoint/导出绑定、取消 run、清理暂存和立即释放已删除内容的历史资产。立即释放必须明确放弃相关撤销和恢复能力。

删除也可能写入 tombstone、日志和控制记录，因此不能假设删除永远不需要空间。系统必须为恢复保留必要预算，避免满额后无法清理。

## 保留根与资源生命周期

内容身份不等于永久保留。每个保留承诺明确申请者、资源承担者、范围、有效期和释放方式。保留根至少覆盖：

- 当前内容及资产、保留期内的历史资源。
- checkpoint、生成版本、固定发布结果、导出和副本包。
- 演示克隆、运行中任务输入与候选结果的有效生命周期。
- 尚未过期的暂存对象，以及仍处于恢复期的已删除 Workspace。

对象桶按 Workspace Owner 的应用空间组织。`assets` 保留资产；`objects` 保留快照和生成版本；`exports` 承载临时导出、bootstrap 和固定内容交付物。不同保留根使用可独立释放的绑定。

保留根不能仅绑定一个含引用的 `jobj` 并假设底层会理解全部业务引用。必须构建覆盖对象闭包的保留集 DirObject，将内容对象、文件、目录及所需资产一起绑定，利用 named store 的已定义级联规则保留。

应用清理过期绑定，底层决定物理回收；删除一个 Workspace 的绑定不能删除其他 Workspace 仍保留的同一内容。暂存对象在上传到业务引用建立之间必须受到有效保留，避免并发回收窗口。

只被历史引用的资源允许按策略到期释放。恢复或撤销需要的资源已回收时返回 `RESOURCE_RECLAIMED`；只剩固定版本身份、保留物已释放时返回 `VERSION_NOT_RETAINED`。删除当前对象未必释放容量，必须解释仍存在哪些保留根。
