## Source、同步与按路径发布

### Source 是数据实体的来源属性

Source 为空时，数据由当前 Workspace 内部维护。具有 Source 的实体保存来源、查询范围、版本选择、刷新策略和授权模式；它对普通 Block 编辑只读。修改来源配置与写入同步结果是不同的授权操作。

```text
外部 Workspace / URL / DirObject
             ↓ 获准读取
       暂存并校验候选版本
             ↓ 单次 Commit
     当前 Workspace 的本地数据实体
             ↓ 受控绑定
           Block / API
```

核心业务依赖通过数据实体提供，不让 Block 任意绕过 Source 读取外部业务数据。装饰性外链可以按浏览器策略显示，但不获得离线、固定版本或可重放保证，不能用装饰性资源例外承载核心依赖。

### 首次可用与刷新

首次创建成功表示已有完整的约定结果可靠进入本地存储。可以显示“正在创建”的占位或进度，但不能把未完成下载的源作为可用数据依赖。

刷新作为一次 run，先获得候选内容及资产，校验后以普通 Commit 原子切换，服务推导 `origin: source`。失败、取消或配额不足时保留最近一次有效版本。v1 每个 Source 各自原子，不承诺多个 Source 同时刷新的一致事务。

完整性针对明确的数据切片，不要求复制整个远端数据库。查询范围、分页完成条件、记录身份和源版本共同定义结果。导入 CSV、表格等材料时，应显式表达截断、解析损失和无法保持的结构，不能以静默丢数据换取“导入成功”。

普通 CSV/XLSX 值导入创建内部可写数据，不自动建立 Source、持续刷新或向原文件回写关系。只有显式配置外部 Source 才适用同步只读规则；“导入一次”与“订阅来源”是不同动作。

自动与手动同步只改变刷新时机，Block 读取本地有效版本的方式相同。手动同步源的新鲜度只能表示“基于最后成功同步版本”，不能声称远端没有变化。

### 同步宿主与副本授权

服务侧仅保留无凭据公开 URL 抓取的窄路径，作为 Source 基础设施，不执行用户代码，并计入 Workspace 流量与资源额度。有凭据或需要自定义能力的 Source 使用托管执行，单独授权输入、输出与外部访问。

默认模式是：获授权身份导入内容，再作为当前 Workspace 的独立副本按其 ACL 共享。导入者必须具有这种共享用途的授权。地址与公开策略可进入文档，凭据及其运行绑定属于服务控制状态。

未物化远端查询是另一类能力，按读取者身份访问；必须声明固定源版本、一致分页、稳定记录身份和离线读取等支持情况。它不自动具备本地 Source 的可用性，不计入完整离线快照，v1 不作为通用稳定的数据源接口承诺。

v1 Source 作用于整个实体；“同步列只读、手工备注列可写”需要明确列组模型，不能由某个编辑器私下绕过只读约束。它可作为 Table 后续扩展，不增加新原语。

### 统一读取看到的数据源

[公共属性](02-数据模型与引用.md#公共属性)里的 `data` 区分三种当前真实存在的数据状态，Agent 在写入前据此判断，不能只看 ACL 能力：

| `data.mode` | 含义 | `data.write` | 读取 |
| --- | --- | --- | --- |
| `local` | Workspace 内部维护的数据，包括一次性导入的 CSV/XLSX | `edit`：按调用者能力经 Commit 修改 | 完整 `body`，可被文本查询和 SQL 读取 |
| `synced` | 带 Source 的本地副本 | `refresh`：只有 Source 的刷新写入内容，普通编辑返回 `SOURCE_READ_ONLY`；标题和说明仍可修改，来源配置只有工作区 owner 能改 | 与本地数据相同，读到的是最近一次有效版本；刷新失败时仍是旧版本，不变成空表。还没有有效版本时（`state: pending`）不是有效依赖，见下文 |
| `url_query` | 行在远端、未物化的 URL 表 | `none`：没有本地行可写 | `body` 只给表定义和来源说明（`state: definition`）；文本查询只覆盖名字和定义，并在 `coverage.skipped` 里以 `definition` 列出；SQL 返回 `NOT_MATERIALIZED`；行读取走 internal 方法 `doc.source_query`，参数沿用原表格查询的 filter、sorts、fields 和 `source_revision` |

`data.source` 是来源配置的摘要（种类、模式、地址、Zone 路径或来源实体、刷新设置），只给已记录的值；凭据不在其中。`synced` 的数据另有：

| 字段 | 含义 |
| --- | --- |
| `state` | `valid`，或 `pending`（定义已有、还没有有效数据：没有 `data_version`）。会话来源恒为 `valid` |
| `version` | 最近一次刷新写下的 `data_version`：`synced_at`（这个版本同步的时间）、`business_time`（数据本身的时间）、`produced_at`、`program { name, version }`、`records`、`truncated`、`content_root` |
| `attempt` | 最近一次尝试 `{ at, status: running / succeeded / failed, error? }`，取自本服务的刷新运行；部署本地状态，不随导出和 Clone |
| `expired` | 业务时间（没有就用最近一次成功同步的时间）超过 `def.freshness.max_age_s`。只用于显示，不触发运行 |
| `def` | 来源定义 `source.def` 原样 |
| `sync` | 写这个文件的同步任务 `source.sync { agent_id, task_id }` 原样，没有为 null |

支持远端回写的来源尚不存在，没有对应的 `write` 取值。

### 数据源定义与未满足的数据源

数据源定义 `source.def` 写明数据含义（必填）、来源说明、主键（1–4 个字段 ID）、时效要求 `freshness.max_age_s`，以及只要前 N 条的 `limit`。定义可以先于数据存在：还没有 `data_version` 的抓取类来源（URL、工作区、Zone 文件；会话来源除外）处于 `pending`，它不是有效依赖：

- `doc.read { as: body }` 给出定义（含义、主键、表的字段），`body.state` 为 `pending`；文本查询只覆盖名字和定义；SQL 和行读取返回 `DATA_PENDING`。它不显示为空表。
- 许愿格可以绑定它，主状态是“等待数据”（`input_problems` 的 `reason: pending`）；编码时快照里是一张只有字段、没有行的表，宏照定义编写；运行阶段拒绝（`NEEDS_INPUT`）。
- 第一次成功的刷新写下 `data_version`，此后才是有效数据。成功同步后结果恰好为空，是一个有效的数据版本。

**记录身份。** 表格来源以主键识别记录：`def.primary_key`，没有时用 `id` 列，都没有时刷新失败（`PRIMARY_KEY_REQUIRED`），不再用行号；记录的 `record_id` 由主键值导出，同一次取回里主键重复时刷新失败（`DUPLICATE_KEY`），什么都不写。取回的行按文件顺序截到 `def.limit`，`data_version.truncated` 记下。

**全量刷新。** URL 和 Zone 文件来源每次刷新都是全量：输出里不再有的记录被删除（由刷新的 Commit 删除，可撤销，历史里可查），这条路径上没有增量同步；增量同步留给“推”（同步运行作为外部执行器提交）。重试是一个新的运行；取回失败或输出失败什么都不写，同样的输出再刷新一次也不写。输出要整体写出（先写临时文件再改名），这是同步程序的责任。

**刷新与版本。** 内容或版本有变化时，刷新在同一个 Commit 里写入内容和新的 `data_version`；内容和版本都没变时只更新最近一次尝试，不产生 Commit。刷新删除或改变类型的字段在运行结果的 `schema_changes` 里列出，读这些字段的许愿格进入“需要编码”。数据变化后下游结果显示过期，不自动运行；运行期间来源被刷新时，结果照常写入，如实记下所依据的版本，并立即显示过期。

**频率与范围。** 刷新间隔至少 900 秒（占位值，DV 之后再调）；单次取回不超过 32 MiB、30 秒。刷新 Commit 只保留最近 50 个版本的策略要等历史压缩，目前历史保留全部 Commit。

**权限。** 增加、修改（含 `def`）或去掉来源只有工作区 owner 能做（含被判定为 owner 的 Agent）；触发刷新要数据源上的 `run`（或编辑权限）；查看刷新记录要 `read`。

### 按数据路径发布

发布的基本单位是指定数据源或产物目录。发布有两种（权限需求 R26）：

- **inner-path 发布**：把工作区里的一个路径公开出去，内容随工作区更新，仍受工作区权限管理。发布本身是一条条目，主体是这次发布（`@pub:<实体 ID>`），只有 `read`；读者经发布路由（`/<workspace>/<name>`、`/kapi/aiworkspace/pub/...`）读到当前内容，不进入工作区、读不到其他实体。撤销发布、删除实体、对该主体拒绝，都让它读不到；发布不打开工作区的匿名访问。读取次数由服务记录。
- **不可变发布**：把某个版本导出成不可变对象，脱离工作区，交给 ShareContentMgr 提供（链接、到期、停止、访问统计），工作区读回信息做关联展示。两种发布都要登记到 MyContent；只靠 `@guest` 条目的公共访问不是发布。

发布方返回规范引用及其 URL 投影；其余内容与 ACL 不因此公开。读取、导出和发布是不同能力。固定版本（`?fixed=<content_root>`）只认这个发布给出过的版本，其他取值一律不存在。

消费方可把链接插入为 Source：同 Zone 可由服务直接读取；跨 Zone 的公开内容走无凭据抓取。默认 live 跟随发布入口，fixed 解析为被保留的实体内容对象或 ContentRoot，不向消费方交付整库克隆。

“公开当前数据源”和“发布一组已确认结果”要明确区分。业务需要审核或配套资产一致性时，应以输出通道指向已确认快照；先准备完整结果集，再切换一个发布根。上游继续编辑工作稿不自动改动已确认输出。产物目录可直接以 DirObject 作为输出契约。

发布方能够查询已登记的引用者。同服务通过跨 Workspace 引用索引登记；跨 Zone 由消费方登记订阅关系（不鉴权，所以每个发布最多保留 256 条、每条要指明工作区 ID）。登记是弱关联，不阻止撤回；未登记访问只能作为访问记录，不能声称掌握所有复制和下游使用。

URL Source 只抓公网地址：按解析后的 IP 拒绝回环、私网、链路本地、组播等地址，以及 Zone 自己的主机，重定向的每一跳都检查。Zone 内的数据走工作区 Source。

撤回使原公开入口、live 解析和后续刷新不可用，不远程抹除已经合法导入的独立副本。消费方保留上次有效内容并显示来源不可用；其本地副本仍按导入授权和自身 ACL 管理。仅持有远端 fixed 身份、没有独立副本或保留承诺的调用者，也不能据此绕过撤权。

## Source Adapter 与同步脚本

数据源的数据类型由有限数据原语及业务 Schema 表达；Source adapter 定义外部来源如何解析、读取和物化，不为每个外部服务增加一种内核类型。Block 读取工作区内同一类型的数据，不直接依赖某个连接器的私有 API。

### Adapter 契约

| 声明 | 约束 |
| --- | --- |
| 连接与查询配置 | 地址、查询、参数及输出类型具有可校验结构；敏感凭据使用受控引用 |
| 读取能力 | 明确固定版本、一致分页、稳定记录身份、增量读取及离线支持情况 |
| 结果边界 | 明确完整数据集或查询切片，不能把未完成分页的内容宣称为完整结果 |
| 刷新规则 | 手动或获准定时触发、超时、失败、重试与取消语义 |
| 身份与资源 | 指定读取身份、执行环境、网络能力、费用承担者和预算 |
| 副本授权 | 明确本地副本是否可按 Workspace ACL 共享，不由远端读取权限自动推导 |

Adapter 沿用[Source、同步与按路径发布](04-数据源发布与同步.md#source同步与按路径发布)中的首次可用、刷新原子切换和失败保留规则，不另设绕过提交准入的同步协议。

来源配置、公开查询与 adapter 实现可随文档携带；凭据、在线委托及定时任务的有效授权不随导出或工作区 Clone 复制。导入、Clone 或迁入新部署后，需要目标环境重新建立适用授权。正常重开已授权的在线工作区沿用仍有效的调度与授权；打开页面本身不额外触发一次同步。

### 本 Zone 联系人

工作区 owner 或获准代其操作的 Agent 调用 `source.bind_contacts`。创建参数包含 `workspace_id`、`epoch`、`entity_id`、`idempotency_key`、`create {parent_id, order_key, name}`。现有表改用 `expect_content_rev` 指定确认替换时看到的版本。服务解析本 Zone 的工作区 owner 账号和 DID。共享工作区中，有权读取这张表的成员可以看到同步进来的联系人。

本地表的 `source` 使用 `{"kind":"builtin","provider":"contacts","def":{"meaning":"工作区所有者在本 Zone 可见的联系人","primary_key":["did"]}}`。请求的 `mode` 默认为 `auto`，在描述中增加 `refresh.interval_s = 900`。`manual` 省略 `refresh`。两种方式均立即首读，之后有表运行权限的成员可以启动 `source.refresh@1`。自动模式由服务调度。`once` 在首读成功的同一次提交中将表转为可编辑副本。已有有效版本的表可以用带来源键修订的 `entity.unset_keys` 就地解绑，保留行 ID、视图和控件。重绑本地表会在候选完整且表修订仍匹配时替换本地行和字段。

刷新使用 AIWorkspace 当前服务身份，按 200 条一页读 Message Center 的 owner 视图。候选包含 `did`、`name`、`tags`、`friend_state` 和 `contact_ref`。缺失的旧 DID 逐一复核，分页重叠、超限或中途失败时保留上一版。原记录链接交由 Message Center 鉴权。成功时间记录本次检查的时间。

部署本地的控制库保存工作区 ID、epoch、实体、owner DID、绑定代次和修订。读取和提交校验授权。导入、Clone 或恢复可带表快照。读模型的 `data.binding = needs_rebind` 表示当前工作区需要 owner 重新确认后才能读取上游。用户撤销与部分撤销都检查联系人表的只读状态。owner 从历史恢复来源描述后，也需要重新绑定。

### Zone 文件来源（“拉”）

同步程序把结果写到工作区 owner 家目录下的一个文件，数据源以 `kind: zone` 指向它：`{ kind: zone, path: "/home/<owner>/…", refresh?, def }`。刷新时服务以当前工作区 owner 的身份读这个文件：路径不在当前 owner 的家目录下就失败，所以 Clone 给别人的工作区要重新配置；不跟随指向家目录外的链接；大小和时间上限与抓取相同。表格必须声明 `def.primary_key`。

文件可以是普通 JSON / CSV / Markdown（与 URL 相同的解析），也可以是同步程序的信封：

```json
{ "format": "aiws.sync.v1", "status": "ok", "error": "status 为 failed 时程序写的原因",
  "program": { "name": "quotes", "version": "3" }, "business_time": "…", "produced_at": "…",
  "fields": [{ "field_id": "symbol", "name": "Symbol", "type": "text" }], "records": [{ "symbol": "AAPL", "price": 1.0 }], "truncated": false }
```

`status: failed` 时这次刷新失败，原因取 `error`，保留上一个有效版本；`fields` 缺省时沿用表现有的字段；业务时间、产出时间和程序版本进入 `data_version`。工作区不接触程序本身：程序在哪里、按什么调度运行，由 owner 计算空间里的执行设施决定。

### 同步任务

执行设施是 Agent 宿主里的同步任务（[余下任务 TODO](../../../notepads/aiws-ai-native-remaining-todo.md) §8.2）：以 owner 的 Agent 运行，按任务自己的时间表把产出原子写到 AgentRoot 下的 `sync/<task_id>/out.json`。数据源用 `source.sync = { agent_id, task_id }` 指明是哪个任务，只能出现在 `kind: zone` 上，和来源的其他字段一样只有 owner 能设；带 `sync` 时 `path` 必须正好是 `/home/<owner>/agents/<agent_id>/sync/<task_id>/out.json`（`check_source_sync`），`<owner>` 照常在刷新时与当前 owner 比对。

- **立即同步就是触发刷新**（`proc.start source.refresh@1`，要 `run`）：服务先经节点网关（`http://127.0.0.1:<端口>/kapi/<agent_id>`，独立后端用 `--agent-gateway`）以自己的会话调这个 Agent 的 `sync.run { task_id, wait_ms: 120000 }`，再照常读文件。服务只为当前 owner 名下的 Agent（看它的 AgentSpec）这样做。
- **执行环境不可用**：没有网关、Agent 不属于当前 owner、Agent 不可达或拒绝（任务已停用）时，这次刷新失败，`DEPENDENCY_UNAVAILABLE/SYNC_UNAVAILABLE`；Agent 报这次运行失败时，刷新失败，原因取运行的 `error`。两种情况数据都停在最近一个有效版本。
- **定时器只重读文件**：时间表由 Agent 宿主执行，服务的定时器不调 `sync.run`。
- **任务本身**（程序、时间表、访问的域名、凭据、启用停用、运行记录）是 Agent Service 的 `sync.*` kRPC：Desktop 数据源属性里，owner 用自己的会话读任务、启用停用、填写凭据（只写不读）；其他人看到写这个数据源的是哪个任务和 AIWS 记下的最近一次尝试，有 `run` 时能立即同步。

### 自带同步脚本的执行

同步脚本可以复用宏语言和部分对象 API，但其执行形态是托管任务。它绑定确定的 adapter/程序修订、输入配置、输出 Source、身份与能力，不能作为任意代码嵌入数据内核的 Apply 或 Get。

服务内仅保留无凭据公开 URL 抓取的有限路径，不执行用户同步代码；有凭据、需要联网工具或自定义解析的任务进入统一托管运行协议。同步脚本需要的后端环境由执行平台提供，不为扩展再建立一套拥有系统身份的脚本宿主。

执行器通过受控能力读取外部内容并生成候选结果，提交端检查 run/attempt、当前授权、配置摘要、输出范围、资产和版本条件，再赋予合法同步写入语义。脚本不能靠填写 `origin: source` 绕过只读实体或其他权限。

Source 内容对普通 Block 编辑保持只读；同步任务只写声明的结果范围。若需要“同步字段 + 本地备注”等混合数据，应使用明确的组合模型或将来的列组 Source，不由 adapter 私自开放部分字段或修改类型规则。

定时刷新必须有明确宿主、资源额度与暂停/失效状态；保存一个周期值不等于已有后台调度。缺少凭据、委托失效、程序修订变化或执行环境不可用时，停止本次执行并报告原因，不借用服务或其他用户的身份继续运行。

同步 run 的重试、幂等、取消和结果未知沿用统一任务协议。远端接口的副作用另行声明与核实；历史重放、恢复备份或复制 Source 均不重新调用外部接口。
