## 统一任务运行与执行授权

### Workspace 是任务发起端

Workspace 保存任务定义、输入与输出契约、逻辑运行和候选计划，负责数据访问及结果提交。执行平台负责启动、托管、停止和回收用户计算，Workspace 服务不默认成为任务宿主或权限来源。

v1 仅有两种执行形态：

| 形态 | 承载方式 | 数据写权限上限 |
| --- | --- | --- |
| 本地执行 | 浏览器客户端；生成程序在受限 Worker 沙箱执行 | 宏身份 ∩ 已确认输出声明 |
| 托管执行 | 经 AppLoader 启动 Agent Work Session；v1 使用 Owner 指定的 Agent 和配置 | 宏身份 ∩ 已确认输出声明，并受 Owner 当前委托范围约束 |

不另立“用户后台模式”或“Agent 模式”。Node Executor 等属于托管执行的底层实现选择。

**宏身份**（权限需求 §4.5）是一次运行读写工作区时使用的权限：默认与触发者相同；许愿格可以绑定一个逻辑组（按许愿格 ID，不跟宏的版本），取并集或交集。并集给出的、超出触发者自己的部分只在可信执行者上生效，本期不支持以 owner 身份执行宏，所以并集不超出触发者；交集照常生效，给宏设上限。执行者不是权限来源：托管执行的 Agent 只负责执行，它自己的授权不进入宏身份。

宏身份既管写也管读：编码和运行阶段的快照、宏的 `aiws.sql`、执行器用 run token 的读取都按宏身份，交集绑定的组读不到的输入，宏也读不到（运行以 `DEPENDENCY_UNAVAILABLE` 失败）。分析是分析者自己的工作，按触发者本人。应用按“宏身份 ∩ 输出声明”检查，不按点击应用的人；宏身份在应用时按当前的条目、成员关系和绑定重新计算，预览的预检也按它判断，所以预览“可以应用”时应用一定能通过权限检查。Commit 上记触发者、执行者、应用者和所用的绑定。

分析和编码会把触发者的文字交给模型、产生新的宏版本，只开放给许愿格上有 `update` 的人；运行阶段要许愿格上的 `run` 或任何写能力。每次运行至少要把结果和 `last_run` 写回许愿格，所以宏身份要对许愿格有 `update`、对结果去处（输出文件夹或已有结果）有写能力；做不到的运行不启动，`proc.start` 返回 `PERMISSION_DENIED` / `MACRO_CANNOT_WRITE`，不花任何人的 AI（权限需求 Q31）。本期宏身份不超出触发者，所以只有 `run` 的人还不能运行：等可信执行者支持并集提权后再开放。只有 `run` 的人能看到的只是自己发起的运行。

### 每次运行的执行上下文

运行必须显式绑定：

| 内容 | 要求 |
| --- | --- |
| 触发者、执行身份 | 分别记录点击者与实际执行 principal，以及适用的 Agent/AppInstance |
| 任务定义 | 固定的配置或程序版本及摘要 |
| 输入 | 允许读取的实体、选择器、固定版本与快照 |
| 输出 | 允许修改的目标、操作及新建位置 |
| 执行环境 | 本地或托管、工作目录、文件、网络、进程与工具能力 |
| 资源 | AI 与计算分别由谁承担、预算与拒绝规则 |
| 委托 | 授权依据、有效期、尝试租约、取消与撤权条件 |

缺失所需身份、环境、资源归属或授权返回明确错误，不回退到系统服务、设备或其他用户的权限。

Owner 管理允许的任务、触发者、Agent、能力和额度。授权摘要覆盖程序、输入范围、输出目标及操作、外部能力、执行身份与环境等边界；扩大或改变这些边界使旧授权失效，返回 `DELEGATION_STALE` 并要求重新确认。动态输入只能在预先声明的范围内变化。运行权限不等于修改任务配置权限。

run/attempt 作用域凭据可以限制执行器访问，但不是新的权限来源，也不能突破执行身份的当前权限：run token 只在所属尝试仍是当前尝试、运行仍在执行时有效，持有者按触发者记录的类别重建身份、成员关系现查。领取令牌只交给上下文指定的执行者（托管的 Agent、本地的发起者），`proc.claim` 只接受它。只有 `proc.apply` 能写带 `run_id` 的 Commit。托管配置的 `limits`（每日次数、工具轮数）在服务端执行，工具轮数只数模型循环的工具调用，宏自己的 `sql`、AI 缓存调用不算；应用时复核配置摘要和上下文有效期。运行记录里托管配置的细节（`limits`、配置摘要、派发给 Agent 的目标）只给工作区管理者看（权限需求 V1）。Workspace ID 不是执行身份；仅填写 userid/appid 也不构成隔离。

### 逻辑运行与结果协议

```text
确认任务配置、输入范围和授权
          ↓
持久化 run 意图与固定输入
          ↓
本地或托管执行器领取 attempt
          ↓
执行并报告候选数据、资产、操作与 readset
          ↓
校验并确认 plan_digest
          ↓
带 run / attempt 资格与版本条件 Apply
          ↓
原子 Commit accepted → succeeded
```

run ID 标识一次用户执行意图；attempt ID 区分执行尝试并隔离迟到执行者；提交 key 和 `plan_digest` 标识结果写入。显式重新生成创建新 run；恢复同一次提交沿用原身份。

输入快照、任务配置和确认计划独立版本化。修改操作、目标或前置条件必须产生新计划身份；prepare 或用户先前确认不是后续免检凭证。Apply 时仍检查当前权限、输入/输出条件、管理关系、资源及运行有效性。

任务可以在声明位置创建结果对象，但 `run` 不自动授予创建或修改 Source 的能力。引入外部来源要通过单独授权的 Source 流程；不能把“允许新建结果”扩大成“可任意扩充外部输入”。

状态应区分执行中、等待确认、应用中、成功、失败、取消和 interrupted。候选结果完成不等于共享变更成功；只有接受记录证实结果已提交，才报告对应写入 succeeded。

### 可靠性、取消与恢复

逻辑运行记录以 Workspace 服务为权威；执行器或 Agent 的任务记录是执行侧状态。意图先持久保存，服务启动或租约失效后主动识别中断，标记 interrupted，由用户或明确策略续跑，不自动重做未知副作用。

执行意图与共享修改跨 `local.sqlite` 和 `doc.sqlite` 时，通过 run 引用及接受记录建立可恢复衔接。例如先保存意图，再提交带 run ID 的修改，启动时核对其是否已生效；不得依赖 WAL 下跨 SQLite 库事务具有未定义的原子保证。

本地模式以心跳/租约判断标签页关闭或执行失联；托管执行通过领取、心跳、报告协议反馈。处于 applying 的运行先查询结果提交事实，不能因为执行进程消失就重新写入。

取消请求、进程停止和结果提交是不同事实。服务端按确定顺序裁决取消与提交：取消已生效或 attempt 已失效则拒绝新结果；结果先 accepted，则后来取消不回滚该结果，需要显式补偿。

Workspace 幂等只保证其自身结果不重复写入。第三方副作用须由下游幂等或结果核实保障；结果未知时保留待核实事实，不盲目重试。历史重放、导入、工作区 Clone 和恢复备份不重新运行历史任务或恢复旧委托。

### 本地生成程序的隔离

Workspace 页面与其他 Workspace、Desktop 使用独立源；各子域使用自己的 host-only 登录态，由受控 SSO 委派衔接。这不等于生成程序已与页面隔离。

生成程序运行在隐藏的 `<iframe sandbox="allow-scripts">` 内部 Worker 中；iframe 不承载 Workspace 页面，不授予 `allow-same-origin`，并用 CSP 禁止网络与远程脚本。Worker 仅经受限 postMessage 协议取得输入快照、程序输入及能力代理结果。

token 留在可信页面主线程，不传给程序；程序不能直接取得页面 cookie、宿主存储、DOM 或任意网络能力。主线程验证消息来源、类型、形状和运行身份，只代理声明且获准的桥调用：`sql`、`ai.complete`、`llm.map`、`zone.fetch`。超时或取消销毁对应执行容器并终止 Worker。

### 宏的执行边界：以 Zone 为界

许愿格的宏（编码阶段写成、运行阶段反复执行的程序）在所有执行位置遵守同一条边界（AI Native 第一期 §2.6）：

- 只读本次运行的快照，且只物化宏声明的输入和字段；运行时不提供整棵数据树和画布树。
- 集合计算经 `aiws.sql` 交给服务，在本次快照上只对声明的输入表执行。
- AI 调用经执行器的桥，以执行者自己的 AICC 会话完成，有声明的预算和按内容的缓存；服务不调用模型。
- 可以读 Zone 内资源（`aiws.zone.fetch`，以执行者的会话，只到本 Zone 的主机，只用 GET / HEAD，只到 `declare.zone` 列出的路径前缀，由宿主强制），不访问 Zone 外资源。
  - 已知风险（权限需求 Q33，owner 定为维持现状）：宏由有 `update` 的人写，可能由权限更高的人运行；`zone.fetch` 带的是运行者的会话（本地是浏览器 cookie，托管是 Agent 的令牌），所以宏能以运行者的身份读到作者自己读不到的 Zone 资源（例如知道节点 ID 的文件），再写进作者看得到的结果。运行别人写的宏之前，看一下它的 `declare.zone`。
- AI 判断的缓存按 AI 归属的用户分开：一个人的执行者写入的答案不会被别人的运行命中。
- 落点只来自许愿格的输出声明和它已有的结果：声明的输出文件夹与画布（没有声明画布时，显示该许愿格的 Block 所在的画布）；输入实体不是可写的根，只有输出契约声明了派生列时，才能写那张输入表本身。
- 产物里的 HTML 代码在编码时固定；运行只更新绑定的数据。应用运行结果（来源 `program`）写入页面代码不要求 `manage`，但只有宏身份对该定义有 `manage` 时才标为已信任；编辑者编码出的页面在别人的查看模式里只显示快照，管理者确认（写 `trusted`）后才自动运行（权限需求 Q32）。确认信任不算对结果的手工修改。

浏览器用上文的 sandbox iframe + Worker；托管位置由 `buckyos aiws run-exec / run-program` 起受限的 Deno 子进程：只读 stage 目录、只写其 `output/`、只联网到 Zone 主机、清空环境变量，桥走 stdio，run token 和 `claim.json` 都不在它能读到的范围内。两处的桥由同一份 `aiws/host.js` 应答。

Worker 本身不是安全边界：同源 Worker 可通过请求携带 cookie，也可能访问源内存储；仅有 sandbox 而无 CSP 也不能保证无网络。隔离必须同时验证源、CSP、消息桥、资源限制和取消生命周期。

### AICC 与资源归属

许愿格的所有模型调用都出自执行器：本地运行用发起者自己的会话，托管运行用 Owner 的 Agent。服务不再调用模型，也不再有服务内执行路径（浏览器优先规划 M1–M2）。应分别审计触发者、执行者、费用承担者与实际执行环境。

AICC 资源归属正确不代表文件、网络、工具或结果写入权限正确；把 xllm 换成子进程也不自动形成用户隔离。模型能力、执行环境和结果准入必须各自满足契约。

服务内执行的过渡路径已下线：服务只做数据内核的事——物化快照、回答只读工具与宏的 SQL、校验产物、规划候选、事务提交。

## 许愿格、生成结果与可选心流

许愿格是带 Schema 的任务内容对象，保存提示词、已确认依赖、目标与执行配置。运行进度、token 流和临时文件属于运行态；共享结果和来源关系通过 Commit 保存。

许愿格分三个阶段，各有产物（AI Native 第一期 §2.1）：

| 阶段 | 产物 | 回到这一步的原因 |
| --- | --- | --- |
| 分析 `analyze` | 任务契约：输入绑定、输出契约、检查项 | 需求、口径、输入范围变化 |
| 编码 `code` | 宏版本（源码 + 声明清单）和试运行候选；应用时宏与结果同一次提交 | 声明的字段被删除或改了类型、宏运行失败、HTML 代码变化 |
| 运行 `run` | 结果候选；只执行已保存的宏，没有模型循环 | 数据更新 |

宏读取的字段在编码时按 ID 固定（声明清单），字段或表改名不影响运行；所有结果都由宏产出，文字类结果由宏调用 AICC 生成，数据更新后运行时一并更新。主状态按“需要补充信息 → 需要分析 → 需要编码 → 等待数据（查看者读不到某个输入时为“读不到输入” `no_access`）→ 无法运行 → 进行中 → 结果待确认 → 结果已过期 → 最新”取第一个成立的（core `main_status`）。查看者读不到的输入，不在“需要编码”的原因里出现（不透露它的字段变化）。

依赖识别只能探索当前获准范围。歧义、缺失和无权限输入要明确显示；未解决的名称不得由 AI 静默猜测。确认后固定实际输入版本，再执行生成。

AI 的产出可以是数据、资产，也可以是 Renderer 与配置。已有 Renderer 足够时复用配置；需要新界面时生成扩展资源，但仍通过受控绑定和 Command Bridge 读写。导入、工作区 Clone 或打开生成 Renderer 不自动扩大执行权限。

生成的 HTML Renderer 在用户确认前只放在禁止脚本的 sandbox iframe 中预览。确认后，它作为普通 HTML 定义写入工作区，按[HTML、版本与回退](05-Block控件与标准库.md#html版本与回退)的信任模型运行：确认结果就是引入这段代码。Renderer 及其依赖可随文档导出；禁用或缺少扩展时保留数据并回退到通用视图。

### 结果的四个独立维度

| 维度 | 含义 |
| --- | --- |
| 运行状态 | 某次 run 是否执行、等待确认、成功、失败或取消 |
| 输入新鲜度 | 输入或配置是否变化，依赖是否失效，版本是否仍可核实 |
| 人工修改 | 当前产物是否偏离生成基准，必须由版本事实判断 |
| 管理关系 | 产物是否仍由该许愿格刷新和替换，与来源记录是否保留分开 |

生成来源记录输入版本、提示词/程序配置、执行器、产物与提交关系；完整模型上下文和私有草稿不默认公开。

刷新先准备新候选，再检查旧产物的当前版本和管理关系。失败或取消保留旧有效结果；不能以一次新 run 失败清空上次产物。对人工修改内容明确选择 keep、replace 或 new；确认替换后又发生编辑，必须重新校验。

新建副本使用新产物身份；原结果与下游引用保持有效。解除 AI 管理通过 Command 修改关系，迟到任务必须重新检查，不能继续覆盖；来源记录可按权限和保留策略继续保存。布局调整不应无故改变业务源版本或触发重算。

### 心流与建议

心流是可选工作模式。建议区与正式文档分离，忽略建议不改变共享内容；接受建议时，依据生成基准重新检查版本、目标和权限，转成普通 Command。

观察未提交草稿与把草稿发给远程模型是两种授权，必须分别限定。关闭心流停止后续观察与触发，并处理正在运行的任务。Workspace Mode 可声明布局、工具和辅助配置，不可借文档配置静默修改宿主安全设置或启用监测。
