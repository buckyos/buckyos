## 统一事件与动作模型

Block、control、工具栏、菜单、快捷键、宏和许愿格共用事件与动作入口。内置功能与扩展调用同一套宿主能力，不各自增加绕过 Command/Commit 的写入通道。

| 概念 | 契约 |
| --- | --- |
| 事件 | 由定义声明名称、参数 Schema 和触发条件，例如一次用户点击或输入确认 |
| 动作 | 可调用的宿主能力，声明参数、结果、所需能力和作用范围 |
| 绑定 | 将实例事件或工具栏入口连接到动作/宏，并明确参数映射 |
| 触发上下文 | 来源实例、操作者、Workspace/Canvas、输入参数、触发身份与适用模式 |
| 执行结果 | 本地 UI 更新、共享 Commit 或带独立生命周期的 run，三者明确区分 |

一次用户触发由确定的执行主体处理，其他客户端观察结果。组件挂载、渲染、布局、订阅回调和历史重放不得再次执行相同业务副作用。影响共享内容的重试沿用可恢复的触发、提交或 run 身份。

选中、hover、弹出菜单等个人反馈留在 UI 状态；修改共享数据形成 Command；需要异步计算、网络或后台运行的动作进入任务协议。界面可以提前显示本地反馈，但只有 accepted 才表示共享变更已成立。

动作不能仅根据“处于运行模式”判断权限。服务按当前身份、目标和能力检查，输入参数与目标范围也受约束。定义更新时检查已有事件绑定；删除或改变参数不能让旧实例静默调用另一个动作。

数据变化触发的自动化必须显式配置，记录触发版本与因果来源，并限制递归、重复触发和调用预算。多客户端同时观察到变化不能各执行一遍；后台触发由确定的执行宿主负责。对尚未提供的触发种类应拒绝或禁用，不由前端轮询隐式代替。

## JavaScript 宏与稳定对象 API

宏是用 JavaScript 编写、通过稳定宿主对象操作工作区的程序。UI 操作和宏使用相同语义，宏不依赖 DOM 结构、React 组件名、菜单文本或屏幕坐标。

### 对象面与作用域

下表是必须具备的 API 能力分组；具体函数名和签名以版本化 SDK 为准，不将说明性名称视作新增 RPC。

| 对象面 | 必须说明的能力与限制 |
| --- | --- |
| Workspace | 身份、版本、数据树、画布枚举，以及获准的文档级操作 |
| Canvas/Surface | 指定画布的 Block Tree、布局和局部操作上下文 |
| 数据与引用 | 稳定 ID 解析、选择器、获准读/查、fixed/live 及读集合条件 |
| Block/control | 定义与实例、属性、绑定、子节点/slot，以及结构修改 |
| 选区与 UI | 当前用户交互状态、提示和选择；后台环境不存在这些能力 |
| Commands | 候选操作、prepare、提交、结果恢复及可补偿操作 |
| 资源 | 获准资产读取、暂存和引用，不暴露任意宿主文件系统 |
| Tasks/AI | 发起、查询、取消获准 run，以及受预算限制的模型/工具调用 |

宏声明 Workspace 或 Canvas 作用域。Workspace 宏可在授权范围内操作多个画布；Canvas 宏默认限定该画布，跨范围访问必须在能力声明中明确。作用域确定可发现和可操作的边界，不能替代 ACL，也不自动授予绑定数据的写权。

宏定义、代码版本、入口、参数和触发绑定是文档或扩展内容；本次输入、执行尝试、进度和错误属于运行状态。复制、导出和模板实例化保留代码与必要依赖，但不携带有效 token、旧授权或自动重做历史运行。

### 执行、事务与兼容

前端运行时承载交互宏和获准的 xllm 循环；生成程序经受限执行环境运行。后台宏/同步脚本由托管执行器承载，不在数据服务中另设任意 JavaScript 执行入口。

所有由文档或扩展携带的前端宏，无论人工编写还是 AI 生成，都在受限运行器中执行，通过声明的对象 API 与能力桥访问宿主；不能直接取得页面 token、宿主 DOM/存储或任意网络权限。可信宿主中的 xllm 编排可以代理获准调用，不构成任意宏在页面主线程执行的许可。

前后端共享适用的数据、引用、命令和任务协议；DOM、选区、文件、网络等环境特有能力通过明确的能力面提供。程序不得依赖“碰巧在浏览器里”或“宿主进程有权限”获得额外能力。

宏先读取带版本的输入，计算后形成候选修改。一组需要共同成立的修改以一个 Commit 提交；长流程可以有多个提交或 run，并明确各步的成功与补偿边界。网络、模型调用或等待用户输入不占据长期数据库事务，也不承诺整个宏天然原子。

宏 API 必须固定参数、返回值、错误类别、异步行为、取消及资源限制。同名 API 不改变副作用含义；旧宏选择对应 API 语义。程序读取失败、版本冲突、运行取消和提交结果 unknown 必须分别处理。

宏执行形成的日志记录确定修改，重放时不再解释 JavaScript。脚本调用外部系统的副作用另行核实；不能用 Workspace 提交幂等推导外部操作恰好一次。

## 公式兼容预留

**本版本不支持公式求值，只冻结兼容入口。** 前端显示求值、后端读时求值、函数库、自动重算和循环依赖处理均不在本版本支持范围内。

用户未来可以通过特殊前缀输入公式，例如 `=price * quantity`。前缀属于编辑器输入语法；持久化保存明确的公式值，普通字符串不能在宿主升级后自动变成可执行表达式。编辑器须允许输入以该前缀开头的字面量；已有字符串保持字符串类型。

```json
{
  "$formula": {
    "lang": "aiws",
    "version": "1",
    "expr": "price * quantity"
  }
}
```

上例只说明预留值形状，不承诺表达式语言和函数已可执行。返回类型由字段或属性 Schema 声明；该声明与普通值使用相同的数据类型体系。

本版本读接口返回公式定义，UI 显示表达式及“未支持求值”的状态；复制、Fork、导出和再次导入必须无损保留。不能以空值、零或过期缓存冒充已求得的值。

后续增加公式时，需要另外冻结依赖寻址、求值语义版本、错误、循环策略和资源预算。Get 不隐式修改权威内容；需要共享保存的计算结果通过普通 Commit 物化，并登记定义与输入依赖。时间、随机值和网络内容不得作为隐藏输入。此处预留这些约束，不把尚未设计的求值规则提前写成已支持能力。

本版本的宏和 AI 任务仍可计算并提交普通数据；这类结果不等于启用了公式系统。
