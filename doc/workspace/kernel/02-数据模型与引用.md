## 身份、版本与规范引用

### 身份与位置分离

| 概念 | 语义 |
| --- | --- |
| Workspace ID、Entity ID | 持续编辑和引用的逻辑身份 |
| record_id、field_id、富文本块 ID | 原语内的稳定子项身份 |
| 名称、路径、显示序号 | 可变的发现与展示入口 |
| Content ID / ObjId | 某个不可变对象版本的身份 |
| URL | 访问位置或引用投影，不天然等于固定内容 |
| epoch、seq | 一段提交历史及其已接受位置 |
| CRDT lineage | 富文本等协作对象的因果历史身份 |
| Schema 版本 | 业务结构或富文本结构的解释规则 |

名称解析后，持久引用和重试使用稳定 ID，不再按当前同名对象重新选目标。对象删除后 ID 不分配给另一个逻辑对象；恢复原对象与新建同名对象是不同操作。表格排序、字段改名和 Block 移动不得改变引用目标。

资源目录成员是值型容器的命名键，属于上述规则的明确例外：成员重命名是删旧键、加新键，不具有记录式的稳定成员身份。需要独立协作身份时使用 Table record 或实体。

### 规范引用对象

规范引用包含 `zone?`、`workspace_id`、`entity_id`、`selector?`、`mode` 与 `version?`。文档内部引用省略当前 `zone` 和 `workspace_id`，以便工作区 Clone 后内部关系仍指向新文档；外部引用不自动转向副本。

| 版本选择 | 含义 | 固定版本身份 |
| --- | --- | --- |
| `live` | 解析逻辑对象或发布通道的当前值 | 不把某次解析结果误认为永久固定 |
| `fixed`，历史位置 | 固定到同一 Workspace 的历史版本 | `{ epoch, seq }`，必须对应已登记的 checkpoint、克隆或物化对象 |
| `fixed`，内容寻址 | 固定到不可变内容根或其路径 | `{ content_root, path? }`，适用于跨 Zone 和独立内容交换 |

`version` 是判别联合，两种固定身份不能作为任意可选字段混填。实体级内容版本可按 `(entity_id, content_rev)` 懒物化并缓存；创建 fixed 引用时必须建立相应保留承诺。

live 引用不携带 fixed 的 `version`。协议中的历史词汇如 follow、published_channel 只能作为明确映射到上述语义的入口表达，不再形成另一套版本模型。

固定身份、内容存在、内容被保留和当前调用者可读是四个独立判断。没有可读保留物时返回 `VERSION_NOT_RETAINED`，不能返回最新内容冒充旧版本。v1 在线库服务当前状态，不承诺任意 seq 的即时历史读取；以后可扩展有成本上限的 checkpoint 加日志重放。

### 选择器与读集合

操作与计算依赖使用有限的选择器目录，解析为版本格修订号或内容 token：

| 选择器 | 寻址范围 |
| --- | --- |
| `entity` | 整个实体 |
| `doc_key` | 一个顶层 payload key |
| `table_members` | 活记录集合，覆盖新增与删除 |
| `table_field` | 字段定义 |
| `table_field_type` | 字段类型 |
| `table_field_values` | 一列的值集合 |
| `table_record` | 一条记录 |
| `table_cell` | 指定记录和字段的数据格 |
| `table_view` | 保存的表格视图及其数据依赖 |
| `table_query` | 声明查询的投影及其依赖 |
| `tree_children` | 直接子项集合 |
| `tree_edge` | 父节点、顺序和 placement |
| `richtext_block` | 一个富文本块 |
| `folder_member` | 资源目录中的命名成员 |
| `entity_prop` | Block/container 的 `config`、`bindings`、`on` 中一个命名属性 |

读集合必须覆盖实际决策依赖。依赖“当前所有记录”时，除了已有记录的值，还要覆盖成员增删；依赖一整列时，可以使用字段值集合版本。视图与查询选择器按协议计算依赖 token，必要时同时记录细粒度读集合；不能只把任意查询名塞进 `expect`。新增选择器属于协议变更。

`A1:F20` 等界面范围须解析为稳定记录和字段 ID，并说明它是固定成员集合还是动态查询。排序、筛选或插入不能在没有声明动态语义的情况下改变已保存引用的目标。

### 实体名字与路径

除根之外每个实体都有 `name`，同一父节点下的活实体之间不重名。唯一性按命名空间判断：共享实体只和共享实体比较；个人或参与者范围的实体还和自己同一范围的实体比较，不和别人的个人实体比较。写入者读不到的同级实体不参与判断（权限需求 V4）：它的名字不会让写入报 `NAME_CONFLICT` 或被挤成 `-2`，于是不泄露它的存在；能同时读到两者的人，后一个按路径遮蔽规则从 `~<id>` 开始。

每个实体还记录创建者 `created_by`（权限需求 R6）：创建它的那次 Commit 按谁判定的主体——一般是写入者，Agent 未在工作区单独配置时是它的 owner，运行的结果是触发者。它不属于内容（不进内容对象和摘要），由部署保存；从模板、Clone、导入得到的实体记为建立这个工作区的人，覆盖式恢复保留原值，移动和改名不改变它。`@creator` 的权限条目按它判断。名字的字符规则：1–128 个字符，不含 `/` 和控制字符，不以 `~` 开头，不能是 `.` 或 `..`。

| 情况 | 名字 |
| --- | --- |
| 创建时给了名字 | 用给的名字；与同级相撞返回 `NAME_CONFLICT`。给的名字恰好等于标题生成的名字时按跟随处理 |
| 没给名字、实体有标题 | 跟随标题：Block、容器、Wish、控件定义等跟随 `title`，Record 跟随 `title` / `name` 属性，资源引用跟随 `title` / `file_name`；`/` 换成 `-`，截到 64 个字符 |
| 没给名字、没有标题 | 计数名字 `<前缀>-<n>`：Block 用视图类型（`text-3`），容器用 kind（`group-2`），其余用类型短名（`table-1`、`doc-1`）；`n` 取同级同前缀（含已删除）的最大序号加一 |
| 跟随的名字相撞 | 加 `-2`、`-3`……；创建、移动、恢复时都不因此失败 |

是否跟随不单独存储：名字仍等于规则给出的值就算跟随，标题变化时在同一个 Commit 里随之改名；手工改成别的名字后不再跟随，`entity.rename { name: null }` 把名字交还给规则。名字由规划器在提交时分配并写进规范化操作，重放、副本和服务端得到同一个名字；离线副本先按同一份代码预测，以服务端接受的结果为准。存储 schema 6 起名字必填：打开 schema 5 的存储时按树的顺序给无名实体回填（不经 Commit、不推进版本号），导入旧包在内容根校验通过后同样回填。

路径是从根开始的各级名字，如 `/data/销售`、`/surfaces/看板/text-3`；第一段可以写成 `~<entity_id>`，表示从该实体往下。服务方法、对象入口、阶段工具、CLI 和 HTML 宿主共用这一套规则和实现（[core/src/path.rs](../../../src/frame/aiworkspace/core/src/path.rs)）：

- 逐段解析，每一段都要求调用者可读；读不到和不存在同样返回 `NOT_FOUND`。
- 打印路径时不写出调用者读不到的祖先，路径从其下最高的可读实体的 `~<id>` 开始。
- 同一名字下同时有共享实体和调用者自己的个人实体时，名字指向共享实体，被遮住的实体用 `~<id>` 访问，列举时标出。
- 路径是发现入口。改名、移动以及跟随标题时改标题都会改变路径；持久引用、重试和写入使用 `entity_id`。按名称或标题查找可能得到多个候选，全部返回，不替调用者选择。

Surface 页面地址、发布名和 Workspace 名字是各自的命名空间，见下两节；它们不并入实体路径。

### 名称与 URL 投影

Workspace 页面使用独立源：

```text
https://aiws-<id>.<zonehost>/<workspace slug>/<surface slug>?id=<surface id>
```

主机标签使用适合 DNS 的 Workspace 标识。路径名用于可读性，`id` 决定 Surface；无 `id` 的地址按名称解析后重定向到规范地址。Surface 名不维护历史别名，携带 ID 的链接在改名后仍可定位。发布名属于独立命名空间，其别名不能与 Surface 名混用。

查询串还可以指定 Surface 内的目标：`block=<Block ID>` 定位 Block；`record=<record_id>` 定位该 Block 显示的一条记录，数据控件翻到所在的日期或列并选中它；`occ=<原始开始>` 再定位重复事件的一次发生项，发生项身份取原始开始时间，与改期后的计划时刻分开；`page=control` 把该控件作为[单控件页](06-布局模式与用户状态.md#可定制工具栏与-app-模式)打开。记录选择器只用于界面定位，持久引用仍用 `table_record` 选择器。

规范引用与地址转换不得丢失对象和版本语义。固定引用的 URL 不能在转换后退化为 live；后续请求不通过名字复用改变重试目标。

### Workspace 的唯一名字

Workspace 可以有一个名字（`^[a-z0-9][a-z0-9._-]{0,63}$`），只能在 `ws.create { name }` 或 `ws.ensure { name }` 新建时确定，之后不能修改。名字在同一所有者的 Workspace 中唯一，与可改的标题无关；`ws.list`、`ws.get_info` 返回它。

| 操作 | 规则 |
| --- | --- |
| `ws.ensure { name, title? }` | 返回调用者该名字的 Workspace，没有就新建（结果带 `created`）；并发调用只建出一个 |
| `ws.create { name }` | 名字已被调用者使用时返回 `NAME_CONFLICT`，并给出已有的 `workspace_id` |
| 删除 | 释放名字，再次 `ws.ensure` 会新建 |
| 工作区 Clone、新建方式的导入、放映克隆 | 不带名字；覆盖已有 Workspace 的恢复保留其名字 |

名字让 Agent 和命令找到约定的 Workspace。例如私人日程 Workspace 名为 `schedule`，其中待办表、日程表使用固定实体 ID `todo`、`calendar`。

## 有限原语与业务 Schema

### 冻结的协作原语

数据的类型、来源和求值方式是三个维度。外部 Source 和公式不与 Table、RichText 等并列成为新的存储原语。

| 原语 | 原子修改与协作单位 | 关键约束 |
| --- | --- | --- |
| 树节点与树边 | 稳定实体 ID、父子关系、`order_key`、placement | 结构关系明确；几何配置由业务 Schema 解释 |
| 按 key 分格的对象 | 默认每个顶层 key 独立版本；key 内值整体替换 | 仅正式定义的命名属性可细分版本格，不提供任意路径修改 |
| Table | 稳定字段、记录、数据格及结构版本 | 同列类型与字段约束；数据格和结构修改按各自版本条件处理 |
| RichText | 专用结构与 CRDT 更新 | 保留协作 lineage；节点和标记集合按富文本 Schema 版本演进 |
| AssetRef | 已校验不可变资源的引用整体替换 | 文件正文不在内核做内容级合并 |
| 资源目录 `dir` | 成员名到文件/子目录的映射；亦可整体替换 | 与 DirObject 对齐，无序、名称唯一、可确定物化 |

基础值域、空值、数字精度、最大大小与嵌套深度由对应值 Schema 和 Limits 明确定义，未知或越界值必须返回明确错误。JSON 只是编码，不能根据 JSON 的外观推断协作语义。

v1 不新增按任意数组下标协作的列表原语，不提供通用 JSON Patch，不支持自由表格。需要独立并行编辑的集合优先建成 Table records；需要树关系时使用子实体。自由表格未来通过 Table 的列类型或配置显式演进，不另造一套提交模型。

已定义的有限例外是 `entity.set_props`：Block/container 的 `config`、`bindings`、`on` 可按命名属性修改，每个属性有独立版本格和 `expect`。整体替换这些 key 时，同时推进受影响属性的版本，确保此前的属性条件失效。这不授予任意深层 JSON 路径修改能力；属性名、数量、大小与实体适用范围仍受协议限制。

### Table 与 RichText

Table 字段使用稳定 ID；改名不等于换字段，删除或改变含义必须有明确结构操作和迁移。内核强制字段类型、选项、`required`、`nullable` 和 `unique` 等约束。`unique` 涉及跨记录检查，不能因“只做字段约束”而被取消。

title 字段的类型及不可删除规则、record body 与同表富文本的关系及独占规则属于原语结构不变量。收紧约束可以扫描现有记录，但扫描成本必须受准入预算限制。

字段类型 `json` 用于业务扩展字段。它的值 Schema：一个 JSON 对象（字段可空时也可为 null），整体替换，不提供路径修改，同一数据格的并发修改按版本条件冲突；规范化编码不超过 16 KiB，嵌套不超过 8 层（对象本身算一层），字符串受文本长度上限约束；不能保存公式，`$formula` 对象被拒绝。`json` 字段不能排序、分组或设为 `unique`，筛选只支持 `is_empty` / `is_not_empty`，与其他类型之间不能迁移。

表格可以有按提交者归属的记录：一个 `text` 字段声明 `submitter: true`（每表至多一个，只能在表中没有活记录时设置或取消）。服务在插入时用调用者主体填写它，客户端为它写值一律被拒；撤销、导入和重放保留已记录的值。每个提交者至多有一条活记录，再次插入返回 `SUBMITTER_EXISTS` 并给出已有记录的 ID。谁可以改、删哪条记录见[权限](11-权限资源与保留.md#稳定目标与继承)。

`multi_select` 字段可以声明 `max_items`（1–1000），一个值含有更多选项时由内核拒绝；设置或调低它与收紧 `required` 一样扫描现有记录。表视图按 `multi_select` 字段分组时，一条记录在它的每个选项下各计一次（视图编译出的分组 SQL 与求值器一致）；按计数排列、只取前 N 组由读的一方在 SQL 里写（`ORDER BY count(*) DESC LIMIT N`）。

RichText 不是普通字符串；转换为纯文本是投影，不替代结构化正文。每个实体记录其富文本 Schema 版本。内容相同不代表 CRDT 历史相同，只有协作快照承诺可续接对应历史。

### 资源目录与 DirObject

资源目录以 DirObject 为标准交换形态。成员按名称唯一定位，指向 FileObject 或子 DirObject；顺序由业务 Schema 另外表达。v1 标准目录不直接保存任意外部 URL 成员，外部文件先物化为资源，外部 DirObject 通过 Source 接入。

树中的 `container(kind=folder)` 用于组织任意实体，具有顺序；资源目录用于组织文件和子目录。两者不得因为都叫 Folder 而混用操作或保留语义。

成员修改按名称形成版本条件；需要配套切换时，先准备完整的新 DirObject，再原子替换目录引用。读取者先解析确定的目录根，再读成员，不能逐个请求 live 入口来冒充一致读取。

物化 FileObject/DirObject 时固定时间字段，并规范化名称、成员与统计信息；同一规范输入产生相同 ObjId。若以后内部目录允许标准 DirObject 无法表示的成员，必须显式转换、拒绝或标注依赖缺失，不能悄悄改变 DirObject 语义。

### 业务 Schema 与未知类型

实体记录业务 Schema 标识与版本。同一标识和版本的定义不可静默变化。Block、Viewport、连接线、许愿格、演示路径、Scene 等均由原语与业务 Schema 组合。

采用“原语校验 + 业务 Schema 校验”分层；内置业务校验可以先由代码实现，再逐步声明化。新提交执行适用的业务校验；已接受日志的应用不再执行新版本业务校验器。

内置业务校验按 `schema_id` 登记。当前内置两种标准业务表：`buckyos.todo@1`（待办）和 `buckyos.calendar@1`（日程），字段与规则见服务的 [standard-tables.md](../../../src/frame/aiworkspace/schemas/standard-tables.md)。表实体带上其中一个 `schema_id` 即选用对应校验：

| 范围 | 规则 |
| --- | --- |
| 建表 | 必须具备全部标准字段，ID 和类型固定；其他字段可以自由增加 |
| 改结构 | 标准字段不能删除，也不能改类型 |
| 记录 | 必填字段、定时与全天事件的字段互斥、结束不早于开始、排序键格式、扩展字段 `ext` 中已约定键的形状（包括重复规则子集）；未约定的键原样保留 |
| 时机 | 在整个 Commit 末尾对动过的记录按最终值判断一次，多步改动及其撤销不会在中间状态被误拒 |

这些是 schema 类校验，只在准入时运行，重放和导入不运行。

未知业务类型必须以不透明对象保留并参与同步；客户端缺少 Renderer 时退回属性、结构或文件元数据视图。缺少编辑能力不能成为丢弃数据的理由。

v1 不提供任意用户自定义的跨字段、跨记录不变量执行器。例如 `min <= max` 不能仅靠分别合并两个字段保证。需要权威保证时，应限制为受信写入路径，结合写锁或覆盖真实依赖的版本条件，并在该路径上完成校验。版本条件只能证明输入未变化，不能证明调用者做过正确的业务判断。

## 引用、所有权、复制与撤销

### 引用目录

每种引用必须定义版本选择、完整性、保留和新鲜度作用。`live/fixed` 与 `strong/weak` 是不同维度；引用不是权限凭证。

| 默认模式与完整性 | 引用种类 |
| --- | --- |
| live / strong | `bind`、`owns`、`embed`、`value`、`body`、`def`、`member`、`def_source`、`def_dep` |
| fixed / strong | `asset` |
| live / weak | `object_link`、`input`、`produced`、`anchor`、`connector_endpoint`、`show_target`、`show_surface`、`source` |
| fixed / weak | `derived` |

这是同一 Workspace 内的引用目录；跨 Workspace 按下述可失效规则处理。目录项的具体 selector、保留和新鲜度参与方式由对应 Schema 定义，新增引用种类必须显式纳入协议。

同一 Workspace 内，数据绑定、结构嵌入等强引用由事务维护；目标删除前要解除或替换依赖。普通对象链接、评论锚点、来源与派生关系可以失效，失效时保留可解释的目标信息，不自动移到相近对象。

富文本 `object_link` 是可失效链接，不得错误索引成阻止删除的 embed。跨 Workspace 引用一律允许失效，不隐含分布式引用完整性；必要可用性通过本地物化和独立保留建立。

### Block 的绑定与自有内容

绑定不表示拥有数据。归属按创建与显式转换语义决定，不以当前名称、位置或“恰好只有一个视图”推断。

| 情形 | 规则 |
| --- | --- |
| 数据模式创建的数据 | 共享数据，不属于某个 Block，不随 Block 删除 |
| 随 Block 在画布上创建的数据 | Block 自有数据，具有可维护的所有权关系 |
| Block 显式声明非自有绑定 | 始终只引用数据 |
| 同一画布内复制 Block | 默认克隆自有数据；共享或非自有数据仍复制引用 |
| 跨画布复制 Block | 默认引用同一数据源；这里的画布均在同一 Workspace 内 |
| 复制整张画布 | 克隆自有数据，保留共享数据引用 |
| 自有数据提升为共享 | 显式 pin/归属转换，解除随 Block 回收的关系 |

命名绑定（Cell、组合控件、数据控件的 `bindings`）的值是一个引用 `{ entity_id, selector? }`；控件声明为 `many` 的绑定是引用的列表 `[{ entity_id }, …]`（最多 32 项，不能重复，空列表等于不绑），每一项各有一条 `bind` 边。大纲里同样输出 id 或 id 列表。控件（数据控件、组合控件、扩展 Cell）放置时 on_bind 新建的数据，按下表“随 Block 在画布上创建的数据”归它所有；复制时列表逐项按自有 / 共享处理。

`owns` 与 `bind` 分开表达所有权和绑定。自有数据被跨画布引用后，删除原 Block 不能删掉仍被使用的数据；删除最后一个使用它的 Block 时才可按归属级联。实现通过历史 owns 等信息持续保存归属，不能在第一个 owns 边消失时丢失后续判断依据。级联仍须通过其他强引用、权限和预算检查；不能满足时拒绝整个事务，不无条件删除。pin 必须解除全部相关所有权关系，使数据成为共享数据。

整组复制使用统一 ID 映射，保持组内原有共享关系。跨 Workspace 粘贴不由上述规则自动推导，必须显式选择引用、物化导入或工作区 Clone。

级联删除由准入规划展开为显式日志操作；重放不能重新按当前引用数计算。永久物理回收另受历史、快照和运行保留约束。

### 撤销与重做

私有未提交操作可在本地回退。共享 Undo 是当前状态上的新补偿提交，继续检查授权、版本、引用和约束，不能恢复整份旧快照覆盖其他人的后续编辑。

需要部分撤销时，先返回可执行范围、冲突及 `plan_digest`，调用方确认该确定计划后执行。目标或计划变化必须重新确认。缺少逆操作、历史资源已回收或权限失效时明确失败。

不能承诺所有命令可撤销：富文本 `apply_update` 无可用逆操作的提交应返回 `NOT_UNDOABLE`；过大迁移或外部操作也按操作协议声明限制。重做同样是受准入控制的新操作。

## 公共属性、纯文本呈现与 SQL 逻辑表

本节规定统一读取看到的实体：所有类型共有的属性、每种类型的纯文本呈现，以及表在 SQL 查询里的形态。它们都是读取时由原生结构派生的，不另存一份状态，也不替代类型专用的精确读写。字段与接口细节见[服务 README](../../../src/frame/aiworkspace/README.md)“Finding, reading and querying”，设计取值与理由见 [AIWS 核心 API 设计](../../../notepads/aiws-core-api-design.md)。

### 公共属性

`doc.read { as: "meta" }` 给出所有实体共有的属性，读取时不扫描正文或表的记录：

| 属性组 | 内容 |
| --- | --- |
| 身份 | 实体 ID、规范引用、对象 URL |
| 名字与位置 | `name` 及是否跟随、标题、类型与 kind、业务 Schema、范围（共享、个人、参与者、演示者）、父实体、当前路径、可读子项数 |
| 版本 | 各版本格的修订号（内容、元信息、生命周期、结构）、epoch、head |
| 正文 | `body` 的状态、格式、格式版本和 `etag`；资源的字节数；不知道的数量给空值，不为填它扫描 |
| 数据来源 | 数据实体才有：`mode` 为 `local`、`synced`（带 Source 的本地副本）或 `url_query`（行在远端的 URL 表），`write` 为 `edit`、`refresh` 或 `none`，以及来源和生成记录的摘要；只报告当前真实存在的状态 |
| 显示关系 | Block 显示的数据（读不到时只给 ID 并标明不可用）；表视图另给编译出的 SQL；控件给各绑定；实例给它的定义 |
| 能力 | 调用者当前的能力（按 ACL 计算，与其他入口相同）；该类型接受的 Commit 操作（[operations.json](../../../src/frame/aiworkspace/schemas/operations.json) 的 `types` 列） |

公共属性是只读的派生视图。可改的部分只经已有操作修改：改名是 `entity.rename`，移动是 `tree.move`，标题等键是 `entity.set_keys`，Block 和容器的配置属性是 `entity.set_props`；ID、版本、能力和同步状态不接受写入。能力和操作列表只说明 ACL 和类型允许什么，数据能不能被编辑还要看 `data.write`：本地副本只由 Source 的刷新写入，URL 表没有本地行，对它们的数据写入返回 `SOURCE_READ_ONLY`。

### 纯文本呈现

`body` 是实体在纯文本环境里的呈现：Agent 读取、文本查询匹配、以后的读屏支持用的是同一份文本。它是可重建的投影，原生结构仍是真相源，`content` 的原生含义不变。

| 实体 | 呈现 |
| --- | --- |
| RichText | Markdown，一个顶层块一个部分 |
| Table（本地行） | CSV：表头是 `_id` 加各活字段名，之后一条记录一行，按 `record_id` 排序 |
| URL 表 | 表定义、字段和来源说明，标明行在远端未物化（`state: definition`） |
| Record、批注 | 每个属性一行；批注写明目标路径、引文和文本 |
| 文件夹、目录 | 每个可读子项或成员一行 |
| 画布、分组 | 标题，之后按阅读顺序每个 Block 一段 |
| Block | 标题和配置里的文字，它显示的数据写成路径（表视图另写视图条件和 SQL）；不内联所显示数据的内容 |
| 资源引用 | 文件名、媒体类型、大小；不超过 256 KiB 的文本文件内联原文，其余 `unavailable` |
| Wish、控件定义 | 任务说明、输入输出路径、状态；控件的自描述、参数和绑定 |
| 未知、降级、视口、演示路径等 | 原生 payload 的规范 JSON，标为 `fallback` |

- **显示值。** 类型化的值按显示形式写出：select 写选项标签，多选用 `; ` 连接，引用写目标标题和路径，decimal 写存储的十进制串，货币写 `<币种> <金额>`，日期写 ISO 串，公式和空值为空。因此选项改名或被引用实体改名会改变 `body`，而记录版本不变。
- **版本。** `etag` 由格式版本和所依赖实体的版本算出（表含字段定义与被引用目标，画布和文件夹含子项）。投影规则变化时提升格式版本（`BODY_FORMAT_VERSION`，当前 1），并重建 Desktop 的 WASM。
- **分段。** 正文由部分顺序组成，每个部分对应一个选择器（`table_record`、`richtext_block`、`folder_member`、`doc_key`）或一个子实体。分页以部分为单位，只有单个部分超过一页时才在字符边界切开并标出；续读游标绑定 `etag`，文本变化后旧游标返回 `SNAPSHOT_EXPIRED`，不拼接不同版本。对正在变化的大表做一致的完整读取，先建保留点再读固定版本（首批 `body` 只读当前版本）。
- **定位。** 文本查询命中给出所在部分的选择器（表精确到 `table_cell`）。文本里的偏移只在该 `etag` 内有效，不能作为修改的持久身份；写入使用选择器和实体 ID。CSV 是数据表示，不授予整表覆盖写入。

### 表的 SQL 逻辑表

`doc.query { sql }` 对表执行单条 SELECT。记录仍存放在共用的 `table_records` 里，每条记录的字段值是一个 JSON；服务为语句提到的、调用者可读且有本地行的表按需建立只读的逻辑表（查询连接里的临时视图），不改存储结构，也不为每张表建物理表。

- **表名。** 表实体的路径（`"/data/销售"`）、`"~<entity_id>"` 或实体 ID；阶段工具里还可以用输入句柄。
- **列。** 每个活字段两列：显示列 `"<字段名>"`，取值与 `body` 的显示形式一致（select 为标签，decimal 和货币金额为 REAL，引用为路径，公式和类型不符的值为 NULL）；原生列 `"<字段名>#raw"` 给存储值（选项 ID、精确的十进制串、引用对象）。货币另有 `#currency` 列。系统列 `_id`、`_rev`、`_body`（记录正文的路径）、`_record`（`doc.read` 的记录形式）。只含未删除的记录和字段。
- **语义。** 手写 SQL 的比较、排序和空值按 SQLite 的规则。表视图 Block 保存的定义（筛选、排序、分组、手工排序、显示字段）格式不变，由 core 编译成 SQL，结果与 core 的求值器逐行一致；持有离线副本的 Desktop 仍用求值器，副本上不执行 SQL。
- **权限与范围。** 沿用实体级 ACL：能引用的表就是调用者能读的表，没有行列级权限；不可读和不存在同样返回 `NOT_FOUND`。只读连接加 authorizer 白名单，内核表、直接读 `table_records`、写入、`ATTACH`、`PRAGMA` 和递归 CTE 都被拒绝。结果附上实际读到的表及其内容版本。
- **成本。** 时间、输出行数和字节数都有上限，超出返回结构化错误或明确的截断标记，不静默缩小数据范围；数值和 JOIN 写法见[接口治理与验收](12-接口治理与验收.md#查询预算与性能验收)。
- **不可用的情况。** URL 表没有本地行，返回 `NOT_MATERIALIZED`；首批只对当前版本和阶段快照执行，固定版本返回 `UNSUPPORTED_VERSION`。
