## Block 与 Renderer 宿主

Block 是工作区内可定位、绑定、呈现和操作的界面实例。Renderer 决定一个 Block 如何呈现；宿主提供数据、模式、几何、权限、状态和命令能力。内置代码、声明式定义与 HTML 实现遵循同一宿主契约，HTML 是实现方式之一。

### 定义、实例与公开接口

Block 定义包含稳定类型身份、版本、接受的数据类型、公开属性、命名绑定、呈现能力及宿主 API 要求。Block 实例保存定义引用、属性覆盖、绑定、布局与文档关系，不复制一套独立的业务数据模型。

| 契约 | 冻结要求 |
| --- | --- |
| 身份与版本 | 类型身份、发布版本、工作区定义修订和所需宿主 API 分别表达，不以标题作为身份 |
| 属性 | 声明类型、默认值、校验与编辑方式；实例覆盖与定义默认值分开保存 |
| 数据绑定 | 使用命名绑定，声明接受类型、必填性及读写意图；运行时再按当前权限取得有效能力 |
| 呈现入口 | 至少有安全的静态表现；可提供简化、查看、编辑、属性面板和打印表现 |
| 几何能力 | 声明默认/最小尺寸、缩放或重排方式、形状与连接锚点；父容器决定最终布局 |
| 生命周期 | 接收挂载、输入变化、尺寸/模式变化、暂停及卸载；释放订阅、计时器和执行资源 |
| 交互能力 | 动作、事件、快捷键和工具栏使用统一事件与动作模型，不直接调用宿主内部组件 |
| 成本声明 | 声明编辑器、HTML、媒体等运行成本，由宿主决定激活、降级与挂载数量 |

实例化应形成一次可校验的操作组，原子创建必要数据、Block 与绑定。新建实例不等于执行其中的宏或业务动作。

同一份数据可由多个 Block 呈现。颜色、标题覆盖、图表参数等展现配置保存在实例或共享附加层，不污染被绑定的数据字段。

### 呈现、编辑与测量

`Static` 是无业务副作用的静态表现，不启动许愿格、宏或媒体播放；复杂 HTML 可以使用对应版本的静态快照。没有快照时显示可解释占位，不能为取得预览而自动运行未知代码。

`Simplified` 服务于缩略、低缩放或预算不足场景；`View` 提供查看时的可交互表现；`Editor` 提供内容编辑；`Inspector` 编辑实例属性和绑定。缺少某入口时回退到静态表现，不能继承另一模式的写入行为。

宿主传入经过授权的数据投影、数据可用性、实际能力、只读原因、尺寸、缩放及当前模式。Renderer 不直接持有数据库连接，也不能从“处于编辑模式”推导出写权限。

宿主输入还包括可信时间。服务提供 `ws.time`（返回 `server_ms`），`doc.wait_changes` 的返回也带 `server_ms`；Desktop 取三次 `ws.time` 中往返最短的一次，按一半往返时间估计与本机时钟的偏差，每 5 分钟重新校准。按共享时刻计时或播放的表现（播出位置、限时内容的剩余时间、HTML 的 `aiws.serverNow()`、动作里的 `{{now}}`）都用这个时钟，不用设备时钟。

尺寸测量必须有明确输入和适用范围。可测量文本在宽度约束内报告固有尺寸；不能可靠测量的媒体、HTML 或专用 Block 使用明确尺寸或声明的宽高比。布局不得依赖无限次 DOM 试探，也不得在测量时产生共享写入。

渲染和测量结果属于当前布局计算，用户显式调整的尺寸属于文档。测量完成不自动把每个客户端算出的像素值写回共享状态。

### UI State 与写入通道

| 状态 | 所属位置 |
| --- | --- |
| 默认样式、实例属性、绑定、保存的展现配置 | 共享文档，经过 Commit |
| 用户列宽、个人折叠偏好、尚未提交的表单草稿 | Workspace + User + Block 的私有状态 |
| hover、按下、焦点、拖动预览、当前选区 | Session 临时状态 |
| 任务进度、候选结果、错误与取消状态 | 运行记录，不混入 Block 正文 |

共享编辑通过 Command Bridge 提交；私有持久状态通过 User State 接口保存；纯交互状态留在当前会话。相同的“折叠”或“选项”可以按用途进入不同状态域，但其定义必须明确，不能由组件临时决定。

准备计划、显示预览和客户端校验都不免除服务端准入。编辑器被暂停或卸载前应保留尚未提交的输入，卸载不能等价于丢弃草稿。

### HTML、版本与回退

HTML Renderer 运行在页面内的同源 iframe 中。iframe 负责样式隔离、崩溃隔离和挂载管理，不是安全边界：HTML 代码与页面脚本同权，可以用当前用户的会话访问该用户有权访问的内容。宿主经 `window.aiws` 提供带版本的 API，写入经 Command Bridge 走正常的权限、锁、撤销和保存状态；这保证规范的写入路径，但不限制代码的能力。

信任在引入时决定。内置 Block 随系统发行，视为可信。扩展定义在 Workspace 内 build 或 import 需要所在文件夹的 `structure` 或定义的 `update` 权限；执行这一操作就是为全体协作者引入这段代码，信任根是 Workspace Owner。

HTML 代码不随打开文档自动运行：编辑和查看时显示静态快照或占位，运行态下由用户点击激活，并受挂载预算限制；在 Block 内出现第一次真实的指针或按键操作之前，`emit` 被拒绝。调用超时、崩溃或无响应时回退到静态快照，不影响其他 Block。重新 build 后旧运行时被卸载，迟到的回调被丢弃；禁用某个 Renderer 后不得继续执行其回调。手机上同样可以点按激活 HTML，组合控件的子 Block 照常交互；访客（guest）和回放始终不运行。

任务程序 Worker 的信任前提不同：生成程序由 AI 在运行中产生，未经人工引入就会执行，因此必须按[本地生成程序的隔离](08-任务执行与AI.md#本地生成程序的隔离)隔离。HTML Renderer 不要求同等隔离；两类宿主分别控制生命周期、预算和超时。

宿主 API 采用明确版本。新宿主维持已支持旧 API 的语义；定义升级不能静默改变已有实例的属性、绑定或用户内容。兼容升级保留实例覆盖；不兼容升级通过显式迁移，失败保留最后可用修订。

当前宿主运行 HTML host API 2、3、4，新版本只增加成员。host API 4（需要 `manifest_version` 4）增加：

| 成员 | 作用 |
| --- | --- |
| `aiws.onConfig(cb)` | 实例属性变化时推给运行中的 HTML，同时刷新 `aiws.context.config`；生命周期中的“输入变化”包括实例属性 |
| `aiws.serverNow()` | 上述可信时间 |
| `aiws.userState.get/set` | 本人私有状态，键位于 `block:<entity_id>/` 命名空间，与控件的个人视图同一条通道 |
| `aiws.mediaUrl(binding, member?)` | 绑定的音视频资产（或绑定目录的一个成员）可 Range 播放的流式地址（`asset.stream_url`），不必整块读成字节 |
| `aiws.on('action:<id>', …)` | 接收宿主转来的声明动作（见下节的 `forward`） |

用到全部这些成员的例子是 [control-examples](../control-examples/README.md) 的“一起听”。

定义、运行资源及必要静态快照随工作区保存、Fork 和导出。缺失定义、未知版本、不支持的数据类型、依赖不可用和扩展被禁用应分别解释；通用只读视图保留原始数据与引用，不能靠删除未知内容完成打开。

### 扩展声明的动作

扩展的 `component.json`（`manifest_version` 4）可以声明至多 16 个 `actions: [{ id, title, icon?, modes?, needs?, run }]`。宿主把它们放在实例的近身工具栏上：只在 `modes`（`edit` / `view`，缺省两者）列出的模式中出现，只对具备 `needs` 所列能力的人出现；查看模式下同样出现，HTML 控件尚未激活时也可以使用。组合定义的动作随大纲投影为 `def_actions`。

`run` 是一个或至多 4 个处理：

| 处理 | 效果 |
| --- | --- |
| `write`、`wish`、`open`、`notify` | 与实例事件的同名处理相同 |
| `config` | 写本实例自己的属性：可撤销的 `entity.set_props`，每个属性带版本条件 |
| `forward` | 作为请求 `action:<id>` 转给运行中的 HTML；控件未运行时宿主先启动它 |

字符串可以使用 `{{now}}`（可信时间）和 `{{config.<key>}}`（实例值，未设置时取定义默认值）。动作是点击者本人的操作，按其权限执行；`config` 与 `write` 产生的操作合成一个 Commit。

## Block-control 与组合模型

Block 负责一个节点的表现；Block-control 负责一组真实子 Block 的组织、布局、连接和容器级操作。是否需要编排子 Block 是两者的分界，不按视觉复杂程度区分。

control 的子节点有两类：slot 中的用户内容是持久化的真实 Block；投影子节点由控件按数据项（记录、目录成员、观众）实例化模板得到，不持久化。两者一起参与布局和绘制，只有前者是文档中的实体。

组合控件使用通用容器承载定义与实例。客户卡片、按钮组、脑图、画布 Block 看板等组合不因此成为新的数据原语；各节点继续使用 Block 的选择、编辑、权限、批注和连接能力。

“看板”有两种，按卡片是什么区分，不能混用：

| 看板 | 卡片 | 拖动的含义 |
| --- | --- | --- |
| 记录投影看板（官方待办的看板模式） | 一张表的记录投影出的卡片，不是 Block；列是 `status` 字段的选项 | 改记录的 `status` 和排序字段，一个 Commit |
| 画布 Block 看板（组合控件） | slot 里的真实 Block，可以是任意 Block | 树操作：移动、换 slot、改顺序 |

前者的卡片随记录增删，Agent 只写表；后者的每张卡片是一个实体，具备 Block 的全部能力（各自绑数据、连接线），但增删卡片要改 Block 树。

### 组合定义

| 内容 | 契约 |
| --- | --- |
| 公开属性 | 声明类型、默认值及到内部表现的映射 |
| 命名绑定 | 将外部数据映射到明确的子 Block 输入；不得通过任意查找兄弟节点建立隐含绑定 |
| 内容 slots | 声明名称、接受的节点类型、数量规则、布局角色及默认内容 |
| 模板外观 | 由容器外观层绘制边框、背景、装饰和隐式边，不冒充用户内容实体 |
| 布局 | 指定受支持算法、输入与可自动计算的几何分量 |
| 动作与事件 | 暴露统一模型中的接口；内部转发须有明确目标与参数 |
| 依赖 | 固定所引用定义与实现资源的版本闭包，拒绝未定义的循环依赖 |

slot 中的用户内容是真实 Block，具有稳定身份。修改控件背景、默认样式或算法不得重建这些节点；移除 slot、改变必填属性或破坏绑定的更新必须显式迁移。

定义只保存可复用结构与初始化约定。实例保存属性覆盖、命名绑定和实际子节点；用户内容不回写定义，不因另一个实例编辑而改变。

### 投影子节点

投影子节点由模板实例化。模板是一棵由 `label`、`shape`（SVG 图形）、`asset`（媒体）节点组成的小树：每个节点有模板内唯一的 `id`、相对数据项方框的 `box` 和 `config`，可带 `when`（条件显示）、`role`（按下时对手势的含义）和 `edit`（就地编辑写入的字段）。字符串中的 `{{item.<field>}}`、`{{config.<key>}}`、`{{viewer.<key>}}` 在实例化时代入；整串恰好是一个占位符时保留值的类型。

| 约定 | 规则 |
| --- | --- |
| 持久化 | 不持久化。Agent 增删记录无需同步建 Block，也不形成另一份业务数据 |
| 身份 | 由控件、模板节点和数据项推导：`<控件>~<节点>~<数据项>`；重复事件的数据项是 `<记录>@<原始开始>`，组合控件的投影是 `<控件>.<投影名>~<节点>~<数据项>`。刷新、重排之间保持稳定 |
| 寻址 | 选中、批注、复制链接都落到数据项对应的记录，批注锚到 `table_record` 选择器 |
| 编辑 | 在投影出的 label 上编辑就是改那条记录的字段，经正常 Commit |
| 成本 | 只实例化可见范围内的数据项；label、svg 走轻量绘制，不占编辑器或 HTML 的挂载额度 |

投影由读取方计算，不写回：查询结果、重复事件在可见范围内的发生项、计数排名都是派生显示。

### 数据控件：按数据定位的布局、手势与弹层

官方待办（`todo`）和日历（`calendar`）是数据控件，其容器 kind 登记在控件共享常量的 `data_controls` 中。它们把所绑定表格的记录全部作为投影子节点显示，自身不收任何子 Block；`layout` 隐含为 `{ mode: "data" }`，尺寸是用户设定的数值，不能为 `"auto"`；`bindings` 按 Cell 绑定的规则校验。随控件在画布上同一次创建的表归控件所有（`owns`），复制与删除按[数据模型](02-数据模型与引用.md#block-的绑定与自有内容)的自有数据规则处理。

布局算法随宿主发布，只读模板实例、字段值和尺寸测量，只产生位置，不提交数据：

| 算法 | 位置由什么决定 | 使用者 |
| --- | --- | --- |
| `list` | 排序字段；拖动时显示插入位置 | 待办列表 |
| `columns` | 选项字段决定列，列内按排序字段；列可折叠 | 待办看板 |
| `month` | 7 列日期网格；跨天事件画成横条，按周分泳道，放不下时显示“+N 更多” | 日历月视图 |
| `time_grid` | 纵向时间轴，按开始和结束定位；重叠事件并排、向右伸展 | 日历周、日视图 |
| `agenda` | 按日期分组的列表 | 日历日程视图 |

手势映射到数据写入。鼠标移动 4 px 后开始拖动；触摸长按（420 ms）后才拖动，未长按时照常滚动，并另有“移到…”菜单；Esc 或指针取消时什么都不写。拖动中只改本机预览（Session 状态），松手后把相关字段作为一个 Commit 提交，并立即以本地叠加显示结果；被拒或冲突时回到服务端的值并说明原因；提交进入撤销栈。重复事件提交前先询问“仅此一次 / 此后全部 / 全部”。

控件弹层锚定在投影节点上，用于事件详情、快速新建、“+N 更多”的当天列表、重复设置和选日期。它按屏幕坐标绘制，不随画布缩放，手机上改为底部抽屉；内容是宿主的记录表单和标准字段编辑器，不用 Block 拼装。

这些能力目前由代码注册的两个数据控件使用。组合定义可以声明式地使用其中的投影（见下节）；看板的分列、时间网格、拖动写入和弹层仍只属于宿主实现。

### 组合定义的投影、媒体与可见性

`composition.json` 自 `manifest_version` 4 起可以声明以下内容，全部由宿主执行，组合控件仍不运行代码：

| 声明 | 契约 |
| --- | --- |
| `projections { <名字>: { source, mark?, template, layout, placement?, max_items? } }` | 至多 8 个。`source.kind`：`records`（绑定表的记录）、`members`（绑定目录的成员：名称、`object_id`、媒体类型、大小）、`counts`（绑定表中一个列表字段的元素计数，多者在前，select 的元素按选项名对应；`of` 按键连接另一个投影的数据项，同票按该投影的顺序；`top` 取前 N）、`viewer`（当前观众：主体、首次打开时间、剩余时间）。`mark { binding, field, as }` 在观众本人提交的记录列出该数据项时把 `item.<as>` 置为真。模板节点只能是 `label`、`shape`、`asset`；`layout` 是 `list` 或 `grid`；投影区按 `placement`（`top` / `stack` / `bottom`）像 slot 一样排进组合布局；`max_items`（1–1000）限制排出的数量 |
| `media { slot, anchor, loop? }` | 该 slot 里的媒体 Block 按配置项 `anchor` 的值 `{ pos_ms, at_ms, playing }` 播放：服务端时间 `at_ms` 时位于 `pos_ms`，每个观众按可信时间计算当前位置，经流式地址按 Range 播放，不需要激活。观众本机的暂停、静音和“回到直播”只影响本机；播完停在末帧，`loop` 指向的配置项为真时循环。slot 为空时，同时有 `update` 和 `structure` 的人可以从系统文件选择器（先列 Zone 中的文件）选视频或音频 |
| slot 的 `visible { from: "first_open", for_ms }` | 按观众求值的呈现规则，见[slot 对单个观众的可见性](06-布局模式与用户状态.md#slot-对单个观众的可见性) |
| 事件的 `from { projection, role? }` | 运行态下按下该投影中这个 `role`（缺省 `body`）的节点时引发，参数为 `{ item, projection }` |
| 事件的 `on` | 默认处理：实例没有为该事件绑定处理时执行 |

例子见 [control-examples](../control-examples/README.md)：电视屏（`media`）、限时可见（`visible`、`viewer` 投影）、照片投票（`members`、`mark`、`counts` 投影与事件默认处理）。

### 布局归属与组合操作

父容器拥有直接子节点的布局。Block 可以报告尺寸需求，不能擅自改动兄弟节点位置；嵌套 control 先形成自身尺寸与内部布局，再作为一个节点参与父布局。

布局求解读取明确的子树、配置和测量输入，只产生已声明的自动分量。固定分量由用户或操作设置；算法不能在渲染期间反向提交数据、改变成员关系或反复触发自身。

组合控件可以引用已有布局算法。新增组合类型不要求增加内核 kind；引入任意新算法代码需要通过执行与扩展契约，不能只在配置里填脚本便获得宿主权限。

连接可以是容器根据结构绘制的隐式边，也可以是独立连接线 Block；二者的身份、编辑和导出语义应明确。不能把隐式边当作可独立删除的持久实体。

创建、复制、粘贴、移动、分组和拆分使用统一操作协议。复制通过统一 ID 映射重建组内关系，按所有权规则克隆自有数据或保留共享引用；不能让某一种 control 成为所有粘贴行为的默认包装。

移除被实例或其他定义引用的定义必须处理强依赖。安装来源升级、工作区定义升级和单实例编辑是不同动作；更新本机扩展库不自动更新已引入的工作区定义。

“保存片段”产生插入后独立的内容副本；“定义控件”产生可供多个实例引用和升级的定义；“工作区模板”初始化完整工作区。三者不得共用一个含糊的复制入口。

## 内置 Block 标准库

内置 Block 是宿主契约的标准实现集，不因随系统发行而拥有额外数据权限。它既提供开箱即用能力，也作为扩展开发者实现相同接口的参照。

“原子 Block”指无需编排其他真实子 Block 即可完成其职责的可复用界面单元，不是数据内核原语。原子集合应小而稳定；复合业务界面优先由这些单元与 control 组合。

| 类别 | 代表对象 | 标准库责任 |
| --- | --- | --- |
| 基础呈现 | label、media | 文本/值显示、媒体资源呈现、尺寸与静态替代；保持命名绑定和模式规则 |
| 普通图形 | SVG 图形、Frame | 图形样式、几何、锚点；Frame 提供明确区域与用途，不隐含业务数据所有权 |
| 复杂编辑 | RichText/richedit、Table | 结构化内容编辑、专用协作和稳定子项寻址；复用内核原语，不另造提交历史 |
| 特殊交互 | 连接线、笔迹 | 端点/路径或笔画数据、命中和交互、跨模式表现；保留自身稳定身份与引用规则 |

label 可以显示常量或绑定值，不因显示数值就拥有另一份数值真相。它是文本视图 `label`：常量即其标题；绑定时读 Record 的一个属性（`config.prop`）或表格的一个数据格（`config.record_id` + `config.field_id`），每次显示当前值。格式有文本、日期（含短日期、星期、日、月）、时间、日期时间、相对时间、数字、百分比、时长和倒计时；字号、颜色、粗细、对齐、单行截断或换行属于实例配置。它在宽度约束内报告文字的固有尺寸，在控件内宽高可为 `"auto"`。投影出的 label 使用同一绘制，不挂载 Block 外壳。

media 以资产或来源引用为正文，播放位置等运行状态与共享资源版本分开。

Table Block 是 Table 数据的视图和编辑器，不把每个数据格变成画布 Block。RichText Block 保留结构化正文、稳定锚点和协作历史，不以 HTML 字符串替代原语。

连接线与笔迹可具有专用命中、编辑和绘制路径，但仍经过公共生命周期、权限、命令、导出和回退协议。“通常不组合”只是使用习惯，不构成绕过宿主契约的例外；确实不能放入某种 control 时，以能力声明和结构校验表达。

Frame 的视觉区域、成员关系、演示目标与打印页用途必须分别声明。把对象移进一个矩形范围，不自动改变其父节点、授权或业务数据归属。

新增标准 Block 原则上增加标准库定义与实现；只有需要新增数据原语、操作或宿主能力时才修改相应核心协议。标准库维护与外部扩展遵循同一版本和迁移原则。

### 标准控件：待办与日历

官方待办和日历是随标准库发行的数据控件，读写标准业务表 `buckyos.todo@1`、`buckyos.calendar@1`（见[业务 Schema 与未知类型](02-数据模型与引用.md#业务-schema-与未知类型)）。Agent 命令（`buckyos aiws todo` / `cal`）读写同一份表，不经过控件。

| 控件 | 绑定 | 视图 | 记录上的操作 |
| --- | --- | --- | --- |
| `todo` | `items`：待办表（必填） | 列表、看板（按 `status` 分列）；隐藏已完成、折叠的列 | 快速添加、勾选完成、拖动排序或换列、加一列（即加 `status` 选项，需要 `structure`）、详情、复制链接、批注、单独页面打开、删除 |
| `calendar` | `events`：日程表（必填）；`todo`、`todo_<名字>`：待办表，可绑多张，截止日期只读显示；其他名字：更多日程表 | 月、周、日、日程；周起始日、一天起始时间、是否显示待办、隐藏的日历或待办表 | 点空白或拖出时段新建、拖动改期（吸附 15 分钟、可跨天）、拖底边改结束、跳过这一次、复制、删除、复制链接、批注 |

在画布上插入时，宿主按主绑定（`items` / `events`）的 `schema_id` 找工作区里的表：

- 没有：在当前画布的内容文件夹里新建一张，和控件在同一个 Commit 里创建，归控件所有；与同级重名时名字后加 ` (2)`、` (3)`。
- 只有一张：直接绑定它。
- 有多张：让用户选一张或新建一张。

没有绑定表格的控件（例如 Agent 只建了容器）显示同一个入口，选定后用 `entity.set_props { key: "bindings" }` 写入绑定。

日历的待办表是可选绑定：插入时工作区里只有一张待办表就一并绑定为 `todo`，有多张时不问。之后在日历的菜单里可以：

- 再显示一张日历表（工作区里没有未显示的就新建一张），绑定名 `events_2`、`events_3`……
- 显示某张待办表的截止日期，绑定名 `todo_2`……
- 不再显示某张表：只去掉绑定，表格和记录都还在。

隐藏某张表只是自己的视图，不改文档。

两者的公开契约用与扩展 `component.json` 相同的形状声明：`manifest_version` 4、`ident { author_did: "did:bns:buckyos", name }`、`kind: "builtin"`、契约版本 `version`（当前为 1）、`config_schema`、`user_state`（每人自己保存的属性）、带 `schema_id` 的 `bindings`、投影用的 `templates`、`layouts`、各 `role` 的手势及其写入、`actions` 和给 Agent 的 `agent` 自述。契约由标准库代码生成为 `aiws/contracts/<kind>.json`，`control.describe { kind }` 在返回的 `control.contract` 中给出。模板的 role、手势的写入或属性发生读者需要知道的变化时提升契约版本。
