## 1. 目标与原则

### 1.1 为什么要整理

现在的界面是按期叠加出来的，位置已经基本固定，但内容都写死在组件里：

- **入口各自找位置。** 手写笔、设计 / 运行切换、使用引导、开始放映、五种文件导入都是各自加进某个工具栏或菜单的。右上的工具栏最多有 7 类控件，其中几个带文字；主菜单第一级约 20 行，代码里有两处注释在提醒“菜单不能超出小窗口”。
- **手机是裁剪出来的。** 手机上只保留一条工具栏，没有主菜单、数据视图和对象工具栏；自由画布只能看，上面的表格是只读的缩略显示，目录在手机上完全够不到。而目标用户以手机为主，很多人没有电脑。
- **Block 的界面契约不一致。** 一个类型的操作分散在 `actions`、`toolbar`、`hover`、`Inspector` / `configFields` 四个通道里，菜单和动作的数据形状至少有九种；流式页上没有 Block 工具栏和右键菜单，富文本的字号颜色、资产的预览与展开、许愿格的运行在流式页都够不着。
- **数据视图只能一次看一个对象**，权限界面还是旧的“主体 × 工作区或画布”形状，首页卡片只有标题和几个按钮。

### 1.2 目标

| 目标 | 要达到的结果 |
| --- | --- |
| 每个界面元素都有归属 | 外壳只有五个工具区、一个属性面板、一个侧边抽屉；Block 自己的界面有统一的三个出口（工具栏、右键菜单、属性面板） |
| 新功能不改外壳 | 加一个功能等于注册一个动作并声明落点；外壳的布局、溢出和手机形态由框架处理 |
| 手机能完成主要工作 | 浏览和切换画布、编辑流式页、编辑数据源、改 Block 属性、手写、评论、运行宏、导入文档、导出工作区、管理基本权限、在首页打开和新建工作区 |
| 可以定制 | 工作区、画布和个人三层都能调整工具区；全部隐藏就是 App 模式 |
| 同一件事处处一样 | 同一个动作在任何入口都是同一个名字、图标和不可用原因 |

### 1.3 原则

1. **手机先行。** 每个新入口先给出手机上的形态。依赖悬停、右键、键盘或精确拖动的操作必须有触摸等价入口。
2. **动作只定义一次。** 工具栏、菜单、右键、快捷键、宏和 Agent 共用动作，不为某个入口单独写一份逻辑。
3. **工具区有职责和容量。** 放不下的进“更多”或下一级，不新增常驻工具条。
4. **共享配置决定有什么，个人配置决定怎么摆。** 个人调整不改变别人看到的界面。
5. **隐藏不是权限。** 定制和 App 模式只改变呈现，能力仍由服务按当前身份检查。
6. **不可用要说明原因。** 沿用现有约定：禁用的入口给出原因；当前模式下没有意义的入口不显示。
7. **状态各有归属。** 共享内容进文档，个人偏好进用户状态，过程状态留在本窗口（§12）。

### 1.4 范围

本文规定：工作区外壳的工具区和定制规则、数据模式、手机端、数据源 Block 的交互要求、工作区权限编辑面板、首页、Block 相关的界面契约。

本文不规定：

- 放映舞台、公开课房间、提示器的内部界面，沿用[演示模式 PRD](<BuckyOS AI Workspace 演示模式PRD.md>) 和第三、四期规划；本文只要求它们的控制条落在情境工具区的同一规范里（§4.4）。
- 权限模型本身，以[权限系统整理需求](../../notepads/aiws-permission-system-prd.md)为准；本文只写它的界面。
- 视觉规范（间距、圆角、颜色、焦点），沿用 UI 改进 §11。
- 各类 Block 的内容设计（脑图、日历、图表等）。

### 3.3 动作、工具项、工具区

框架的核心是把“做什么”和“放在哪”分开。

**动作**是唯一的功能单位：

| 字段 | 说明 |
| --- | --- |
| 标识 | 稳定、带命名空间：`ws.*`（工作区）、`surface.*`（画布）、`view.*`（视图）、`collab.*`（协作）、`block.*`（所有 Block 通用）、`block.<类型>.*`（类型专有）、`data.*`（数据对象）、扩展声明的动作和宏 |
| 名称、图标 | 走现有 i18n；所有入口显示同一个名字 |
| 作用对象 | 工作区、当前画布、当前选区、一个 Block、一个数据对象 |
| 显示条件 | 模式、布局、设备、是否有候选（例如有没有演示路径）。不满足时不显示 |
| 可用性 | 能力、只读状态、联网状态。不满足时禁用并给出原因 |
| 候选 | 可选。动作有多个目标时列出它们（演示路径、宏），界面据此决定直接执行还是下拉 |
| 执行 | 调用现有的提交、运行或界面切换逻辑；不新增绕过 Command / Commit 的写入通道 |

**工具项**把动作放进工具区，形态有按钮、开关、下拉、指示器（只显示状态）和少数内置专用控件。有候选的动作统一按“一个直接执行，多个下拉”呈现。

**工具区**规定位置、方向、容量和溢出方式。放不下的工具项按声明的优先级收进“更多”；手机上没有的工具区，其动作进主菜单。

这与内核文档 [07 统一事件与动作模型](kernel/07-事件宏与公式预留.md#统一事件与动作模型) 是同一件事的界面侧：那里要求工具栏、菜单、快捷键、宏和许愿格共用动作入口，而现在内置的工具栏、菜单和快捷键都没有走这套模型（依赖 K5）。

### 3.4 设备与尺寸

- **设备档**：手机；触摸为主的平板和触屏笔记本；鼠标键盘。判定沿用现有实现，依据设备而不是窗口宽度。
- **尺寸档**：沿用应用容器宽度的三档 `wide`（≥1100）、`medium`（≥760）、`narrow`。桌面上的窄窗口仍是完整的编辑布局，只是工具项收得更紧。
- 触摸设备上所有可点目标至少 44×44px。现在 `(pointer: coarse)` 只放大了工具按钮、菜单项和弹层项，表格工具、行内按钮、链接和树行都要纳入。

## 4. 工具区

### 4.1 标题区（左上）

> owner：主 title；选择画布支持目录结构，日记工作区的画布可能很多，支持搜索；main menu，注意第一级高度不能太高。

**组成，从左到右：** 画布图标｜画布名 ▾｜模式标签｜数据模式｜主菜单 ⋯

- 画布图标和画布名的行为不变：点图标换预设图标和页面背景，点名称原位改名。
- 模式标签只在不是编辑模式时出现（现有行为）。
- 数据模式是一个单图标开关，在数据模式里变成“返回画布”。owner 的要点里左上只列了画布选择和主菜单，这个图标是保留现有入口（已定 Q4）。
- 现在的“协作”按钮取消：在线成员从协作区的头像进入，权限管理进数据模式的权限节点（§8）。

#### 4.1.1 画布选择器

点画布名旁的 ▾ 打开。手机上点整个标题打开，占满屏幕高度。

| 部分 | 要求 |
| --- | --- |
| 顶部 | 工作区名，“返回首页” |
| 搜索框 | 始终显示。按画布名和目录名做不区分大小写的子串匹配，在整个工作区里找，不受目录折叠影响；结果平铺，带所在目录路径；回车打开第一项 |
| 最近 | 画布超过 20 张时显示本人最近打开的 5 张 |
| 目录树 | 多级目录，可折叠。画布行显示图标、名称、自由 / 流式标记，当前画布高亮 |
| 底部 | “新建画布”“新建目录”，需要 `structure` |

- **目录是共享的文档结构**，不是个人视图：所有人看到同一棵树，目录的新建、改名、移动、删除需要 `structure`，可以撤销。目录折叠状态和“最近”是个人的。
- 每行的更多菜单（⋯、右键或长按）：重命名、创建副本、移动到…、权限…、删除。目录另有“在此新建画布”。只能删除空目录。
- 电脑上可以拖动调整顺序和所属目录；触摸设备用“移动到…”。
- 同一目录内默认按手动顺序排列，可以切换成按名称排序。切换只影响本人看到的顺序，不改共享顺序。
- 数量要求：几百张画布时，打开选择器、输入搜索、滚动都不卡顿。画布大纲已在本地，列表需要按需渲染。
- 日记这类工作区靠搜索和按名称排序定位某一天。“打开今天的日记”这样的快捷入口不做成框架功能，由模板提供一个宏，再通过工具栏定制放到标题区或协作区（§4.6）。
- 画布的访问链接按画布 ID 定位，移动到别的目录不影响已发出的链接。
- **目录与实体路径保持一致（已定 Q5）。** 核心 API 已经给每个实体一个路径（`/surfaces/看板/text-3`），画布目录就是这条路径上的层级：一张画布的位置是 `/surfaces/<目录>/…/<画布>`，Agent 读写用的路径、权限规则里的资源路径和选择器里看到的目录是同一个东西。
  - 目录是 `surfaces` 下真实的文件夹实体。它的名字按核心 API 的命名规则生成：跟随标题，同级重名时自动加 `-2`、`-3`。
  - 权限按目录继承：对一个目录授权，它下面的画布都生效。
  - 选择器里画布和目录的菜单有“复制路径”。
  - 路径语法本身已经支持多级，要改的只是树的结构规则：现在 `surfaces` 节点下只接受画布（`core/src/plan.rs` 的 `child_allowed`），需要允许文件夹（依赖 K1）。

#### 4.1.2 主菜单

**高度规则：**

### 4.2 协作区（右上）

> owner：多人协作。节约宽度，都是单图标，默认 3 个按钮：启动播放（有多个点击会下拉）、执行宏（多个点击会下拉）、添加评论。头像区显示同时在线的头像（自己的在第一个，堆叠）；查看在线成员时可以看到其所在用户组。

**组成，从左到右：** 播放｜宏｜评论｜缩放比例｜头像堆叠｜分享链接

- 播放、宏、评论是默认的三个按钮，都是单图标，名称放在提示里。
- 缩放比例和分享链接留在现在的位置，形态不变（已定 Q1、Q2）：缩放比例是显示当前比例的按钮，点开是缩放面板，只在自由画布上出现；分享链接在最右，宽窗口带文字，窄窗口只有图标。
- 窄窗口里先减少显示的头像数，再把缩放比例收进“更多”（UI 改进 §9.1 的现有规则）。

| 工具项 | 只有一个候选 | 有多个候选 | 没有候选 |
| --- | --- | --- | --- |
| 播放 | 直接打开这条演示路径的“开始放映” | 下拉：演示路径、使用引导；末尾是“公开演示…”和“历次演示” | 有 `structure` 的人点它进入路径编辑；其他人不显示 |
| 宏 | 直接运行 | 下拉：最近用过的那个宏排第一，然后是当前画布上的宏，再是工作区其他的宏（已定 Q10） | 不显示 |

评论没有候选的概念：流式页上点它直接进入选择评论对象；自由画布上下拉“评论对象 / 添加便签”（现有行为）；没有 `comment` 能力时禁用并说明。

- **播放**合并了现在的“开始放映”和“使用引导”两个按钮。放映的规则不变。
- **宏**是新入口。现在宏是许愿格里保存的程序（`program`），只能在许愿格面板或许愿格 Block 上运行。
  - 候选是当前用户能运行、且程序与输入匹配（不处于“需要重新编码”状态）的许愿格。
  - 从这里运行与在许愿格面板里点“运行”完全相同：同样的身份、同样的结果处理，进度和结果在状态栏的工作日志里可见。
  - 工作区或画布可以把某个宏单独做成一个工具项，自带名称和图标（§4.6）。
  - “最近用过”是个人的，按工作区记。
  - 依赖 K5：需要能列出工作区里可运行的宏。
- **评论**就是现有的批注功能（`comment` 能力）。界面上统一叫“评论”，不再用“批注”和“标注”，owner 认为“批注”太专业（已定 Q14）。便签仍叫便签。实体类型、能力名和代码里的标识不改。

**头像堆叠：**

- 自己在第一个，其他在线成员向右叠放，超出的显示 `+N`。按尺寸档显示 5、3、1 个。
- 点头像区打开在线成员面板（手机上从状态栏的在线人数进入）：
  - 每行：头像、名字（访客显示称呼）、所在用户组、所在画布（点击跳到那张画布）。同一账号多设备只算一个人。
  - 用户组显示逻辑组的标题；`@owner` 显示为“所有者”；不属于任何组的显示为“访客”。
  - “我”这一行承接现在身份面板的内容：账号信息、退出登录；访客是填写称呼和登录。
  - 有 `manage` 的人在面板里有“成员与权限…”，打开权限编辑面板（§8）。
- 工作区级的在线状态现在没有（依赖 K2）。接入前头像区只显示自己，不用授权名单或提交作者冒充在线成员。
- 只有管理者能看到别人的组别，其他人只看到自己的（已定 Q6）。权限需求规定非管理者不能列出组成员，对所有人显示组别等于部分公开了成员关系。

**现有工具项的去向：**

| 现在在右上的 | 去向 |
| --- | --- |
| 使用引导、开始放映 | 合并为“播放” |
| 添加标注 | “评论” |
| 设计 / 运行切换 | 工具选择区的指针组（已定 Q3） |
| 缩放比例 | 不动（已定 Q1） |
| 身份头像 | 头像堆叠的第一个 |
| 分享链接 | 不动（已定 Q2） |

手机上不显示协作区：缩放靠双指手势和主菜单的“视图”，分享链接在主菜单的“协作”里（§6.1）。

### 4.3 工具选择区（左侧）

> owner：左侧：工具选择。

沿用 2026-11-12 定下的双排结构（15 个按钮，选择、表格、形状带第二排），本文只把它规定为一个工具区：

| 分组 | 内容 | 说明 |
| --- | --- | --- |
| 指针组 | 选择 / 手形、设计 / 运行、笔 | 决定点击和拖动的含义。设计 / 运行从右上移到这里（已定 Q3）。流式页上只有设计 / 运行 |
| 对象组 | 文本、富文本、媒体、表格、脑图、形状、连接线、框、许愿格、便签、插入…，以及固定的扩展控件 | 选中后在自由画布上一次性放置，在流式页上追加 |
| 历史组 | 撤销、重做 | — |

- 只在编辑模式、非手机上出现；路径编辑时让位给路径面板（现有行为）。
- 容器高度不够时，对象组从下往上收进“插入…”，指针组和历史组始终保留。
- 对象组里出现哪些类型，现在是代码里的一份名单。纳入框架后由配置决定：工作区或画布可以减少、调整顺序或固定扩展控件，例如看板画布只留便签和待办；个人固定的扩展仍按现有方式（`ui:pinned-defs`）。
- 新的 Block 类型默认进“插入…”的目录，不直接占用常驻按钮。

### 4.4 情境工具区（正下）

> owner：正下：手绘工具区 / 协作工具区。

这是按情境出现的工具条：没有激活的情境时不显示，同一时刻只显示一条。

| 工具条 | 出现条件 | 内容 |
| --- | --- | --- |
| 手绘 | 当前工具是笔或橡皮。手机上从主菜单的“手写”进入（§6.3） | 现有 `InkBar`：笔、橡皮、颜色、粗细、压感、触摸锁、完成 |
| 协作 | 处于一场放映或公开课中 | 主讲：上一步、下一步、激光笔、笔、结束。观众：跟随 / 返回主讲视角、反应、弹幕输入 |
| 文本格式 | 手机上有文本编辑器获得焦点 | 编辑器的格式工具，贴在软键盘上方 |

- 手绘条和舞台、房间的控制条现在各有实现（`aiws-ink-bar`、`aiws-show-bar`、`aiws-session-bar`），位置已经都在底部居中。本文要求它们使用同一个工具区的位置、尺寸和避让规则，内容不变。

- 两个情境同时成立时（放映中使用笔），手绘工具作为协作条里的一组出现，不叠两条。
- 以后的协作工具（跟随某位成员的视角、语音等）注册为这里的工具条或其中的工具项，不占用协作区的常驻位置。
- 位置：底部居中。手机上在状态栏上方，有软键盘时在键盘上方。宽度不够时横向滚动，不换行。

### 4.5 状态栏（右下）

> owner：右下：工作区状态栏。可展开收起；展开显示最近的工作日志；默认显示在线人数 / 提交状态。

**收起时（默认）：** 在线人数｜提交状态。

- 在线人数依赖 K2，接入前不显示。
- 提交状态沿用现有四种：已提交、未保存 N、已保存到本设备 N、需要处理 N。连接不正常时在最前面显示连接状态文字（现有行为）。
- 条件项：离线副本标记、正在进行的离线操作。缩放比例不放在这里，它留在协作区（已定 Q1）。
- 画布视图里它是右下角的浮动面板；数据模式里是底部通栏（§5.5）；手机上是贴底的通栏。

**展开后：** 状态栏上方出现面板，高度不超过容器的一半，内容可滚动。手机上是底部面板。

| 部分 | 内容 |
| --- | --- |
| 需要处理 | 需要处理、未保存、仅保存到本设备的修改，带重试、重新编辑、放弃。即现在“修改状态”面板的列表。没有时不显示这一部分 |
| 连接与离线 | 连接状态、离线副本、准备离线、接管、导出本机修改。默认折叠 |
| 最近工作日志 | 时间、操作者、做了什么、对象。点一条定位到对象所在的画布或数据模式标签页 |

- 工作日志的条目种类：文档提交（人、Agent、宏运行分别标明）、许愿格和宏的运行（开始、完成、失败）、导入、放映和公开课的开始与结束；有 `manage` 的人还能看到权限变更。
- 默认显示最近 50 条，可以加载更早的；筛选：全部、我的、Agent 与宏。
- 日志只包含当前用户读得到的内容。
- 出现新的“需要处理”时自动展开（现在的行为是自动打开右侧面板）。
- 展开或收起是个人偏好。

**告警不变：** 同步停止、本机写入失败、离线只读、放映锁定等持续性问题仍叠在状态栏上方，不自动消失，带各自的处理按钮。它们不受展开、收起或工具栏定制影响。

日志依赖 K3：现在 `doc.get_changes` 只能从旧到新翻页，不带提交说明；提交说明（`commits.message`）已经保存，但内容是作者当时界面语言的文字。接口到位前，展开面板先显示“需要处理”和“连接与离线”两部分。

### 4.6 工具栏定制

> owner：用户全局配置 / 画布 / 工作区都可以自定义 toolbar。

**配置分层，后面的覆盖前面的：**

| 层 | 谁能改 | 对谁生效 | 存放 |
| --- | --- | --- | --- |
| 内置默认 | 随版本 | 所有人 | 代码 |
| 工作区 | 有 `manage` 的人 | 这个工作区的所有人、所有画布 | 工作区的共享设置（依赖 K4，现在没有工作区级的设置存放处） |
| 画布 | 对这张画布有 `structure` 的人 | 这张画布的所有人 | 画布的 `config`（现有，已用于背景和页面尺寸） |
| 个人 | 本人 | 本人，所有工作区 | 跨工作区的个人偏好（依赖 K4，现在只有按工作区保存的用户状态） |

- **共享层决定有什么**：增加工具项（绑定一个动作或宏，可以自带名称和图标）、隐藏工具项、调整顺序、隐藏整个工具区、给工具项加显示条件（模式、设备、能力）。
- **个人层决定怎么摆**：显示或隐藏、顺序、折叠、属性面板的固定位置、状态栏是否展开。个人层只能在“内置项加共享层提供的项”里选择。
- 共享层可以把某个工具区或工具项标为**锁定**，个人层不能改它。App 模式靠它实现。
- 谁能改共享层：工作区级需要 `manage`，画布级需要对该画布的 `structure`（已定 Q15）。
- 画布对工作区配置的关系是继承、追加、覆盖或隐藏四选一，按工具项的稳定标识合并，结果必须确定（内核文档 [06 可定制工具栏与 App 模式](kernel/06-布局模式与用户状态.md#可定制工具栏与-app-模式)）。
- 个人的布局偏好是全局的。引用了某个工作区里实体的个人固定项（固定的扩展控件、固定的宏）只在那个工作区生效，沿用现有的按工作区用户状态。
- **个人层先做机制，界面入口可以后补（已定 Q8）。** 配置的合并从一开始就支持个人层，并且对所有工作区生效；增删和排序工具项的个人定制界面先不提供。已经有入口的个人偏好照常：工具区的显示开关、固定的扩展控件、属性面板的固定位置、状态栏是否展开。
- 工作区和画布的工具栏配置是工作区内容的一部分，随模板、Clone 和导出传播；个人偏好不传播。

配置的形状示意（不是最终 schema）：

```json
{
  "zones": {
    "collab": {
      "items": [
        { "action": "show.start" },
        { "action": "macro.run", "args": { "wish": "~w_today" }, "title": "今天的日记", "icon": "calendar-plus" },
        { "action": "annotate.add" }
      ]
    },
    "tools": { "hidden": true, "locked": true }
  }
}
```

**不能定制掉的：** 状态栏上方的告警；App 模式的退出入口；内置动作的含义（定制只改变位置和外观）。

**定制界面：** 主菜单“视图 ▸ 自定义工具栏…”打开对话框。先选范围（本画布、本工作区，按能力显示；“我的”这个范围以后再加），再按工具区列出工具项，可以勾选、拖动排序、添加动作或宏、恢复默认。

**App 模式：** 工作区或画布把全部工具区隐藏并锁定，画布上的控件成为主要操作入口。

- 它只是呈现配置，不是权限角色，能力检查、保存状态和运行反馈照常。
- 退出入口：有 `structure` 或 `manage` 的人在左上角有一个收起的 ⋯，可以临时显示工具区并进入定制。其他人没有这个入口，离开工作区靠窗口或浏览器自身的返回和关闭。
- 告警仍然显示。
- 现有的单控件页（`page=control`）是它的最小版本，行为不变。

## 5. 数据模式

> owner：UI 需要重做，整体 UI 类似 Text-Editor。左侧是对象树：可以搜索和过滤，默认只显示数据源对象；通过右键菜单可以在指定位置插入数据源；workspace 权限编辑是特殊的节点，点击后中间内容区变成 workspace 权限编辑器；宏也是 block，点击可看到宏代码。中间主要区域是“处于可编辑状态的 block”，支持多 tab，每个类型的数据源都有标准的可编辑 block。右侧边栏是属性 / 权限 / 修改记录。底部状态栏。手机可用。


- 四个部分：左侧对象树、中间多标签页编辑区、右侧边栏、底部状态栏。左右两栏可以拖动调宽，也可以收起；宽度和收起状态是个人偏好。
- 标题区显示工作区名、“返回画布”和主菜单。协作区照常，评论的对象是当前标签页的对象。工具选择区和情境工具区不出现。
- 窄窗口里右侧边栏变成抽屉，再窄则对象树也变成抽屉。手机见 §5.6。

现在的数据视图已经是三栏（数据树、单个对象的详情、属性），所以这是在现有结构上改，不是从头做：中间从“一次一个对象”变成多标签页，树加上图标、右键菜单和特殊节点，右栏变成三个页签。

### 5.2 对象树

对象树是整个工作区的实体树，默认只显示数据源对象：

| 默认是否显示 | 内容 |
| --- | --- |
| 显示 | 表格 `buckyos.table-source`、富文本 `buckyos.richtext`、记录 `buckyos.record`、资产 `buckyos.asset-ref`、目录 `buckyos.dir`，以及包含它们的用户文件夹 |
| 显示，默认折叠 | “画布自带的数据”：`canvas-content` 下每张画布一个文件夹，里面是在画布上直接创建的数据 |
| 显示，固定在树的下方 | “宏”分组、“工作区权限”节点 |
| 不显示，可用筛选打开 | 没有程序的许愿格、控件定义 `buckyos.block-def`、评论 `buckyos.annotation`、演示路径和视口、画布及其上的 Block、其他系统文件夹 |

**搜索和筛选**

- 搜索按名称做子串匹配（现有，另可按 ID），结果保留所在的层级。
- 筛选：类型（多选）、来源（全部、原始、生成，现有），以及“显示全部对象”。
- 筛选条件和展开状态是个人的。

**每一行**是类型图标、名称和状态标记：生成的结果及其新鲜度、需要写锁、已发布、外部来源、内容降级。现在类型是文字标签，没有图标。

**右键菜单**（触摸设备上是每行末尾常显的 ⋯，长按也可以）：

| 位置 | 菜单项 |
| --- | --- |
| 文件夹或空白处 | 新建 ▸（表格、富文本、记录、目录、链接的数据源、许愿格、文件夹）；导入 ▸（从 Zone 选择文件…、上传本机文件…、导入表格数据…、导入文件夹…）；粘贴表格数据 |
| 数据对象 | 打开、在新标签页打开、放到画布…、在画布上定位 ▸、重命名、移动到…、权限…、发布…、复制路径、查看引用与依赖、删除 |

- **在指定位置插入**：在文件夹上打开菜单，新对象进这个文件夹；在某个对象上打开菜单，新对象成为它的下一个兄弟。
- 现在树下方的内联新建表单取消，由右键菜单和树顶部的 ＋（在当前选中的位置新建）代替。
- 选文件默认面向 Zone（系统文件选择器），本机上传是次要入口。
- 电脑上可以拖动来移动和排序。删除前的引用预检不变。

**特殊节点**

- **工作区权限**：点击后在编辑区打开权限编辑面板（§8）。所有人都能看到这个节点；没有 `manage` 的人打开的是只读的“我的权限”。
- **宏**：列出带程序的许愿格。点击打开它的标准编辑器，并直接落在“代码”页。
  - 现在宏不是独立的实体，是许愿格的 `program`。内核文档 07 描述的独立宏定义（作用域、入口、参数）还没有实现。界面先把“带程序的许愿格”当作宏列出；以后有了独立的宏实体，这个分组的位置和行为不变。

### 5.3 编辑区

owner 说的“处于可编辑状态的 block”：数据模式里显示的就是这类数据的 Block 编辑器，只是不放在画布上，占满编辑区。现在的详情栏已经复用了画布 Block 的编辑器（`TableEditor`、`RichTextCell` 等）。

**标签页**

- 单击树上的对象，在“预览标签页”里打开（标题用斜体，下一次单击会复用这个标签页）。双击，或者在里面做了修改，它就成为固定标签页。
- 标签上是图标和名称，另有未保存圆点和只读标记。可以拖动排序；放不下时横向滚动，并提供列表下拉。
- 标签的菜单：关闭、关闭其他、关闭右侧、在画布上定位、复制路径。
- 只有当前标签页的编辑器处于挂载状态。切换标签页不丢输入（沿用草稿机制）和滚动位置。最多 20 个，超出时关掉最早打开且没有修改的。
- 打开了哪些标签页、当前是哪一个，是个人状态，回到数据模式时恢复。对象被删除或不再可读时，标签页显示原因，不静默消失。
- 从画布上“查看数据”进入数据模式时，在新标签页里打开那个对象。
- 不做分屏。

**每种对象的标准编辑器**

| 对象 | 标准编辑器 | 现状 | 要补的 |
| --- | --- | --- | --- |
| 表格 | 表格编辑器 | `TableEditor` | §7.3 |
| 目录 | 文件列表 | `DirectoryDetail`，没有对应的 Block | §7.4 |
| 富文本 | 富文本编辑器，含 Markdown 源码 | `RichTextCell` | 手机上的格式条（§4.4） |
| 记录 | 记录表单 | `RecordCell` 属性表 | 与表格里的记录表单用同一个组件（§7.3） |
| 资产 | 预览和替换 | `AssetCell` | 替换时默认从 Zone 选 |
| 宏（许愿格） | 三页：任务、代码、运行记录 | `WishPanel`，代码是底部一个可展开的文本块 | 代码成为独立的一页：等宽字体、行号，不能编辑时说明原因 |
| 控件定义 | 摘要和“管理” | `BlockDefDetail` | — |
| 评论、便签 | 文本 | `NoteEditor` | — |
| 文件夹 | 子项列表 | `FolderDetail` | — |
| 演示路径、视口 | 只读摘要和“在路径编辑中打开” | 原始 JSON | 摘要和跳转 |
| 工作区权限 | 权限编辑面板 | — | §8 |
| 未登记的类型 | 原始内容，只读 | `RawDetail` | 给会话类型（`buckyos.task` 等）登记名称 |

数据层的只读约束（外部来源、需要写锁、没有能力）照常生效，数据模式不能绕过来源的写入限制。

### 5.4 右侧边栏

跟随当前标签页的对象，三个页签：

| 页签 | 内容 | 现状 |
| --- | --- | --- |
| 属性 | 分节、可折叠（规则同 §10.2）：基本（名称、查找名、类型、路径、大小或行数）；来源与同步；发布；生成与新鲜度；引用与依赖（被哪些 Block 显示，点击定位）；写入策略与锁；诊断（ID、版本号，默认折叠） | `PropertiesPanel`、`SourceSection`、`PublicationSection`，以及详情里的“引用与依赖”页 |
| 权限 | 按实体的权限视图（§8.4） | 只显示“我在此实体上的能力” |
| 修改记录 | 这个对象的版本列表：时间、作者、来源（人、Agent、宏运行）、说明；可以恢复到某个版本，恢复是一次普通的可撤销提交 | `PropertiesPanel` 里已有，用 `doc.list_versions`（依赖 K9） |

当前标签页是权限编辑面板时，右侧边栏只有“修改记录”，内容是权限的操作记录（`acl.audit`）。

### 5.5 底部状态栏

数据模式里状态栏是底部通栏。左半是当前对象的信息：类型、行数或大小、只读原因、新鲜度，表格另有当前所在的行。右半与画布视图相同：在线人数、提交状态，同样可以展开（§4.5）。告警叠在它上方。

### 5.6 手机

现在手机进不了数据模式：外壳强制回到画布，从别处打开一项数据时只能定位到显示它的 Block，找不到就提示“到电脑上查看”。改为：

- **入口**：主菜单的“数据模式”；自由画布上情境窗口的“展开”直接进入对应对象的编辑器（§6.4）。
- **单栏三层**：
  1. 对象树：全屏列表，顶部是搜索和筛选，行高至少 48px，每行末尾常显 ⋯。
  2. 编辑器：全屏。顶栏是返回、对象名、已打开对象的数量（点开切换，相当于标签页）和 ⋯。
  3. 右侧边栏的三个页签以底部面板出现，从 ⋯ 或状态栏的对象信息进入。
- 从评论、属性等处打开一项数据时，直接打开它的标准编辑器，不再降级成“定位到 Block”。

## 6. 手机端

> owner：flow 模式：在 block 标题处出现。只有主 title + 状态栏。画布模式：自动进入 view mode；点击触发 block 的 context window；点“扩展”进入数据源 block 编辑模式；点属性进入 block 属性编辑模式。

原文有两处是展开理解的，owner 已确认（已定 Q11）：“在 block 标题处出现”指流式页上 Block 的工具出现在它的标题行；“扩展”指把 Block 展开成全屏的数据源编辑器，按钮暂名“展开”。

### 6.1 外壳

手机上常驻的只有标题区和状态栏。电脑上的每个部件在手机上都有去处：

| 协作区 | 不显示。播放、宏、评论、分享在主菜单的“协作”里；评论也在 Block 的情境窗口和标题行菜单里；缩放靠手势和主菜单的“视图”；在线成员从状态栏的在线人数进入 |

| 属性面板 | 底部面板 |
| Block 工具栏 | 流式页上是 Block 的标题行；自由画布上是情境窗口 |

| 侧边抽屉 | 底部面板 |
| 对话框 | 全屏 |

- **弹层统一成底部面板。** 手机上所有菜单、下拉、色板、选择器都从底部升起。现在只有数据控件的弹层、绑定对话框和侧边抽屉有手机形态。
- 布局避开安全区，工作区内禁止页面级的双指缩放（现有）。

### 6.2 流式页

手机上流式页是编辑模式（现有）。改动在 Block 工具的位置：

- **Block 的工具出现在它的标题行**，从左到右是：拖动把手 ⋮⋮、类型图标和标题、主要动作（最多两个）、⋯。
  - 有标题的类型（表格、记录、许愿格、控件等）标题行常显。
  - 不显示标题的类型（富文本、资产、便签、形状、框）只在获得焦点或被选中时出现一条细的工具行，不打扰阅读。
  - ⋯ 打开这个 Block 的完整菜单（§10.3），里面有属性入口。现在把手的菜单只有上移、下移、属性、删除。
- 这条规则在电脑的流式页上同样适用，悬停或聚焦时出现。现在流式页上没有 Block 工具栏和右键菜单，类型工具只有编辑器自己画出来的那部分：富文本的字号和颜色、资产的适应方式与预览、许愿格的运行都够不着，而手机恰好只能编辑流式页。
- ＋ 把手、`/` 菜单、Markdown 快捷输入、原位改名不变（[流式页交互改进](流式页交互改进.md) §2–§4）。
- 文本格式工具在软键盘上方（§4.4）。

### 6.3 自由画布

- **自动进入查看模式**：画布上不能移动、缩放、旋转和插入对象，便签和手写除外。手势不变：单指平移、双指缩放、双击缩放到 Block、长按。
- **点一下 Block**：选中它并打开情境窗口，代替现在的就近工具栏。
- **长按 Block**：打开同一个 Block 的完整菜单。长按空白处是现有的“添加便签”等。
- Block 里的按钮和链接照常响应点击，运行态的控件照常运行（现有）。

**手写（已定 Q16）。** 现在手写只在非手机的自由画布上提供。手机上改为提供：

- 入口是主菜单的“手写”。进入后底部出现手绘工具条（§4.4），点“完成”退出。
- 现在只有笔尖和鼠标能写，手指不写，手指用来移动画布。手机上多数人没有手写笔，所以手机的手写模式里单指书写，双指平移和缩放；设备带手写笔时沿用现有规则，笔写、手指移动画布（已定 Q17）。
- 手写是往画布上加笔迹，需要与插入相同的能力；没有时“手写”禁用并说明原因。
- 手写期间画布仍是查看模式，不能选中和移动别的对象。
- 没有手写笔时，工具条上的压感和触摸锁两项不显示。流式页上没有手写（现有）。

### 6.4 情境窗口

- 位置贴近 Block，在它的上方或下方，始终留在屏幕内；Block 占满屏幕时停在底部。
- 第一行是类型图标和标题。第二行是动作：展开、属性、评论、这个类型在查看模式下可用的主要动作（最多两个）、⋯（完整菜单）。
- 点空白处关闭，点另一个 Block 切换过去。

| 动作 | 效果 | 条件 |
| --- | --- | --- |
| 展开 | 全屏打开这个 Block 的数据源的标准编辑器，与数据模式的标签页是同一个编辑器。顶栏是返回画布、对象名、⋯ | Block 有数据源。数据控件（待办、日历）展开为现有的单控件页；资产展开为全屏预览；纯界面对象（形状、框、标签）没有“展开” |
| 属性 | 以底部面板打开属性面板（§10.2），分节与电脑相同 | 所有 Block；没有 `update` 时只读 |
| 评论 | 对这个 Block 评论 | 有 `comment` |

**写入规则（已定 Q12）：** 手机上的自由画布固定为查看模式，对已有 Block 的写入只经过“展开”和“属性”两个显式入口，能不能改按能力和只读状态判定。这改变了现在“手机上自由画布只读”的行为，owner 确认这正是目的。电脑的查看模式维持现状。

### 6.5 手机上的范围

| 手机上必须能做 | 说明 |
| --- | --- |
| 切换画布 | 目录、搜索、最近 |
| 新建流式页和目录 | 日记场景每天一页。现在手机不能新建画布；自由画布只能从模板、副本或导入文档得到（已定 Q9） |

## 7. 数据源 Block

> owner：数据源单元格。首要原则：手机上可编辑。交互需要大幅优化数据源 block：目录、表格。

### 7.1 原则

1. **一种数据源只有一个标准编辑器**，三处复用：画布上 Block 的编辑态、数据模式的标签页、手机上“展开”后的全屏。不为手机另写一套数据逻辑。
2. **手机上可编辑是验收的第一条。** 不依赖悬停、右键、键盘和精确拖动；每个这样的操作都有触摸入口。
3. **窄屏时改变结构，不是整体横向滚动。** 表格变成卡片，行内的多个按钮收进行菜单。
4. **按值的类型给输入方式**：日期用选择器，选项用列表，数字调出数字键盘。
5. **写入规则不变**：能力、只读原因、撤销、保存状态与现在相同。

### 7.2 共同结构

| 部分 | 内容 |
| --- | --- |
| 标题行 | 类型图标、名称（原位改名）、状态（只读原因、外部来源、过期）、这个类型的工具、⋯ |
| 内容 | 类型自己的界面 |
| 底栏 | 数量、分页或加载状态、新建入口 |

同一个编辑器有三种尺寸：嵌在画布上（有边界的框）、数据模式的标签页、手机全屏。手机自由画布上嵌着的是只读的缩略显示，编辑要先“展开”。

### 7.3 表格

**现状。** `TableViewCell` 已有虚拟滚动、分页（每页 200 行）、单击即编辑、字段管理、筛选排序（一个条件加一个排序）、公式显示与物化、底部新建行。在手机上的问题：

- 每列固定 150px，整张表横向滚动；列宽不能调，列不能拖动排序。
- 表格工具按钮是 28×26px，行删除按钮是 26×24px；单元格的评论按钮（现在叫批注）只在悬停时出现。
- 字段管理是一张四列的表，里面是内联的文字按钮和输入框。
- 没有记录表单，没有多选，交互以键盘为主。
- 手机自由画布上表格是只读的缩略显示，没有任何工具。

**要求。**

| 项 | 要求 |
| --- | --- |
| 两种呈现 | **网格**和**卡片**。卡片是每条记录一张：第一个字段作标题，另显示最多三个字段。手机默认卡片，电脑默认网格；可以切换，选择是个人的 |
| 记录表单 | 点卡片（或网格行首的展开按钮）打开一条记录的表单：全部字段纵向排列，按类型给输入控件，必填标记，校验错误显示在对应字段下。手机上是全屏面板，电脑上是侧边面板。可以切到上一条、下一条 |
| 提交方式 | 表单里逐字段提交，与电脑上单元格编辑的语义相同（每次修改是一步可撤销的编辑）。新建记录在点“添加”时一次提交 |
| 新建 | 底部固定的“＋ 新建记录”。手机上总是打开空表单，可以“添加并继续” |
| 字段管理 | 字段列表，每行是名称、类型、显示开关和拖动把手；点一行进入字段详情（名称、类型、选项、必填、默认值、删除）。改类型沿用现有的预检 |
| 筛选排序 | 手机上是底部面板；生效的条件以标签显示在标题行下方，可以单独去掉 |
| 记录的操作 | 表单的 ⋯：评论、复制链接、删除（要确认）。评论入口不再依赖悬停 |
| 多选 | 长按卡片（电脑上勾选行首）进入多选，底部出现操作栏：删除、复制为表格 |
| 网格在手机上 | 第一列固定；点一下选中单元格，再点一下在底部（键盘上方）出现这个值的编辑条。列宽在字段管理里选窄、中、宽 |
| 导入 | 表格的 ⋯ 里有“导入数据…”，文件默认从 Zone 选。现在只能从数据树和主菜单导入 |
| 大表 | 滚动到底自动加载下一页，底栏显示已加载数和总数 |
| 只读与来源 | 外部来源或没有能力时没有新建和编辑入口，标题行说明原因 |
| 公式格 | 显示求值结果，不能直接编辑；“物化”在记录的 ⋯ 里 |

电脑上的补充（不阻塞手机）：列宽拖动、列拖动排序、多个筛选条件。

### 7.4 目录

**现状。** `DirectoryDetail` 是一张四列成员表（名称、类型、大小、操作），支持上传、替换、重命名、移除、下载和内联预览。问题：

- **目录只存在于数据视图里**：没有任何 Block 的 `accepts` 包含 `buckyos.dir`，所以它不能放到画布或流式页上，手机上完全够不到。
- 没有路径导航，点子目录会跳到另一个对象；不能新建子目录；没有多选。
- 每行最多四个文字按钮挤在操作列；移除没有确认；同名文件直接拒绝。

**要求。**

| 项 | 要求 |
| --- | --- |
| 目录 Block | 增加显示目录的 Block，可以放到画布和流式页上，编辑态就是标准编辑器 |
| 导航 | 顶部是面包屑。点子目录在同一个编辑器里进入，点面包屑返回上级 |
| 列表 | 每行是缩略图或类型图标、名称、大小；子目录在前。可以切换成缩略图网格 |
| 添加 | “＋ 添加”：从 Zone 选择（默认，可多选）、从本机上传、新建子目录、加入已有目录 |
| 同名 | 询问：替换、保留两者、跳过 |
| 行的操作 | 每行的 ⋯（长按也可以）：预览、重命名、替换、移动到…、保存到 Zone 或下载（需要 `export`）、复制链接、移除（要确认） |
| 多选 | 长按进入，底部操作栏：移动、下载、移除 |
| 预览 | 手机上全屏，可以左右切换上一个、下一个；电脑上在侧边或下方 |
| 上传 | 每个文件有进度，可以取消；超过大小上限时说明上限是多少（普通文件 32 MiB，音视频 2 GiB）。进度同时出现在状态栏的工作日志里 |
| 空目录 | 显示明确的添加入口 |

电脑上的补充：把文件拖进来上传，拖动行来移动。

### 7.5 其他数据源类型在手机上的最低要求

| 类型 | 要求 |
| --- | --- |
| 富文本 | 流式页上已经可以编辑；补键盘上方的格式条。自由画布上经“展开”编辑 |
| 记录 | 用表格的记录表单 |
| 资产 | 全屏预览；替换时默认从 Zone 选 |
| 宏 | 能查看代码和运行记录，能运行；编辑代码不做手机优化 |
| 待办、日历 | 已有手机适配（详情面板、日程列表、单控件页）。它们各自的弹层和菜单改用框架的底部面板和动作 |

## 8. 工作区权限编辑面板

> owner：管理工作区逻辑分组；管理规则列表。在这里添加规则需要手输入资源路径，要给帮助；更常见的添加入口是在对象树上操作。

权限模型以[权限系统整理需求](../../notepads/aiws-permission-system-prd.md)为准，接口 `acl.*` 已经具备。这里只定义界面。现有的 `PermissionsPanel` 和 `api/legacyGrants.ts` 映射层由它取代。

### 8.1 入口

| 入口 | 打开的内容 |
| --- | --- |
| 数据模式对象树的“工作区权限”节点 | 权限编辑面板，作为一个标签页 |
| 主菜单“协作 ▸ 成员与权限…”、在线成员面板里的同名入口 | 切到数据模式并打开权限编辑面板 |
| 对象树上对象的“权限…”、右侧边栏的“权限”页签 | 这个对象的按实体视图（§8.4） |
| 画布上 Block 的“权限…”、画布选择器里画布或目录的“权限…” | 同一个按实体视图，以侧边抽屉打开，不离开画布 |

权限操作需要联网，不进离线队列，也不进文档的撤销栈（现有规则）。界面按权限版本号（`acl_rev`）实时刷新。

### 8.2 逻辑分组

面板的第一部分是分组列表：

- **固定组**排在前面，带说明，不能删除、不能改 ID：
  - `@owner`：所有者，恒有全部能力，这里只显示。
  - `@all`：能进入这个工作区的所有人。
  - `@guest`：匿名访客，以及已登录但不属于任何组的人。公共匿名访问没有打开时，在这一行标明“当前不生效”，并给出打开的入口。
  - `@creator`：每个对象的创建者。
- **逻辑组**：标题、ID、说明、成员数、规则数。可以新建、改标题和说明、删除。

选中一个组，看到两部分：

| 部分 | 内容 |
| --- | --- |
| 成员 | 列出成员及来源：单个用户、Agent 或外部 DID；BuckyOS 用户组；联系人组；Zone 全体账号；经分享入口加入的人（标明是哪个入口）。可以添加和移除。添加时从候选里选，也可以直接输入 DID |
| 这个组的规则 | 以资源路径组织的条目，可以直接改允许和拒绝，即“按主体编辑它能访问的资源” |

- 带 `manage` 的组及其成员只有所有者能改，其他管理者看到的是只读并说明原因。
- 组不能套组，界面不提供把组加进组的入口。
- 成员按名字显示。用户和 BuckyOS 用户组的名字向 control-panel 取，取不到时才显示原始 ID。

### 8.3 规则列表

面板的第二部分是这个工作区的全部规则。

| 列 | 内容 |
| --- | --- |
| 主体 | 用户、逻辑组、固定组，按名字显示；发布产生的条目单独标明 |
| 资源 | 当前路径，带类型图标；点击定位到对象 |
| 允许 | 能力标签 |
| 拒绝 | 能力标签，用不同的颜色 |

- 可以按主体、按资源路径前缀筛选，可以只看带拒绝的规则。
- **编辑一条规则**：九项能力（`read`、`append`、`update`、`delete`、`structure`、`comment`、`export`、`manage`、`run`）各有三个状态：允许、拒绝、不设置。预设（只读、可评论、可编辑、可管理）是快捷方式，选了之后仍然可以逐项调整。允许和拒绝都清空等于删除这条规则。
- 现有界面在撤销重授时会悄悄覆盖已有的拒绝条目；新界面里拒绝是显式可见、可编辑的。
- 固定组的限制直接体现在界面上：`@all`、`@guest` 不能选 `manage` 和 `run`，`@creator` 不能选 `manage`。

**添加规则**要选主体、填资源路径、选能力。资源路径需要手输入，所以给帮助：

| 帮助 | 内容 |
| --- | --- |
| 输入时补全 | 按树逐级提示：`/data/…`、`/surfaces/…` |
| 从对象树选择 | 输入框旁的按钮打开对象选择器。手机上这是首选方式 |
| 示例 | 输入框下方常显：`/` 整个工作区；`/data/销售` 一个数据文件夹或一张表；`/surfaces/看板` 一张画布；`/surfaces/看板/text-3` 画布上的一个 Block |
| 即时校验 | 解析成功时显示对象的图标、名称和类型；失败时说明是不存在、当前身份读不到，还是个人或会话范围的对象不能授权 |
| 说明 | 规则绑定的是对象本身，改名和移动之后仍然生效；继承按对象当前所在的位置计算 |

**检查权限**：选一个用户和一个路径，逐项列出每个能力是允许还是拒绝，由哪一条规则决定（`acl.query` 的 `explain`）。面板里用一段固定的文字解释判定顺序：离对象最近的一层先决定；同一层里个人规则先于组规则，组规则先于所有人的规则；同一档里有拒绝就拒绝。

### 8.4 按实体的权限视图

这是更常用的入口：先在对象树或画布上选中对象，再看和改它的权限，不用输入路径。

- 列出对这个对象有规则的每个主体：有效能力、来源（本对象、继承自某个上级路径、工作区级）、被哪条拒绝压过。
- 可以直接修改，或“添加”一个主体。资源已经定了，只选主体和能力。
- 绑定了组的宏作为一种来源出现：“经宏 X 可写”，并列出谁能修改宏 X。宏自己的身份设置（绑定的组、并集还是交集）在这个宏的“权限”页签里。
- 没有 `manage` 的人看到的是“我的权限”：自己属于哪些组、对这个对象的每项能力及其来源。

### 8.5 其他

- **匿名访问和分享入口**仍在“分享”对话框里。权限编辑面板里只显示它们的状态并提供跳转。分享入口补上目标组、过期时间和人数上限。
- **操作记录**（`acl.audit`）在面板的右侧边栏。
- **手机**：分组列表、分组详情、规则各占一屏逐级进入；规则以卡片显示；能力编辑是底部面板；资源路径首选“从对象树选择”。
- Desktop 客户端目前只封装了 `acl.set`、`acl.query` 的 `all`、`acl.groups`、`acl.set_group`、`acl.members`、`acl.set_anonymous`，其余接口要补（依赖 K8）。

## 9. 首页

> owner：用卡片的方式列出已有的工作区，点击卡片打开；最近的公开演示 session 也是卡片；分类：最近 / 所有工作区 / 所有公开课；支持搜索和过滤设置；有添加入口和 import 入口；移动端友好。

**现状。** `WorkspaceList` 已经是卡片，但卡片上只有标题、工作区 ID 和提交序号，以及打开、克隆、删除、导出四个按钮；没有搜索、排序和分类，顺序是服务端按 ID 排的；公开课是卡片下方的一个列表；导入是页面底部的内联表单。

### 9.1 结构

顶栏是标题、搜索、过滤设置、“新建”和“导入”；下面是三个分类和卡片网格。

| 分类 | 内容 | 默认排序 |
| --- | --- | --- |
| 最近 | 本人最近打开过的工作区和公开课，混排，最多 20 张 | 最近打开的在前 |
| 所有工作区 | 我能进入的全部工作区 | 最近修改的在前 |
| 所有公开课 | 公开课，即公开演示的 session | 直播中的在前，其余按开始时间倒序 |

- 有最近记录时默认停在“最近”，否则停在“所有工作区”。
- “所有公开课”列出所有我能打开的公开课，卡片上标出我是不是主讲人（已定 Q7）。“能打开”指不凭链接就能进入或回放，以服务端的判定为准。现在的接口只能分别列出“我拥有、主讲或参加过的”和“某一个工作区里的”，需要一个跨工作区、按“我能打开”列出的接口（依赖 K7）。
- UI 改进 §4 的打开与恢复规则不变：Desktop 窗口普通启动时恢复最近的工作区，`/workspace` 地址显示首页。

### 9.2 卡片

**工作区卡片**

| 元素 | 内容 |
| --- | --- |
| 封面 | 画布的缩略图（依赖 K6）。没有封面时用图标加由工作区 ID 派生的底色，保证卡片之间能区分 |
| 标题 | 最多两行 |
| 信息行 | 所有者（不是我时显示）、最近修改时间、我的角色（所有者、可编辑、可评论、只读） |
| 标记 | 已准备离线、已公开、有正在直播的公开课 |
| ⋯ | 在新标签页打开、Clone、导出…、准备离线、详细信息（ID、提交序号）、删除（要确认） |

点卡片的任何位置都是打开。现在卡片正面的 ID、提交序号和一排按钮都收进 ⋯。

**公开课卡片**

| 元素 | 内容 |
| --- | --- |
| 封面 | 舞台画面的缩略图，没有时用默认图 |
| 标题、课件名 | 课件名只有主讲和所有者拿得到，拿不到时不显示 |
| 信息行 | 主讲人、状态（直播中、未开始、已结束可回放、已过期）、时间 |
| 标记 | 我是主讲人时标“我主讲”（已定 Q7） |

点卡片：直播中和未开始的进入，已结束的回放，已过期的不可点并说明原因。

### 9.3 搜索、过滤、新建、导入

- **搜索**在当前分类里按标题、所有者、课件名即时过滤。
- **过滤设置**：
  - 工作区：归属（全部、我创建的、共享给我的）、我的权限（可编辑、只读）、已准备离线；排序（最近修改、最近打开、名称）。
  - 公开课：状态、只看我主讲的。
  - 设置是个人偏好，下次打开仍然生效。
- **新建**打开现有的新建对话框（空白、模板）。“所有工作区”的第一张卡片也是“新建工作区”。
- **导入**打开系统文件选择器（默认面向 Zone）选择工作区包，再选“导入为新工作区”或“恢复”。取代现在页面底部的内联表单。
- 卡片 ⋯ 里的**导出**默认把工作区包保存到 Zone，也可以下载到本机。现在只有浏览器下载。导入和导出在手机上都要能用。
- 访客没有工作区列表；受限账号没有新建和导入（现有规则）。
- 列表取不到时（离线），以同样的卡片显示已准备离线的工作区（现有的离线兜底）。
- 数量多时分批加载，封面懒加载。

### 9.4 手机

- 单列。卡片是横向的紧凑形态：左边小封面，右边标题和信息，一屏至少看到五张。
- 分类是顶部固定的分段控件；搜索收成图标，点开占满顶栏；过滤设置是底部面板。
- 新建和导入是右下角的悬浮按钮。
- 现在卡片的最小宽度是 420px，手机上会横向滚动，改为随容器宽度。

### 9.5 数据缺口

- `ws.list` 每项只有 ID、标题、提交序号、能力，没有所有者、修改时间和封面（依赖 K6）。在此之前，卡片按现有字段显示，“最近修改”排序和所有者不可用。
- “最近”现在每个身份只记一条，存在浏览器本地；而每个工作区有自己的 origin，首页读不到在工作区页面里留下的记录。“最近”这个分类需要服务端按用户记录最近打开时间（依赖 K6）。

## 10. Block 相关的界面

> owner：属性 Panel：同时只显示一个；位置一般在 block 旁边，可以 pin 在屏幕固定位置（比如有人喜欢放在最右边）；有最大高度；可以分节收起，最常用的属性放在第一节。通用 contextmenu。block 自定义 toolbar：action 入口、快速属性编辑。block 有通用 action / 属性。

### 10.1 一个类型向框架声明什么

现在一个类型的界面分散在四个通道里，去向还互相影响：类型没有声明 `toolbar` 时，它的 `actions` 变成工具栏上的文字按钮且不进右键菜单；声明了 `toolbar`，`actions` 就只出现在“更多”和右键里。统一为：

| 声明 | 内容 | 框架用在哪里 |
| --- | --- | --- |
| 动作 | 标识、名称、图标、适用模式、所需能力、显示条件、执行；可以标为“主要” | Block 工具栏（主要动作）、右键菜单（全部）、手机情境窗口（主要动作）、快捷键、宏和 Agent |
| 属性 | 分节的属性表：每项有类型、默认值、校验和编辑控件；可以标为“快速” | 属性面板（全部）、Block 工具栏的快速属性（标了“快速”的） |
| 悬停附件 | 现有：最多一个标签加两个按钮 | 只在鼠标下出现。每个附件按钮必须同时是一个动作，保证触摸设备上也够得着 |
| 自绘的属性节 | 内置类型可以给属性面板提供一节自己画的界面（现有的 `Inspector`） | 属性面板里的一节 |
| 编辑器格式工具 | 现有的 `setEditorToolbar` | 编辑时在 Block 工具栏最前面；手机上在键盘上方 |

- 内置 Block（`BlockDefinition`）、内置控件（`ContainerDefinition`）、扩展控件（`component.json`）使用同一套语义。扩展控件现在能声明 `actions`（只进就近工具栏，图标被忽略）和 `config_schema`（进属性表单）；纳入后，它声明的动作同样进右键菜单和情境窗口，属性可以标“快速”。
- 动作出现在哪里只由“主要”标记决定，不再取决于类型有没有声明工具栏。
- 同一个属性只实现一次。现在形状的外观在工具栏和属性面板里各写了一遍。
- 宿主里按类型名写死的名单改为类型自己声明的能力：能直接打字开始编辑的类型、流式页上不显示标题的类型、流式页上不能插入的类型、工具选择区的对象名单。
- 待办和日历自己的 ⋯ 菜单和弹层改用框架的动作和面板。

### 10.2 属性面板

| 规则 | 要求 |
| --- | --- |
| 同时只有一个 | 整个窗口只有一个属性面板；多选时显示共有的属性。对另一个 Block 点“属性”，面板换成它的内容，不叠出第二个 |
| 默认位置 | 在 Block 旁边：优先右侧，放不下时依次尝试左侧、下方、上方；避开五个工具区和窗口边缘。画布平移或缩放结束后重新定位，过程中不逐帧跟随 |
| 固定 | 面板标题栏上有固定按钮。固定后停在屏幕上的固定位置，默认贴右边，可以拖到别处。是否固定和固定在哪是个人偏好，对所有工作区生效 |
| 最大高度 | 不超过容器高度减去上下工具区，且不超过 560px。超出时面板内部滚动，标题栏不动 |
| 分节 | 每一节可以收起。第一节是“常用”，默认展开；其余各节的收起状态按 Block 类型记在个人状态里 |
| 打开 | 只由“属性”这个动作弹出：点 Block 工具栏或右键菜单里的“属性”（已定 Q13）；F2 是同一个动作的快捷键。选中 Block 不会自动弹出 |
| 关闭 | 没有固定的面板，在选中别的 Block 或取消选中时关闭。固定的面板打开后保持打开，选中变化时换成新选中的内容，没有选中时显示当前画布的页面属性，直到用户点关闭 |
| 写入 | 每次修改是一步可撤销的提交。没有能力或处于查看模式时只读，并说明原因 |
| 手机 | 底部面板，可以上拉到全屏；分节相同 |

**节的顺序**（通用的节由框架提供，类型的节由类型声明）：

| 节 | 内容 | 来源 |
| --- | --- | --- |
| 常用 | 标题；这个类型最常用的属性 | 通用加类型声明 |
| 类型自己的节 | 外观、视图配置等 | 类型声明：现有的 `configFields`、扩展的 `config_schema`、自绘的节 |
| 数据 | 数据源（点击打开）、命名绑定、控件定义（打开定义） | 通用 |
| 布局 | 位置、尺寸、旋转的数值，锁定。只在自由画布上有 | 通用。数值编辑是新增的，现在只能拖动手柄 |
| 交互 | 链接、提示、自定义数据；事件绑定 | 通用，现有的 `MetadataForm`、`EventsForm` |
| 演示 | 放映时可操作；框的背景、备注和说明 | 通用 |
| 诊断 | 实体 ID、数据源 ID、渲染器及版本。默认收起 | 通用 |

现在右侧面板里的“属性”页签取消。固定在右边的属性面板与侧边抽屉占同一个位置：抽屉打开时属性面板暂时让出，抽屉关闭后恢复。

### 10.3 通用右键菜单

所有 Block 共用一个骨架，自上而下：

| 组 | 项 |
| --- | --- |
| 类型动作 | 这个类型声明的动作，主要动作在前 |
| 打开 | 编辑内容、展开、属性 |
| 协作 | 评论、AI（对它许愿） |
| 剪贴板 | 复制、剪切、创建副本 |
| 排列 | 置顶、置底、分组 / 解组、锁定 / 解锁、移动到画布… |
| 关联 | 复制链接、查看数据与依赖、增加视图…、权限… |
| 删除 | 删除 |

- 它与 Block 工具栏的“更多”是同一份列表。
- 按模式和能力过滤：当前模式下没有意义的不显示，缺能力的禁用并说明原因。
- 类型动作现在不进右键菜单，扩展声明的动作也不进；纳入后都在第一组。
- 触发方式：鼠标右键、触摸长按、键盘的菜单键或 Shift+F10、手机情境窗口和流式页标题行的 ⋯。流式页上的 Block 现在没有这个菜单。
- 电脑上超过 12 项时，“排列”和“关联”两组各折成一个子菜单。手机上是可滚动的底部面板。
- 空白处的菜单沿用现有的项（常用对象的快捷插入、添加便签、插入…、已有数据…、粘贴、适应全部），增加“页面设置”。
- 数据模式对象树的右键菜单（§5.2）用的是同一套动作，对象换成数据实体。

### 10.4 Block 工具栏

**组成，从左到右：** 编辑器格式工具（仅编辑时）｜主要动作｜快速属性｜通用区（评论、锁定、AI）｜更多 ⋯

- **主要动作**是类型标为“主要”的动作，以图标按钮出现。这就是 owner 说的“action 入口”。
- **快速属性**是标为“快速”的属性，用紧凑的控件直接改：颜色、枚举下拉、开关、字号。它和属性面板里的是同一个属性，两处显示同一个值。
- 放不下时从右往左收进“更多”（现有）。现在面板类的工具项收进“更多”时会被丢掉，要改成在“更多”里仍然能打开。
- 查看模式下只有适用于查看的动作和评论，没有快速属性。

同一份内容有四种宿主：

| 宿主 | 形态 |
| --- | --- |
| 自由画布（电脑、平板） | 就近工具栏：在选区上方，放不下转到下方，避开工具区（现有的 `NearToolbar`） |
| 流式页 | Block 的标题行（§6.2） |
| 手机上的自由画布 | 情境窗口（§6.4） |
| 数据模式的标签页、手机上的全屏编辑器 | 编辑器标题行里的工具 |

### 10.5 通用动作和通用属性

**通用动作**（每个 Block 都有，按条件出现）：

| 动作 | 条件 | 现在的入口 |
| --- | --- | --- |
| 编辑内容 | 有编辑器，有能力 | 双击、Enter、直接打字 |
| 展开 | 有数据源，或者是数据控件、资产 | 不通用：数据控件的“单独页面打开”、资产的展开与预览、许愿格打开右侧面板 |
| 属性 | 所有 | F2、更多、流式页把手的菜单 |
| 评论 | 有 `comment` | 就近工具栏、右键 |
| AI | 可以插入 | 就近工具栏 |
| 复制、剪切、创建副本 | 编辑模式；手机上没有复制和剪切 | 更多、右键 |
| 锁定 / 解锁 | 编辑模式 | 就近工具栏、右键 |
| 置顶 / 置底 | 自由画布 | 更多、右键、Ctrl+] 和 Ctrl+[ |
| 分组 / 解组 | 多选，或选中的是分组 | 就近工具栏、更多 |
| 移动到画布… | 编辑模式 | 更多 |
| 复制链接 | 所有 | 新增 |
| 查看数据与依赖 | 有数据源 | 更多 |
| 增加视图… | 有数据源 | 更多 |
| 权限… | 所有；没有 `manage` 时是只读的“我的权限” | 新增 |
| 定义为控件… | 非手机 | 更多 |
| 删除 | 编辑模式 | 更多、右键、Delete |

**通用属性**：

| 属性 | 现状 |
| --- | --- |
| 标题 | 有五种入口：属性面板的输入框、流式页的标题行、框的原位标题、形状跟随文本首行、标签的正文。统一为原位改名加属性面板的“常用”节；标题就是正文的类型不变 |
| 位置、尺寸、旋转 | 只能拖动手柄，没有数值；属性面板里只读显示坐标，不显示旋转 |
| 锁定 | 工具栏和右键 |
| 数据源与绑定 | 属性面板里的链接；控件实例的绑定在实例属性里，日历的在它自己的菜单里 |
| 控件定义 | “打开定义” |
| 链接、提示、自定义数据 | 属性面板 |
| 事件绑定 | 扩展实例的属性里 |
| 放映时可操作 | 属性面板里的勾选 |

折叠不做成通用属性：脑图节点的折叠是个人状态，看板列的折叠是实例配置，语义不同，仍由类型自己声明。

## 11. 新需求进入框架的规则

| 新需求是 | 落点 | 要做的 |
| --- | --- | --- |
| 工作区或画布级的一个命令，例如新的导出格式 | 主菜单已有分组的第二级 | 注册动作，声明所属分组 |
| 一种新的可导入文件 | 主菜单“插入 ▸ 从文件导入”；会产生新工作区的，另进首页的“导入” | 注册导入动作 |
| 一个新的 Block 类型 | 工具选择区的“插入…”目录。需要常驻按钮时改 §4.3 的默认名单 | 声明动作和属性；有数据源的提供标准编辑器 |
| 一种新的数据源类型 | 对象树的新建菜单和图标 | 按 §7.1 提供标准编辑器，手机上可编辑 |
| Block 上的一个新操作 | 这个类型的动作 | 声明动作；标了“主要”才上工具栏 |
| Block 的一个新设置 | 这个类型的属性 | 声明属性并放进合适的节；标了“快速”才上工具栏 |
| 一种协作能力，例如投票、跟随视角、语音 | 协作区的非默认项，或情境工具区的一条工具条 | 协作区默认仍是三个按钮 |
| 需要持续显示的状态或后台进度 | 状态栏的条件项，加工作日志的一种条目 | 不新增浮动提示条 |
| 必须由用户处理的问题 | 状态栏上方的告警 | 带处理按钮，不自动消失 |
| 一个列表类的面板，例如搜索结果、任务列表 | 侧边抽屉 | 同时只有一个 |
| 某个工作区专用的入口，例如“今天的日记” | 工作区或画布的工具栏配置，绑定一个宏 | 不改代码 |
| 一个独立的全屏体验 | App 模式或单控件页 | 不新增页面类型 |

**合入前的自检：**

1. 它是哪个动作？标识、名称、图标，不可用时的原因是什么。
2. 手机上从哪里进入，是什么形态。
3. 不靠悬停、右键和键盘能不能完成。
4. 它产生的状态属于共享文档、个人状态还是本窗口。
5. 文案进了 i18n，有测试标识。
6. 有没有新增常驻的工具条、浮层或主菜单第一级。有的话先改本文。

## 15. 验收场景

环境：1440、1024、768 宽的电脑窗口；Pixel 7 仿真（现有 `tests/aiworkspace/mobile.spec.ts` 的方式）。真机（iOS Safari、Android Chrome）在实测之前单列为未验证。

#### 16.3.2 实现层的默认做法

- **外壳。** “页面设置…”打开标题区的图标与背景弹层，没有独立对话框。“自定义工具栏…”只有本画布、本工作区两个范围（“我的”以后加，Q8）。标题区只能整体隐藏或锁定，不能往里加工具项，宏按钮只能放在协作区；情境工具区不在定制界面里。定制写入时没调过顺序就写“追加”（以后内置新增的项仍会出现），调过顺序就写“覆盖”。只有工具区级的锁定有界面。“播放”下拉的末尾合成一项“公开演示与历次演示…”。宏运行成功和等待确认只进工作日志，失败仍弹通知。主菜单不显示图标。主菜单的“成员与权限…”所有人可用（没有 `manage` 的人看到“我的权限”），头像面板里只给管理者。App 模式退出入口的条件包括对当前画布有 `structure`。
- **在线与日志。** 账号在在线列表里显示账号名，自报的称呼只接受访客的。直接授权、但不属于任何组的成员显示为“访客”。只有工作区包导入标为“导入”，PDF、Office、表格、draw.io 导入是普通提交。运行条目的可见范围同 `proc.get`：自己的运行，或对许愿格有写权限。非公开放映的开始和结束只记在内存里，服务重启后没有。在数据模式里报告的“所在画布”是回去时会回到的那张。
- **Block。** 没有数据的纯界面 Block（形状、框）不显示“评论”。流式页标题行除了最多两个主要动作，还放快速属性（§15 第 17 条的“适应方式”是快速属性）。置顶、置底只在自由画布，流式页的“排列”里是上移、下移。锁定、剪切、删除缺能力时禁用并说明原因（原来是隐藏）。电脑上的“展开”打开数据模式里的对象、单控件页或资产预览。
- **画布选择器。** 新建画布默认放在当前画布所在的目录。目录不提供“创建副本”。目录菜单多了“在此新建目录”（手机上建多级目录要用）。搜索结果画布在前、目录在后。按名称排序时目录在前，按数字感知的自然顺序。“最近”指画布成为当前画布，从链接进入和打开工作区时的默认画布都算。
- **数据模式。** 预览标签页只在本窗口，刷新后只恢复固定标签页。空的用户文件夹也显示。新建先弹命名对话框。对象的菜单里也有“新建 ▸”“导入 ▸”，用来实现“成为下一个兄弟”。重命名：有标题的改标题，没有标题的改查找名。手机进数据模式不写入顶层模式，刷新后回到画布。删除确认是模态对话框，被引用时只有“取消”。“放到画布…”只列有 `structure` 的画布。
- **表格。** 网格 / 卡片的选择按设备分开记。列的显示、顺序、宽度：有 Block 时写在 Block 的视图配置里，没有 Block 时存为个人状态。多个筛选条件只有“并且”。去掉了行内删除按钮，删除走多选操作栏或记录 ⋯，都要确认。记录表单是常显的输入框。复制记录链接只在有 Block 时可用。
- **目录。** 长按进入多选，行菜单靠常显的 ⋯。上传每个文件一次提交（各自可撤销、可取消）。同名替换遇到文件夹时改为保留两者。复制链接借用控件的记录链接（`block=&record=`），目录还没放到画布上时提示先放。列表 / 网格偏好所有目录共用一个。
- **权限。** 取消公开只关匿名访问，`@guest` 的规则保留。路径校验不区分“不存在”和“读不到”（服务端有意让两者一样）。分享入口按预设新建的组第一次建立后复用。面板宽度不到 640px 时用逐级进入的窄布局。每次权限版本变化都重读整个大纲，工作区很大时有开销。
- **首页。** “所有工作区”的默认排序是最近打开。在首页“准备离线”准备的是 Zone 主机 origin 上的副本，从 `/workspace` 页面打开的工作区在自己的 origin 上，用不到它。导出到 Zone 时字节经过浏览器，建议服务端以后加交接接口。过滤也作用于“最近”。
- **手机。** 没有设计 / 运行切换：自由画布是查看模式、控件照常运行，流式页是设计态。自由画布上“页面设置”按能力可改。“展开”用独立的全屏宿主（顶栏是返回画布、对象名和这个 Block 的 ⋯），与数据模式的标签页用同一个编辑器但不进标签页。自由画布上导入表格时数据放进 `data` 根目录。draw.io 在手机上单页也新建画布。“用过手写笔”记在本设备。所有对话框全屏。精简主菜单里有“开始放映…”，但手机上没有协作区的“播放”，两处入口不一致。
- **设置与偏好。** 工作区设置要 `manage` 和 `update`。画布只有 `config.toolbar` 要 `structure`，背景和页面尺寸仍只要 `update`。个人偏好按顶层键后写覆盖先写。
