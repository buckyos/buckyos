# BuckyOS AI Workspace 第四期规划

> 状态：阶段规划草案 v0.1，2026-10-08；在第三期对象、编排和 Run 契约稳定后进入详细设计。
>
> 实现基线：仓库提交 `31f51f76` 及本次检查的工作区源码。第三期和本期新增能力均为计划，本文不构成实施完成记录。
>
> 核心目标：**基于第三期的混合演示路线创建公开演示房间，记录演示过程中的全部受支持行为，并在原链接下提供有权限的历史回放、课堂数据和课后交流。**

## 1. 本期定位与继承关系

[第三期规划](<BuckyOS AI Workspace 第三期规划.md>)完成 Frame、Viewport、混合路线、使用引导、当场演示、运行数据隔离和统一状态入口。本期将本地 Run 扩展为服务端管理的 Presentation Session，对齐[演示模式 PRD](<BuckyOS AI Workspace 演示模式PRD.md>)的房间、多人交互、保存及回放目标。

本期继续遵循：

- Frame 主要承载演示页面；Viewport 只定义某张 Surface 上的视觉中心和 zoom。
- `frame1 → frame2 → viewport1 → viewport2 → frame3` 使用同一套步骤和播放器；Viewport 间的平移缩放使用第三期有版本的动画求值。
- 普通复杂画布使用引导不必创建房间。画布市场上架／交易仍是独立产品范围，不因公开演示而建设支付系统。
- 一份作品可以开展多场演示，作品版本、各场运行数据和记录相互可追溯。
- 原生音频只做一路主讲广播和录音，多人交流可以配合外部会议，不建设多人音视频会议或持续录屏平台。

“公开演示”表示具有可分享的房间入口，不等于默认全网匿名可读。观看、互动、保存、评阅、导出及管理权限分别控制。

## 2. 第三期交接要求

| 第三期提供 | 第四期增加 |
| --- | --- |
| Frame、Viewport、路线、稳定 step ID、备注／说明引用 | 固定到房间课件版本，输出角色化数据投影 |
| 目标解析、相机运动纯函数、裁剪与运行覆盖 | 服务端时间线驱动、多端恢复和按时间定位 |
| Run 与本场副本、原作品来源 | Session 生命周期、房间身份、授权和长期索引 |
| 统一动作入口、已确认结果事件、状态序列化 | 服务端事件序列、持久暂存、幂等、快照、资源保留 |
| 主讲者输入、手写、媒体和扩展运行上下文 | 任务授权、独立响应、公共结果发布、回放只渲染 |
| 同机公共投影与提示器 | 跨设备公共大屏、Presenter 平板、观众个人终端 |

已有的 `doc.get_changes` 是文档提交传播机制，不包含全部相机、媒体、指针和内部交互状态，且按当前读权限过滤。因此它可以成为时间线的输入，不能直接暴露为完整 Replay。参见 [workspace.rs](../../src/frame/aiworkspace/store/src/workspace.rs)。

第三期未启用持久记录的 Run，不能在本期通过“发布”凭空补出过去的过程。新公开场次应从开始前启用记录；旧本地成果可以作为新场课件或静态成果分享，但须如实标明没有历史录像。

## 3. 房间与生命周期

### 3.1 Session 最小信息

| 信息 | 用途 |
| --- | --- |
| `session_id`、稳定链接 | 标识本场，不使用原 Workspace 链接冒充 |
| 来源 Workspace、路线及课件版本 | `epoch + seq + snapshot/content_root`，固定本场开始时的内容及编排 |
| 运行数据上下文 | 引用本场副本或等价隔离空间，不覆盖原作品 |
| Owner、Presenter 授权、参与身份 | 管理和现场控制分开，支持 Presenter 与 Owner 不同 |
| 访问／互动／保存策略 | 解释谁能加入、输入、公开结果、归档及管理 |
| 当前权威状态与事件 head | 当前步骤、转场、任务、已发布结果、恢复位置 |
| 记录与资源状态 | 正常记录、缺口、音频状态、待保存及归档 manifest |
| 课后数据入口 | 答案、评阅、讨论、评价与作品历次演示索引 |

建议延续第三期的“课件基线＋本场运行副本”，复用内容寻址资源，避免全量物理复制。它是逻辑隔离方案，不承诺已有 `ws.fork` 一次调用就足够；身份、授权、索引、保存和资源生命周期需要补齐。

### 3.2 生命周期

```text
准备 → 演示中 → 已结束／待保存 → 保存中 → 已归档
```

访问受限和删除是独立管理状态；不能把关闭新观众、结束直播、关闭评论和删除归档做成同一个操作。

- 创建房间生成唯一 Session 和稳定链接；再次授课创建另一场，不覆盖旧场。
- 准备阶段限制观众能看到的内容，不能提前发送老师备注、答案或准备中的草稿。
- 记录在演示开始时启动并持续暂存，“结束后保存”是决定保留和完成归档，不是从最终画面反推历史。
- 结束停止现场任务，但房间暂存仍按政策保留；结束者没有保存权限时等待 Owner 或已授权者处理。
- 保存成功后原链接进入本场回放与讨论；版本改动、重新授课不改变旧链接指向。
- 暂存保留期限、容量和不保存后的房间表现，在本期 M0 明确；不能将未保存场次宣传为长期可用。

## 4. 角色、设备与权限

| 角色／终端 | 可用能力 | 数据投影 |
| --- | --- | --- |
| Owner | 授权、保存、访问管理、导出和删除 | 按管理职责读取 |
| Presenter | 翻页、指针、现场操作、发题、选人、查看答案、发布结果 | 公共状态＋获授权的私有提示器数据 |
| Audience | 观看、跟随／自由浏览、获准反馈、本人作答与结果 | 公共状态＋本人的任务／响应 |
| Public Display | 展示当前公共状态 | 仅公共内容；不因账号也是 Presenter 而切入私有视图 |

Public Display 是终端用途，权限来自身份和受限访问上下文。终端用途必须在刷新、重连时保持；一个设备改成公共显示，不改变同账号平板的用途。

既有权限按实体／子树授予，没有字段／表格行级权限，也没有下级 deny。不能把老师备注和所有人的答案放进一个对观众可读的对象，再在客户端隐藏；不能给观众原 Workspace 的全量 read 后依赖播放裁剪保护数据。参见 [access.rs](../../src/frame/aiworkspace/core/src/access.rs)。

建议采用服务端公共投影＋分作用域的数据访问：

- 备注是独立受限实体；答案按任务和参与者独立保存，只有本人及获授权的主讲／评阅者读取。
- 对老师和学生都需可见的答案不宜直接使用只允许单一 owner 可见的个人 scope；应采用可显式授权的隔离实体或本场数据分区。
- 老师发布答案时，生成本次明确发布的内容版本／公共结果，不因给原始答案授权而将其全部历史、草稿和评语暴露出来。
- 读取、变化流、事件、快照、附件下载和导出都经过相同的权限过滤，避免只保护实时 UI。
- 公共端使用受限凭据／访问上下文，不能把 Owner 会话传给观众。现有同源无沙箱 HTML 扩展不能视为安全边界；本期需确定隔离执行方案，或只发布受控的状态／静态快照。

匿名观看、稳定访客互动及身份恢复另行冻结。“每人仅答一次”的可靠性必须与身份强度相符。

## 5. 跨设备同步与现场互动

### 5.1 同步与控制

服务端维护本场权威状态；控制端提交命令，成功确认后形成单调事件序列。命令具有幂等键和作用域版本，重复发送不重复翻题、占位、提交或结束。

加入和重连先获取有权限的当前快照，再补事件；不能要求新观众从开场逐条执行到当前。控制端断开不终止所有观众的房间，恢复后按服务端状态继续。

观众可停止跟随并自由浏览可见内容，然后回到主讲视角。个人浏览不修改主讲相机。Frame 在各端按舞台尺寸适配，Viewport 在各端保持同一世界中心和 zoom，不因公开广播而变成自动 fit 的对象。

初期建议采用一个活动主控制端，并提供明确接管；是否允许多个 Presenter 同时控制及其冲突策略在 M0 冻结。传输优先复用现有服务能力，依据相机、笔迹和反馈延迟实测决定是否增加实时通道，不预先把传输库当作架构前提。

### 5.2 反馈、弹幕和任务

| 功能 | 要求 |
| --- | --- |
| 位置反馈 | 使用 Surface／对象相对内容坐标，带类型和时间；不把屏幕像素贴到其他页 |
| 弹幕 | 主讲者配置区域、方向和可用策略；接收端可进入纯净模式 |
| 点名 | 明确任务、对象和参与者，授权后才获得输入能力 |
| 限额抢答 | 服务端原子确认名额；重试幂等、不可超额；断线不自动重复分配 |
| 作答 | 选择、文本、手写复用 Block 输入契约；每人独立响应 |
| 结果发布 | 默认只供老师和本人查看；老师选择内容及发布范围 |
| 评阅 | 支持记录判断、评语及需要时的分数；发布由权限控制，不默认加入 AI 批改 |

任务至少包含稳定题目标识／版本、task ID、所属 Session、Block 引用、授权方式、人数上限、提交及修改策略、状态。响应至少包含 task、参与者、内容版本、提交时间与确认状态。

“每场独立作答”和“同一题目每人仅答一次并复用”分别配置。题目改版是否仍为同题、同场重发是否新任务、资格撤销和迟到提交的规则在 M0 冻结；复用时保留原始场次来源，不能假装是本场新提交。

## 6. 全过程记录：覆盖范围和一致性

### 6.1 记录范围

默认记录所有受支持、可观察的演示行为，包括主讲和观众的行为；按作用域保存，而非全部放进公共录像。

| 轨道 | 包含内容 | 默认读者 |
| --- | --- | --- |
| 公共讲解 | Frame／Viewport 切换、相机动画、手动浏览、公共指针／板书、显隐、媒体状态、公开 Block 变化、临时内容、发题和结果发布 | 获准观看本场者 |
| 公开互动 | 位置反馈、弹幕及其位置／生命周期 | 获准观看者；纯净播放可以隐藏效果，原记录仍在 |
| 主讲私有 | 与任务有关的选人、授权、私有评阅及管理状态变化 | 获授权的主讲／管理者 |
| 参与者个人 | 本人的作答编辑／提交、个人浏览及相关状态 | 本人及被授权的管理者；不广播到公共回放 |
| 运行与诊断 | 命令结果、失败、连接中断、媒体缺口、资源与归档状态 | 对应管理权限；不混进公开内容 |

“所有行为”以系统支持的语义和实际呈现状态为边界：既记录离散动作，也记录影响过程的连续状态。记录文本编辑或笔迹时，应保存能还原该阶段的内容变化，不能只存“发生过输入”；个人敏感输入不进入公共轨道。第三方会议内部行为和任意扩展无法观察的内部状态，不在没有采集能力时宣称已被记录。

不逐项记录无关系统按键、浏览器 UI 或用户密码；影响演示结果的输入通过对应组件的状态契约保存。扩展、外部动态数据和媒体在开始前做记录能力检查；缺失能力必须显式降级，归档标明范围。

### 6.2 事件和时间

事件最小公共头：`event_id`、`session_id`、服务端 `seq`、演示相对时间、实际接收时间、actor／参与身份、作用域、类型、关联命令 ID 和 schema 版本。时间线使用统一的单调相对时间；设备采样时间经过校准，不能靠各设备系统时钟直接排序。

相机事件保留 Surface、目标语义、实际起止中心／zoom、开始时间、时长、缓动和算法版本；Frame 还保留当时矩形和必要的舞台上下文。相机、指针和笔迹可以批量记录采样，但必须能重建过程中间状态；丢弃样本时记录精度或缺口，不能无提示只存最后一个点。

事件引用当时已确认的状态和不可变输出。AI、代码、数据查询记录实际结果／资源版本；随机和定时驱动的 Block 需要保存足够的状态或采用快照。点击“运行”本身不足以还原结果。

### 6.3 持久化与恢复

- 本场数据 Commit 与时间线事件建立可恢复关联。建议在提交事务中写出待发布事件，再由记录器消费；采用其他方案时也需覆盖“数据已写、事件未写”的故障窗口。
- 只有成功确认的业务结果进入成功状态事件；失败及未知结果分别记录，重试按命令身份去重。
- 事件、关键快照、媒体分片和资源清单持续落盘，服务重启能恢复已确认范围并报告缺口。
- 快照需要绑定事件 seq、文档提交位置、运行状态及资源版本，保证跳转时读取的是同一时刻。
- 暂存失败时立即显示记录异常；有权限者可选择继续演示并接受不完整记录，不能继续显示“完整记录中”。

## 7. 结构化回放与音频

### 7.1 重建路径

```text
本场固定课件基线
    + 不晚于目标时间的状态快照
    + 快照之后至目标时间的有权限事件
    + 当时的输出、笔迹、媒体及扩展快照
    → 目标时间的画面与交互结果
```

复用第三期目标解析和动画求值。播放、暂停、变速、按时间定位为必需；按 Frame／Viewport 步骤或题目定位作为导航入口。定位到转场中间时计算中间相机；定位到一笔尚未完成时显示相应笔段，不能只恢复落笔后的最终图形。

回放读取历史版本，不读取当前课件、当前动态 URL 数据或当前 AI 输出冒充历史。renderer／动画契约版本需要保留；实现不支持历史版本时使用归档快照或明确缺失提示。

### 7.2 无副作用呈现

Replay 宿主只应用已保存状态，禁止重新运行 AI、执行产生副作用的代码、提交答案或发送业务请求。不能仅把 live 界面的按钮禁用后继续挂载会自动执行的扩展。

复用组件必须有只渲染历史状态的实现；没有这种实现的 HTML Block 使用归档的静态快照／受控媒体替代。回放中的课后评论是新的房间数据，不修改历史事件。未来“再练一次”必须创建新任务上下文。

公共、主讲私有、个人回放分别生成授权投影。权限撤销后停止后续读取，不因事件在历史上曾可见就绕过当前访问控制；已公开的内容版本与之后的私有编辑也必须分清。

### 7.3 音频

内置支持一路 Presenter → Audience 音频，并将实际录得的分片映射到演示时间轴。设备切换、中断、静音和丢片形成明确区间；播放位置或速率变化时内容与音频一起调整。

外部会议可承载多人交流，但不假设 Workspace 自动获得其录音。只有本场实际启用且可用的主讲音源进入归档。传输、编码、OOD 带宽和存储容量在详细设计中测量选型，不在本规划中承诺未经验证的规模。

## 8. 保存、资源保留与长期房间

归档 manifest 至少固定课件基线、事件范围及版本、快照索引、历史输出／资产、音频分片与时间映射、缺失清单和访问策略引用。

保存成功表示声明保留的内容已可靠保存、原链接可读取；部分音频、资源或扩展状态缺失时，只能显示不完整归档。资源保留必须覆盖本场使用的历史图片、媒体、程序结果和 renderer 快照，不能因原作品更新或删除而错误清理。

房间结束后继续支持：

- 时间点感受：保存回放时间和实际发表时间，便于在同一讲解时刻呈现。
- 普通评论：属于本场整体，不强制绑定播放时间。
- 课程评分／建议：独立于学生作答成绩，归属本场。
- 答案和后续评阅：保留原始提交，课后新增评语记录实际时间，不插回历史冒充现场操作。
- 原作品中的历次演示入口：可追溯不同版本、不同场次的记录与反馈。

Owner 可限制观看、关闭新评论或删除房间；这些操作分别生效。删除时清理本场专有资源引用，共享对象由引用保留规则管理，不能误删其他场次或原作品资源。

## 9. 实施工作包

| 阶段 | 内容 | 完成门槛 |
| --- | --- | --- |
| M0：契约与容量基线 | 冻结 Session／身份／权限投影、控制端策略、任务规则、记录覆盖矩阵、暂存及归档格式；测量目标 OOD | 每类行为能指出采集入口、写入目标、记录格式、权限与回放方式 |
| M1：房间与同步 | 创建／加入、稳定链接、公共大屏／提示器／观众、跟随、重连 | 同账号多终端与不同身份不会串视图、串数据；服务端状态可恢复 |
| M2：互动和持续记录 | 反馈、弹幕、任务、独立响应、结果发布；从开始持续记录上述行为 | 并发名额不超额，私有数据不泄露，数据提交与事件可对账 |
| M3：保存与回放 | 版本基线、快照、资源归档、音频、时间定位、无副作用 Replay | 同链接恢复历史，中途定位正确，原作品改版不改变旧场 |
| M4：长期房间与可靠性 | 讨论、评价、评阅、历次记录、访问撤销、容量／弱网／异常恢复 | 完整 PRD 主线和关键异常通过，有实际环境与容量证据 |

记录器随 M1 的基本动作开始接入，M2 扩展事件类型；不能先上线完整多人互动，再到 M3 才尝试补采集。各阶段为依赖顺序，不是工期承诺。

## 10. 验收与需要冻结的选择

| 编号 | 场景 | 必须成立的结果 |
| --- | --- | --- |
| P4-01 | 同一课件启动两场公开演示 | 链接、参与者、答案和事件相互独立，可由作品追溯 |
| P4-02 | 平板提示器、公共屏、多个观众加入与重连 | 角色与终端用途正确；公共网络响应、事件和附件都不包含私有备注／答案 |
| P4-03 | 混排 Frame／Viewport、动画中断、自由浏览和返回跟随 | 直播和回放保留正确中心／zoom、步骤与转场；个人浏览不拖动主讲 |
| P4-04 | 超过名额的观众同时抢答并重试，题目同时结束 | 名额不超额、不重复；迟到和撤销结果明确，答案不丢、不互相覆盖 |
| P4-05 | 答案先私有、随后发布一份，再私下修改评语 | 观众只看到被发布的版本；无法由历史流／快照读取其他内容 |
| P4-06 | 反馈、弹幕、板书、媒体和 AI 输出出现在同一段时间线 | 可重建过程；纯净模式只隐藏氛围效果；回放不运行原业务 |
| P4-07 | 直接定位到动画／笔画／媒体播放的中间 | 状态与可用音频对齐，不要求从开头逐项观看 |
| P4-08 | 原课件升级，外部数据变化，原资产失效 | 优先使用已归档历史资源；缺失如实显示，不以当前资源替代 |
| P4-09 | 服务在 Commit 后、事件发布前崩溃 | 恢复后无重复业务结果，事件可补齐或准确报告缺口 |
| P4-10 | 主讲者断线、音频中断、暂存／保存空间不足 | 其他终端按策略继续；缺口明确；不宣称完整保存成功 |
| P4-11 | Presenter 无保存权限而结束，Owner 后续保存 | 权限分离；原链接进入正确归档，不擅自发起新场 |
| P4-12 | 回放时评论、评分、追加评阅，再撤销访问或删除房间 | 课后内容与原时间线分开；后续读取受当前权限控制，其他场次不受误删影响 |

本期实施前需要冻结的选择：匿名／访客身份及恢复、活动控制端与接管、题目版本与答案复用、迟到提交和抢答资格回收、未保存暂存期限、记录保留／删除政策、扩展隔离方案、音频传输与存储，以及目标并发、状态延迟、音画容差、回放定位耗时和容量上限。

这些待选项不改变“本场独立、按权限记录全部受支持行为、保存后原链接回放”的目标。验证应覆盖真实 OOD／Zone、服务重启、弱网、不同尺寸设备和真实媒体；仅通过单机浏览器测试不能宣称公开演示已完成。
