# 连接线：实施记录与验收报告

> 日期：2026-10-07。对应设计：[连接线实现方案讨论](<连接线实现方案讨论.md>) v0.3（C0–C4），以及 [标准对象的交互改进](<标准对象的交互改进.md>) §6（S4）。
>
> 环境：独立运行的 `aiworkspace` 服务（调试构建）+ Vite 开发服务器，Desktop 外壳使用模拟运行时，Chromium（Playwright，无 GPU 光栅化）；性能探针跑在生产构建（`vite preview`）上。没有在 DV 或真实 Zone 上运行。

## 1. 结论

连接线已经实现。它是 `view.type = connector` 的 Cell：外框加 `flip` 给出两个存储端点，端点可以绑定到对象的连接点（`auto` 或 `point`），三种路由（直线可加折点、直角、曲线）都可以编辑控制点，标签可以沿线拖动，外观有线帽、线型、粗细、颜色。标准对象的交互改进 S4 一并实现：选中对象的四个连接柄、连接线工具（L）、端点吸附、端点 / 折点 / 线段 / 标签手柄、松开在空白处的“下一个对象”小目录、拖动到画布边缘时自动平移。

与设计的差异记在设计 §14（14-1 至 14-23）。其中需要注意：

- **版本**：只把 `PROTOCOL_VERSION` 升到 0.3，`FORMAT_VERSION` 保持 0.3（14-1）。已有的 0.3 工作区和导出包照常打开；本次升级前打开的标签页会提示“请刷新页面”。
- **一处原有的性能问题被一并修掉**：Block 外框上的两条 `:has()` 样式规则，使画布上任何一处 DOM 变化都要重新检查所有外框，重新计算样式要慢约 5 倍。改为由 RenderHost 在外框上写 `data-chrome` / `data-view` 属性。1,000 个 Block 的拖动，最长一帧从 117ms 降到 33ms（§5）。

## 5. 性能探针

`probe.spec.ts` 跑在生产构建上；下表为关闭 Playwright 跟踪（`--trace=off`）后的一次运行。跟踪开启时，Playwright 每个动作都抓 DOM 快照，会在大画布上额外制造 40–60ms 的长任务，所以探针数字以关闭跟踪为准。帧时间单位 ms，“拖动”列为 p50 / p95 / 最大 / 长任务数。

| 场景 | 首屏 | 平移 p95 / 最大 | 拖动 |
| --- | --- | --- | --- |
| 1,000 Block（无线） | 359 | 16.8 / 16.8 | 16.7 / 33.3 / 33.4 / 1 |
| 5,000 Block（无线） | 1329 | 16.7 / 16.8 | 16.7 / 33.3 / 300 / 5 |
| 1,000 Block + 1,000 条线（打开时的视图，54 条线可见） | 830 | 16.7 / 16.8 | — |
| 同上，适应全部（1,000 条线全部可见） | — | 16.8 / 400（4 个长任务） | — |
| 拖动连着 200 条线的对象（200 条线逐帧重新路由） | — | — | 16.7 / 16.8 / 317 / 2 |
| 三个画布切换 | 396 / 183 / 118 / 109 | — | — |

- 逐帧开销在预算内：200 条线逐帧重新路由时 p95 仍为一个刷新周期。
- 剩下的长帧只出现在手势开始和结束时，并且画面上有大量线：画布世界层进入和退出 `will-change: transform` 时，无 GPU 的 headless Chromium 要重新光栅化整个画面。真实浏览器有 GPU 光栅化，这部分会短得多，但没有在真机上测。
- 与修改前（标准对象的交互改进报告 §4）相比：1,000 Block 拖动最长一帧 117 → 33，5,000 Block 首屏 1521 → 1329，主要来自 §1 所说的 `:has()` 修正。
- 一个 200 条线外框都覆盖的点上，浏览器自身的命中测试约 1.2ms 一次（没有线时 0.05ms）。画布的命中是几何计算，不依赖它；这是外框 `z-index` 带来的层叠上下文开销，记为已知。

## 6. 实测中发现并修正的问题

| 问题 | 后果 | 修正 |
| --- | --- | --- |
| 第一次点击选中线后，中点的虚拟手柄出现在原处，接住了双击的第二次按下；按线身时调用 `preventDefault` 也会吞掉 dblclick | 双击线不能编辑标签 | 画布自己识别“两次按下”（400ms、8px 内），线身按下不再 `preventDefault`（方案 14-18） |
| 标签默认在线的中点，与中点虚拟手柄重叠 | 拖标签变成了加折点 | 标签框下不显示虚拟手柄（14-19） |
| 删除提交返回后清空整个选区 | 删除过程中点选的对象被清掉（原有竞态，加了冻结读取后更容易出现） | 只把被删除的对象移出选区（14-15） |
| 删除路径重构后，锁定检查调用了两次 | “已锁定”提示出现两次（OX08 用例失败） | 只计算一次 |
| 400 个挂载上限也作用于线 | 缩小到能看到很多对象时，超出部分的线消失 | 线不计入上限 |
| Block 外框上的 `:has()` 规则 | 线框重绘或任何外框内的变化都会重新检查所有外框，重算样式慢约 5 倍 | 改为外框属性 `data-chrome` / `data-view` |
| 垂直线的标签按外框宽度换行 | 每个字一行 | 标签宽度取内容宽度（最宽 240） |
| 测试辅助：`getScreenCTM()` 在 React 替换 SVG 内容后的瞬间偶尔返回单位矩阵 | 用例点到了世界坐标（误判为失败） | 用外框位置与 viewBox 换算 |
