## 1. 结论

**连接线是一个内置的标准对象。它有两个端点，每个端点要么是某个对象上的连接点，要么是一个坐标。两端都是坐标时，它就是一个普通的矩形对象。折线和曲线的控制点、标签位置都保存在对象的数据区（payload）。**

- **对象：** 类型为 `buckyos.cell`，`view.type = connector`。它和框、形状一样是纯 UI Block，没有数据源（已定）。
- **几何：** 树边上的 `placement` 是两个端点存储位置的外框，方向由 payload 中的 `flip` 说明。这相当于 PowerPoint（OOXML）连接线的 `xfrm` 加 `flipH`/`flipV`（已定）。
- **绑定端：** 渲染在目标的连接点上。目标移动时只重新解析，不写连接线。
- **路由：** 首版支持三种路由（直线可加折点、直角折线、曲线），并且可以编辑控制点。如果首版只做直线，控制点的坐标系和变换规则很容易做错（已定）。
- **写入路径：** 整体移动、拖动坐标端点、分组、解组、剪切粘贴、移到其他画布，都沿用现有的布局路径，权限和并发规则与普通 Block 相同（第二期 D1）。只有绑定、控制点、标签和外观会写 payload。

视觉上的箭头不代表许愿格输入、数据依赖或执行顺序；这些业务关系继续使用各自的契约。[第二期规划](<BuckyOS AI Workspace 第二期规划.md>) §1 和 D10 主动延后了连接线，[第二期验收报告](<BuckyOS AI Workspace 第二期实施记录与验收报告.md>) §7 记录它尚未实现。

## 3. 范围与模型选择

### 3.1 首版范围

- 在自由画布上创建、选择、删除、复制、移动和编辑连接线；查看模式和演示模式只显示。
- 端点可以是坐标，也可以绑定到对象的连接点。端点可以重新绑定或解绑，并跟随目标的移动、尺寸变化和所在分组的移动。
- 路由支持直线（可加折点）、直角折线和曲线。控制点可以编辑，也可以重置为自动路由。
- 外观支持两端线帽、线型、粗细、颜色，以及一个可沿线拖动的文字标签（§5）。
- 与提交、权限、撤销、离线、导入导出一起交付。

### 3.2 后续扩展

- 由对象 Renderer 声明的具名连接端口
- 连接线之间的绑定
- 自动避障、交叉处跳线
- 跨 Surface 的连接
- 多个标签、富文本标签
- 触摸编辑
- 许愿格直接生成连接线
- 把线显式转成业务关系

### 3.3 模型比较

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A：几何全部放在 payload，线不写 placement（v0.1） | 整体移动、改父容器、分组等操作都要额外写 payload，需要 `update` 权限和 expect，违背 D1 | 放弃 |
| B：把 placement 扩展为几何联合类型 | 布局语义好，但端点引用要在树操作中维护 | 放弃 |
| C：矩形 placement，加上 payload 中的方向、端点和控制点 | 两端都是坐标时就是一个矩形对象；结构操作全部沿用现有路径；引用仍从 payload 提取 | **采用（已定）** |
| 独立实体类型 `buckyos.connector` | 类型身份更清楚，但要扩展类型表、树规则和前端的类型过滤 | 不采用（已定） |

## 4. 数据契约

### 4.1 示例

```json
{
  "op": "entity.create",
  "entity_id": "connector-1",
  "type_id": "buckyos.cell",
  "parent_id": "surface-main",
  "order_key": "m",
  "placement": { "x": 320, "y": 180, "w": 320, "h": 60 },
  "payload": {
    "view": { "type": "connector", "version": 1 },
    "title": "下一步",
    "start": { "entity_id": "cell-a", "anchor": { "kind": "point", "x": 1, "y": 0.5 } },
    "end": null,
    "route": "elbow",
    "controls": [{ "u": 0.5, "v": 0 }, { "u": 0.5, "v": 1 }],
    "label": { "t": 0.5, "offset": 0 },
    "config": { "stroke": "#64748b", "width": 2, "dash": "solid", "start_cap": "none", "end_cap": "arrow" }
  }
}
```

在这个例子中：

- 没有 `flip`，所以起点是外框的左上角，绑定到 `cell-a` 的右边中点。
- 终点是外框的右下角 (640, 240)，是一个坐标端点。
- 两个控制点构成一条“先水平、在两端的水平中点处竖直转折、再水平”的直角折线。

### 4.2 字段

| 位置 | 字段 | 说明 |
| --- | --- | --- |
| 树边 | `placement {x, y, w, h}` | 两个端点存储位置的外框，相对父容器。连接线必须有 placement，`w`、`h` 不小于 0 |
| payload | `flip` | `{ h, v }`，省略表示都不翻转。默认起点在左上角、终点在右下角；`h` 表示水平翻转，`v` 表示垂直翻转（同 OOXML） |
| payload | `start`、`end` | `null` 表示坐标端点，位置就是对应的角；绑定端点为 `{ entity_id, anchor }` |
| payload | `route` | `straight`（默认）、`elbow`、`curve` |
| payload | `controls` | 控制点数组，见 §4.4；为空表示自动路由 |
| payload | `label` | `{ t, offset }`，标签位置，见 §4.5；省略时为 `{ t: 0.5, offset: 0 }` |
| payload | `title` | 标签文字，沿用 Cell 的 `title` |
| payload | `config` | 外观属性（§5），由前端注册表校验，core 只限制大小（D6） |

这些字段是相互独立的 payload 键，两人分别修改不同的键时可以自动合并。

### 4.3 端点、连接点与绑定规则

**存储位置。** 每个端点都对应外框的一个角，这个角就是它的存储位置。

- 坐标端点的位置就是这个角。
- 绑定端点的存储位置，是最后一次写这条线时（通常是绑定时，或者目标在本窗口被删除时）的位置。只有在目标不可用时才会用到它。

**连接点（anchor）。**

| 形式 | 含义 | 参考 |
| --- | --- | --- |
| `{ kind: "auto" }` | 浮动连接：从目标中心指向另一端参考点的线段，与目标外形的交点就是连接点。另一端是坐标或固定连接点时，参考点是那个位置；另一端也是 auto 时，参考点是另一端目标的中心。目标或另一端移动时，连接点沿外形滑动 | tldraw 的非精确绑定（`isPrecise: false`）、draw.io 不设 `exitX` 时的浮动连接、FigJam 的 magnet `AUTO`、Miro 的 `snapTo: auto` |
| `{ kind: "point", x, y }` | 固定连接点：目标布局矩形内的归一化坐标，取值范围 `[0, 1]`。拖到对象上时吸附到四边中点（例如 `(0.5, 0)`），也可以放在任意边缘或对象内部 | tldraw 的 `normalizedAnchor`、Excalidraw 的 `fixedPoint`、draw.io 的 `exitX`/`exitY`、Miro 的 `position` |

- 默认使用 `auto`。
- 目标的外形由它的 Renderer 声明（矩形或椭圆，未声明时按矩形处理），`auto` 与这个外形求交。形状 Block 的椭圆首版就支持。
- 具名端口（类似 OOXML 的连接点序号、React Flow 的 handle）留到后续，届时新增一种 `kind` 即可。

**绑定规则。** 新建或改变绑定时由 core 校验：

- 目标必须是同一 Workspace 内存活、可读的 Cell 或 UI Group，并且和线在同一个自由 Surface 上。
- 可以跨 Group 连接，也可以绑定线所在的祖先 Group：Group 的位置是显式保存的，不会形成循环。
- 不能绑定数据树实体、Surface 本身、线自己或其他连接线（线连线留到后续）。
- 两端绑定同一个对象（自环，例如状态图里的自转移）时，两端都必须是 `point` 连接点且位置不同，路由也不能是 `straight`。
- 绑定的是 Block，不是数据：同一份数据的不同视图在画布上的位置不同。

### 4.4 控制点

**用途。**

- `straight`：控制点是折点，线依次经过这些点，形成任意角度的折线。
- `elbow`：控制点是直角拐点。
- `curve`：控制点是曲线经过的点。

**坐标系（端点系）。** 设解析后的起点为 S、终点为 E（世界坐标）。控制点存为 `{ u, v, dx?, dy? }`，对应的位置是：

```text
P = ( Sx + u·(Ex − Sx) + dx ,  Sy + v·(Ey − Sy) + dy )
```

**写入时的规范分解。** 每个轴分别处理：

- 如果该轴上 p 位于 S 和 E 之间，并且跨度不小于 1，则 `u = (p − S) / (E − S)`，`d = 0`。
- 否则取该轴上较近的端点，`u` 取 0 或 1，`d` 等于 p 与该端点坐标之差。

每次写 `controls` 时，都按当时的解析端点重新分解全部控制点。

**由此得到的行为。**

- 整体平移时，控制点跟着平移。
- 拖动端点或绑定目标移动时，位于两端之间的控制点按比例伸缩；位于两端之外的控制点（绕行部分）与较近的端点保持固定距离。
- 与某个端点在同一轴上对齐的点（`u` 为 0 或 1、`d` 为 0）始终保持对齐。同一次分解中共享 x（或 y）的两个点，之后也仍然共享。所以无论端点怎么变，直角折线都保持直角。
- 跨度为 0（水平线、垂直线、两点重合）时不会退化。

各工具的控制点存储方式对照见 §5.1。这里的比例部分与 PowerPoint 的 `adj`（外框比例）和 tldraw 的 `elbowMidPoint` 一致；绕行偏移则弥补了“只按比例存储”在零跨度和绕行时不够用的地方。与 draw.io 的绝对坐标折点不同，端点移动后折点会随之调整，而不是停在原地。

**自动路由。** `controls` 为空时，由前端路由器计算路径：

- `elbow`：按两端连接点的出入方向生成直角路径；坐标端点的方向按两端的相对位置推断。
- `curve`：生成沿出入方向的三次贝塞尔曲线。
- `straight`：一条直线。

用户第一次拖动线段或曲线时，先把当前的自动路径物化成控制点再修改。“重置路由”会清空 `controls`。

**渲染规则。**

- `elbow` 中相邻两点不在同一轴上时，补一个拐点以保持直角。
- `curve` 用经过各点的平滑插值（例如向心 Catmull-Rom 转三次贝塞尔），首末段的切线沿连接点的出入方向。
- 端点变化很大时，用户的控制点可能让首段先折回对象内部。首版保留用户的控制点（与 draw.io 保留折点的做法一致），由用户“重置路由”解决，不做静默重算。

**确定性。** 路由和插值都是前端纯函数，所有客户端算出的结果相同。这些算法属于 `connector@1` 的一部分；如果算法变更会改变已有文档的外观，必须提升 `view.version`。

**限制。** 最多 64 个控制点；没有折点的 `straight` 用空数组。

### 4.5 标签

- **文字：** 使用 Cell 的 `title`，最多 256 个字符，允许换行。
- **位置：** `label.t` 是沿渲染路径的弧长比例，取值范围 `[0, 1]`。`label.offset` 是垂直于路径的偏移（世界单位，正值在行进方向的左侧）；拖动时如果离路径不超过 6 个屏幕像素，就吸附回 0。控制点变化后，标签仍在同一比例的位置。
- **排版：** 文字始终水平排列。默认在标签框处断开线段（tldraw、Excalidraw 的做法）；`config.label_fill` 可以改为加底色（draw.io、React Flow 的做法）。字号、颜色等外观属性见 §5.2。
- **参考：** 沿路径 0–1 比例是 tldraw、Excalidraw 和 Miro 的共同做法；垂直偏移参考 draw.io 边标签的 `y`，以及 Miro 的 `textAlignVertical`（线上方、线上、线下方）。

### 4.6 core 校验

- 连接线专用键（`flip`、`start`、`end`、`route`、`controls`、`label`）只在 `view.type = connector` 时有效。连接线不能带 `source_ref`、`bindings` 或 `def_ref`。
- 创建后不能把 `view.type` 改成 `connector` 或从 `connector` 改走，否则同一个对象会在矩形和线之间来回切换。
- 对连接线，`entity.create`、`tree.move`、`tree.place` 中的 placement 必须存在且为有限数值，`w`、`h` 不小于 0；两端都是坐标时，外框不能缩成一个点；拒绝 `placement: null`。普通 Block 的规则不变。`check_placement` 需要知道对象类型，这三个入口都能取到。
- 所有数值必须有限；`controls` 最多 64 个；`label.t` 在 `[0, 1]` 内；`flip` 只能包含布尔值 `h`、`v`。
- 导入时沿用“写严读宽”：目标缺失或不在同一 Surface 的端点原样保留，作为失效端点。

## 5. 外观属性：主流工具对照与首版取值

调研对象共八个：tldraw、Excalidraw、draw.io（mxGraph）、Miro REST API、FigJam 插件 API、JSON Canvas 1.0、React Flow（xyflow）、PowerPoint（OOXML `p:cxnSp`）。2026-10-07 依据它们各自的源码、规范或 API 文档核对，来源列在 §13。

### 5.1 对照

| 属性 | 各工具的做法 | 共识 |
| --- | --- | --- |
| 端点与连接点 | **归一化坐标：** tldraw `normalizedAnchor`（0–1），加 `isPrecise`（为 false 时对准对象中心）；Excalidraw `fixedPoint`（0–1）；draw.io `exitX`/`exitY`（0–1），不设时为浮动并投影到外形；Miro `position`（0–100%）。<br>**按边或自动吸附：** Miro `snapTo: auto/top/right/bottom/left`；FigJam `magnet: AUTO/TOP/LEFT/BOTTOM/RIGHT/CENTER`；JSON Canvas `fromSide`/`toSide`。<br>**具名端口：** React Flow 的 handle、OOXML 的连接点序号 `idx`。<br>**自由端点：** tldraw、Excalidraw、draw.io、FigJam 支持；Miro、JSON Canvas、React Flow 要求两端都连到对象 | 外框内的 0–1 坐标，加上“自动／浮动”方式 |
| 路由 | tldraw `kind: arc/elbow`；Excalidraw 尖角、圆滑和 `elbowed`；draw.io `edgeStyle`（`none`、`orthogonalEdgeStyle`、`elbowEdgeStyle` 等）加 `curved`；Miro 和 FigJam 为直线、直角、曲线；React Flow `default`（贝塞尔）、`straight`、`step`、`smoothstep`、`simplebezier`；OOXML `straightConnector1`、`bentConnector2–5`、`curvedConnector2–5` | 直线、直角、曲线三类 |

## 6. 端点引用与生命周期

### 6.1 引用

`entity_refs` 从 `start`、`end` 中提取 `kind = connector_endpoint` 的引用，用 `src_selector` 的 `{ kind: "connector_end", end: "start" | "end" }` 区分两端。

- 不阻止目标删除：它不在 `blocks_delete` 的白名单中。
- 不参与新鲜度计算。
- `doc.relations` 会把它列在目标的入向引用中。

### 6.2 失效与恢复

| 事件 | 行为 |
| --- | --- |
| 目标移动、改变尺寸，或所在 Group 移动 | 重新解析端点，不写线 |
| 在本窗口删除目标 | 在同一次删除提交中，用 `tree.place` 把相连线的对应角写为当前位置，绑定保留。此后该端以失效状态显示在删除时的位置。如果对线的父容器没有 `structure` 权限，就跳过这一步，回落到原来的存储位置 |
| 远端或通过 API 删除目标 | 使用存储位置，也就是最后一次写线时的位置 |
| 撤销删除、恢复目标 | 绑定自动恢复；撤销时冻结写入也一并还原 |
| 目标被移到其他 Surface | 端点失效（`off_surface`），使用存储位置，不跨画布追踪 |
| 目标对当前用户不可读 | 显示为“端点不可用”，使用存储位置，不读取目标的位置、名称和内容 |
| 用户解绑 | 端点改为坐标，同一次提交写入当前解析位置 |

失效端点在编辑模式下显示为空心标记，并提供“重新连接”；在查看和演示模式下，按普通线端显示。

替代方案是删除目标时连带删除相连的线。这需要对线有 `delete` 权限，一次撤销也能全部恢复。推荐“冻结”，因为它不会删除用户没有选中的对象（R3）。

### 6.3 权限与导入导出

- 能读线，不代表能读目标。解析器只使用读模型中可读的目标，不复制目标的标题或内容。存储位置和标签属于线自身的内容。
- 新绑定必须通过 `check_ref_target`（目标存活且可读），不能用任意 ID 绕过 read 检查。
- 导入包可以带失效端点：`check_deferred_refs` 只检查会阻止删除的引用，与现有规则一致。
- 导出时不会为了补齐端点，而带出无权导出的目标。

## 7. 提交、并发与权限

| 动作 | 操作 | 权限与并发 |
| --- | --- | --- |
| 创建 | `entity.create`（含 placement） | 父容器的 `structure`；绑定目标必须可读 |
| 拖动整条线（坐标端随之平移；两端都绑定时禁用） | `tree.place` 写 placement | 父容器的 `structure`；自动合并（D1） |
| 拖动坐标端点 | `tree.place` 写 placement；越过另一端所在的轴时，同批 `set_keys flip` | 同上；`flip` 带 expect |
| 绑定、换绑 | `set_keys start/end`，同批 `tree.place` 把该角写为当前位置（以及 `flip`） | 线的 `update`，加父容器的 `structure` |
| 解绑 | `set_keys start/end` 设为 `null`，同批写入当前位置 | 同上 |
| 改路由、编辑控制点、重置路由 | `set_keys route/controls` | 线的 `update`，带 expect |
| 拖动标签、改外观和文字 | `set_keys label/config/title` | 线的 `update`，带 expect |
| 调整层叠 | `tree.place` 写 order_key | 沿用现有规则 |
| 分组、解组、剪切粘贴、移到其他画布 | 现有的 `tree.move`/`tree.place`，只换算 placement | 沿用现有规则，payload 不变 |
| 删除、恢复 | `entity.delete`/`entity.restore` | 沿用 `life_rev` 检查 |
| 移动绑定目标 | 只写目标自己的布局 | 不需要对线有任何权限 |

- **提交粒度：** 一次手势只产生一次提交；按 Esc 取消时不提交。
- **并发：** placement 沿用 D1，后到者生效，被覆盖的一方会得到提示并可以重新应用。例如一人拖动坐标端点、另一人同时重新绑定，后者写入的 placement 会覆盖前者。payload 的各个键都带 expect，同一个键被并发修改时会产生可见的冲突。
- **权限：** 现有的权限预设（编辑者、管理者）同时包含 `update` 和 `structure`。自定义权限只有其中一个时，UI 按动作分别判断，不能直接用 `canLayout` 放开所有操作。
- **批次顺序：** 同一批次中，绑定目标必须在连接线之前创建。这与 `source_ref`、`bindings` 的规则相同；不新增“按批次最终状态检查”的机制。
- **内容 ObjectId：** 线的 payload 变化会改变内容 ObjectId；整体移动和拖动坐标端点只改 placement，不改内容，这一点与普通 Block 相同。

## 8. 复制、分组、跨画布与流式页

### 8.1 复制和粘贴

规则：**只保留复制集合内部的绑定**。同一条规则适用于所有画布；而且不会出现粘贴后与原线完全重合、看起来像什么都没发生的情况。

| 场景 | 结果 |
| --- | --- |
| 同时复制 A、B 和 A→B 的线 | 新线绑定新的 A 和新的 B |
| 只复制节点 | 不复制未选中的线 |
| 只复制线 | 两端都改为坐标端点，位置取复制时的解析位置，并随粘贴偏移 |
| 复制 A 和线，不含 B | 起点绑定新的 A；终点改为坐标，位置取复制时的解析位置 |
| 粘贴到其他自由画布 | 同上，这条规则不区分画布 |
| 粘贴到流式页 | 拒绝包含连接线的粘贴，并说明原因 |

实现要点：

- 先为整个复制集合预分配 ID，再生成操作；节点和 Group 的创建排在连接线之前。
- 端点改为坐标时，同时重算 placement 和 `flip`。
- 剪贴板保存复制时的解析位置，不修改原线。

剪切粘贴保留实体身份。线和目标一起移动、并且仍在同一个 Surface 上时，绑定保持不变；只移动其中一方时，按 `off_surface` 处理。

### 8.2 分组、解组和移动

- 连接线在 `laid` 中的条目以存储外框作为 `rect`（§9.2）。因此，现有的分组、解组、剪切、移到其他画布这些从 `rect` 换算 placement 的代码，对线照常工作。
- 控制点和绑定不受父容器变化影响，因为端点系是相对解析端点定义的。
- 分组外框、适应全部等用于显示的地方，改用线的解析外框。
- 移动 Group 时，组内的坐标端点随父坐标一起移动；绑定端点只按目标的最终位置解析，不再叠加一次 Group 的位移。

### 8.3 流式页

流式页不显示连接线。

- core 只要求创建和新绑定发生在自由 Surface 上。
- 之后如果 Surface 被改为流式布局（目前只有 API 能改），或者线被移入流式页，都不做预检：线的数据保留，只是不渲染；改回自由布局后恢复显示。
- UI 中的粘贴、移到画布等入口，对流式页拒绝连接线。

这样就不需要在 `tree.move`、布局切换等入口扫描子树。

## 9. 画布宿主与渲染

### 9.1 计算归属

- **core／WASM：** 字段校验、placement 规则、绑定目标与权限、引用索引、导入和副本。core 不计算路径。
- **前端几何模块（新增，纯函数）：** 连接点解析、与外形求交、端点系分解、三种路由器、路径、弧长、包围盒、点到路径的距离。
- **前端布局：** 两遍布局，以及“目标 → 连接线”的邻接索引。
- **RenderHost：** 绘制、命中、裁剪、LOD、手柄和手势预览。
- **Block 注册表：** 目录项、属性面板和动作。

### 9.2 两遍布局与读模型

1. 第一遍用现有的 `layoutSurface` 计算 Cell 和 Group 的世界矩形。
2. 第二遍解析连接线：先由存储角（placement 加 `flip`，换算到世界坐标）得到两端位置，再把绑定端替换为目标矩形上的连接点，然后路由，得到路径、包围盒、标签框和端点状态。

连接线也放进 `laid`，但带两个外框：

- `rect`：存储外框的世界矩形，供所有写 placement 的路径使用。
- `bounds`：路径加上线宽、线帽和标签，供空间索引、裁剪、命中、LOD、选中框、就近工具栏和适应全部使用。

条目中还带 `path` 和端点状态。`relativeTo` 对线不再把宽高钳到 1。

Rust 的 `outline_extras` 和 TS 的 `extras` 都要投影 `flip`、`start`、`end`、`route`、`controls`、`label`，并把这些键加入增量补丁识别的键列表；不投影 `config`。命中容差取“屏幕像素下限”和“最大线宽的一半”中的较大值，因此不依赖 config。

### 9.3 层叠顺序（P0，已实施）

**修复前：**

- RenderHost 按 `computeMounts` 的结果顺序输出帧（按到视口中心的距离排序），`zIndex` 取树深度。
- 命中测试按深度加同级 order_key 判断。
- 结果是：同一深度、相互重叠的对象，置顶/置底看不出效果；绘制顺序和命中顺序可能不一致；组内子对象总是画在所有顶层对象之上。

**修复（2026-10-07 已实施）：**

- 绘制和命中统一为 BlockTree 的前序顺序 `Laid.paint`：父在子前，同级按 order_key 排列。
- 层叠通过 `zIndex = paint + 1` 实现。正在编辑的 Block 放在最上层，取代原来 CSS 中固定的 `z-index: 100`。世界层设置 `isolation: isolate`。
- 帧的 DOM 顺序按 ID 固定。这样挂载、裁剪和置顶/置底都不会移动已有的帧，避免内嵌文档重新加载或编辑器失去焦点。修复前，帧的顺序随相机变化，平移时会触发 DOM 节点移动。
- 命中测试取绘制顺序中最上层的对象，正在编辑的 Block 优先。
- 语义变化：组内子对象只在所在分组之上；分组之后的同级对象会画在这些子对象上面。
- 验证：e2e `tests/aiworkspace/ui.spec.ts` 中的 “P0 stacking”。把 `zIndex` 改回按深度后，该用例会失败。

连接线作为普通同级对象参与同一顺序；新建的线和其他新建对象一样，放在同级的最上层。

### 9.4 命中、裁剪和 LOD

- 空间索引先按包围盒粗筛，再按点到路径的距离精确命中。斜线按它实际经过的网格单元登记，避免一条长斜线占满整个包围矩形的网格。
- 两端都在视口外、但路径穿过视口时，照常绘制。
- LOD：线不退化成占位块；低倍率时隐藏标签、简化线帽；屏幕上的线宽不小于 1px。
- 每条线是一个绝对定位的 SVG 元素，参与上面的层叠顺序。

### 9.5 拖动预览

- 拖动节点时，按邻接索引找出受影响的线，每帧用“已提交布局＋手势偏移”重算路径，直接修改 SVG，不经过 React 状态。
- 拖动整条线时，绑定端不随 DOM 平移，同样按帧重算。
- 拖动超过 24 个对象会进入轮廓模式，此时相连的线一并隐藏。
- 远端的布局变化、目标的生命周期变化和权限变化，都会触发相关线重算。

### 9.6 交互

- **创建：**
  - 方式一：对象工具栏中的连接线工具，按下确定起点，拖到终点后松开。
  - 方式二：悬停或选中对象时，显示四边中点的连接柄，从连接柄直接拖出连接线（白板工具的常见做法）。
  - 拖到对象上时显示吸附的连接点：放在对象内部为 `auto`，靠近四边中点时吸附为 `point`。
- **编辑（选中后）：**
  - 两端的端点手柄：拖动可以改坐标或重新绑定，拖离对象即解绑。
  - 控制点手柄：直线线段的中点有一个“虚拟点”，拖动即新增折点；直角折线可以整段拖动线段；曲线可以拖动控制点；双击或通过菜单删除控制点。
  - 标签手柄。
  - 就近工具栏：切换路由、线帽、线型、粗细、颜色，以及“重置路由”。
- **取消与模式：** 按 Esc 取消；查看模式不提供任何编辑入口。
- **触摸：** 首版只支持显示和点选。触摸编辑和平板上的触摸编辑一起做；目前普通 Block 的触摸编辑也还没有实现。

### 10.2 需同步的入口

`schemas/`、后端和 Desktop 的两份 README、前端类型、Rust 客户端和 Web SDK 的消费入口。Rust 客户端主要透传 JSON，但不能因此假定 SDK 和 AI 工具都不受影响。外部读者只看 placement 时，绑定端的位置是存储位置，不是渲染位置；要拿到渲染位置，需要按 §9.2 解析。

### 10.3 版本识别

旧内核的 `CELL_KEYS` 白名单在导入和副本重放时同样执行（副本经由同一个 planner 重放远端提交）。所以一个旧的离线标签页，第一次收到连接线提交就会重放失败，停在 REPLICA_BROKEN。处理方式：

- `PROTOCOL_VERSION` 从 0.1 升到 0.2，`FORMAT_VERSION` 从 0.2 升到 0.3。D15 允许 breaking change，不做兼容层。（2026-10-07：这次提升已随[标准对象的交互改进](<标准对象的交互改进.md>)的旋转与锁定完成；连接线修改核心白名单时需要再升一次。）
- 客户端在打开工作区（工作区信息中带 `protocol_version`）以及重连时比较协议版本。不一致时停止同步，提示“已有新版本，请刷新”，并保留待提交的内容，而不是报告副本损坏。（已实现：`VERSION_MISMATCH`，见标准对象的交互改进 13-15。）

### 10.4 许愿格

如果要让许愿格程序直接生成可编辑的连接线，需要另外扩展它的结果结构、planner 和 renderer catalog。首版可以由获授权的客户端通过普通 Commit 创建连接线。

## 11. 验收建议

以下为拟议的验收项，不是已执行的结果。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| CN01 | 自由线的三种路由与各种线帽组合；水平线、垂直线、反向绘制 | 保存后重开一致；外框零宽或零高时正常 |
| CN02 | 绑定后移动目标、改变目标尺寸 | 端点实时跟随；只提交实际编辑的对象；控制点按 §4.4 变换，直角保持 |
| CN03 | `auto` 与 `point` 连接点；椭圆形状；自环 | 连接点位置正确，吸附正确 |
| CN04 | 添加、拖动、删除折点；拖动直角线段；拖动曲线控制点；重置路由 | 一次手势一次提交；可以撤销 |
| CN05 | 标签文字、拖动位置与偏移、控制点变化后的位置 | 比例位置保持；能吸附回路径 |
| CN06 | 拖动坐标端点越过另一端 | `flip` 正确，只产生一次提交 |
| CN07 | 跨组连接、分组与解组、移动 Group | 世界位置正确，没有重复偏移 |
| CN08 | 复制和粘贴的各种情形（§8.1） | 集合内绑定重映射，集合外端点转为坐标 |
| CN09 | 在本窗口或远端删除目标、撤销、恢复、移出 Surface | 冻结位置、失效显示和绑定恢复都符合 §6.2 |
| CN10 | 目标不可读；自定义权限只有 `update` 或只有 `structure` | 没有越权的解析或写入；工具入口与服务端一致 |
| CN11 | 同时拖端点与改外观；同时改 `controls`；拖端点与重新绑定同时进行 | 合并、冲突和覆盖提示符合 §7 |
| CN12 | 离线、冷启动、重连、撤销与重做；旧版本客户端 | 行为一致；版本不一致时提示刷新，而不是报副本损坏 |
| CN13 | 导出、导入、Fork、目标被排除在包外 | 失效端点保留；`diag.verify_refs` 一致 |
| CN14 | 线与节点重叠、置顶置底、分组背景 | 绘制顺序和命中顺序一致 |
| CN15 | 两端在屏幕外但线穿过视口、低缩放、超长斜线 | 可见、可命中，LOD 正确 |
| CN16 | 查看与演示模式、流式页、手机 | 没有编辑入口；流式页不显示线 |

性能探针至少覆盖 1,000 个节点加 1,000 条线，另外覆盖高连接度节点（一个节点连 200 条线时拖动它）和多选移动。既有的 1,000/5,000 Block 探针只能作为回归基线。具体门槛在 C0 冻结，C4 记录实测结果。

## 12. 裁决

| 编号 | 问题 | 结论 | 状态 |
| --- | --- | --- | --- |
| R1 | Cell 还是独立实体类型？ | Cell，`view.type = connector`，内置标准对象 | 已定 |
| R2 | 几何保存在哪里？ | 矩形 placement 加 payload 中的 `flip`、端点、控制点；两端都是坐标时就是矩形对象 | 已定 |
| R3 | 删除节点时线怎么办？ | 引用不阻止删除；本窗口删除时同批把相连线冻结在当前位置，保留绑定。替代方案：连带删除 | 推荐 |
| R4 | 失效端点停在哪里？ | 存储位置：本窗口删除时为删除瞬间的位置，其他情况为最后一次写线时的位置 | 推荐 |
| R5 | 并发规则？ | placement 自动合并（D1）；payload 各键独立，带 expect | 推荐 |
| R6 | 权限？ | 移动和拖坐标端点需要 `structure`；绑定、控制点、外观需要 `update` | 推荐 |
| R7 | 复制时绑定怎么处理？ | 只保留复制集合内部的绑定，集合外的端点转为坐标 | 推荐 |
| R8 | 首版路由？ | 直线（可加折点）、直角、曲线，三种都支持控制点 | 已定 |
| R9 | 首版是否接入许愿格？ | 后续接入 | 推荐 |
| R10 | 连接点模型？ | 默认 `auto`，另有 `point`（吸附四边中点）；具名端口留到后续 | 推荐 |
| R11 | 流式页怎么处理？ | 不显示线；core 只校验创建和新绑定；UI 入口拒绝 | 推荐 |
| R12 | 线帽、线型、粗细的取值？ | 见 §5 | 推荐 |
| R13 | 版本识别？ | 提升协议版本和包格式版本；客户端版本不一致时提示刷新 | 推荐 |
| R14 | 层叠顺序？ | 树前序，绘制和命中一致（P0） | 已实施 |
