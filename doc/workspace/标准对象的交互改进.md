# BuckyOS AI Workspace 标准对象的交互改进

> 状态：v0.3，2026-10-07。S1–S3 已实施（外观与状态层、工具栏与编辑态、旋转与锁定）；S4 已随连接线实施（[连接线实施记录与验收报告](<连接线实施记录与验收报告.md>)），S5 为后续项。§12 的推荐项已按推荐实施，全部改为“已定”。实施与原方案的差异见 §13，验收见 [实施记录与验收报告](<标准对象的交互改进实施记录与验收报告.md>)。
>
> 基线：实施前的工作区源码（第二期、许愿格、UI 改进、手机画布之后；连接线方案 v0.2 尚未实现）。§2 描述的是实施前的现状。
>
> 参照物：Miro 的对象状态（静止无框、hover 轻提示、选中圆角手柄与蓝色连接点、选区上方的图标工具栏、原地编辑）。本文只借鉴交互，不复制视觉风格；颜色一律从 Desktop 主题派生（UI 改进 §15-16）。

## 1. 结论

**对象只负责内容，宿主负责状态。** 画布上的标准对象在静止时没有宿主加的边框、底色和内边距；hover、选中、编辑这三种状态全部由 RenderHost 的覆盖层（overlay）表达，对象的 DOM 结构不因状态变化而改变。工具跟着任务走：hover 只浮现一两个“此刻最可能要点的东西”，选中才出现完整的图标工具栏，编辑是“选中 + 可以输入”，不再换成另一套厚重的编辑器皮肤。

四点要求与本文的对应：

| 要求 | 本文的处理 | 章节 |
| --- | --- | --- |
| 1. 非选中非 hover 时尽量透明、无框 | 去掉 Block 外框（`.aiws-frame-block`）的卡片外观；外观由各类型自己声明 | §4.1 |
| 2. hover 轻量浮现重要控制点 | 新增“hover 附件”契约：数据源名字、许愿格运行、表格加行、便签回复等由类型声明，宿主在覆盖层放置 | §4.2 |
| 3. 选中出现 Miro 样式的框：缩放清楚、易旋转、易拉连接线 | 圆形角手柄＋边缘拖动＋旋转柄＋四个连接柄；旋转需要新增 `placement.rotation` | §4.3、§7 |
| 4. 快捷操作栏参考 Miro，双击进入的富文本编辑太重太丑 | 图标化的就近工具栏，类型相关格式工具迁入其中；富文本、表格、便签的 Block 内工具栏移除；编辑态保持选中框 | §5、§4.4 |

连接线虽未实现，但它的交互（创建、吸附、端点与控制点手柄、工具栏）与对象状态是一体的，本文 §6 给出完整的产品定义，供 [连接线实现方案](<连接线实现方案讨论.md>) 的 C2、C3 阶段直接使用。

## 3. 设计原则

1. **对象 = 内容，宿主 = 状态。** Renderer 不画宿主边框、底色、阴影、内边距；类型自带的外观（便签色底、形状填充、框的描边）是内容的一部分，继续由 Renderer 画。状态只出现在覆盖层。
2. **五个状态，一套几何。** 静止、hover、选中、编辑、拖动中。所有状态都围绕同一个对象矩形（旋转后为同一个旋转矩形）绘制，不因状态改变对象尺寸或位置。
3. **按任务出现。** 静止时什么都没有；hover 最多一个名字标签和一个主动作；选中给手柄和工具栏；编辑给输入焦点和格式工具。拖动、框选、相机动画期间全部隐藏。
4. **工具栏在对象外，格式在工具栏里。** 所有“对对象做什么”的控件都在选区上方的图标工具栏或右键菜单中；Block 内只保留内容本身的交互（表格单元格、便签文字、许愿格候选列表）。
5. **一个契约，三处消费。** `BlockDefinition` 声明外观、hover 附件、工具栏项；RenderHost（覆盖层）、NearToolbar（工具栏）、ContextMenu（右键）消费同一份声明。HTML 扩展后续通过 `window.aiws` 得到同样的能力。
6. **颜色从主题派生。** 选中、hover、连接柄用 `--cp-accent`；AI 用 `--aiws-ai`；底色用 `--aiws-selected-bg / --aiws-pressed-bg`；不写死色值（[UI 改进 §15-16](<BuckyOS AI Workspace UI改进.md>)）。浅色与深色两种主题截图核对。
7. **先能力，后限制。** 锁定、权限等只在 UI 层约束，core 不新增强制规则（“先能力后安全”的既定做法）。

## 4. 对象状态规范

以下尺寸都是屏幕像素（CSS px），不随画布缩放。

### 4.1 静止态

**宿主外框透明。** `.aiws-frame-block` 去掉背景、边框、圆角和内边距，只保留定位、尺寸和 `overflow: hidden`（表格等需要裁剪的类型）或 `visible`（形状、框、便签阴影）。由定义声明：

```ts
interface BlockDefinition {
  /** 宿主外框的外观：none（默认，透明）或 clip（透明但裁剪溢出内容） */
  chrome?: 'none' | 'clip'
  /** 对象外形，供连接点求交与 hover 轮廓使用（连接线方案 §4.3） */
  shape?: 'rect' | 'ellipse'
}
```

各内置类型的静止外观：

| 类型 | 外观 | 变化 |
| --- | --- | --- |
| 富文本 | 文字直接落在画布上，无底无框（Miro 的 Text） | 去掉白底；`.aiws-prose` 的内边距改为 Renderer 自己的 4px |
| 便签 | 色底、6px 圆角、极淡的投影（`0 1px 2px color-mix(--cp-text 12%)`）；作者名右下角小字 | 去掉外层白框；meta 行（📎、保存状态、“编辑”链接）移除，保存状态改为右下角 6px 圆点（未保存为 warning 色，需要处理为 danger 色，hover 显示文字） |
| 表格 | 表格线属于内容；`compact` 不显示工具条 | 去掉外层内边距；表头吸顶不变 |
| 记录 | 两列属性表，无框 | 同上 |
| 图片 / 附件 | 图片本身；不可用时虚线占位 | 去掉外层白框和 1px 图片边框 |
| 框 | 2px 描边 + 标题标签（现状） | 不变 |
| 形状 | 填充 + 描边（现状） | 不变 |
| 分组 | 虚线框 + 标题（现状） | 只在 hover / 选中时显示虚线框；静止时只显示标题 |
| 许愿格 | 一张“卡”：`--cp-surface` 底、1px `--aiws-ai` 色 40% 的边、8px 圆角，无阴影 | 它是动作对象而不是内容，保留卡片外观；去掉宿主白框后只剩这一层；删除“双击或‘打开许愿格’进入流程”提示文字（控件见 §4.2） |
| 连接线 | 线本身 | 见 §6 |
| 通用回退（未知渲染器、数据不可读、渲染器出错） | 内容保持可见（D6），警示改为左上角 16px 角标 + hover 说明；原始配置 `<details>` 保留 | 去掉整块的虚线 warning 边框和底色 |

**LOD。** 占位态改为 1px `--cp-border` 轮廓 + 居中名称（透明底）；simplified 态保留现有文字摘要但去掉底色。

**只读 / 无权限。** 不在静止态表达；选中后在工具栏说明（§5.3）。

### 4.2 Hover 态

**轮廓。** 1px `--cp-accent` 实线（不再是虚线），透明度 0.55，紧贴对象外沿（形状为椭圆时沿椭圆）。分组 hover 时显示整组虚线框。查看模式同样显示。

**hover 附件（affordance）。** 由定义声明，宿主在覆盖层放置：

```ts
interface HoverAffordance {
  id: string
  /** 名字标签（文字）或一个图标按钮 */
  kind: 'label' | 'button'
  /** 位置：对象外沿上方左侧 / 右上角内侧 / 底边外侧居中 / 右下角内侧 */
  at: 'top-left-out' | 'top-right-in' | 'bottom-out' | 'bottom-right-in'
  label: string
  icon?: LucideIcon
  /** 引用一个 BlockAction 的 id，或自带 run */
  action?: string
  run?: (ctx: RenderContext) => void
  /** 只在这些子模式显示；默认只有 edit */
  modes?: CanvasMode[]
}
interface BlockDefinition { hover?: (ctx: RenderContext) => HoverAffordance[] }
```

规则：

- 延迟 150ms 出现，指针离开对象和附件自身后立即消失；拖动、框选、相机动画、放置、编辑中不显示。
- 最多 1 个 label + 2 个 button；超过的忽略并在开发模式 warn。
- 按钮 24×24px，白底（`--cp-surface-opaque`）、1px 边、圆角 6px、投影同就近工具栏；点击执行动作并保持 hover。
- 附件不随缩放变化尺寸；对象在屏幕上短边小于 64px 时只显示 label，不显示 button。
- 触摸设备没有 hover：附件在选中时一并显示在同样位置。
- 查看模式只显示 `modes` 含 `view` 的附件（默认只有数据名字标签）。

各内置类型的 hover 附件：

| 类型 | label | button |
| --- | --- | --- |
| 表格 / 记录 / 图片 / 富文本（有数据源） | `top-left-out`：类型图标 + 数据名（`source.name ?? source.title`）+ 新鲜度徽标（有依赖时）；edit 与 view 都显示 | 表格：`bottom-out` “+ 行”（有 `append` 能力时）；其余无 |
| 许愿格 | `top-left-out`：许愿格名 + 执行器 chip + 新鲜度 | `top-right-in` ▶ “运行”（第一次运行叫“运行”，已有结果叫“重新运行”；运行中显示进度环并可“取消”）；`bottom-right-in` “打开”进入完整流程 |
| 便签 | 无（便签自己显示作者） | `bottom-right-in` “回复”（§7.3）；`top-right-in` 颜色（点开色板，直接换色） |
| 框 / 形状 / 分组 | 框和分组已有标题，不加 | 无 |
| 连接线 | 无 | 无；hover 只加粗（§6.4） |
| 扩展（HTML / 声明式） | 数据名（有数据源时） | 后续通过 `window.aiws` 声明（§7.5） |

“运行”按钮的语义沿用许愿格 W0–W4：第一遍分析、第二遍执行，候选结果在右侧面板或 Block 内预览后应用，整次应用可撤销。hover 上的运行等于“打开许愿格并立即开始”，不跳过预览。

### 4.3 选中态

**选中框。** 1.5px `--cp-accent` 实线，紧贴对象外沿（旋转后随之旋转），直角不加圆角；形状为椭圆时仍画外接矩形。多选时每个对象 1px 轮廓（透明度 0.7）加整体 1.5px 包围框。

**手柄（Miro 样式）。** 只在编辑模式、可布局（`policy.layout && canLayout`）且对象未锁定时显示：

| 手柄 | 外观 | 行为 |
| --- | --- | --- |
| 四角 | 直径 10px 圆形，`--cp-surface-opaque` 填充，1.5px `--cp-accent` 描边；hover 放大到 12px | 拖动改宽高；按住 Shift 等比；图片、便签默认等比，按住 Shift 自由（由定义声明 `resize.aspect`）；最小 40×40 不变 |
| 四边 | 不画手柄；边线内外各 5px 是拖动区，光标变为 `ns-resize` / `ew-resize` | 单方向改尺寸 |
| 旋转柄 | 选中框左下角外侧 18px 处的 ↻ 图标（16px，Miro 位置），光标自定义为旋转 | 绕中心旋转；Shift 吸附 15°；拖动时在柄旁显示角度；双击旋转柄归零。需要 `placement.rotation`（§7.1） |
| 连接柄 | 四边中点外侧 14px 处的直径 8px `--cp-accent` 实心圆；hover 放大到 10px 并显示“拖出连接线”提示 | 按下拖出连接线（§6.1）；只在有连接线能力（父容器 `structure`）时显示；连接线自身、分组标题不显示 |

多选时整体框显示四角手柄做整体等比缩放（P2），首版只显示框，不显示手柄。

**尺寸按指针类型。** 鼠标：上表尺寸，命中区比视觉大 4px。触摸（`pointer: coarse`）：角手柄视觉 14px，命中 44×44；边拖动区 12px；连接柄视觉 12px、命中 44px；旋转柄 24px。触摸编辑整体仍是后续项，但手柄尺寸先定下来，避免再改一次。

**手柄与内容的层叠。** 覆盖层始终在所有 Block 之上，手柄不会被相邻对象盖住。对象之间的叠放已统一为 `Laid.paint`（§2），编辑中的对象临时置于最上（`laid.size + 1`），选中框不改变这个顺序。

**不可布局时的选中。** 查看模式或没有 `structure` 权限：只有选中框，没有任何手柄；工具栏说明原因。锁定的对象（§7.2）：选中框改为 `--cp-muted` 色，左上角显示锁图标，工具栏只有“解锁”。

**键盘。** 保持现有：方向键移动 1px、Shift 10px；Enter 进入编辑；F2 属性；Delete 删除；Ctrl+G / Ctrl+Shift+G 分组。新增：Ctrl+] / Ctrl+[ 置顶 / 置底；R 后按方向键旋转 15°（可选）。

### 4.4 编辑态

**编辑 = 选中 + 可输入。** 进入编辑后：

- 选中框保留，手柄全部隐藏（避免误拖），连接柄隐藏。
- 外框不加阴影；保留 `z-index` 提升（避免编辑中的下拉被相邻对象盖住），`overflow: visible` 只给需要弹出内容的类型。
- 就近工具栏切换为“内容格式”模式（§5.2）：类型的格式工具在前，通用动作收进更多。
- 不改变对象尺寸：Editor 不渲染任何工具栏、锁条、状态行；高度自然增长时按现有规则（富文本自动增高 / 表格固定高度内滚动）。

**各类型的编辑态：**

| 类型 | 进入 | 编辑中 | 退出 |
| --- | --- | --- | --- |
| 富文本 | 双击、Enter、选中后直接打字（可打印字符插入到文末，Miro 行为） | ProseMirror 直接在原位置可编辑，字号与静态一致；格式按钮在就近工具栏（§5.2）；“嵌入单元”“对象链接”改为工具栏“链接”按钮打开带搜索的 popover，不再用 `<select>`；锁状态改为工具栏右侧的锁图标 + tooltip（持有者、获取、释放），锁丢失仍在 Block 顶部显示一行 alert（这是必须看见的） | Esc、点击空白、选中其他对象；先 blur 再卸载（现有规则） |
| 便签 | 双击、Enter、选中后直接打字 | textarea 透明、无边框、字号与静态一致、自动增高；颜色和字号在工具栏 | 同上；空便签退出时保留（不自动删除） |

| 图片 | 不进入编辑；工具栏提供“替换”“适应方式”“预览” | — | — |
| 框 / 形状 | 双击编辑标题（框标题 / 形状居中文字），原位置输入 | 颜色在工具栏 | 同上 |
| 许愿格 | 双击、Enter、hover 的“打开” | **不在 Block 内挂载 WishPanel**，而是在右侧面板打开许愿格（提示词、输入、候选、预览、应用），Block 保持卡片并显示“正在编辑”状态；画布可继续操作（选输入时直接点画布上的对象） | 关闭右侧面板或选中其他对象（面板保留直到关闭） |

许愿格改为右侧面板是推荐项（§12 R6）：WishPanel 的内容（输入列表、上下文、候选、预览）在 420×300 的 Block 里只能滚动，放右侧面板后画布本身成为“选输入”的工作面，与许愿格设计 §12 的交互一致。保留 `compact` 版本以便数据源视图使用。

## 5. 快捷操作栏（就近工具栏）

### 5.1 形态

- 位置与避让沿用 `NearToolbar`：选区上方居中 8px，放不下时移到下方，避开浮动工具栏与窗口边。编辑态下跟随对象，拖动中隐藏。
- 图标按钮 32×32px，图标 18px，分组之间 1px 竖线；带文字的只有下拉（字号、形状、路由）。tooltip 显示名称与快捷键。
- 按下态用 `--aiws-pressed-bg` 配 accent 图标；AI 按钮用 `--aiws-ai` 色图标，不用渐变底。
- 宽度超过可用空间时从右往左依次收进“更多”。
- 弹出层（色板、字号、链接搜索）用现有 `popover.tsx`；色板 8 个主题派生色 + 自定义；选择立即写入并可撤销。

### 5.3 不可用的说明

- 查看模式：类型区不显示，通用区只有批注和更多（查看数据、属性只读）。
- 没有 `update`：格式类按钮禁用，tooltip 写“没有编辑权限”；没有 `structure`：没有手柄，更多里的分组 / 层级 / 移动禁用并说明。
- 数据不可读、渲染器未知：类型区不显示，通用区显示“查看数据与依赖”“属性”，角标说明原因。

### 5.4 契约

```ts
type ToolbarItem =
  | { kind: 'button'; id: string; icon: LucideIcon; label: string; key?: string; active?: boolean; disabled?: string | false; run: () => void }
  | { kind: 'menu'; id: string; icon?: LucideIcon; label: string; value?: string; items: { value: string; label: string; icon?: LucideIcon }[]; onPick: (value: string) => void }
  | { kind: 'color'; id: string; label: string; value: string | undefined; onPick: (hex: string) => void }
  | { kind: 'separator' }

interface BlockDefinition {
  /** 选中态的类型区；按当前上下文计算（能力、模式、数据状态） */
  toolbar?: (ctx: RenderContext) => ToolbarItem[]
  resize?: { aspect?: 'free' | 'locked' }
}
interface RenderContext {
  /** 编辑器在挂载后注册自己的格式工具；光标变化时重新调用以更新 active 态 */
  setEditorToolbar: (items: ToolbarItem[] | null) => void
  pointerType: 'mouse' | 'touch'
}
```

`actions` 保持为完整动作列表（右键与更多）；`toolbar` 项可以只引用 action id。NearToolbar 渲染顺序：`setEditorToolbar` 注入的项（编辑态）→ `toolbar(ctx)` → 通用区 → 更多。

## 6. 连接线交互

数据契约、路由、生命周期见 [连接线实现方案](<连接线实现方案讨论.md>) v0.2；这里定义用户看到和操作的部分，并补充该方案 §9.6 未展开的内容。

### 6.1 创建

| 方式 | 行为 |
| --- | --- |
| 从连接柄拖出（主要） | 选中对象 → 按住四个连接柄之一拖动。起点为该边中点的 `point` 连接点；拖动中显示预览线（默认直线、终点箭头）和终点吸附提示 |
| 对象工具栏的“连接线”工具 | 加入标准对象组（图标 `Spline`，快捷键 L）。在空白处按下拖到松开，两端都是坐标；在对象上按下即绑定起点 |
| 松开在空白处 | 创建坐标终点，同时在终点旁弹出小目录（便签 / 文本 / 形状 / 许愿格，4 项，Miro 的“下一个对象”菜单）：选一项就在终点创建该对象并把终点绑定到它；Esc 或点别处保留坐标终点 |
| 松开在对象上 | 终点绑定：指针距四边中点 12px 内吸附为 `point`（显示为实心点），否则为 `auto`（显示对象外形高亮） |
| 松开在起点对象上 | 自环：要求两端都是 `point` 且不同位置（方案 §4.3），否则取消 |
| 边缘自动平移 | 拖动到视口边缘 24px 内时相机匀速平移（也用于拖动对象和框选） |

拖动过程中所有可绑定对象 hover 时显示外形高亮和四个吸附点；连接线自身、分组标题、不可读对象不高亮。

### 6.2 选中态

| 手柄 | 外观 | 行为 |
| --- | --- | --- |
| 端点 | 直径 10px 圆：绑定端实心 `--cp-accent`，坐标端白底 accent 边，失效端白底 `--cp-muted` 边并带“!” | 拖动改坐标或重新绑定，拖离对象即解绑（方案 §9.6）；双击失效端打开“重新连接”提示 |
| 中点虚拟手柄 | 每段中点 8px 半透明圆（透明度 0.5） | 拖动即新增折点（直线）/ 整段平移（直角）/ 新增经过点（曲线）；双击已有控制点删除 |
| 控制点 | 直径 8px 实心圆 | 拖动；Shift 吸附到水平 / 垂直 |
| 标签 | 标签框 1px 虚线（只在选中时） | 拖动沿线移动与偏移（方案 §4.5）；双击编辑 |
| 整体 | 两端都是坐标时可拖动整条线；任一端绑定时拖线段中部等于拖控制点 | — |

选中线没有角手柄、旋转柄和连接柄。选中框不画（线自己就是选中指示：加粗 1px 并把线色换成 accent？否：保持线色，改为在线两侧加 3px 透明度 0.25 的 accent 光晕）。

### 6.3 状态

| 状态 | 表现 |
| --- | --- |
| 静止 | 按 `config` 绘制；标签处断开线或加底色 |
| hover | 线宽 +1px，光晕 2px；标签不变；光标 `pointer`；端点处 hover 显示“拖动重新连接”tooltip（选中后） |
| 失效端点 | 端点处 10px 空心灰圆带“!”（查看模式按普通线端显示） |
| 目标拖动中 | 线实时跟随（方案 §9.5） |
| 低倍率 | 隐藏标签、简化线帽，线宽不小于 1px |

### 6.4 与对象的联动

- 对象 hover 不显示连接柄，选中才显示，减少噪音；但拖连接线过程中所有对象 hover 都显示吸附点。
- 对象旋转后：`point` 连接点在对象局部坐标（旋转前），渲染时随对象变换；`auto` 与旋转后的外形求交。这是对连接线方案 §4.3 的补充。
- 删除对象：相连线冻结在当前位置（方案 R3）。
- 复制含线的选区：按方案 §8.1。
- 多选含线：线参与整体包围框，但整体手柄（P2）不缩放线的控制点，只平移坐标端。

### 6.5 键盘与触摸

- Delete 删除；Esc 取消拖动 / 退出标签编辑；Enter 编辑标签；Ctrl+D 复制（与对象一致，P2）。
- 触摸首版只显示与点选；连接柄在触摸设备上不显示。

## 7. 数据与契约变化

### 7.1 旋转：`placement.rotation`（P1）

- 字段：`placement = { x, y, w, h, rotation? }`，单位度，顺时针，范围 `[0, 360)`，省略表示 0。放在 placement 而不是 payload：旋转是布局，与移动同权限（`structure`）、同并发规则（D1 自动合并）、同撤销粒度，分组 / 解组 / 跨画布移动的坐标换算一并处理。
- core：`check_placement` 允许 `rotation` 为有限数；`tree.place`、`tree.move`、`entity.create` 三个入口都经过它。流式页忽略该字段。`outline_extras` 与 `outline.ts` 都投影。
- 前端：`laid` 条目带 `rotation`；RenderHost 外框加 `transform: rotate()`（以中心为原点）；空间索引仍用轴对齐包围盒粗筛，命中改为把点变换到对象局部坐标再判断；选中框、手柄、hover 轮廓按旋转矩形绘制；缩放手柄的拖动向量先反旋转再应用；分组的包围盒取各子对象旋转后的外接矩形。
- 分组内对象旋转：子对象的 `rotation` 相对父容器，与 x / y 同理；分组本身可旋转（P2）。
- 连接点见 §6.4。
- 旧内核会拒绝带 `rotation` 的 placement：与连接线一起把 `PROTOCOL_VERSION` 升到 0.2、`FORMAT_VERSION` 升到 0.3（方案 §10.3 的版本识别也一并做）。如果旋转先于连接线落地，版本号先升一次。

### 7.2 锁定：payload `locked`（P1）

- Cell 和 Group 的 payload 新键 `locked: true`，写入需要 `update`。core 只校验布尔值并加入 `CELL_KEYS`，不阻止任何操作（先能力后安全）。
- UI：锁定对象可以被点选（Miro 需要长按，这里不做），但没有手柄、不参与拖动与框选移动、Delete 跳过并提示、不能作为分组成员被移动；工具栏只显示“解锁”和更多（属性、查看数据）。多选含锁定对象时，移动只作用于未锁定的对象。
- 旧内核拒绝新键：与 7.1 一同升版本。

### 7.3 便签回复

- 回复建模为一条新的批注：`type_id = buckyos.annotation`，`kind = note`，`target = { entity_id: <便签实体> }`，`body` 为回复文字。core 现有规则已允许（目标不限类型，需目标可读；作者只能是本人；写入需要 `comment`）。
- 显示：便签底部显示回复数（“2 条回复”），点开在右侧批注面板中按该便签过滤（`ListAnnotationsParams.target_ids`）；回复按 `created` 排序。画布上不展开回复列表（避免便签高度失控）。
- 删除便签时回复按现有批注的级联规则处理（目标缺失的批注保留为失效锚点，写严读宽）。
- 待确认：是否允许回复的回复。推荐不允许（UI 不提供入口，模型上不禁止）。

### 7.4 BlockDefinition / RenderContext

`chrome`、`shape`、`resize`、`hover`、`toolbar`（§4.1、§4.2、§5.4）；`RenderContext.setEditorToolbar`、`pointerType`。全部可选，现有定义不改也能运行（只是没有类型区和 hover 附件）。

### 7.5 HTML 扩展

`window.aiws.context()` 增加 `selected`、`hovered`、`editing`；新增 `aiws.hover(items)`、`aiws.toolbar(items)` 让扩展声明附件与工具栏项，宿主用同一套覆盖层渲染（扩展只给文字、图标名和回调 id）。`HTML_API_VERSION` 升到 3，旧定义继续按 2 运行。P2。

### 7.6 用户工作状态

无新增。工具栏、手柄显示都不是偏好。

## 10. 已知风险与取舍

- **去掉宿主外框后，Renderer 的外观责任变重。** 扩展 Block 如果不自己画边，就会是“裸”的。这是有意为之（Miro 的 embed 也如此），目录说明中提示扩展作者。
- **选中后直接打字进入编辑**与画布快捷键（V / H / L / R）冲突：只有富文本和便签启用，且单字母快捷键在有单选文本对象时让位（Miro 同样如此）。
- **许愿格改右侧面板**改变了已有 e2e 和数据源视图的 compact 用法；数据源视图保持 Block 内挂载。
- **旋转**让空间索引的粗筛变松（外接矩形更大），对 5000 Block 探针影响需实测。
- **锁定不由 core 强制**，API 与 AI 工具可以改锁定对象；记为已知风险，不加校验。

S1–S3 按本文实施。与上文不同或上文没有写到的地方如下；代码以 Desktop `src/app/aiworkspace/README.md` 的“Standard object interaction”一节为索引。

| 编号 | 内容 | 原因 |
| --- | --- | --- |
| 13-1 | `chrome` 的默认值是 `clip`（透明、裁剪溢出），`none` 由框、形状、便签显式声明 | 未知的扩展内容大于 Block 时不应盖住相邻对象；两者都不画边框和底色，§4.1 的“透明”不变 |
| 13-2 | `ToolbarItem` 增加 `panel`（弹出自定义内容：链接搜索、锁状态）；`button` 的图标可省略，省略时显示文字 | 链接和锁需要弹层；没有声明 `toolbar` 的扩展（声明式、HTML）在 S5 之前把它的动作以文字按钮放在类型区，内置类型的动作进“更多” |
| 13-3 | `hover(ctx, store)`、`toolbar(ctx, store)` 多一个 `store` 参数；`HoverAffordance` 增加 `freshness`（标签后显示该实体的新鲜度） | 运行、取消、改便签样式需要读写；名字标签要带新鲜度 |
| 13-4 | `RenderContext` 增加 `annotate`、`showAnnotations` | 便签“回复”要发起批注并在批注面板中只看这张便签的回复 |
| 13-5 | 编辑器工具经 `EditorToolbarContext` 汇入就近工具栏（`useEditorToolbar`），扩展 Editor 用 `RenderContext.setEditorToolbar`；流式页和数据源视图没有就近工具栏，同一组工具画在编辑器上方（`InlineTools`），锁仍是一行锁条 | 一份声明，三处消费；不在两处维护两套格式按钮 |
| 13-6 | 新增按 Block 的“意图”（`requestIntent` / `useIntent` / `consumeIntent`）：打开表格的某个面板、把画布上按下的字符送进编辑器、按双击位置放光标、许愿格“开始”、图片“预览” | 工具栏和 hover 附件在 Block 仅被选中时就可以使用，编辑器挂载后再执行 |
| 13-7 | 表格 hover“+ 行”打开新增记录表单并聚焦第一个输入框，而不是直接插入空行 | 默认表格的“标题”字段必填，空行会被内核拒绝 |
| 13-8 | 便签的颜色不做 hover 附件，只在工具栏；字号写在批注的 `style.size`；便签编辑中按 Esc 改为保存后退出（原为放弃） | hover 契约只有标签和按钮，没有弹层；Esc 退出时内容已提交与富文本一致 |
| 13-9 | 富文本的字号、文字颜色是整个 Block 的 Cell 配置 `config.text_size`、`config.text_color` | 选中态的工具作用于对象；字内格式仍在编辑态工具中 |
| 13-10 | 图片不再有 Editor：替换、适应方式、预览都在工具栏；适应方式写 `config.fit`（静态显示原来读 `options.fit`，与属性面板写的键不一致，一并修正）；画布上的图片不显示文件信息行 | §4.4“图片不进入编辑” |
| 13-11 | 框和形状新增原位编辑：标题 / 文字直接在原位置输入；形状文字颜色按填充色亮度取深色或浅色 | §4.4；深色主题下浅色填充上的文字原来不可见 |
| 13-12 | 许愿格在自由画布上打开时进入右侧面板“许愿格”页签；“运行”打开面板并开始下一步（需要分析时分析，分析就绪时执行），不跳过预览；面板中提供“添加画布上选中的 N 项为输入”；流式页与数据源视图仍在 Block 内显示流程 | R6；流式页没有右侧面板之外的入口 |
| 13-13 | 双击旋转柄（实现为短时间内第二次按下）归零；分组的 `rotation` 暂不绘制（P2）；键盘旋转（R + 方向键）未做；连接柄不显示（S4） | 旋转柄按下即开始拖动并捕获指针，浏览器的双击事件到不了它 |
