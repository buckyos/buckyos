# BuckyOS AI Workspace 演示模式 PRD

**版本：** v1.0 · 需求评审稿  
**日期：** 2026-10-06  
**适用对象：** 产品负责人、交互设计负责人、Workspace 技术负责人、Block 扩展开发者  
**主要依据：** 本轮关于 AI Workspace 演示模式的连续语音讨论。

> **产品定义：一次演示，是基于 Workspace 发起、可通过链接加入、可进行内容交互，并可在保存后长期访问和回放的授课／讲解房间，而不只是一次幻灯片播放。**

## 0. 文档口径

本文把口述需求整理为可供设计、开发和验收使用的产品要求，不直接决定底层存储、传输协议或同步库的选型。

- **已明确需求**：来自本轮口述的产品目标、功能和范围约束。
- **补充约束／建议**：为使流程闭合、权限安全或验收可执行而补足的规则；不是口述中已经确定的所有细节，评审时可调整。
- **待决策**：口述明确保留的实现选择，或尚未给定的产品策略。不得在实现时静默替用户决定。

除明确标注为“补充”“建议”或“待决策”的内容外，下文描述的是本轮已明确需求及其直接产品含义。实施阶段与优先级均为建议，不代表已承诺排期。

本文中的 **Presentation Session** 专指一次演示实例，区别于 Agent Session、普通聊天会话及整个课程的长期群组。“房间”是这个演示实例的用户侧称呼，不意味着必须另外建设一套房间系统。

## 1. 产品背景与目标

### 1.1 从屏幕播放转向多人参与

本产品借鉴 Miro 演示模式等已有产品经验，但不以复刻某个产品为目标，也不以逐项对标现有产品功能为依据。

传统演示场景主要围绕公共大屏，以及演讲者自己的备注／提示器屏幕组织。AI Workspace 的出发点则是：观众可以携带手机、平板或电脑，通过链接成为这次演示的真实参与者，而不只是观看大屏的人。

演讲者从某个 Workspace 发起演示后，可以生成属于**这一次演示**的独立长期链接。观众打开链接，以演示模式加入，观看内容、参与被允许的互动；保存演示后，同一链接继续承载回放、课堂数据和课后讨论。

该形态既适用于线下课堂，也适用于在线授课、公开讲解及其他围绕内容展开的演示活动。课堂是本文的主要示例，不应把底层模型限定为学校专用系统。

### 1.2 产品目标

| 目标 | 需要达到的结果 |
| --- | --- |
| 观众成为参与者 | 观众可通过自己的设备加入，有自己的观看状态、交互权限和作答状态。 |
| 不破坏讲解节奏 | 支持轻量反馈，也支持老师主动发起的、有边界的交互任务。 |
| 保留 Workspace 的可操作性 | 演示中的指定 Block 可以输入、运行和改变状态，不把整个 Workspace 冻结成图片。 |
| 一次授课形成长期成果 | 保存答案、讲解过程和音频后，可从同一链接回看并继续交流。 |
| 保持架构克制 | 复用 Workspace 对象、Block、权限和数据机制，不另造完整会议系统或考试系统。 |
| 兼容传统演示 | 不启用在线加入能力，或没有观众加入时，仍能完成常规单屏／多屏演示。 |

### 1.3 核心原则

**链接属于一次演示，而不只是课件文件。** 同一份课件可以开展多次演示，每次演示有自己的记录、参与者、数据和后续讨论。

**演示模式不等于整体只读，也不等于全面开放编辑。** 展示层变化、Block 的授权操作和原始课件编辑必须区分。

**公共展示、老师私有控制、观众个人操作是不同视图。** “第几块物理屏幕”不是权限依据。

**结束直播不等于关闭房间。** 已保存的演示链接不因授课结束而自动失效。

**产品效果先于存储选型。** 无论采用 Workspace 副本还是 Session 数据分区，用户可见的隔离、保存和回放效果必须一致。

## 2. 范围与明确不做的内容

### 2.1 本 PRD 的重点范围

重点定义观众通过演示链接加入之后的体验：轻量反馈、弹幕、点名／抢答、交互 Block、角色化提示器、答题保存与评阅、历史回放、课后讨论及历次演示记录。

### 2.2 必须具备，但本轮不展开的基础能力

Workspace 可通过一组 Viewport／Frame 组织演示顺序，支持上一页、下一页及每页备注。演讲者可在私有提示器中查看备注，界面需适应单屏、双屏及可能的三屏使用方式。

这些是演示模式的必要基础，不因本轮聚焦在线参与而被删除。具体翻页动画、备注编辑器等标准交互另行设计（已由[第三期规划](<BuckyOS AI Workspace 第三期规划.md>) §9 转场动画方案、§7.1 路径编辑确定并实施）。

### 2.3 不作为本轮建设目标

| 不做／不默认承诺 | 边界说明 |
| --- | --- |
| 多人实时音视频会议 | 不建设观众开麦、连麦、多人语音调度、视频会议和主持人控麦系统。 |
| 原生视频直播或录屏平台 | 回放以结构化演示记录配合主讲音频为主，不以录制整块屏幕为基础方案。 |
| 完整考试／教务平台 | 不因答题需求引入招生、排课、题库运营、监考、考试防作弊等独立业务系统。 |
| 自动字幕系统 | 口述中的“字幕”随后被更正为“弹幕”。本轮不把自动语音转写、翻译字幕作为已确认需求。 |
| 默认 AI 评分或 AI 课件分析 | AI Block 可以在现场运行；自动批改、知识点摘要等并未被确认，不能据此扩张首期范围。 |
| 随机点名、分组作答等扩展 | 当前明确的是老师点名和限额抢答。其他组织方式不列为本轮必需功能。 |
| 不受容量约束的公开广播 | 适配 OOD 部署方式，不预先承诺无限观众、无限存储或某个未经验证的并发规模。 |

## 3. 核心概念、角色与设备

### 3.1 概念定义

| 概念 | 产品含义 |
| --- | --- |
| Workspace／课件 | 可持续修改和复用的内容本体，包含对象、Block、数据引用及演示编排。 |
| Workspace Version | 某次演示所依据的课件版本；用于区分之后的改版及还原历史。 |
| Presentation Session | 一次真实发生的演示实例，关联其课件版本、运行数据、时间线和参与权限。 |
| Presentation Link | 指向该次演示的稳定入口；有权限时，可加入直播或访问已保存记录。 |
| Room／授课房间 | Presentation Session 的持续可访问形态，承载现场互动及课后交流。 |
| Viewport／Frame | 当前观看视角与预先组织的演示区域。Frame 顺序不替代自由浏览能力。 |
| Block／单元格 | Workspace 既有的内容和交互扩展单元。本文不要求另立一套演示专用对象类型。 |
| Interaction Task | 演讲者围绕某个 Block 发起的一次交互任务，如点名答题或抢答。 |
| Response／作答记录 | 某参与者针对某次题目机会提交的答案及关联状态。 |
| Replay | 还原当次演示公开过程的结构化回放；不是重新执行当时全部业务操作。 |
| Presenter View／提示器 | 演讲者的私有角色视图，不限定为扩展桌面的第二块物理屏幕。 |

### 3.2 角色与权限边界

| 角色／视图 | 应具备的能力 | 不应默认获得的能力 |
| --- | --- | --- |
| Owner | 管理 Workspace／记录的保存、访问授权及删除；管理自身内容。 | Owner 权限不会因为公开展示而自动暴露给观众。 |
| Presenter | 讲解、控制视角、开放互动、选人、查看课堂答案、决定公开结果。 | 与 Owner 非同一人时，保存、删除及历史数据管理需明确授权。 |
| Audience | 观看、按权限反馈和发弹幕；获得答题资格后作答；查看自己的答案及获准公开的内容。 | 查看他人未公开答案、老师备注、修改课件或任意 Block。 |
| 获得答题资格的 Audience | 在指定任务和 Block 范围内输入、提交。 | 因为获得某题权限而取得整个 Workspace 的编辑权。 |
| Public Display／公共大屏 | 展示公共内容与已发布的互动结果。 | 老师私有备注、原始答案列表、选人界面及管理操作。 |

Public Display 是**设备视图模式**，不是拥有独立人类身份的角色。一个 Presenter 可以同时使用公共大屏和私有平板，两台设备属于同一场演示。

**补充权限约束：** 界面隐藏不等于数据隔离。未授权终端不能接收他人的私有答案后仅靠前端隐藏；历史数据、同步消息及回放事件也需按权限提供。

### 3.3 设备模型

推荐的教学组合是“公共大屏 + 老师手持平板 + 学生个人设备”。老师的平板直接打开同一个演示链接，通过账号识别 Presenter 身份并进入提示器模式，不要求与大屏建立操作系统级双屏关系。

鼠标、键盘、触控和手写笔都可作为输入方式。普通演讲笔能满足翻页，但不应被假设能完成选人、手写和操作复杂 Block。

## 4. 主要使用场景

### 场景 A：传统演示

演讲者打开课件并开始播放，没有启用在线加入，或没有观众使用链接。公共屏显示内容，私有屏显示备注；只有一台设备时也能完成基础演示。

### 场景 B：线下课堂的随身设备参与

老师将演示链接发给学生。学生用手机、平板或笔记本加入，跟随讲解，也可浏览有权限访问的其他内容；通过位置反馈和弹幕表达兴趣或疑问。

### 场景 C：现场点名或抢答

老师到达预设题目，或临时插入板书题，在提示器上选人／开放抢答。获得资格者进入选择、文本或手写输入状态。答案先供老师查看，老师决定何时向全班展示。

### 场景 D：外部会议配合 Workspace

老师另开 Zoom 等会议或语音房，会议承担听讲或多人发言；Workspace 承担课件、状态同步和内容互动。老师可以共享公共演示屏，不共享提示器。

### 场景 E：课后回放与讨论

有保存权限的人结束并保存授课。学生再次打开同一链接，回看当时的课件和讲解，在某个时间点留下感受，或围绕整次课程发表评论、建议及评分。

### 场景 F：课件持续改进

老师根据上一轮答案和反馈调整课件，从 v1 改为 v2，再次讲授。打开课件可以看到历次演示；旧链接仍对应旧版本下的真实授课记录。

## 5. 演示创建、加入与生命周期

### 5.1 创建与永久链接

**JOIN-01｜一次演示一个入口。** 每次发起演示，可以创建独立 Presentation Session 和对应链接。再次使用同一个 Workspace 授课，不应覆盖上一场的链接和数据。

**JOIN-02｜在线加入可选。** 演讲者可以不生成链接、关闭在线加入，或生成但不分享链接。无观众加入时不妨碍本地展示和提示器使用。

**JOIN-03｜通过链接进入演示模式。** 观众进入的是本次演示，不是原始 Workspace 的完整编辑界面。是否允许匿名访问、是否需登录，由访问策略决定。

**JOIN-04｜保存后持续可访问。** 已保存的演示不因结束而自动过期。链接继续指向原场次；直播时用于加入，结束后用于回放及课后交流。内容受 Owner 的访问授权和删除控制。

**补充约束：** “没有分享链接”不等于禁止访问；链接访问策略与实际分享行为是两件事。长期链接也不代表内容永久公开，Owner 可调整访问范围。

### 5.2 建议的状态模型

以下状态用于产品流程说明，不规定底层状态枚举实现。

| 状态 | 用户侧表现 |
| --- | --- |
| 准备中 | 老师配置课件、互动策略、显示端与音频。已取得链接的人不应提前看到私有准备内容。 |
| 演示中 | 观众可加入，按权限跟随、互动、听讲或作答。 |
| 已结束／待保存 | 现场活动已结束，暂存数据仍待有权限者决定如何保存。 |
| 保存中 | 展示保存进度及异常，不提前宣称完整回放已生成。 |
| 已归档 | 原链接进入回放／课程记录视图，允许按权限继续讨论。 |
| 访问受限／已删除 | 明确说明当前不可访问，不重定向到另一场演示或新的课件版本冒充原记录。 |

**补充流程约束：** 演讲者“结束演示”和 Owner／被授权人“保存结果”应在权限上分开。无保存权限的演讲者不能绕过 Owner 授权。

### 5.3 暂存与保存

要支持“结束时选择保存”，必要的结构化事件和已启用的音频必须在授课过程中先行记录，不能在结束后从最终画面反推完整过程。

**补充默认建议：** 开始前显示本场将记录的内容、录音状态及存储位置／额度状态；课堂中进行暂存，结束后确认保留。音频未录制时，保存结果应明确为无音频或部分音频记录。

选择不保存时，需要说明将失去哪些回放及答题数据，并避免一键误丢失。未保存记录的暂存期限，以及是否保留空房间和元数据，属于待决策策略，不能默认承诺与已保存房间相同的长期保留。

### 5.4 加入后的身份与状态

**补充约束：** 参与者应有可用于授权和识别答案的稳定身份。可以采用账号，也可以采用策略允许的稳定访客身份；“每人只能答一次”所需的身份可靠性必须与访问政策匹配。

断线重连应恢复原场次身份和已确认状态，不重复登记为新答题者。重新进入历史链接不能自动开始新一轮演示。

## 6. 基础播放与观众视角

**VIEW-01｜标准编排。** 支持基于 Viewport／Frame 的演示路径、翻页和页面备注。老师私有备注不进入公共展示。

**VIEW-02｜跟随与自由浏览。** 观众可跟随演讲者视角，也可在权限允许的范围内停止跟随并浏览；应有明确的回到主讲视角操作。

**VIEW-03｜反馈不依赖跟随。** 观众在跟随或未跟随状态下，都可以对自己当前可见的内容使用被允许的点击反馈。

**补充边界：** 自由浏览不授予额外内容权限，也不自动解锁老师未公开的答案或私有对象。“尚未讲到但已公开可见的页面”是否允许提前浏览，可由演示配置决定。

**VIEW-04｜不同视图各自适配。** 手机、平板与大屏可以采用不同布局，但应指向同一内容语义和同一场次状态，而不是要求像素级相同的整屏画面。

## 7. 观众随时可用的轻量互动

### 7.1 点击位置反馈

**REACT-01｜魔法棒式交互。** 在演讲者开放权限时，观众可以选择反馈类型，并点击演示内容上的位置，触发一次性动画／冒泡效果。

可用类型可组成不同的反馈组，例如点赞、疑问、思考、举手等。课堂可开放克制的一组，活动场景可以开放更丰富的效果；不要求所有场次使用同一组。

**REACT-02｜反馈附着于内容位置。** 重点是“我对这里有反应”，不能只在固定角落累计一个无位置的图标。效果应出现在被点击的内容附近，短暂出现后消失，不长期遮挡讲解。

**REACT-03｜演讲者管理权限。** 可启停位置反馈，并选择可用类型／反馈组。权限变化应作用于当前在线参与者。

**REACT-04｜观众管理显示。** 每名观看者可关闭互动特效，进入纯净观看状态。这属于自己的显示选择，不改变其他观众的配置。

**补充位置约束：** 跨设备传播的是内容位置，而非点击者屏幕的绝对像素。技术方案可以采用对象相对坐标或画布坐标等方式。接收端没有看到该内容时，不得把反馈错误地贴到当前另一页；不应为了展示反馈强制切换观众视角。

**补充干扰控制：** 建议提供频率限制、同类效果合并或最大同时显示数，避免多人点击淹没课件。若提供反馈音效，应可独立关闭，并以不干扰授课为前提；默认策略待界面评审确认。

### 7.2 弹幕

**DAN-01｜观众短文本参与。** 演讲者允许时，观众可发送短文本弹幕，展示在指定的叠加区域。

**DAN-02｜受控的区域和方向。** 演讲者可配置弹幕出现区域及运动方式，例如上三分之一、下三分之一、左侧区域向上移动等。实际区域需结合页面内容与终端屏幕适配，不应把例子硬编码为唯三布局。

**DAN-03｜接收端可关闭。** 观众可以不看弹幕；纯净模式可隐藏非必要的反馈动画与弹幕。

**补充约束：** 纯净模式不应把题目、本人答题资格、提交结果或老师主动公开的教学内容隐藏掉。临时弹幕与持久讨论的数据语义需区分，不能因为发出了一条弹幕就自动成为一篇长期课程评论。

### 7.3 举手的含义

本层的“举手”是轻量反馈，不等于申请语音上麦，也不自动获得答题资格。正式答题资格由下一章定义的点名或抢答流程产生。

## 8. 音频边界与外部会议配合

### 8.1 外部会议优先承担多人交流

**AUDIO-01｜可配合外部会议。** 老师可以同时开启 Zoom 等会议或语音房，使用会议系统的共享屏幕和语音能力。Workspace 不要求自行实现会议才能开展演示。

老师可以共享公共演示画面，同时在另一个设备或屏幕上使用提示器。观众需进行多人语音交流时，可在外部会议中进行。

**补充界面建议：** 本场可显示演讲者提供的外部会议入口说明或链接。是否做具体会议平台的 API 集成不属于当前已确认范围；基础流程不应依赖此类集成。

### 8.2 内置音频只做单向主讲广播

**AUDIO-02｜单路主讲。** 内置音频的目标是 Presenter → Audience。主讲者可以开启一路音频，观众选择是否收听。

**AUDIO-03｜观众无原生上麦。** 观众不通过 Workspace 开麦、连麦或加入多人语音房。原生功能不包含上麦队列、多人混音和控麦面板。

**AUDIO-04｜无音频也可使用。** 不开或不听内置音频时，演示内容同步、轻量反馈和答题仍可使用。

### 8.3 录音与设备约束

保存回放时可将主讲音频与演示时间线关联。原生音频链路和实际承载方式需结合 OOD 场景评审，本 PRD 不指定实时传输协议或媒体服务器架构。

**补充约束：** 外部会议中的声音不会因为存在会议链接就自动成为 Workspace 录音。需显式启用可用的主讲录音来源；没有获得音频的场次必须如实标记。

同一老师使用多个设备时，应明确哪个设备承担主讲采音，避免重复上传或重复播放；具体设备切换交互待设计。公共大屏不得因为进入演示模式而自动申请观众麦克风或摄像头。

## 9. 演讲者主动发起的交互任务

### 9.1 题目来源与操作入口

**TASK-01｜预设或临时插入。** 老师可以到达预先准备的题目 Block，也可以在讲解过程中插入新的板书／题目内容，再发起交互。

**TASK-02｜提示器内控制。** 选择参加者、设定／查看人数、确认发题及查看答案主要发生在老师的提示器中，不占用公共大屏。

可以预先配置某一题的模式与人数。到达现场后，再根据实际在线听众列表完成选择和确认。

### 9.2 点名作答

**TASK-03｜选中后才可输入。** 老师从在线观众中选择若干人并确认后，被选者的终端进入对应题目的答题界面；其他观众继续观看题目，不获得输入权限。

同一个选择题 Block，在大屏或普通观众端只是展示选项，在答题者端则可点击选择。身份不同可以改变交互能力，不要求生成互不相关的多份题目页面。

### 9.3 抢答与人数上限

**TASK-04｜可切换为抢答。** 老师可将题目配置成抢答，例如最多三人。符合参与条件的在线观众看到“我要回答该题”按钮。

**TASK-05｜抢到后进入答题。** 成功获得资格的观众进入答题模式；达到名额上限后，其他观众不能继续取得本轮资格。

**补充一致性约束：** 名额由场次的权威状态确认，不以客户端先显示成功为准。重复点击和网络重试不重复占位；结果按系统成功确认的顺序处理，不承诺跨网络环境的绝对抢答公平性。

已取得资格后断线，默认不立即把同一人的名额分给另一人，避免重连后重复授权；老师是否手动收回、多久释放空闲名额，列为待决策策略。

### 9.4 统一输入方式

**TASK-06｜选择、文本、手写是输入形态，不是三套系统。** 获得资格后，可以呈现选择控件、文本框或手写区域。

| 输入类型 | 典型设备与场景 | 产品要求 |
| --- | --- | --- |
| 选择 | 手机、平板、电脑上的选择题 | 可选择并提交，未授权者不可操作。 |
| 文本 | 笔记本键盘、平板输入法 | 支持文字作答，不因没有手写设备而无法参与适合文字回答的题目。 |
| 手写／板书 | 支持书写的电子白板、带手写笔的平板 | 使用对应 Block 输入和展示书写内容；不把手写识别能力列为必需前提。 |

**补充数据约束：** 多名学生独立答题时，每人应有独立响应记录，不能把三个人的输入错误地写入同一个共享文本值。题目及结果展示 Block 可共享，但答案的归属必须明确。

### 9.5 答题状态与结束

**补充建议：** 最小流程为“等待资格 → 可作答 → 已提交 → 已结束／已撤销资格”。可编辑输入应显示保存／提交状态；是否允许提交后修改，由任务策略决定。

题目结束或授权被撤销后，观众应退出可写状态。重连、重复提交和结束瞬间到达的请求，都应有明确结果，不得无声丢弃或重复计算答案。

### 9.6 私有答案与公开展示

**TASK-07｜默认老师查看。** 答案默认出现在老师提示器中，不自动在大屏上公开。答题者可确认自己的提交结果。

**TASK-08｜结果是可展示的 Block 状态。** 老师可通过演示配置和操作，把所选答案或结果展示到公共画面。对观众而言，这是某个 Block 的内容／显示状态发生变化，而不是另外进入一个独立考试系统。

**补充约束：** 公开范围应明确，可是某份答案、若干份答案或结果摘要。未发布的原始答案和老师评语仍受限；切换展示状态不等于永久开放全部答题数据库。

### 9.7 评判与结果反馈

**已明确需求：** 答案需要保存，并存在后续评判需求。口述没有确定评分规则、自动化程度或成绩发布方式。

**建议的最小评阅基线：** 有权限者能按场次、题目和作答者查看答案，记录判断或评语；题目需要分数时可记录分数。老师控制评阅结果是仅自己可见、反馈给本人，还是公开展示。

客观题按标准答案自动判定可作为扩展评审；AI 批改、手写识别评分和复杂考试统计不作为本轮默认功能。课程满意度评分与学生答案得分是不同数据，不能混用。

## 10. 演示模式中的交互 Block 与扩展边界

### 10.1 演示不冻结所有内容

**BLOCK-01｜按 Block 配置可操作性。** 演示模式下，部分单元格仍可按正常模式操作，例如板书输入、原理演示、AI 代码生成等。老师可以现场点选、输入或运行，不要求退出演示才能完成这些动作。

**BLOCK-02｜按角色限制操作。** 可以只允许 Presenter 操作，也可以在特定任务中临时允许选中的 Audience 操作。配置一个 Block 可操作，不意味着放开它所在 Workspace 的全部编辑权限。

### 10.2 展示变化与数据写入的分界

这两类变化必须分开：

| 变化类型 | 例子 | 应遵守的边界 |
| --- | --- | --- |
| 演示显示状态 | 翻页、缩放、临时隐藏内容、显示某个结果 Block | 不应仅因播放操作而改写原课件的持久布局和内容属性。 |
| 被明确授权的数据操作 | 学生作答、老师板书、运行 AI Block 并接收结果 | 是真实数据变化，必须有权限、写入目标、记录和保存策略。 |

因此，“Presentation 是展示覆盖层”与“演示中的 Block 可交互”并不冲突：默认播放行为只改变演示状态；明确授权的 Block 操作可以产生持久数据，但不能伪装成无副作用的显示变化。

### 10.3 复用既有扩展体系

**BLOCK-03｜不建设平行系统。** 选择题、文本题、手写题、答题结果展示等，尽量在现有可扩展 Block 体系下实现。Presenter 的控制面、参与者授权和场次生命周期由演示能力协调，不应每种题型各自另造用户、权限与存储系统。

下列是**建议的产品能力契约**，不是最终 API：

| 契约能力 | Block 与演示模式配合时需要回答的问题 |
| --- | --- |
| 角色化展示 | 普通观众、答题者、老师和公共大屏分别能看到什么？ |
| 输入授权 | 谁能输入、输入范围是什么、何时失效？ |
| 响应归属 | 输入属于哪个场次、任务和参与者？ |
| 结果发布 | 哪些状态可公开，哪些仍保留在私有控制面？ |
| 状态保存 | 需要保存什么，才能在课后看到当时的结果？ |
| 回放呈现 | 能否只还原当时状态，而不重新触发业务动作？ |

并非任何第三方 Block 都天然满足回放要求。开始保存型演示前，应能识别不支持历史还原的 Block，并给出快照降级或明确提示，不能宣称所有扩展可无条件完整回放。

**补充安全约束：** 演示、扩展 Block 和 AI 的实际数据写入仍使用 Workspace 的既有权限／变更入口。不能为演示方便而建立绕过对象权限、版本和历史的写入通道。

## 11. Presenter 提示器与多设备使用

### 11.1 平板是优先考虑的提示器设备

**PRES-01｜同链接识别角色。** 老师可在平板上打开本场链接，登录演讲者账号后进入提示器视图，不必与公共屏共用一台电脑。

**PRES-02｜完成现场控制闭环。** 提示器至少支持当前讲解内容和备注、翻页、在线听众列表、点名／抢答控制、答案查看、结果发布，以及被允许的交互 Block 操作。

控制方式应适应触控，不应要求通过悬停操作或精细鼠标拖拽才能完成选人、确认和展示结果等常用动作。

### 11.2 公共屏与私有屏必须显式区分

**补充隐私约束：** 同一账号可能同时登录大屏和老师平板。账号有 Presenter 权限，并不意味着每台设备都应无条件展示私有提示器。

普通个人设备打开链接时，可按身份进入提示器；指定为“公共大屏”的终端必须保持公共视图，包括刷新和重连后。进入公共显示时应有明确选择，不能在加载、角色恢复或视图切换间隙闪现答案和备注。

同一账号的另一个设备进入公共显示，不应把老师平板也切换成公共模式。显示模式属于终端用途，操控权限属于身份授权，两者应分别管理。

### 11.3 多设备控制一致性

**补充约束：** 多个已授权终端应看到一致的场次状态，如当前题目、选中的学生和已发布结果。公共屏不应反过来获得管理操作入口。

是否采用“主控制设备”或允许多个授权终端共同操作，属于待决策的控制策略；至少必须避免重复发题、重复结束、重复占用答题名额等问题。一个设备断开，不应直接终止其他设备上的演示。

## 12. 答案保存、场次数据与课件版本

### 12.1 先明确用户要得到的效果

**DATA-01｜数据有归属。** 老师可以保存这次授课／考试产生的答案和其他课堂数据。有权限的人能查看本场所有人的答案，普通参与者是否能看全部答案取决于授权，不是链接公开就全量公开。

**DATA-02｜场次不混淆。** 同一 Workspace 多次授课，各场参与者、结果和记录可以辨认；后一次授课不能无意覆盖前一次答案。

**DATA-03｜可按题目配置复用。** 有些题目只允许某参与者答一次，之后进入可看到已有答案；也有些题目每次演示都产生新的答案空间。

**DATA-04｜数据属于课程文档体系。** 本场数据、记录与后续讨论在逻辑上属于这份课件及其演示实例，而不是无法从课件追溯的外部孤立聊天记录。

### 12.2 两种待选的场次数据模型

口述提出了以下两种模型，**本 PRD 不作最终选型**。

| 维度 | 模型 A：每次演示产生 Workspace 运行副本 | 模型 B：同一 Workspace 内保存各场数据 |
| --- | --- | --- |
| 基本方式 | 演示基于课件生成相对独立的数据运行副本。 | 保持一个 Workspace，按演示实例区分答案和运行数据。 |
| 本场写入 | 答题、现场板书和交互结果写入对应运行副本。 | 数据写入本场的分区／集合／等价隔离空间。 |
| 用户认知 | 打开原课件，可进入它派生出的历次演示。 | 看起来仍是一个工作区，其中列出历次演示及数据。 |
| 需解决的问题 | 共享内容与独立数据的边界、版本继承、存储占用和回溯。 | 分区隔离、按场次授权、历史版本还原和数据引用稳定性。 |
| 共同要求 | 两者都要支持长期链接、历史还原、独立答案、访问权限和课件历史入口。 | 两者都不能仅依赖当前课件最终状态来冒充历史记录。 |

副本不必等同于全量物理复制。上述模型描述的是产品与逻辑隔离关系，具体是快照、引用共享还是其他方式，由后续技术设计确定。

### 12.3 数据模型与答题策略是两个维度

“每次演示有独立运行数据”不代表所有题目必须每场重答；“一个 Workspace”也不代表所有场次必须共享一份答案。

| 答题策略 | 用户侧结果 | 待明确的作用域 |
| --- | --- | --- |
| 每人仅答一次并复用 | 下次进入，按权限看到自己的已有答案，不自动获得新的作答机会。 | “同一道题”按哪个稳定标识判断；题目修改／课件改版后是否仍算同题。 |
| 每次演示独立作答 | 每场产生新的响应记录，上一场结果保留。 | 同一场内重新发题算新任务还是覆盖，需要显式规则。 |

**补充约束：** 复用答案时，应知道其原始场次和提交来源，不能把旧答案显示成学生刚在新课堂现场提交。某人在其他班级／场次的私有答案也不能因复用策略向当前所有参与者开放。

### 12.4 建议的数据分层

下表是产品上的逻辑区分，不规定数据库表、目录或对象树的物理布局。

| 数据域 | 典型内容 | 保存与归属原则 |
| --- | --- | --- |
| 课件内容与版本 | 对象、题目、数据引用、演示路径、页面备注 | 允许持续改进；历史授课需能定位原版本。 |
| 场次配置 | 加入权限、反馈组、题目策略、音频设置 | 能解释当时采用了什么规则。 |
| 场次运行状态 | 当前视角、当前任务、已授权答题者、结果公开状态 | 直播中同步；保存时按回放和追溯需要归档。 |
| 作答与评阅 | 答案、提交者、提交状态、评语和成绩 | 按题目策略隔离或复用，并保留访问权限。 |
| 回放记录与资源 | 时间线、状态变化／快照、当时输出、主讲音频 | 用于历史还原，不能依赖当前实时结果。 |
| 课后内容 | 时间点感受、普通评论、课程评分和建议 | 绑定本场，可在授课结束后继续增长。 |
| 个人／终端显示状态 | 是否跟随、是否显示弹幕、音量、公共屏／提示器用途 | 不应当成所有人共享的课件内容。 |

### 12.5 版本绑定与现场修改

**DATA-05｜课件可迭代。** 老师可以从 v1 改到 v2、v3，并用新版再次授课。每场记录应对应当时所用的版本及现场实际发生的变化。

仅保存“开始时的 v1”和“结束时的最终画面”不足以表达中间过程；回放还需要当次展示状态的演变。临时插入的题目、现场生成的内容，也属于需要被保存的本场结果。

**补充边界：** 现场修改是否直接写回原课件，或只留在演示实例中，应由编辑／保存策略明确。本 PRD 不默认把学生答案、临时板书和演示显示状态自动合并回老师的原始课件。

改进课件不得悄悄改变历史房间的内容。历史答案在课后新增评语，可以作为后续评阅数据保存，但不能被伪装成当时授课过程的一部分。

## 13. Replay：结构化演示回放

### 13.1 回放定位

**REPLAY-01｜像游戏录像一样重放过程。** 保存的演示应能按时间重现讲解，而非只打开课件最终状态。核心方式是结构化演示状态／事件配合主讲音频，不以持续录屏为基础。

每个演示链接在保存后都可以成为一份可回放课件。新增授课记录中的主要媒体负担预期来自音频，但不应把“音频是唯一非结构化数据”写成硬性假设：原课件可能已有图片、视频或其他附件，手写 Block 的底层存储也取决于实现。

### 13.2 必须可还原的内容

**REPLAY-02｜还原公共讲解状态。** 包括当时的课件版本、主讲者视角／Frame 切换、公开可见的 Block 变化、临时插入内容、题目发起及结果公开的时间顺序。

**REPLAY-03｜对齐主讲音频。** 已录制的音频应与演示时间线对应。播放速度或位置改变时，内容状态和音频应一起变化。

**REPLAY-04｜基础控制。** 至少支持播放、暂停、快进／变速和按时间定位。按 Frame 或题目跳转可作为定位增强设计，不把 AI 摘要、知识点检索列为当前必需功能。

### 13.3 回放需要状态，不只需要操作名称

以下属于确保回放成立的**补充实现约束**：

| 情况 | 回放必须具备的依据 |
| --- | --- |
| 老师切换视角 | 当时的目标内容和视角状态，而不只是“点了下一页”。 |
| 老师插入题目／修改板书 | 当时新增内容及状态变化。 |
| AI 或代码 Block 产生输出 | 当时已经产生的输出／展示状态。 |
| 引用外部动态数据 | 足以还原当时展示结果的数据或快照；不能无提示改用现在的数据。 |
| 跳到中间时刻 | 能重建该时刻的状态，不应必须让用户从开头逐项观看。 |

事件流、状态快照与关键帧如何组合，由技术方案决定。本 PRD 不假定任意协作同步日志天然就是完整、可跳转的 Presentation Timeline。

### 13.4 回放不重新执行业务

**补充安全约束：** 回放必须展示已经保存的历史结果，而不是重新调用 AI、重新执行代码、重新提交答案、重新发送消息或再次访问会产生副作用的业务接口。

观看者在回放中点击内容，不应无意修改课堂历史。回放可以浏览内容和参加课后互动，但原任务的历史响应保持原意；未来若增加“再练一次”，应创建新的作答上下文，不覆盖课堂记录。

### 13.5 公共和私有数据分开回放

普通观众看到的是有权限的公开演示过程。老师的备注、选人操作界面、尚未公开的答案和评语，不应因为保存完整记录就进入所有人的回放数据包。

老师查看全部答案，是其管理／评阅权限，不意味着需要把整个私有提示器录成公开回放。

**待决策：** 现场的瞬时位置反馈和弹幕是否全部归档、按什么规则过滤，可单独配置。至少应把正式教学结果和可选氛围效果分开，纯净回放不能丢掉关键的教学状态。

### 13.6 不完整回放的处理

**补充约束：** 音频中断、资源缺失、不支持历史还原的扩展或暂存失败，都需在保存结果和回放界面标记。可以在明确告知后保存可用部分，但不能把缺失内容显示成完整记录。

播放缺少音频的片段时，应如实显示无音频／音频缺失，不虚构讲解。若依赖资源已无法恢复，应提示具体缺失，而不是用当前新版内容替换后仍称为历史状态。

## 14. 课后房间、讨论与课程历史

### 14.1 结束之后仍然可交互

**ROOM-01｜保存的房间长期存在。** 在 Owner 未删除、访问权限允许且所需存储与服务可用的情况下，原链接可持续访问。产品不应设置一个与授课结束绑定的默认失效时间。

**ROOM-02｜回放不是唯一内容。** 房间同时承载当次授课数据、答案、回放、课后讨论及课程反馈。观众不是只能播放完就离开。

是否可继续评论、是否开放评分，以及谁能看答案，由房间权限决定。关闭新评论不应自动删除原有回放或既有讨论。

### 14.2 区分三类课后交互

| 类型 | 绑定关系 | 观看与使用方式 |
| --- | --- | --- |
| 时间点感受／回放弹幕 | 绑定本场回放中的某个时间点。 | 其他人看到相应时间点时，可以看到这条想法或感受。 |
| 普通评论／讨论 | 绑定本次授课整体，不强制指定时间点。 | 在讨论区交流听课感想、问题和延伸内容。 |
| 课程评分／意见 | 绑定本次授课的反馈数据。 | 对授课给出评价或改进意见；不等同于学生作答成绩。 |

**ROOM-03｜时间点与真实发表时间分开。** 回放中留下的感受，既有“它针对哪一秒”的回放时间，也有“实际何时发表”的创建时间。后来的内容不能被误认为课堂现场已经发生的发言。

**补充交互建议：** 可显示“课后发表”等来源标识，并允许观看者关闭时间点感受，不妨碍继续访问普通讨论。课程评分采用何种量表、是否允许修改及是否匿名，待评审确定。

### 14.3 讨论的上下文层级

**ROOM-04｜课程群与单次授课房间并存。** 班级大群、物理课程子群等适合讨论一门课的长期问题；某次授课房间适合围绕这一次老师讲的内容讨论。

课程／班级侧可以列出历次授课记录，让学生进入相应房间；从某次回放发表的内容则留在该房间，使讨论有明确的授课上下文。

本需求不要求另造一套完整 IM。具体如何复用已有群聊、评论或消息能力，由应用集成设计决定。自动把房间评论转发到班级群不属于当前已确认功能。

### 14.4 课件上的历次演示入口

**ROOM-05｜从课件追溯全部演示。** 老师打开自己的 Workspace，可以看到该课件的历次 Presentation 记录，并进入各场数据和后续讨论。

**建议的记录列表字段：** 场次名称、授课时间、所用版本、是否已保存、是否有可用音频／回放，以及按权限可见的答案和讨论入口。参与人数等统计可以展示，但不能代替实际场次和版本关联。

该入口应支持老师持续改进课件；不要求在首期自动分析反馈或自动生成新版课件。

## 15. 关键界面与状态要求

本节约束信息组织，不规定最终视觉稿或具体控件样式。

| 界面 | 必须明确的信息／操作 | 需要避免的问题 |
| --- | --- | --- |
| 开始演示／场次设置 | 本场课件、链接／加入开关、互动权限、记录与音频状态。 | 用户不知是否在录音，或以为一场新课沿用旧答案而实际被清空。 |
| Presenter 提示器 | 当前内容、备注、在线名单、题目操作、私有答案、发布控制。 | 私有信息落入大屏；触控设备无法完成主要控制。 |
| Public Display | 公共课件、获准的现场效果和已发布结果。 | 同账号登录后自动展示老师面板。 |
| Audience 观看界面 | 跟随状态、轻量反馈、弹幕开关、听讲状态和当前任务。 | 小屏被常驻面板占满；关闭弹幕同时丢失答题提示。 |
| Audience 答题状态 | 所答题目、获得资格、输入区域、保存／提交反馈。 | 未抢到却显示可答；重复提交不知成功与否。 |
| 结束与保存界面 | 保存权限、将保留的数据、录音完整性、保存进度和结果。 | 结束后即丢数据；文件未写完却提示全部保存成功。 |
| 归档房间／Replay | 历史版本、播放控制、时间点感受、普通讨论、本人或已公开结果。 | 混淆当前课件和历史课件，或把课后评论伪装成现场发言。 |
| Workspace 演示历史 | 各场次、各版本、状态与入口。 | 只能靠搜索聊天链接找历史，或后一次演示覆盖前一次入口。 |

**补充建议：** 加载、等待授权、断线、已结束和权限不足都应有可辨识的界面状态。不要以可点击但无反馈的控件替代明确状态。

## 16. 非功能要求与异常处理

以下是为真实课堂可用性补充的验收约束。并发规模、延迟、同步误差和容量的数值目标须经过评审及测量，本文不虚构指标。

### 16.1 权限与隐私

所有写入、答案读取、结果发布、录制访问和删除操作都应执行授权检查，而不是仅隐藏按钮。临时答题授权限定到场次、任务、Block 和参与者；结束／撤销后及时失效。

公共屏、观众端和公开回放均不得收到未获准的老师私有内容。对答案的访问控制不能因共用数据源、共享编辑或回放下载而失效。

### 16.2 一致性、重连与恢复

答题资格、人数上限、提交结果和保存状态应有一致的最终判断。重复请求不能产生重复名额、重复答案或重复演示实例。

断线重连后恢复当前场次、用户权限和已确认提交；需要重新授权或本地内容尚未提交时，应明确显示。在线状态可以变化，但不能把名单刷新直接当作删除历史答案的依据。

### 16.3 带宽与交互干扰

互动反馈、弹幕和音频应有可控的资源边界，优先保障主要内容及答题操作。多人效果过密时可采用限流／合并等降级，但不能静默丢弃正式提交并显示成功。

面向 OOD 的实际承载上限需要验证。超过容量时应明确提示或限制加入／效果强度，而不是以“全球可参与”的定位承诺不受资源约束的服务。

### 16.4 保存与资源保留

保存成功应表示所声明的数据已被可靠保留，并能由原链接重新访问。若只保存了结构化记录而没有音频，应明确区分。

归档记录依赖的课件版本、现场输出、音频和其他必要资源不能因原课件改版就被错误清理。存储不足时提示释放空间或选择可接受的保存范围，不擅自删除已归档场次。

### 16.5 离线与不支持的环境

不启用在线加入时，可复用 Workspace 已有的本地演示能力；本 PRD 不承诺断网时仍能进行跨设备实时广播和抢答。

音频不可用时仍可参与内容与题目。缺少手写笔时可使用任务支持的文本输入；对于必须手写且当前设备不支持的题目，应明确提示，而不是假装可以提交。

### 16.6 基本内容管理

**补充建议：** Owner／被授权的管理者应能关闭互动、限制违规参与者和处理不当评论。具体审核体系可复用现有能力，不要求为首期演示模式单独建设复杂内容平台。

### 16.7 常见异常的最低处理要求

| 异常 | 最低处理要求 |
| --- | --- |
| 观众抢答时断网 | 未经确认不能显示已获得资格；重连查询最终状态。 |
| 三个名额被同时请求 | 只有配置上限以内的参与者被正式授权。 |
| 答题过程中老师结束题目 | 明确显示关闭状态，按既定规则处理已到达的提交，不悄悄覆盖。 |
| 观众重连时题目已结束 | 显示本人已确认结果／结束状态，不回到错误的可编辑状态。 |
| 老师平板断线 | 公共演示和观众连接不因此自动终止；提示控制端连接异常。 |
| 内置主讲音频断开 | 内容和交互尽可能继续，音频缺失可见，录制记录保留缺口信息。 |
| 保存时空间不足／失败 | 不显示完整成功；保留可恢复状态并说明缺失或待处理内容。 |
| 历史资源不存在 | 说明该资源缺失，不加载当前数据冒充当时数据。 |
| 已结束但没有保存 | 不展示不存在的回放；暂存和房间保留遵循明确策略。 |
| 历史链接权限被撤销 | 明确显示访问受限，不继续提供尚未获准的数据。 |

## 17. 建议实施顺序

以下是研发工作包顺序，不是对最终范围的删减，也不是发布承诺。数据归属、权限和回放可记录性必须在早期确定，不能等到最后再补。

| 工作包 | 主要内容 | 阶段完成条件 |
| --- | --- | --- |
| 1. 场次与角色基础 | 演示实例、链接、加入、基础播放、观众视角、提示器／公共屏分离。 | 同一场次可在老师平板、公共屏、多个观众设备上正确展示；权限隔离成立。 |
| 2. 现场交互 | 位置反馈、弹幕、点名／限额抢答、选择／文本／手写 Block、结果发布。 | 观众输入与老师控制闭环运行，多个答题者的数据不互相覆盖。 |
| 3. 保存与回放闭环 | 数据模型落地、版本绑定、暂存／保存、主讲音频、结构化 Replay。 | 同一链接能回看真实授课过程，跳转不重复执行业务，答案按权限可查。 |
| 4. 长期课程房间 | 时间点感受、普通讨论、评分意见、课件历次记录入口。 | 课后仍能在原房间持续参与，老师能从课件追溯各场次。 |
| 5. 课堂可靠性验证 | 触控、多设备恢复、弱网、容量、保存失败、隐私与回放资源保留。 | 关键异常有明确反馈与恢复路径，性能目标通过实际测试确认。 |

若选择先交付较小版本，必须另行标明未完成的已确认能力；不能把手写、保存、回放或长期房间等核心需求悄悄改写为“仅未来设想”。

## 18. 产品验收场景

验收覆盖完整目标产品；性能量化阈值需另行确定。涉及补充约束的条目，在评审确认后纳入对应阶段验收。

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| AC-01 | 老师不生成或关闭加入链接，进行单屏／双屏演示。 | 翻页、备注及公共展示不依赖在线观众存在。 |
| AC-02 | 同一课件分别开展两次演示。 | 产生可区分的场次和链接，各自数据不会相互覆盖。 |
| AC-03 | 老师平板与公共屏使用同一账号打开同一场次。 | 平板可使用提示器；明确指定的公共屏始终不显示私有备注和答案，刷新后仍正确。 |
| AC-04 | 观众停止跟随，移动至另一内容位置后点击反馈。 | 反馈关联实际内容位置，不贴到其他人的错误页面，也不强制他人跳页。 |
| AC-05 | 不同尺寸设备观看同一位置反馈。 | 效果定位在相同内容语义附近，而非照搬点击者的屏幕像素。 |
| AC-06 | 老师关闭某组反馈或全部反馈。 | 观众不能继续发出被关闭的类型；保留已允许类型的正确状态。 |
| AC-07 | 观众开启纯净模式。 | 动画／弹幕可隐藏，题目、本人资格与老师公开的教学结果不被隐藏。 |
| AC-08 | 老师配置弹幕区域和方向，观众发送文本。 | 在指定规则下显示，小屏有适配，不把语音自动字幕当作必要依赖。 |
| AC-09 | 使用外部会议听讲，Workspace 不开音频。 | 内容同步及互动正常；不要求接入原生会议或开放观众麦克风。 |
| AC-10 | 开启内置主讲音频。 | 观众能选择收听／静音，没有原生上麦或连麦入口，停音频不停止答题。 |
| AC-11 | 老师点名两位学生回答选择题。 | 只有两人获得对应题目的输入权限，其他观众只能观看。 |
| AC-12 | 老师开放最多三人的抢答，多人同时点击。 | 最多三人获确认资格，重复请求不占多个名额，未成功者不会进入可提交状态。 |
| AC-13 | 分别进行选择、文本和手写题。 | 都复用相同的授权与响应归属逻辑，多人独立答案不相互覆盖。 |
| AC-14 | 学生提交答案，老师尚未公开。 | 老师和相应本人可按权限查看；其他观众、大屏及其同步数据不含未公开答案。 |
| AC-15 | 老师公开某一份答案或结果 Block。 | 公共视图出现选中的内容，未选择的答案和私有评语不随之泄露。 |
| AC-16 | 老师在演示中操作板书或 AI 生成 Block。 | 无需整体退出演示；只有被配置的操作可用，不因此开放全部课件编辑。 |
| AC-17 | 观众提交后断线重连或重复提交。 | 已确认结果可恢复，不出现新的身份、重复名额或重复答案。 |
| AC-18 | 题目设为每人只答一次，之后再次进入。 | 显示可追溯的已有答案，不静默新建响应；其他参与者仍遵守权限。 |
| AC-19 | 题目设为每次演示独立作答。 | 新场获得独立机会，旧场的答案保持完整且可追溯。 |
| AC-20 | Presenter 与 Owner 不同，结束并尝试保存。 | 只有 Owner 或已获保存授权者可完成保存；结束不会直接绕过授权。 |
| AC-21 | 保存后再次打开原链接。 | 进入同一场次记录／回放与讨论，不创建新场次，也不跳到新版课件。 |
| AC-22 | 回放暂停、变速、跳至中间时刻。 | 公共内容状态与可用音频匹配，不必重新观看开头才能恢复该时刻。 |
| AC-23 | 回放包含曾经执行 AI／代码的 Block。 | 展示当时保存的结果，不再次执行、付费调用、提交答案或发出业务请求。 |
| AC-24 | 老师把课件 v1 改为 v2，再访问 v1 场次。 | 仍还原当时内容及现场变更，不被 v2 替换；课件历史中能找到两场记录。 |
| AC-25 | 学生在回放某时刻留下感受，并另发普通评论。 | 感受绑定播放时间且保留实际发表时间；普通评论归属本场而不强制绑定时间。 |
| AC-26 | 学生留下课程评分／建议，老师查看历次课程。 | 反馈归属正确场次，和答题成绩分开；老师可由课件入口访问各场数据。 |
| AC-27 | 某段音频或外部资源缺失，或者保存失败。 | 明确显示不完整／失败状态，不宣称完整回放，不用当前资源冒充历史。 |
| AC-28 | 房间限制访问、关闭新评论或被 Owner 删除。 | 各操作只产生其声明的效果；评论关闭不等于回放删除，无权限者不能继续读取受限内容。 |

| 决策项 | 已确定的约束 | 仍需确定的内容 |
| --- | --- | --- |
| 场次存储模型 | 每次演示数据可隔离、可保存、可追溯。 | Workspace 运行副本、Workspace 内场次数据，或保持两者产品效果的等价实现。 |
| “每人只答一次”的作用域 | 可复用已有答案，与每场独立作答并存。 | 题目标识、参与者身份、版本变更后的复用规则及重复发题策略。 |
| 现场数据的写回 | 展示变化不污染课件，授权输入有保存位置。 | 哪些现场修改保留在本场，哪些允许写回原课件及如何确认。 |
| 保存与暂存 | 保存需 Owner 权限或明确授权，已保存链接长期可用。 | 暂存期限、不保存时房间是否保留、异常恢复及资源配额策略。 |
| 参与身份 | 答题和权限必须有可识别的归属。 | 匿名观看／访客互动范围、身份恢复及仅答一次的可靠性要求。 |
| 抢答细则 | 可配置人数上限，资格一致且不可超额。 | 名额超时、断线回收、老师撤销与补选等操作。 |
| 评阅基线 | 答案可保存并有评判需求；成绩与课程评价分开。 | 手动评语／分数的字段、是否首期提供客观题规则判分、结果发布策略。 |
| 音频承载 | 原生仅单路主讲，外部会议承担多人交流。 | OOD 场景下的传输和存储方案、容量目标、音频输入设备切换及同步指标。 |
| 回放记录策略 | 历史可还原、可快进、不得重新执行业务。 | 快照／事件组织、资源归档、扩展 Block 降级、瞬时反馈和弹幕保留范围。 |
| 多设备控制 | 同角色可用多个终端，公共／私有视图隔离。 | 主控制端机制，或多端共同控制的冲突处理。 |
| 课程反馈形式 | 支持评分、意见及两类讨论语义。 | 评分量表、匿名与否、修改规则及内容管理权限。 |
| 性能与可用性指标 | 以真实课堂体验和 OOD 承载能力为边界。 | 并发人数、事件延迟、音画同步容差、回放定位耗时和容量上限。 |

## 20. 端到端示例：一次可持续参与的物理课

以下仅用于验证完整体验，不增加新的必需功能。

老师打开物理课 Workspace v1，开始一场演示，选择在线加入并分享本场链接。教室大屏设置为公共视图，老师手持平板使用同一链接进入提示器；学生通过个人设备进入观众视图。

讲解时，学生可以跟随，也可以在可见内容中自行浏览。在老师开放权限的情况下，学生点击公式旁发出疑问效果，或在指定区域发送弹幕；不希望受干扰的学生开启纯净模式。

老师到达一道预设题目，将模式设为最多三人抢答。成功获得资格的三名学生分别进入自己的答题区域；有人用键盘输入，有人用带笔平板书写。老师先在提示器中查看答案，再把其中一份展示到公共结果 Block，围绕它继续讲解和板书。

本场若使用内置单向音频，记录老师的一路讲解；若听讲来自外部会议，则只有在确实启用了可用主讲录音来源时，本场归档才包含对应音频。

结束后，老师以 Owner 或已授权身份保存。课件版本、本场数据、可回放的讲解状态及实际录得的音频归档。学生仍用原链接打开这次课堂，回到老师讲解该题的时间点，在那里留下感受，或在普通讨论区提问并给出课程建议。

老师从课件的历次演示列表查看本场答案和反馈，改进为 v2 并再次讲授。新一场获得新的记录入口，旧房间继续保留当时 v1 的授课过程和围绕它形成的讨论。
