# BuckyOS AI Workspace UI 改进

本文完善 AI Workspace 的 UI 抛光方案，重点改造画布模式。保留原稿提出的主工具栏、演讲工具栏、竖排对象插入工具栏和统一主菜单，结合用户提供的 Miro 截图，把布局、行为、现有实现和新增依赖分别写清楚。

**文档状态：P0、P1 已实施（2026-10-07），P2 未实施；手机上的画布（§16）已实施。** 实施中的取舍与偏差写在 §15，验收结果见 [UI 改进实施记录与验收报告](<BuckyOS AI Workspace UI改进实施记录与验收报告.md>)；§2 的“当前实现”一列描述的是实施前的状态。布局与功能分组以原稿对 BuckyOS 的裁剪为准，Miro 只提供悬浮样式、留白、视觉层级和交互细节参考，不决定工具栏数量或功能位置。演示业务规则沿用 [演示模式 PRD](<BuckyOS AI Workspace 演示模式PRD.md>)，本文负责其入口和工具栏衔接。

> 第三期（2026-10-08）：本文的“演讲工具栏”在代码中改名为“视图工具栏”（`ViewToolbar`，测试 id `aiws-view-toolbar`，偏好键 `ui:view-toolbar`），“提示器”一词留给放映的提示器链接；“播放编辑”占位改为真实的“路径编辑”，并新增“开始放映”“使用引导”入口。见[第三期规划](<BuckyOS AI Workspace 第三期规划.md>) §2、§7。

## 1. 改造目标与 Miro 参考

默认进入上次打开的画布，让用户先看到内容，再按任务找到工具。工作区身份、创作、协作、视图控制分区放置，减少当前多层横向工具栏对画布的挤占。

常驻工具按原稿收敛为主工具栏、演讲工具栏和对象插入工具栏。缩放与视图导航统一放在演讲工具栏，不设置右下角导航区；右下角是状态区，放保存/连接状态、告警与提示，以后可展开的工作日志也放在这里。低频功能由主菜单承接。画布切换仍属于主工具栏，不随视图导航一起迁移。

| 截图中的设计 | AI Workspace 的采用与裁剪 |
| --- | --- |
| 画布铺满背景，工具以悬浮面板分布在边缘 | 自由画布占满应用内容区；工具栏使用屏幕坐标，不随画布缩放。 |
| 左上角集中显示名称和主菜单 | 当前画布图标、名称与切换、数据源入口、主菜单、协作入口。 |
| 右上角集中放置协作与演示相关操作 | 标注、互动、缩放比例、身份与在线成员、分享链接；按模式显示。 |
| 左侧竖排创作工具，撤销／重做单独成组 | 选择／移动视图、标准对象、工作区扩展、更多插入；撤销／重做归入同一对象工具栏底部，用分隔线分组。 |
| 左侧独立 AI 入口 | 许愿格归入对象工具栏的 AI 分组，进入“描述任务—预览候选—应用结果”流程，不因截图另增常驻 AI 悬浮按钮。 |
| 右下角独立缩放与帮助区 | 不保留缩放与帮助。缩放、适应全部／选区集中到演讲工具栏的比例菜单；快捷键帮助放入主菜单。右下角改为状态区：保存与连接状态摘要，以及叠在其上的告警、提示，以后可展开的工作日志也放在这里。 |
| 浅色网格、留白、统一图标和轻阴影 | 延续 Desktop 主题变量，降低网格对比度，统一按钮尺寸和选中状态。 |

截图中的思维导图、连线和视频等图标不直接变成本期功能清单。对象入口以现有注册表和工作区内的扩展定义为准；连线工具、手绘工具等需要各自的对象模型和交互支持。

## 2. 现有实现与改造边界

以下前端路径均相对于 `src/frame/desktop/src/app/aiworkspace/`。

| 能力 | 当前实现 | 本次设计要求 |
| --- | --- | --- |
| 打开工作区 | `AIWorkspaceAppPanel.tsx` 先展示 `WorkspaceList`，用户手动打开。 | 新增按身份隔离的最近工作区恢复；仍保留列表入口。 |
| 画布与数据源 | `WorkspaceShell.tsx` 已共用 Session、Store、撤销栈和待提交队列；默认画布，可恢复顶层模式。 | 合并入口，明确应用启动时“回到上次画布”的优先级。 |
| 多画布 | `SurfaceNav` 已支持自由画布／流式页的新建、切换、重命名、删除预检。 | 搬到主工具栏，名称编辑与下拉切换分开操作。 |
| 视口恢复 | `CanvasView.tsx` 使用 `surface:active`、`canvas:mode`、`viewport:<surfaceId>`。 | 继续复用，补齐失效画布回退和新布局下的可视区域计算。 |
| 画布操作 | 已有选中、多选、拖动、调整尺寸、分组、层级调整、跨画布移动、就近工具栏和右键菜单。 | 整理为竖排工具、上下文工具和主菜单共用的动作。 |
| 对象插入 | `insertChoices()` 由 Block 注册表生成；已有数据／增加视图使用 `Picker`。通用 HTML／声明式宿主未列入普通插入列表。 | 增加分组、搜索、扩展定义选择和统一插入对话框。 |
| 模式 | `edit`、`view` 已实现；`presentation_edit` 是静态只读占位，“开始演示”按钮禁用。 | 保留三种画布子模式的区分；真实放映和场次控制单独建设。 |
| 许愿格 | 已有真实执行器与 Mock 执行器、候选预览、反馈、应用、历史和过期状态。 | 将许愿格作为正式 AI 入口；旧“受控加工”面板收进开发工具。 |
| 权限与协作 | 已有授权、变更同步、富文本协作和写锁；`PermissionsPanel` 支持工作区／画布授权。 | 协作按钮先复用权限面板。在线成员、头像、跟随视角仍需新增 presence 能力。 |
| 分享 | 已有分享导出包和个人恢复备份。当前 Workspace 入口未接收画布定位参数。 | 访问链接需要新增启动定位链路；分享包、访问链接、演示场次链接分别标明。 |
| 离线与保存 | 已有在线直连、离线副本、四种保存状态、待处理列表、未提交内容导出。 | 收纳正常状态，保持异常可见、可处理，不改变保存语义。 |
| 模板 | 列表已有项目样例、季度经营分析、AI 短片工作流；创建函数生成完整工作区。 | 纳入统一新建对话框，明确创建范围，保留 Mock 标识。 |
| 尚缺的基础交互 | 未有画布对象剪贴板、预设画布图标选择、统一主菜单、常驻选择／手形工具切换。 | 明确列为新增工作，不写成单纯换皮。 |

画布图标还有数据契约依赖：`src/frame/aiworkspace/core/src/types.rs` 的 Container 校验只接受既有字段，当前不接受 `icon`。要实现可共享、可撤销的画布图标，需要同步扩展核心校验、读模型和前端类型。

## 3. 默认布局

### 3.1 自由画布编辑模式

```text
┌────────────────────────────── 应用内容区 ───────────────────────────────┐
│ [图标 画布名 ▾ | 数据源 | ⋯ | 协作] [标注 | 互动 | 100% ▾ | 头像 | 分享] │
│                                                                        │
│ ┌对象工具┐                                    ┌─按需打开的右侧面板─┐  │
│ │选择/手形│                                   │ 属性／依赖／批注   │  │
│ │标准对象│        画布内容                     │ 协作／修改状态     │  │
│ │AI/许愿格│             [选中对象就近工具]     │                   │  │
│ │工作区扩展│                                  └───────────────────┘  │
│ │＋更多  │                                                             │
│ │────────│                                                             │
│ │撤销/重做│                                                            │
│ └────────┘                                     ┌告警／提示（叠放）─┐   │
│                                                └───────────────────┘   │
│                                  [已提交 ✓／已保存到本设备／需要处理 N]  │
└────────────────────────────────────────────────────────────────────────┘
```

图中的右侧面板默认收起；互动、分享等区域按实际能力和模式显示。未接入的功能不放置可点击但无结果的按钮。可保留明确标注“尚未实现”的演示入口，与当前占位语义一致。

布局以 Workspace 所在窗口为边界，而非浏览器全屏。左上和右上是两个独立面板，中间留空；移除当前横跨全宽的多层工具条。左侧对象工具栏收纳许愿格与撤销／重做。缩放与视图导航由右上演讲工具栏统一承接，画布底部不设置导航面板。右下角的状态区属于工作区（画布或数据源），右侧面板打开时随工作区左移，不被面板遮挡（§10）。

### 3.2 面板与浮层

- 右侧常规面板同一时刻显示一类内容：属性、引用与依赖、批注、协作、修改状态。切换标签即可切换，不并排挤出多个窄栏。
- 宽窗口中面板占用实际布局宽度，画布和 Camera 使用扣除面板后的尺寸；窄窗口改为抽屉，关闭后恢复原视口。
- 就近工具栏避让主工具栏、右侧面板和窗口边缘；放不下时折叠次要动作到“更多”。
- 菜单／对话框打开时暂停画布手势。工具栏点击不穿透到画布，非模态工具栏容器的空白区域不拦截画布操作；模态框使用正常遮罩与焦点约束。
- 画布对象、选区、就近工具、全局工具、菜单、模态框由低到高叠放；HTML Block 不得盖住宿主工具或对话框。

### 3.3 流式页与数据源模式

自由画布和流式页共用名称、菜单、协作与对象目录。流式页保留段落顺序和插入位置，不套用自由画布坐标；首版隐藏相机缩放工具，避免把页面滚动和画布缩放混为一谈。

数据源模式继续使用现有数据树、详情和属性／关系／权限面板。左上“数据源”切换为“返回画布”，返回之前的 Surface 和视口；从数据对象打开某个 Block 时，定位到该 Block 所在画布。模式切换不重新打开工作区 Session。

## 4. 打开与恢复规则

1. **显式打开优先。** 从列表选择工作区，或未来通过链接指定工作区／画布／对象时，使用该目标，不被最近记录覆盖。
2. **普通启动进入最近画布。** 无显式目标时，恢复当前登录身份最近成功打开的工作区及其中的 `surface:active`；普通启动进入画布视图。数据源模式仍可在当前会话中保留和切换，但不阻止“启动先回画布”。
3. **恢复视口和子模式。** 恢复该画布的视口，以及工作区的面板偏好和上次编辑／查看／路径编辑状态；不能自动开始放映（一个仍在进行的放映只在同一标签页重新载入时由舞台继续，见第三期规划 §11.3）。
4. **目标失效。** 画布已删除或不可读时，进入同工作区第一张可读画布；没有画布则进入空状态，提供新建自由画布／流式页。有工作区但无权限时回列表，不反复自动重试。
5. **离线启动。** 沿用 `openPreparedReplica()` 的判断。有可用且可持有的副本时打开；否则展示现有不可用原因和可打开列表，不伪装成空工作区。
6. **关闭工作区。** 返回列表，本次应用会话暂停自动恢复；下一次普通启动仍可恢复最近成功打开的工作区。关闭不删除工作区或本机副本。
7. **独立标签页。** 常用方式是在浏览器标签页中独占打开 `https://<zone 主机>/workspace/<工作区>`，地址就是打开目标：`/workspace` 是列表，`/workspace/<工作区>` 是该工作区，不做最近记录的自动恢复（规则 2 只适用于 Desktop 窗口）。在标签页里打开、切换、关闭工作区都会改变地址，浏览器的前进、后退和重新载入跟随地址。

新增“最近工作区”记录放在应用级本机状态，至少按 Zone／服务目标和 principal 隔离；它不能放进必须先打开工作区才能读取的 `UserWorkState`。工作区内视口等继续使用既有状态通路。恢复记录只在打开成功后更新；身份切换不能展示另一身份的最近内容。

## 5. 主工具栏

**顺序：画布图标｜画布名＋独立下拉箭头｜数据源图标｜主菜单（⋯）｜协作（图标＋文字）。** 保存状态入口在右下角状态区（§10）。

### 5.1 画布图标与名称

- 点击图标，弹出预设图标面板；选择后更新当前 Surface。首版不增加图片上传。未设置时按自由画布／流式页显示默认图标。
- 图标是画布的共享属性，走文档提交、权限校验和撤销流程；拟新增 `icon` 字段保存稳定的预设标识，不能只写入当前浏览器。
- 点击名称进入行内编辑；Enter 提交，Esc 取消，失焦提交非空变更。Esc 后的失焦不能再触发保存。空名称恢复旧值，并提示原因。
- 复用现有重命名的版本检查，保持 Surface 的标题与名称一致。提交被拒绝时保留用户输入并给出错误，不静默覆盖他人的改名。
- 名称过长时省略，悬停显示全名；工作区名称放在下拉面板顶部，避免把工作区名和当前画布名混用。
- 图标和改名操作按实际所需能力启用，不能因为进入编辑模式就假定拥有写权限。

### 5.2 画布下拉

下拉列出当前工作区的所有可读画布，显示图标、名称、自由／流式类型和当前项；数量较多时可搜索。每项的更多菜单承接重命名、删除等低频操作。底部 `＋ 新建画布` 打开统一新建对话框的“画布”页签。

切换画布保留各自视口；删除沿用已有预检、引用列表和“把画布内容移到数据树后再删除”路径。存在无权查看的引用时只提示存在受限引用，不暴露其内容。

### 5.3 协作入口

点击“协作”打开右侧协作面板，先复用 `PermissionsPanel` 的主体、权限预设和作用范围。拥有管理能力的人可授权／撤回；其他人只看对自己生效的授权。权限操作仍需联网，不进入离线待提交队列，也不进入普通文档撤销栈。

当前授权列表不等于在线成员列表。新增 presence 之后再显示“在线”页签、人数和成员所在画布。协作按钮负责管理访问权限，右上“分享链接”负责拿到可传播的访问地址。

## 6. 主菜单与统一对话框

### 6.1 主菜单结构

主菜单承担完整功能索引，常用功能同时保留快捷入口。二级菜单按任务组织，避免将所有按钮平铺成一长列。

```text
新建画布…                         打开“新建 / 画布”
新建…                             画布 / 工作区 / 模板
打开工作区…                       返回工作区列表
────────────────────────
插入 → 文本与便签 / 数据与媒体 / 布局 / AI / 工作区扩展
插入对象…                         打开可搜索对象目录
添加已有数据…                     只创建引用该数据的视图
────────────────────────
撤销 / 重做
复制 / 剪切 / 粘贴 / 删除          跟随当前编辑焦点和选择
────────────────────────
视图 → 对象工具栏 / 演讲工具栏 / 网格
       属性 / 引用与依赖 / 批注 / 修改状态
       恢复默认布局
缩放 → 25% / 50% / 75% / 100% / 150% / 200%
       适应全部 / 适应选区
画布模式 → 编辑 / 查看 / 路径编辑
开始放映…                         需要演讲路径（第三期规划 §7.2）
使用引导 ▸                        工作区有使用引导时可用（第三期规划 §7.3）
────────────────────────
导入工作区包… / 导出… / 创建工作区副本（Fork）
离线与同步 → 准备离线 / 接管副本 / 修改状态 / 导出本机未提交内容
开发工具 → 受控加工（Mock）        开发环境可见
帮助 → 快捷键与操作说明
────────────────────────
关闭工作区
```

菜单项根据当前模式、选区、权限和连接状态启用；禁用时解释原因。删除选中对象、删除画布、删除工作区必须使用不同文案，后者保留在工作区管理中。离线副本重建／删除等低频维护动作收进状态详情，保留现有数据丢失提示。

“视图”开关是个人偏好；主菜单入口和严重错误提示始终可达。“恢复默认布局”只重置工具栏／面板显示，不修改画布内容或清除未提交修改。菜单、按钮、右键和快捷键调用同一动作逻辑，避免出现不同的权限判断和提交次数。

### 6.2 新建对话框

| 页签 | 输入与行为 | 复用与新增 |
| --- | --- | --- |
| 画布 | 名称、自由画布／流式页、预设图标；创建到当前工作区，完成后切入新画布。 | 复用 `createSurfaceOps()`；画布与内容文件夹保持一次提交。图标依赖字段扩展。 |
| 工作区 | 工作区名称；成功后打开新工作区，进入新建第一张画布的引导。 | 复用 `ws.create` 和现有打开链路。 |
| 模板 | 模板名称、简短说明、预览、产出范围；选用后填写名称。 | 首批收录项目工作区样例、季度经营分析、AI 短片工作流。 |

**现有模板的产出范围是“新工作区”。** `createSampleWorkspace()` 和 `createDemoWorkspace()` 创建数据、画布、定义和依赖，不能直接重放到当前工作区。按钮写“从模板创建工作区”，成功后打开结果；已有工作区不被覆盖。支持“把模板添加到当前工作区”时，另行实现 ID、引用、资产和依赖的重映射，不在本轮入口搬迁中假定已经支持。

模板中的模拟内容保留明确标识；打开模板不自动运行许愿格。创建失败展示失败阶段和已创建结果的处理入口，避免用户重复点击后生成多个不明工作区。

### 6.3 插入对象对话框

对话框包括搜索、分类列表、对象说明／预览和创建操作；同一目录供主菜单、左侧“＋”和空白处右键使用。

- **标准对象：** 富文本、便签、表格视图、记录、图片／附件、框、形状、许愿格。面向用户使用这些名称，类型 ID 放在详情里。
- **已注册的样本对象：** 指标、柱状图、折线图、逐帧预览等保留“样本”标签，不与成熟标准对象混淆。
- **工作区扩展：** 从当前可读的 `buckyos.block-def` 取得具体定义，展示名称、版本、说明和支持的数据类型。HTML／声明式是宿主实现，不作为缺少定义的空对象直接插入。
- **已有数据：** 选择已有实体及适用渲染器，只创建视图；明确提示“与原视图共享数据，视图配置独立”。

目录优先复用 `BlockRegistry`、`insertChoices()`、`forSource()` 和定义校验，补充必要的展示分类。创建前检查 `accepts`、`allow_no_source`、默认尺寸、配置及定义可用性；缺少数据绑定时引导选择，不能先插入必然报错的对象。

### 6.4 复制、剪切、粘贴与删除

目前没有画布对象剪贴板，需要独立实现。首版范围限定为**同工作区的 Block／分组操作**，并明确数据引用语义：

| 操作 | 目标行为 |
| --- | --- |
| 复制／粘贴 | 新建 Block／分组身份，复制布局和视图配置；数据 Block 仍引用原数据。菜单／粘贴反馈说明“复制视图，共享数据”。独立数据副本不作为首版隐含行为。 |
| 剪切／粘贴 | 剪切时只标记待移动对象；粘贴时一次提交移动，保持对象身份和数据引用。取消、失败或目标无权限时原对象保留。 |
| 放置位置 | 右键粘贴使用点击位置；菜单／快捷键使用可视区中心并逐次偏移，避免重叠。跨画布剪切复用已有移动语义。 |
| 删除 | 复用当前删除与引用检查。明确告知可能同时删除只由这些视图使用的画布内容数据；仍被其他视图引用的数据保留。引用检查失败时展示可处理原因。 |

分组递归复制时为新 Block／分组分配 ID，并修正复制集合内的树关系与引用；文档写入经过同一 Store，粘贴／移动各形成一个撤销步骤。跨工作区粘贴需要完整导入与引用重映射，首版明确提示暂不支持。

焦点位于富文本、表格单元格、输入框或扩展内部编辑器时，由编辑器处理文本剪贴板；画布快捷键不得截获正在输入的文本。对象复制不承诺包含原对象的批注历史、运行历史或独立数据快照。

## 7. 左侧对象工具栏与 AI

### 7.1 竖排结构

从上到下分为：**选择／手形 → 标准对象（含 AI／许愿格）→ 本工作区扩展 → ＋全部对象 → 撤销／重做**。撤销／重做位于同一竖排工具栏底部，用分隔线与插入动作区分；许愿格入口在标准对象中适度强调。

标准对象优先露出富文本、便签、形状／框、表格、图片／附件，其余进入分组弹出面板。扩展数量较多时只展示用户固定的少量入口，其余通过“工作区扩展”目录访问；固定顺序属于用户偏好。

### 7.2 工具状态与插入

- 选择工具用于单选、多选、框选和对象拖动；手形工具只移动视图。当前模式持续高亮并切换指针形态。
- 保留空格临时平移和鼠标中键平移；空格松开后恢复原工具。`V`／`H` 切换选择／手形属于新增快捷键，且只在画布拥有焦点时生效。
- 选择对象类型后进入一次性放置状态，指针携带预览，点击画布创建，Esc 取消；完成后回到选择工具。弹窗“插入”可直接放到当前可视区中心，随后选中新对象。
- 基础文本、便签、框和形状使用默认标题，插入后直接进入适当编辑状态；替换当前阻塞式 `window.prompt()`。需要数据、文件或配置的对象先完成对应步骤。
- 新建数据对象和 Block 继续一次提交；已有数据只创建 Block。取消放置或对话框不能留下空实体。
- 权限不足、查看模式或服务停止同步导致不可写时，禁止插入和布局写入；工具提示说明原因。

### 7.3 许愿格入口

点击对象工具栏中的 AI／许愿格入口：选中许愿格时打开其现有任务界面；否则引导在当前画布创建许愿格，把当前画布、可视区和合适的选中数据作为上下文。复用 `WishService`、`WishPanel` 和已有候选预览，不另造一套聊天执行通路。

新入口只组织任务和上下文，不自动执行或自动应用候选。继续保留分析、执行、反馈、候选检查、应用和历史；手工修改保护、结果过期提示和整次应用可撤销的语义不变。离线时允许可持久化的任务描述编辑，依赖在线服务的执行按钮显示具体不可用原因。

## 8. 演讲工具栏与模式

### 8.1 演讲工具栏

**目标顺序：添加标注｜互动按钮（可多个）｜缩放比例 ▾｜当前身份＋其他在线头像｜分享链接。** 在普通编辑／查看场景中统一承接协作、缩放与视图导航；放映场景中按角色和本场配置调整。缩放操作收在比例控件的弹出面板中，保持工具栏紧凑。

| 控件 | 普通画布 | 放映场景与实施边界 |
| --- | --- | --- |
| 添加标注 | 优先复用现有批注：选中可批注内容后创建，未选择时进入目标选择；无 `comment` 能力不可写。 | 手写、激光笔和临时标记属于另外的演示交互，不能用持久批注冒充。 |
| 互动 | 只展示当前真正可用的操作；现阶段没有全局互动系统，不用空按钮占位。 | 演讲者配置可用互动；观众只看本场允许的按钮，可通过更多面板查看全部。遵循演示 PRD 的反馈、弹幕、答题规则。 |
| 缩放比例／视图导航 | 常驻显示比例，点击展开缩小／放大、比例预设与输入、适应全部／选区；统一使用当前画布的 Camera。 | 跟随主讲时显示跟随状态；自由浏览后在同一区域提供返回主讲视角。 |
| 当前头像 | 显示当前 principal 对应身份；资料不可用时用名称首字／默认头像。 | 身份菜单承接账户信息和退出登录；退出调用 Desktop 统一认证流程。 |
| 其他头像 | 只有 presence 可用后才展示真实在线成员；溢出显示 `+N`，点击打开在线列表。 | 演示中区分主讲、观众和同账号多设备，不把设备当成新增用户。 |
| 分享链接 | 访问链接定位当前工作区／画布，受既有权限约束。 | 演示分享复制本次 Presentation Session 的链接，不替换成原工作区编辑链接。 |

现有批注主要围绕数据对象、富文本范围、表格单元格等锚点工作。纯 UI 对象或画布空白点的标注需要补充对应锚点支持；接入前不把点选任意画布位置描述为已可用。

点击当前头像可进入包含“我的身份”和“在线成员”的面板，并提供退出登录。退出前复用工作区离开时的保存检查；开发直连身份不能伪装成具有正式登录／登出能力的 Zone 账号。

### 8.2 三种画布子模式与开始演示

| 状态 | 允许行为 | 工具显示 |
| --- | --- | --- |
| 编辑 `edit` | 根据能力编辑数据、插入、布局、批注。 | 完整创作入口、对象上下文工具与协作工具。 |
| 查看 `view` | 浏览和对象阅读交互；拥有批注能力时可批注。 | 隐藏创作、剪切／粘贴、布局删除等写入口；保留浏览、批注、协作。 |
| 路径编辑 `presentation_edit` | 编排演讲路径与使用引导：Frame、Viewport、步骤、舞台尺寸、转场、备注和说明（第三期规划 §7.1）。不修改其他 Block 的内容和布局。 | 左侧路径面板，画布上显示步骤取景框。 |
| 开始放映 | 第三期：非公开放映，舞台窗口加提示器链接（第三期规划 §8、§11）。公开演示房间、观众与回放属于第四期。 | 主菜单、视图工具栏与路径编辑中的“开始放映”。 |

“数据源／画布”是顶层工作视图，“编辑／查看／路径编辑”是画布子模式，实际放映是独立的舞台视图（第三期）或演示场次（第四期）。三者不得压缩成含义不清的三个并列按钮。主菜单提供完整切换，主工具栏可用紧凑标签提示当前子模式。

切换到查看时退出内容编辑和插入状态，保留可用的选区、视口、草稿与撤销历史；写操作入口仍受模式限制。真实放映中允许的互动写入要由场次与 Block 权限共同决定，不能直接沿用当前占位的“全部只读”策略。

### 8.3 链接与在线成员的新增依赖

- 分享链接是工作区的独立标签页地址 `/workspace/<工作区>?surface=<画布>&block=<对象>`（§4 规则 7、15-2），登录后恢复目标，打开后再次校验访问能力。
- 复制链接不自动授权，不包含认证 token；无权限的接收者看到明确的访问受限状态。现有 `doc.export(mode=share)` 继续叫“导出分享包”。
- 画布授权沿用现有工作区基础访问与 Surface／内容目录附加授权关系，UI 不承诺独立匿名画布分享。
- Presence 需要在线会话登记、心跳／过期、成员可见范围和断线状态。不能通过历史提交作者、授权主体或写锁推算在线人数。
- 演示长期链接、观众跟随、互动配置等按演示 PRD 分期接入；本次界面重排不宣称这些服务已经存在。

## 9. 演讲工具栏内的视图导航、对象上下文与操作反馈

### 9.1 比例控件与视图导航

演讲工具栏常驻显示 **缩放比例 ▾**，点击打开视图导航面板：

- `−／＋`、常用比例与自定义比例输入。
- “适应全部”“适应选区”；无选区时后者禁用。空画布执行“适应全部”恢复到 100% 和初始位置。
- 演示场景下的跟随状态和“返回主讲视角”，在演示能力接入后按场次权限显示。

沿用 `Camera` 当前 **5%～400%** 范围；演讲工具栏、主菜单中的缩放命令和画布手势共用同一个相机状态。按钮缩放以实际可视区中心为锚点，Ctrl／Cmd＋滚轮沿用指针锚点缩放。流式页不显示不适用的画布比例。

不增加独立缩放工具栏、右下角导航区或单独的导航显示开关。主菜单保留原稿中的缩放命令，作为功能索引及演讲工具栏隐藏时的入口；快捷键帮助统一放在“主菜单 → 帮助”。窄窗口中比例控件可进入演讲工具栏自身的更多菜单，仍不迁移到底部。

缩放和平移只改变用户视口，不提交文档、不产生撤销步骤。实时变化只更新相机及必要的比例读数，不让整个对象树逐帧重渲染；手势结束后继续使用现有节流保存机制。

### 9.2 对象上下文工具

复用 `NearToolbar`、对象 `actions` 和 Inspector，根据单选／多选及对象能力展示动作。常用动作靠近对象，完整动作在右键和更多菜单中：编辑内容、属性、批注、查看数据／依赖、增加视图、分组／解组、层级、移动到画布和删除。

对象没有对应能力时不展示无意义的通用按钮。未识别渲染器、扩展失败、数据不可读时继续在对象内部降级；宿主的选择、诊断和可用操作保持可用。状态信息优先说明“哪里不可用、如何处理”，类型 ID、版本、布局坐标等放入详情。

## 10. 保存、异常与关闭

保存、连接与离线状态放在工作区右下角的状态区。正常情况下只显示紧凑摘要；告警与提示叠放在摘要上方，以后可展开的工作日志也放在这里。点击摘要打开修改状态／离线与同步详情；不能为了视觉简洁删除现有恢复操作。

| 状态 | 画布上的呈现与动作 |
| --- | --- |
| 已提交／无未提交修改 | 小型成功状态，不常驻展开提交计数和传输细节。 |
| 未保存 | 显示未保存数量；输入还未持久化时不能显示为已保存。 |
| 已保存到本设备 | 明确“本设备”，可展开待提交队列、连接状态和导出入口。 |
| 需要处理 | 常驻警示和数量，点击定位到具体修改，保留重试、重新编辑或放弃路径。 |
| 本机写入失败／同步停止 | 显著且持续的错误提示，保留导出、重新打开等可行操作；不能仅作为自动消失的 Toast。 |
| 工作状态待同步 | 作为次要状态展示，不与文档未保存混在一起。 |

关闭工作区、切换工作区、退出登录和应用主动重新载入时，先结束当前编辑并等待可完成的保存。已安全提交或持久化到本设备的正常关闭不重复询问；确有仅在内存中的输入或保存失败时提供“返回处理／导出后离开”等选择。不得因隐藏修改面板而丢失草稿或跳过当前输入的 flush。

联机直连与离线副本仍由现有 Session 实现决定；工具栏不自行判断“浏览器在线就一定能写”。连接中、服务不可达、离线副本被其他窗口持有等区别在详情中可见，严重影响当前操作时在画布内明确提示。

## 11. 视觉与可访问性规范

以下为本轮设计起始值，按实际 Desktop 窗口宽度验证后调整：

| 项目 | 规范 |
| --- | --- |
| 边距与间距 | 工具栏距应用内容边缘 12px；组间 8px；组内采用统一间距。 |
| 面板 | 圆角 12px，1px 弱边框，轻阴影；浅色主题用白色／浅灰，深色主题跟随现有变量。 |
| 图标按钮 | 桌面点击区至少 36×36px，触控布局至少 44×44px；图标约 20px。 |
| 颜色 | 使用现有 `--cp-*` 变量；蓝色用于选择和主要动作，AI 可用独立强调色，状态同时有文字／图标。 |
| 背景 | 保留现有点阵作为默认网格，降低对比度并提供显示开关；网格变化不写文档。 |
| 文案 | 默认面向用户，避免在常驻工具栏展示 OPFS、Session ID、rev 等实现细节；详情仍可诊断。 |
| 焦点 | 所有图标有可访问名称、提示和清晰焦点环；菜单支持方向键、Enter、Esc；关闭后焦点回到触发按钮。 |

图标复用 Desktop 已有的 `lucide-react` 和既有组件能力，不为本轮抛光增加图标或 UI 依赖。

响应式按**应用容器**宽度适配：宽窗口展示双顶部面板；中等窗口先省略长名称、次要文字和溢出头像；窄窗口将次要动作收到更多菜单，侧面板变抽屉，竖排工具可折叠。以 1440、1024、768、390 CSS px 和浏览器 200% 缩放检查布局，不能让工具栏互相覆盖或出现无法关闭的弹窗。

画布快捷键只在对应 Workspace 活跃且焦点合适时触发；输入法组合输入期间不抢占键盘。沿用已有撤销／重做、删除、Enter 编辑、方向键移动、分组快捷键；新增选择／手形、对象剪贴板快捷键同时写入帮助面板。富文本、表格和 HTML 编辑器保留各自输入语义。

## 12. 状态归属与实现入口

### 12.1 状态归属

| 状态 | 存放位置／通路 |
| --- | --- |
| 画布名称、图标、对象内容、布局、批注 | 共享文档；通过 `WorkspaceStore.submit()`，服从权限、版本和撤销规则。 |
| 当前画布、模式、视口、网格、工具栏开关、面板偏好 | `UserWorkState`，IndexedDB＋服务端用户状态；不计入文档提交或导出。 |
| 最近工作区 | 新增应用级本机状态，按服务目标和身份隔离。 |
| 当前选区、菜单、悬停、未完成放置手势 | 当前窗口的 UI 状态；取消不留文档写入。编辑草稿继续交给现有编辑／保存机制。 |
| 在线成员、远端指针、跟随 | 待新增的 presence／演示会话通路，不写入文档历史。 |
| 访问授权 | 既有在线 `ws.grant`／`ws.revoke`；区别于文档编辑。 |

新增用户状态键先定义统一前缀和失效清理规则。既有 `pruneSurfaces()` 的匹配范围有限，实施时同时核对活动画布、各 Surface 视口及新增面板状态的恢复与清理，不能假定记录了就必然可正确恢复。

### 12.2 代码改动落点

## 16. 手机上的画布（2026-10-07）

手机上只提供画布，并且只能查看：工具栏只保留带缩放的查看工具，另加画布图标和本工作区的画布切换；画布操作参考 Miro 的移动端手势。

### 16.1 判定

主要指针是触摸（`pointer: coarse`）、并且屏幕短边小于 600 CSS px 的设备才算手机。平板和触屏笔记本仍使用完整的编辑布局，触摸手势照样可用（§16.3 末段）。判定依据是设备，不是窗口宽度：桌面上的窄窗口仍可编辑，§11 的尺寸档不变。

### 16.2 布局与模式

- **只有画布。** 不显示数据源视图；用户工作状态里的 `mode` 即使是数据源，手机上也进入画布。从批注、属性等处打开某项数据时，定位到显示它的 Block（优先当前画布）；如果没有 Block 显示它，就提示到电脑上查看。
- **只有查看模式。** 手机不读也不写 `canvas:mode`，所以在手机上打开不会改变电脑上的编辑/查看状态。
- **只有一条工具栏。** 演讲工具栏铺满顶部，最前面是画布切换器（当前画布图标、名称、▾），后面依次是批注、缩放比例、身份、分享，都只显示图标。主工具栏、主菜单和对象工具栏都不显示；“演讲工具栏”的显示偏好在手机上不起作用。
- **画布切换器。** 列出工作区的全部可读画布，只能切换，不能改名、删除或新建。面板顶部依次是工作区名、“切换工作区”（经过离开检查后回到工作区列表）和“手机上只能查看”的说明。
- 右侧面板一律以抽屉形式出现。就近工具栏和长按菜单里没有“复制”，因为手机上没有可以粘贴的地方。右下角的状态区保留。
- **视口。** 手机的视口单独记在 `phone-viewport:<画布>`，不会覆盖电脑的 `viewport:<画布>`。在手机上第一次打开某张画布时适应全部，比例最大 100%。切换画布仍然写 `surface:active`，所以电脑下次会回到这张画布。
- 工具栏和状态区避开 `env(safe-area-inset-*)`。工作区内禁止页面级双指缩放，因为 iOS 不遵守 `user-scalable=no`。

### 16.3 手势

| 手势 | 效果 |
| --- | --- |
| 单指拖动 | 平移画布；快速甩动后松手，画布继续滑行并逐渐减速。在已选中的 Block 上拖动时，滚动该 Block 自身的可滚动内容（例如表格）。 |
| 双指捏合／张开 | 以两指中点为中心缩放，同时跟随中点平移；抬起一指后，剩下的手指继续平移。 |
| 单击 | 选中手指下的 Block 并显示就近工具栏；点空白处取消选中。Block 内的按钮和链接照常响应点击。 |
| 双击 | 在 Block 上：缩放到该 Block。在空白处：以该点为中心放大 2 倍。两种情况都带动画。 |
| 双指轻点 | 以两指中点为中心缩小 2 倍。 |
| 长按（0.5 秒） | 打开该 Block 或该空白处的右键菜单，菜单始终留在屏幕内；不会出现浏览器自带的长按菜单和文字选择。 |

手势只改变视口或选区，不写文档，也不产生撤销步骤。

画布及其内部元素都设为 `touch-action: none`，触摸手势全部由画布自己处理；正在编辑的 Block 保留浏览器的默认触摸行为。非手机的触屏设备处于编辑模式时：单指从 Block 上开始拖动会移动该 Block（与鼠标一致），从空白处开始拖动则平移画布（不是框选）；双击 Block 进入编辑；双指手势与上表相同。

实现位置：`ui/canvas/render/touch.ts`（手势识别）、`RenderHost.tsx`（各手势的含义）、`camera.ts`（`animateTo`、`glide`）、`shellContext.ts`（`usePhone`）。验收用例为 `tests/aiworkspace/mobile.spec.ts` 的 UI-M01 和 UI-M02：在 Chromium 中仿真 Pixel 7，通过 CDP 输入真实的多点触摸。
