> 核心目标：**补齐为演示设计的 Frame，新增用于使用引导的 Viewport，用演讲路径混排两类对象；以“非公开放映”服务作者在本地检验放映效果，并提供网站式使用引导。** 简单、快速优先；协作问题在放映期间以关闭写入的方式处理。

## 1. 定位与两期边界

第三期、第四期是 Workspace 整体建设的阶段编号，分别对应演示能力建设的第一期、第二期。

已确认的产品口径：

- **Frame 的主要设计目的是演示。** 它定义一页演示的区域，可以保存演示属性，包括讲解备注。
- **Viewport 最常见的用途是使用引导。** 引导的形式与网站常见的新功能引导相同：逐步带用户看并配说明，不让用户在引导中操作。画布市场的作者可以随功能画布提供引导。
- **Viewport 只定义视觉中心和缩放比例。** 可见范围由引用它的演讲路径的舞台逻辑尺寸决定。
- **一个 Workspace 可以有多条演讲路径。** Frame、Viewport 可在路径中混排，例如 `frame1 → frame2 → viewport1 → viewport2 → frame3`。
- **每条路径有确定的舞台逻辑尺寸。** 默认 16:9，可以调整。路径中的 Frame 统一为该比例；编辑时提示只有舞台范围内的内容会被看到。
- **转场动画是写意的。** 过程流畅即可，不作为数据契约；到达后正确显示是唯一的硬要求。具体方案见 §9。
- **第三期的放映是非公开放映。** 它服务作者在本地检验放映效果。放映期间原作品对其他会话关闭写入；需要现场写入时使用临时克隆，放映结束自动清理。
- **讲解备注是 Frame／Viewport 的附加属性。** 只出现在提示器面板里。
- **提示器通过“提示器链接”提供。** 在任何浏览器打开该链接，即进入本场放映的演讲者控制面板，不依赖浏览器的多屏能力。
- 第四期负责公开演示房间、在线观众、过程记录和回放。

## 4. Frame：一页演示

### 4.1 结构

Cell 增加 `presentation` 键。键名与字段在 M0 冻结。

| 字段 | 适用 | 语义 |
| --- | --- | --- |
| `background` | Frame | 放映时这一页的背景色；缺省使用路径背景 |
| `notes` | Frame | 讲解备注，纯文本（保留换行），上限 16 KiB；只在提示器显示 |
| `caption` | Frame | 公开说明，纯文本；引导时显示在说明气泡里，放映时不显示 |
| `live` | 任意 Cell | “放映时可操作”，见 §10.2 |

- `background`、`notes`、`caption` 只允许出现在 `view.type = frame` 的 Cell 上，与连接线专属键的做法一致。
- 备注、说明都是普通字符串，不引用独立的 RichText 实体。这样它们不会出现在数据树里，也不会进入许愿格上下文，导出时可以直接去掉（§6.4）。
- 比例不单独保存，就是 `placement` 的 w/h。Frame 加入路径或路径舞台尺寸变化时，按路径比例调整 Frame：保持中心和宽度，一次提交，可以撤销。
- 同一 Frame 出现在比例不同的路径中时，显示诊断。放映时按“完整放入舞台”适配，以背景色补边。
- 放映不做旋转相机：演示中的 Frame 要求旋转为 0，已旋转的 Frame 显示可修正的诊断。
- 删除 Frame 只删除框，引用它的步骤变为失效项。

### 4.2 放映语义

- Frame 矩形映射为整块舞台；比例一致时正好铺满。
- 舞台以 Frame 矩形裁剪，部分相交的对象被裁切。Frame 的边框、标题条和编辑标记不显示。
- 裁剪只是显示效果，不代表成员关系，也不授予或限制权限。
- 放映期间原作品已关闭写入（§8.1），Frame 不会在放映过程中被别人改动。

## 5. Viewport：导航点

### 5.1 定义

新增数据实体 `buckyos.viewport`，放在系统容器 `shows` 中（§6.2）。payload 示例：

```json
{
  "surface_ref": { "entity_id": "sf-workflow" },
  "center": { "x": 1200, "y": 800 },
  "zoom": 1.25,
  "notes": "讲到这里时演示参数区",
  "caption": "在这里调整生成参数"
}
```

- `center` 是 Surface 世界坐标中的视觉中心。
- `zoom` 是世界单位到**舞台逻辑像素**的比例。可见范围是以 `center` 为中心、宽 `stage.w / zoom`、高 `stage.h / zoom` 的矩形，`stage` 取引用它的路径。
- 数值必须有限，zoom 为正数且在 0.05–4 之间。
- `notes`、`caption` 的含义同 Frame。
- Viewport 不保存 Frame 引用、矩形、可见性列表、动画或权限。
- 同一 Viewport 被舞台尺寸不同的路径引用时，可见范围会不同，路径编辑器显示诊断。

### 5.2 编辑

- **添加当前视角**：在当前画布可用区域的中央显示一个取景框，比例取路径舞台比例，并提示“只有框内的内容会被看到”。保存时，`center` 取取景框中心，`zoom` 取 `stage.w / 取景框的世界宽度`，同时追加步骤；一次提交，一次撤销。
- **调整**：在路径编辑中选中 Viewport 步骤，画布画出它的取景框。拖动框体改 `center`，拖角缩放改 `zoom`（保持比例）；Inspector 可以编辑备注和说明。
- 普通编辑和查看模式不绘制 Viewport。
- 只支持自由布局 Surface；流式 Surface 显示不支持的诊断。

### 5.3 统一取景与相机换算

每个步骤都先解析为一个世界矩形 R：

- Frame 取 `placement`。
- Viewport 取 `center ± (stage.w, stage.h) / (2 · zoom)`。

舞台在窗口中是一个按路径比例“完整放入”并居中的屏幕矩形 S，两侧留边。相机按“R 恰好填满 S”求出：`zoom_cam = S.w / R.w`，`camera.x = R.x − S.x / zoom_cam`，`camera.y = R.y − S.y / zoom_cam`。

窗口尺寸变化时只重算 S，R 不变。所以任何窗口、任何设备看到的取景内容都相同，只有补边多少不同。保存当前视角是同一换算的逆运算，不把编辑器相机的左上角直接当中心存储。

## 6. 演讲路径

### 6.1 定义

新增数据实体 `buckyos.show-path`，用户侧称“演讲路径”。一个 Workspace 可以有多条，例如“首次使用”“五分钟介绍”“完整演示”。

```json
{
  "title": "五分钟介绍",
  "purpose": "presentation",
  "stage": { "w": 1920, "h": 1080 },
  "background": "#ffffff",
  "steps": [
    { "id": "s1", "target": { "kind": "frame", "entity_id": "frame1" } },
    { "id": "s2", "target": { "kind": "frame", "entity_id": "frame2" } },
    { "id": "s3", "target": { "kind": "viewport", "entity_id": "viewport1" } },
    { "id": "s4", "target": { "kind": "viewport", "entity_id": "viewport2" }, "transition": "fade" },
    { "id": "s5", "target": { "kind": "frame", "entity_id": "frame3" }, "hide": ["cell-answer"] }
  ]
}
```

- `purpose` 为 `presentation` 或 `guide`，决定出现在“开始放映”还是“使用引导”入口；两者 schema 相同，运行语义见 §7.3 和 §8。
- `stage` 是舞台逻辑尺寸，预设 16:9（1920×1080）、4:3（1440×1080），也可以自定义。
- `background` 是舞台补边和 Viewport 步骤的背景。

步骤字段：

| 字段 | 语义 |
| --- | --- |
| `id` | 稳定的步骤身份；同一目标重复出现时，仍是不同的步骤 |
| `target` | `frame` 或 `viewport` 的类型化引用，不复制目标数据 |
| `title` | 可选的步骤标题；缺省使用目标标题 |
| `enabled` | 默认 true；跳过步骤时不删除对象 |
| `transition` | 进入本步骤的转场：`auto`（默认）、`fly`、`fade`、`cut`，见 §9 |
| `hide` | 本步骤隐藏的 Cell id，只用于放映；每次进入步骤都从“全部显示”重新计算，不累积 |

备注和说明属于目标对象，不在步骤上覆盖。同一个 Frame 出现两次时备注相同；需要不同的备注，就另建 Frame 或 Viewport。步骤只负责导航和显示，不自动执行提示词、运行 AI 或提交数据。

### 6.2 引用、存放与生命周期

- 新增系统容器 `shows`，与 `canvas-content` 同为 `data` 下的系统容器，存放路径和 Viewport。
  - 数据源视图默认折叠它。
  - 许愿格上下文不收录 `shows` 下的内容；许愿格工具读取 Cell 时，去掉 `presentation.notes`。
- `entity_refs` 为 `steps[].target` 建立索引，新引用类型为 `show_target`（非阻断），selector 为 `step:<id>`。Viewport 的 `surface_ref` 使用新引用类型 `show_surface`（非阻断）。
- 写入时校验目标存在、类型匹配、调用者可读。Frame 所在的 Surface 从 BlockTree 解析，必须是自由布局 Surface。
- 目标或 Surface 被删除后，步骤保留并标记失效。放映前列出失效项，默认跳过并提示；路径编辑器可以重绑或删除这些步骤。
- 复制步骤只复制引用；复制 Frame 或 Viewport 不会自动加入路径；删除路径不删除目标。

### 6.3 并发：按步骤命令自动重放

整个 `steps` 是一个键，写入时带 `expect`。路径编辑器把每次修改表达为按步骤 id 的命令，比如插入到某步之后、移动、删除、修改字段。

提交冲突时，编辑器读取最新的 `steps`，重放命令后重新提交，最多重试 3 次。只有命令依赖的步骤已被删除这类无法重放的情况，才进入“需要处理”。放映锁生效期间，路径本身也不可写。

### 6.4 导出导入

- 路径和 Viewport 随作品导出。导入保留实体 id（现有包语义），引用不需要重映射。
- 导出对话框增加“包含讲解备注”：
  - 个人备份默认包含；
  - 面向他人的导出（市场作品、分享副本）默认不包含，导出时去掉 Frame 的 `presentation.notes` 和 Viewport 的 `notes`。
- `caption` 是公开内容，总是保留。
- 用户状态（引导进度、编辑视角）本来就不导出，买家从头开始。打开作品不会自动调用模型。

### 6.5 版本

新增类型、Cell 键和系统容器，都要升级 FORMAT 与 PROTOCOL，服务、WASM 和前端同步。产品尚未上线，不迁移旧工作区：升级后已有工作区（包括 DV 上的测试工作区）无法打开，测试数据需要重建。

## 7. 编辑与入口

### 7.1 路径编辑

现有 `presentation_edit` 占位换成真实的路径编辑：

```text
路径列表／步骤列表       画布：Frame 与取景框、路径连线       步骤与目标属性
用途、名称、舞台尺寸     选中步骤时飞到该取景               标题、转场、隐藏对象
失效项与诊断            Viewport 取景框可拖动、缩放          备注、说明
```

- 这个模式只能创建、调整 Frame 和 Viewport，编辑路径；不能改其他 Block 的内容和布局。需要改内容时切回编辑模式，路径编辑的选择保留。
- 选中步骤时，画布飞到该步骤的取景，这本身就是预览。步骤列表不做内容缩略图。
- “添加当前视角”“添加 Frame”“新建 Frame 并加入”各是一次提交。拖拽、按钮和键盘排序调用同一套命令，都支持撤销。
- 修改舞台尺寸时提示，并用一次提交调整路径中所有 Frame 的比例；同时被其他路径引用的 Frame 给出诊断。
- 删除 `WorkspaceShell` 中把 `presentation_edit` 改回查看模式的回退逻辑。

### 7.2 放映入口

主菜单“开始放映…”：选择 `purpose = presentation` 的路径和起始步骤（默认第一步，或路径编辑中当前选中的步骤）。

放映是独立的顶层视图（`TopMode` 增加 `show`），不复用编辑态 `CanvasView` 的用户状态写入。退出后回到原来的画布、视角和子模式；原作品的 Store、撤销栈和待提交输入在放映期间一直保持存活。

### 7.3 使用引导：网站式导览

- **入口**：画布上的“使用引导”，只在存在 `purpose = guide` 的路径时显示。打开作品时可以提示一次，是否提示记在用户状态里。
- **画面**：引导在当前工作区窗口中运行。步骤取景按“完整放入”适配画布可用区域，取景外的区域变暗。说明气泡显示 `caption`、步骤序号，以及上一项、下一项、结束按钮。
- **不允许操作**：引导期间画布不接受操作，由遮罩拦截指针，键盘只用于导览。用户随时可以结束引导，停在当前位置正常使用。
- **进度**：进度存为用户状态 `guide:<path_id>`，下次可以继续。
- **不写文档**：不加锁，不克隆，不写文档；离线和手机上都可用（手机本来就只有查看）。
- **与放映的区别**：引导不显示备注；Frame 步骤不裁剪、不换背景，只高亮取景；`hide` 不生效。

## 8. 放映与数据归属

### 8.1 放映锁：关闭写入

- **加锁条件**：有工作区级写权限的用户开始放映时，对原作品加放映锁。
- **锁的效果**：放映期间，其他会话提交的文档写入一律被拒，错误码 `SHOW_LOCKED`，附带放映者和开始时间。其他会话包括协作者、本人的其他窗口，以及离线副本回传的写入。
  - 客户端把它当作可重试的错误，离线待发的写入保留到解锁后再发送。
  - 用户状态写入不受影响。
- **续期与释放**：锁由舞台窗口续期，建议每 20 s 续一次，60 s 过期。正常退出立即释放；窗口崩溃或断网时，锁在过期后释放。Owner 可以强制结束放映，沿用 `lock.break` 的语义。
- **只读用户**：没有写权限的用户也可以放映，但不加锁、不克隆，只读；内容可能在放映过程中被别人修改。
- **基线**：锁住之后原作品不再变化，基线就是锁定时的 head，不需要额外固定版本。
- **开始前的检查**：先结束活动编辑，等待未提交的写入完成。如果仍有“需要处理”的编辑，提示用户选择继续或取消。

### 8.2 两种放映

| | 只读放映 | 可操作放映 |
| --- | --- | --- |
| 触发 | 路径涉及的 Surface 上没有“放映时可操作”的 Block | 有这样的 Block |
| 数据 | 直接读原作品 | 原作品的临时克隆 |
| 启动 | 立即开始 | 克隆完成后开始 |
| 结束 | 释放锁 | 删除克隆，释放锁 |

两种放映的状态栏都提示“非公开放映：本场修改不会保存”。指针和板书不写文档（§10.3），所以只读放映也可以使用。

### 8.3 临时克隆

- **复制方式**：服务端在该工作区的写入互斥中，用 SQLite 备份接口（或 `VACUUM INTO`）把 `doc.sqlite`、`local.sqlite` 复制到新目录。然后改写工作区身份，并标记 `purpose = show`、来源工作区、show_id 和过期时间。
- **保留**：实体 id、seq/epoch、RichText lineage、授权，以及许愿格运行记录（运行目录用硬链接共享）。因此预演时准备好的许愿格候选可以在本场直接应用。
- **不保留**：用户状态、锁、上传会话。
- **对象共享**：资源、快照、程序这类对象一律按内容寻址存放。本期把 `FsObjectStore` 边界接入系统 named store：克隆只增加引用，不复制字节；删除克隆只解除引用。
- **可见范围**：克隆不出现在工作区列表、最近打开和离线准备中，只能由本场舞台打开。
- **清理**：放映结束立即删除；舞台失联导致锁过期时，由服务端删除；服务启动时清理所有残留的克隆。
- **性能**：M0 用现有性能样例（1 万行 × 20 字段的表格，加上资源）实测克隆耗时，目标不超过 1 s。超出时，启动界面显示进度。

### 8.4 离线

- 引导：离线可用。
- 放映：离线时只支持单窗口的只读放映，不加锁（无法加锁），不能生成提示器链接，也不能进行可操作放映。界面要明确说明这些限制，不显示成完整功能。

## 9. 转场动画方案

原则：转场是写意的。到达后的取景必须精确；中间过程只要求流畅、能看清方向。转场不进入数据契约：不版本化，也不要求按时间复现中间帧。

### 9.1 转场类型

| 类型 | 表现 |
| --- | --- |
| `fly` | 平滑飞行，中心和缩放同时变化。距离远时先拉远再推近（van Wijk–Nuij 平滑缩放），距离近时退化为直接平移加缩放 |
| `fade` | 舞台淡出到背景色（150 ms），切换取景，再淡入（150 ms） |
| `cut` | 直接切换 |

### 9.2 默认规则（`auto`）

| 情况 | 默认 |
| --- | --- |
| 同一 Surface，至少一端是 Viewport | `fly` |
| 同一 Surface，Frame → Frame | `fade` |
| 跨 Surface | `fade` |
| 放映开始的第一步 | `fade` |
| 系统设置了“减少动态效果” | `fly` 降为 `fade` |

- 步骤上的 `transition` 覆盖“进入该步骤”的转场。后退和目录跳转同样按目标步骤的设置，来源是当前画面。
- 跨 Surface 设为 `fly` 时也按 `fade` 执行，因为两张画布之间没有共同坐标系。
- 转场时长不提供配置。

### 9.3 飞行

- **路径**：起点和终点都表示为“中心加可见宽度”`(cx, cy, w)`，用 van Wijk–Nuij 平滑缩放求路径，ρ = 1.4。实现为一个纯函数 `flyPath(from, to) → { duration, at(t) }`，约 40 行，以 d3-interpolate 的 `interpolateZoom` 为参照，不引入依赖。
- **时长**：与路径长度成正比，限制在 0.4–1.2 s，系数在 M2 体验调参。缓动采用 ease-in-out。
- **Frame 的裁剪和背景**：离开 Frame 时，裁剪和背景在前 150 ms 淡出；到达 Frame 时，在最后 150 ms 淡入。全程不显示 Frame 的装饰。
- **途中显示**：飞行途中，经过的 Block 可以显示占位或简化形态；到达时目标取景内的 Block 必须完整显示。
- **刷新方式**：相机每帧只更新 CSS transform，不触发整幅画布的 React 渲染。放映舞台不使用编辑态的选择和手柄覆盖层。

### 9.4 到达时内容就绪

- 转场一开始，就把目标矩形内的 Block 设为固定挂载、完整 LOD，并预读它们的数据，不等相机停稳。
- 停留在某一步时，预读下一步的数据，但不挂载 HTML 运行时。
- `fade` 在画面被完全遮住时切换相机；等目标 Block 就绪后淡入，最多等 300 ms。
- 跨 Surface 时，舞台保留当前步骤和下一步骤的 Surface 挂载（最多两个），避免来回切换时整体重挂载。

### 9.5 打断与窗口变化

- **转场中再次翻页**：以最后一次命令为准。`fly` 从屏幕上当前的相机位置出发，开始新的飞行；`fade` 先立即完成当前切换，再开始新转场。旧动画的回调凭令牌作废，不会稍后把画面拉回去。
- **自由浏览**：放映中手动拖动或缩放画布，进入自由浏览，当前步骤不变；“回到本步骤”会飞回该步骤的取景。
- **窗口尺寸变化**：直接重算当前取景，不播放动画。

## 10. 放映中的操作

### 10.1 放映模式

- **基础**：放映模式以查看模式为基础。不显示编辑工具、对象工具栏、网格和选择框；不能改布局、插入、删除或批注。
- **独立于编辑态**：不读写编辑态的用户状态，包括 `canvas:mode`、`surface:active`、`viewport:*`、`ui:side`。编辑态的设置也不影响放映。
- **舞台控制条**：提供上一项、下一项、步骤目录、黑屏、指针、板书、复制提示器链接和退出。鼠标静止 2 s 后隐藏。单屏排练时，可以在控制条里展开当前步骤的备注。

### 10.2 可操作 Block

- **开关**：Cell 的 `presentation.live = true` 表示“放映时可操作”，在 Block 检查器中设置。只有这些 Block 在放映时开放编辑和运行入口，其余 Block 静态显示。
- **粒度**：只到 Block 和该 Block 声明的动作，不做字段级范围控制。
- **激活**：操作前先激活 Block，方式与编辑模式一致（双击或 Enter）。激活后键盘归该 Block，Esc 把键盘交还给放映。
- **写入**：放映使用克隆的 `WorkspaceStore`，HTML 桥和许愿格都绑定这个 store，因此所有写入都进入临时克隆，结束即丢弃。
- **许愿格**：可以在本场运行、预览、应用。克隆带上了原作品的运行记录，预演时准备好的候选可以直接应用，避免现场等待和重复花费。
- **HTML Block**：在舞台上显式激活后运行，未激活时显示快照或占位。舞台本身就是观众看到的画面，不存在第二个窗口的镜像问题。
- **媒体**：播放和暂停由主讲者操作，不随翻页自动播放。
- **实现**：`CanvasMode` 增加 `show`。`modePolicy` 在 show 模式下只对 live Block 开放写入。每个 `BlockAction.modes` 都要逐个确认在 show 模式下是否提供，默认不提供。

### 10.3 指针与板书

- **激光笔**：主讲者用鼠标、触控笔或触控在舞台上指出位置，轨迹会淡出，只存在于本场内存。
- **板书**：支持触控笔或鼠标书写、橡皮和撤销。笔迹以世界坐标保存在本场内存中，结构为笔画数组，记录点坐标、时间偏移和可选的压力，随画布缩放。翻页不清除笔迹，提供“清除板书”。
- **不落盘**：退出放映即丢弃，不写入文档，所以也不需要克隆。笔画结构与第四期的保存格式保持一致，第四期可以直接把它持久化。

### 10.4 按键归属

放映模式下，没有激活的 Block 时：

| 键 | 动作 |
| --- | --- |
| → ↓ PageDown Space Enter | 下一项 |
| ← ↑ PageUp Backspace | 上一项 |
| Home／End | 第一项／最后一项 |
| B 或 . | 切换黑屏 |
| Esc | 自由浏览时回到本步骤；否则退出放映 |

- 激活 Block 后，键盘全部交给该 Block，Esc 退出激活。
- 引导模式：→ 和 ← 用于翻页，Esc 结束引导，画布快捷键不生效。
- 编辑模式的快捷键保持不变。

## 11. 提示器链接

### 11.1 模型

- **舞台**：开始放映的窗口就是舞台，即观众看到的画面，也是本场状态的权威。双屏时，用户把舞台窗口全屏放到外接屏。在支持 Window Management API 的 Chromium 中，可以一键把舞台放到指定屏幕，这只是增强，不是前提。
- **链接**：放映开始后生成提示器链接 `https://<zone>/workspace/<workspace_id>/show/<show_id>#k=<token>`。在任何浏览器（本机另一个窗口、手机、平板、另一台电脑）打开，都进入本场的演讲者控制面板。
  - 令牌放在 `#` 之后，不会进入服务端访问日志和 Referer。
  - 舞台控制条提供复制链接。二维码需要新依赖，另行确认，第三期可以不做。
- **链接即能力**：持有链接的人可以控制本场翻页，并看到备注；本场结束后链接立即失效；不需要登录。已知风险：链接泄露期间，他人可以翻页和读取备注。第三期接受这个风险，第四期接入身份授权。

### 11.2 控制面板

- **内容**：当前步骤的标题和备注（大字号，可调）、下一步标题、步骤目录、已用时间；操作有上一项、下一项、跳转、黑屏、回到本步骤。
- **小屏幕**：屏幕较小（手机）时只显示面板，不渲染画布。
- **大屏幕**：屏幕较大且能读取该工作区（例如同机已登录）时，背景渲染当前步骤的只读画面，面板叠在上面。不能读取时只显示面板。
- **多个提示器**：可以同时打开多个提示器。关闭任何一个都不影响放映。
- **路由**：提示器路由 `/workspace/:id/show/:showId` 在 `main.tsx` 的登录检查之前分流，只有需要背景画面时才初始化工作区会话。

### 11.3 中继

aiworkspace 服务在内存中维护本场放映：

| 方法 | 调用方 | 作用 |
| --- | --- | --- |
| `show.start` | 舞台 | 加锁、按需克隆，返回 show_id、提示器令牌和克隆工作区 id |
| `show.heartbeat` | 舞台 | 续期放映锁和克隆 |
| `show.publish` | 舞台 | 发布最新状态，带递增的 `seq` |
| `show.command` | 提示器、舞台 | 发送命令，带 `command_id` 用于去重 |
| `show.watch` | 双方 | 长轮询：取 `seq` 之后的状态，或某个游标之后的命令 |
| `show.notes` | 提示器 | 凭令牌读取路径中各步骤的标题和备注 |
| `show.end` | 舞台 | 释放锁、删除克隆，令牌失效 |

- 舞台执行命令后发布新状态。提示器只显示舞台发布的状态，不自行推算。
- 舞台刷新后，从 `show.watch` 取回最新状态继续放映；前提是锁和克隆仍在有效期内。
- 中继状态只在内存中，服务重启即结束本场；第三期接受这一点。
- `show.*` 方法除了会话认证，也接受提示器令牌认证；令牌只能调用 `show.command`、`show.watch` 和 `show.notes`。

## 12. 放映状态与命令入口

- **命令**：所有控制入口（键盘、舞台控制条、提示器、触控）都生成命令 `{ command_id, kind, args }`，交给舞台上的放映控制器。控制器校验后更新状态，再发布出去。
- **状态**：状态是一个可序列化的小对象，例如 `{ show_id, path_id, path_rev, step_id, free_camera?, black, pointer?, seq }`。板书不进入中继状态，只留在舞台上。
- **转场**：只记录目标步骤和实际采用的转场类型，不记录中间帧（§9）。
- **终端用途与身份**：终端用途（`stage`、`prompter`）与身份分开管理，不放在同一个枚举里。
- **不建设**：第三期不建设事件日志、持久化和回放。状态对象和命令格式是第四期房间的输入。
